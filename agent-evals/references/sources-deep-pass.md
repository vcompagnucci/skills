## Resolved conflicts

- **Judging every ticket.** AWS (2026-07-23) replaces judging every live ticket (Lorikeet, 2026-06-09): code checks run on every ticket, frozen judges on a random sample sized from the interval, with a cap per run. Judge every ticket only where each one triggers its own action.
- **The noise band.** ±1/√(cases × runs) is the within-case special case; clustered standard errors over per-case means replace it whenever per-case pass rates spread (Anthropic, Miller 2024; Bowyer et al. 2025 for small samples).
- **Generated rubrics.** Google and Microsoft (2026) recommend LLM-generated rubrics as the primary measure. Rule 1 stands: a generated rubric is a list of candidate checks the expert edits, each surviving item its own validated binary check.
- **Automated judge tuning.** The two-revision cap governs manual edits made while reading dev disagreements. An optimizer (GEPA) is allowed only with separate train, dev, and test, and its frozen result is scored once on test (Hamel Husain and Shreya Shankar, Shopify, 2026-09).
- **One change per attempt.** Anthropic (2026-09-29) allows one breadth pass over many small independent buckets, and a re-read of the rubric when a bucket stalls for three rounds.
- **Corrected rates.** The course bootstrap (2026-09-30) stays for the corrected rate over the closed-form alternative.
