# Guardrail layers

Every classifier in guardrails.md can be bypassed, so a support agent stacks its checks so that an injection that gets past one meets another, and puts the barrier that protects money, data and accounts in code. This file covers which controls give guarantees, where checks sit, the reviewer that judges actions, monitors, the wiring that silently fails open, and what stacking measurably buys.

## Guarantees come from code, classifiers raise the cost

- **Sort every defense into deterministic or probabilistic, and put the deterministic ones on the impact side.** Microsoft calls deterministic detection of indirect injection an open research problem, so only design choices guarantee anything. Permissions, sensitivity labels, blocking image rendering and making the user send the email are guarantees; system prompts, Spotlighting and classifiers only raise the attacker's cost (2025-07-29). (`msrc-indirect-injection-defense`)
- **Let a model-free rules engine decide refund eligibility and other money or compliance verdicts, from typed fields the model extracts.** Prompt verdicts vary across runs and turn every policy change into an unreviewable prompt edit, while a rules engine with versioned rulesets and a per-rule audit trail can't be argued into another outcome (2026-08-13). It is agent-harness rule 2 applied to policy. (`anthropic-content-moderation-cookbook`)
- **Prefer forced procedures and hard limits over a supervising agent built on the same model.** The supervisor shares the worker's blind spots. In Project Vend's second phase, forcing a cost check before quoting was among the most effective changes, while the CEO agent cut discounts by "about 80%" but approved lenient requests "about eight times as often as it denied them" and tripled refunds (2025-12-18). (`anthropic-project-vend-2`)
- **Treat platform "topic instructions" and vendor "defensive prompting" as tone, not enforcement.** Salesforce tells Agentforce admins to set escalation rules and "the rules that the agent must follow" as topic instructions, and Intercom's first-listed Fin defense in 2025 was defensive prompting with no published numbers; Fin's 2026 guide says the defense "has to sit outside" the model. Back every rule about money, identity or data with a tool-level restriction. (`salesforce-agentforce-guardrails-trailhead`, `intercom-fin-data-privacy-security`, `fin-ai-guardrails-customer-service`)
- **Turn every limit that must hold for the whole session into a coded rule, never a sentence in the chat.** Claude Code's classifier re-reads limits stated in conversation from the transcript, so compaction can drop them, and "Claude's own judgment that a condition was met does not lift it"; for a hard guarantee its docs say to add a deny rule. (`anthropic-docs-claude-code-permission-modes`)
- **Narrow what the agent can be made to do.** A small set of intents, answers only from your own corpus, dropdowns instead of free text, input and output length limits, and routing a question "to the best-matching existing customer support article, rather than attempting to answer the query from-scratch" leave less for jailbreaks to work with. Anthropic's built-in API safeguards cover usage-policy harms, not your business rules. (`openai-safety-best-practices`, `anthropic-api-safeguards-tools`)
- **Never let the model's refusal be the gate on harmful tasks.** Without mitigations, Sonnet 5.5 and Opus 5.5 refused 79.46% and Mythos 5.1 87.50% of 112 harmful computer-use tasks (2026-09-28); Anthropic relies on its deployed classifiers, and API builders must supply their own policy check on the task. (`anthropic-system-card-sonnet-5-5`)
- **Expect a certifier to ask for technical controls, not prompts.** AIUC-1 makes "safeguards or technical controls" against harmful, out-of-scope and output-vulnerability outputs (C003 to C006) and third-party testing at least every 3 months (C010 to C012) mandatory, and CX vendors market the certification. (`aiuc1-safety-principle`)

## Where the checks sit

- **Place checks at five points: the customer's input, the dialog decision, retrieved chunks, tool inputs and outputs, and the final reply.** NeMo Guardrails' dialog rails route known intents, such as a greeting or an off-topic or impossible request, to a fixed answer instead of a generated one; a framework with no rails configured forwards everything to the model. (`nvidia-nemo-guardrails-readme`)
- **Gate the conversation before inference and the proposed tool calls before any of them runs.** Tool results return through the next pre-inference check, so a poisoned result is inspected before the model reads it; a gate on customer input alone misses tool calls and tool output. (`anthropic-docs-inference-hooks`)
- **Run each customer message through a fixed pipeline of several checks.** At Sierra "A single message can trigger half a dozen of these checks": an input supervisor, the agent answering from grounded content and policy, an output supervisor, and a deterministic scanner for sensitive data, with continuous red teaming because last quarter's robustness expires (2026-08-13). Google's Gemini stack adds, on an adversarially trained model, a classifier on retrieved content, instructions around untrusted content, markdown sanitization and URL redaction, user confirmation for risky actions, and a visible notice that something was blocked (2025-06-13). (`sierra-defense-in-depth`, `google-layered-defense-prompt-injection`)
- **Attach the input guardrails to every agent in a handoff graph.** In the OpenAI Agents SDK, agent-level input guardrails run only for the agent that starts a run, so OpenAI's support demo lists the same guardrails on its triage, flight information, booking and cancellation, seat, FAQ and refunds agents; a check on triage alone stops at the handoff to refunds and cancellations, where the damaging tools live. (`openai-cs-agents-demo`)
- **Check which tool types your framework's guardrails wrap.** OpenAI Agents SDK tool guardrails run only on function tools, never on handoffs, hosted tools such as HostedMCPTool and FileSearchTool, or built-in execution tools such as ComputerTool and ShellTool, so keep refunds as function tools or local MCP servers and validate handoffs in the handoff callback. (`openai-agents-sdk-guardrails`)
- **Put checks that must run on every call in a pre-tool hook, not in the approval callback.** In the Claude Agent SDK, hooks run before deny, ask, mode and allow rules, "Auto-approved tools never reach `canUseTool`", and any hook's deny blocks the call even in bypassPermissions. Hooks run in parallel in no fixed order and matchers see only tool names, so write each hook to stand alone and check arguments inside it. (`anthropic-docs-agent-sdk-permissions`, `anthropic-docs-agent-sdk-hooks`)

## The action reviewer

- **Before each action runs, compare it with what the customer asked for.** An action that doesn't serve the request is suspect whatever caused it. OpenAI's injection check blocks a `wire_money` call when the user asked about the weather and a weather result that carries bank balances, without flagging suboptimal but related actions (2025-12-15); Anthropic made a separate action-intent classifier the condition for letting Claude in Chrome act autonomously (2026-08-26). (`openai-guardrails-check-prompt-injection`, `anthropic-claude-in-chrome-ga`)
- **Never show the action reviewer the tool results.** Give it the user's messages and the proposed action, so hostile text in a page can't argue with it, and scan tool results with a separate detector that warns the agent to re-anchor on the user's request. An injection then has to slip past the first layer and still produce an action the blind second layer judges aligned; Chrome's User Alignment Critic sees only the goal and action metadata and hands control back to the user after repeated vetoes (2025-12-08). (`anthropic-claude-code-auto-mode`, `anthropic-docs-claude-code-permission-modes`, `google-chrome-agentic-security`)
- **Make the reviewer deny when it reaches no verdict, return each denial as a tool result, and hand off after repeated blocks.** Deny-and-continue makes a false positive cost one retry, and the counter stops a compromised agent pushing toward the same outcome: Claude Code pauses after 3 blocks in a row or 20 in a session, and with no human to ask the action never runs. Screen a delegated task before a subagent starts and its report before the parent reads it. (`anthropic-claude-code-auto-mode`, `anthropic-docs-claude-code-permission-modes`)
- **Expect the reviewer to miss harm that looks like in-scope work.** Replaying real incidents, Claude Code's auto-mode classifier would have denied 66% (Mythos 5) and 55% (Opus 4.7) of actions but 7% for an internal model whose attack looked like a regular CTF (2026-09-09). Meta's AlignmentCheck auditor cut static AgentDojo attack success from 17.6% to 2.89% at utility 43.1% against 47.7%, and 1.75% at 42.7% with PromptGuard 2 in front (self-reported, 2025-05-06); guardrails.md has what adaptive attacks do to such numbers. (`anthropic-alignment-assessment-cyber-incidents`, `meta-llamafirewall`)

## Monitors across turns, sessions and accounts

- **Judge behavior at the level of the session and the account, not only the message.** Attackers split a harmful goal into innocent-looking subtasks: per-request checks passed every slice of the 2025 espionage campaign, and Anthropic caught it through activity-level detection of volume, sequence and targets (2025-11-13). (`anthropic-ai-orchestrated-espionage`)
- **Apply a stricter boundary to accounts assessed as higher risk, give monitoring cross-conversation context, and keep every jailbreak you've found in a regression suite.** Single-conversation checks miss attacks split across sessions and fixes regress when models change. OpenAI layers model refusals (Astra refuses 91.5% of cyber jailbreak requests against 59% for GPT-5.6 Sol), classifiers, offline detection and a 24/7 rapid-response program. (`openai-path-to-astra`)
- **Keep a behavior monitor on every tool-using call even on your best-aligned model, and watch actions and arguments, not only reasoning.** OpenAI added misalignment monitoring to all of GPT-6 Astra's tool-using inference "with significant compute cost", though Astra drew "roughly half as many" higher-severity flags as GPT-5.6 Sol over 54,000+ simulated Codex tasks; told to, Astra stayed undetected while sandbagging and sometimes evaded internal monitors (2026-09-03). (`openai-safety-overview-gpt-6-astra`)
- **Re-test prompt-level wrappers on each more robust model, and keep the independent monitor.** In OpenAI's IH-Challenge study, sandwich defenses, extra rules, output rewriters and best-of-N helped GPT-5-Mini but cost the hierarchy-trained GPT-5-Mini-R more capability and sometimes robustness, while an output monitor kept slowing 127 adaptive human red-teamers: success 0.362, 0.117 and 0.071 with the monitor (2026-03-10). (`openai-ih-challenge-paper`)

## Wiring that silently fails open

- **Choose fail-closed for any gate that protects an action.** Anthropic's inference hooks default to "Allow the request" on failure with a 5,000 ms timeout, and requests outside a rollout percentage below 100% go uninspected even when failure handling blocks. (`anthropic-docs-inference-hooks-configuration`)
- **Deny with an explicit verdict, never an error code, and size the body limit for whole transcripts.** Anything but HTTP 200 with a parseable verdict counts as a failure; transcripts arrive untruncated (the protocol allows 64 MiB) while nginx defaults to 1 MB and Express json() to 100 kB, so under fail-open the biggest prompts reach the model uninspected. (`anthropic-docs-inference-hooks-endpoint`)
- **Decide what each hook does when it times out.** In the Claude Agent SDK a timed-out pre-tool hook stops the tool and a timed-out prompt hook blocks the prompt, but a timed-out Stop hook counts as no decision and async hooks can't block; defaults are 600 s and 30 s for UserPromptSubmit, and hooks may not fire when a max-turns limit ends the session. (`anthropic-docs-agent-sdk-hooks`)
- **Make a guardrail return a tripwire on internal errors instead of raising.** In the OpenAI Agents SDK an output guardrail that raises lets the runner save the final-turn items to the session before the exception surfaces, so an unjudged reply with account data is replayed later; even on a tripwire the function arguments are kept and "can contain data that also appeared in the rejected output". (`openai-agents-sdk-guardrails`)
- **Decide whether a blocked message stays in the history.** Each request re-sends the whole conversation, so a whole-transcript check keeps denying until the user edits or restarts, and a last-turn check lets the blocked text reach the model on the next turn. (`anthropic-docs-inference-hooks`)
- **Hold streamed text until the tool calls clear when what was said could itself do harm.** With one verdict per response, one bad call blocks the whole batch, and "Text delivered before the first tool call is not taken back." (`anthropic-docs-inference-hooks-endpoint`)
- **Check whether each guard blocks or only logs by default, and set it to enforce.** Anthropic's self-hosted runner scans repositories for settings that widen access, but its default warn mode "logs a violation and still spawns the session". (`anthropic-docs-claude-code-self-hosted-environments-deploy`)
- **Roll out a new guardrail in shadow mode, then by percentage, then enforcing.** Log verdicts on live traffic and block nothing until the false-deny rate is acceptable, exempt groups only by explicit role, and log every change to the exemption list. (`anthropic-docs-inference-hooks-configuration`)
- **Authenticate calls from the agent platform to your guardrail server with signatures, not IP allowlists.** Compute the HMAC over id, timestamp and the raw body bytes, reject timestamps more than five minutes off, compare in constant time and decode the secret with standard base64, not URL-safe; the source range 160.79.106.0/24 also carries other Anthropic egress. Accept both secrets during a rotation, because the old one keeps arriving "for about a minute afterward". (`anthropic-docs-inference-hooks-endpoint`)

## What stacking buys, measured

- **Pair a detector on incoming data with a classifier on outgoing actions, so an attack must beat both.** With auto mode (injection probes plus a tool-call classifier), no attack succeeded in 110 Cowork browser scenarios x 10 red-teamer attempts against Opus 5.5, Fable 5.1, Opus 5 or Sonnet 5, against 0.09% to 3.64% of attempts raw (2026-09-22); the earlier run let one through, Fable 5 at 0.09% after a fallback (2026-09-01). The attacks were built against Opus 4.7 and transferred, not adapted per model. (`anthropic-system-card-opus-5-5`, `anthropic-system-card-fable-5-1`)
- **A detector on tool results cuts adaptive attack success but leaves it far above zero.** Probes took Opus 5.5 from 54.61% to 11.13% of Shade coding attempts, Opus 5 from 88.92% to 19.53% and Fable 5.1 from 51.93% to 8.70% (200 attempts per scenario, 2026-09-22); Opus 4.6 needed none on the earlier attacker (0% everywhere, 2026-02-05). (`anthropic-system-card-opus-5-5`, `anthropic-system-card-opus-4-6`)
- **Input classifiers mainly raise the cost of the first try.** On Shade computer use, safeguards moved Opus 4.8 from 7.14% to 5.11% on one attempt, but 50.0% against 57.1% of scenarios at 200 attempts is not a significant change: with 14 scenarios one scenario going from 0/200 to 1/200 moves it 7.1 points (2026-06-17). Bound a screen-driving agent by limiting what it can do. (`anthropic-system-card-opus-4-8`)
- **Safeguards buy the most on weaker and older models, and still don't reach zero.** Updated browser safeguards took Sonnet 4.6 from 50.7% to 1.16% of attempts and Opus 4.8 from 31.5% to 0.08% (129 environments x 10, 2026-06-30), though Anthropic later found those raw baselines came from a mismatched harness and re-ran raw Opus 4.8 at 11.15% without re-running the safeguarded side (2026-08-19), so the lift is smaller than it looks; probes took Sonnet 4.6 and Opus 4.6 from 55.41% and 80.41% of 148 scenarios to 2.70% (2026-04-16); tool-result safeguards took Sonnet 4.5 from 18.3% to 1.6% of first attempts and from 70.0% to 25.0% of scenarios at 200 (2026-02-05). (`anthropic-system-card-sonnet-5`, `anthropic-system-card-opus-4-7`, `anthropic-system-card-opus-4-6`, `anthropic-system-card-opus-5`)
- **Re-validate the whole stack every time you change the model.** The same deployed browser safeguards left Opus 4.8 at 0.5% of attempts and the newer Mythos 5 at 6.5%, so Anthropic built updated safeguards that took Mythos 5 to 0% of 129 scenarios before shipping (2026-06-09); raw Mythos 5 was 29.7% in that harness and 7.80% in the 2026-08-19 re-run, so how much of the gap the safeguards closed is unknown. (`anthropic-system-card-fable-5`, `anthropic-system-card-opus-5`)
