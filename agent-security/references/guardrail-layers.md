# Guardrail layers

Every classifier in guardrails.md can be bypassed. A support agent therefore stacks its checks, so an injection that gets past one meets another, and puts the barrier that protects money, data and accounts in code. This file covers which controls give guarantees, where checks sit, the reviewer that judges actions, monitors, the wiring that silently fails open, and what stacking measurably buys.

## Guarantees come from code, classifiers raise the cost

- **Sort every defense into deterministic or probabilistic, and put the deterministic ones on the impact side.** Microsoft calls deterministic detection of indirect injection an open research problem, so only design choices guarantee anything. Permissions, sensitivity labels, blocking image rendering and making the user send the email are guarantees. System prompts, Spotlighting and classifiers only raise the attacker's cost (2025-07-29). (`msrc-indirect-injection-defense`)
- **Let a model-free rules engine decide refund eligibility and other money or compliance verdicts, from typed fields the model extracts.** Prompt verdicts vary across runs and turn every policy change into an unreviewable prompt edit. A rules engine with versioned rulesets and a per-rule audit trail can't be argued into another outcome (2026-08-13). This is agent-harness rule 2 applied to policy. (`anthropic-content-moderation-cookbook`)
- **Prefer forced procedures and hard limits over a supervising agent built on the same model.** The supervisor shares the worker's blind spots. In Project Vend's second phase, forcing a cost check before quoting was among the most effective changes. The CEO agent cut discounts by "about 80%", but it approved lenient requests "about eight times as often as it denied them" and tripled refunds (2025-12-18). (`anthropic-project-vend-2`)
- **Treat platform "topic instructions" and vendor "defensive prompting" as tone, not enforcement.** Salesforce tells Agentforce admins to set escalation rules and "the rules that the agent must follow" as topic instructions. Fin's 2026 guide says the model "cannot reliably separate instructions from content, so the defense has to sit outside it". Back every rule about money, identity or data with a tool-level restriction. (`salesforce-agentforce-guardrails-trailhead`, `fin-ai-guardrails-customer-service`)
- **Turn every limit that must hold for the whole session into a coded rule, never a sentence in the chat.** Claude Code's classifier re-reads limits stated in conversation from the transcript, so compaction can drop them, and "Claude's own judgment that a condition was met does not lift it". For a hard guarantee, its docs say to add a deny rule. (`anthropic-docs-claude-code-permission-modes`)
- **Narrow what the agent can be made to do.** Use a small set of intents, answers only from your own corpus, dropdowns instead of free text, and input and output length limits. Route a question "to the best-matching existing customer support article, rather than attempting to answer the query from-scratch". Each of these leaves less for jailbreaks to work with. Anthropic's built-in API safeguards cover usage-policy harms, not your business rules. (`openai-safety-best-practices`, `anthropic-api-safeguards-tools`)
- **Never let the model's refusal be the gate on harmful tasks.** Without mitigations, Sonnet 5.5 and Opus 5.5 refused 79.46% and Mythos 5.1 87.50% of 112 harmful computer-use tasks (2026-09-28). Anthropic relies on its deployed classifiers. API builders must supply their own policy check on the task. (`anthropic-system-card-sonnet-5-5`)
- **Expect a certifier to ask for technical controls, not prompts.** AIUC-1 requires "safeguards or technical controls" against harmful, out-of-scope and output-vulnerability outputs (C003 to C006). It also requires third-party testing at least every 3 months (C010 to C012). CX vendors market the certification. (`aiuc1-safety-principle`)

## Where the checks sit

- **Place checks at five points: the customer's input, the dialog decision, retrieved chunks, tool inputs and outputs, and the final reply.** NeMo Guardrails' dialog rails route known intents, such as a greeting or an off-topic or impossible request, to a fixed answer instead of a generated one. A framework with no rails configured forwards everything to the model. (`nvidia-nemo-guardrails-readme`)
- **Gate the conversation before inference and the proposed tool calls before any of them runs.** Tool results return through the next pre-inference check, so the gate inspects a poisoned result before the model reads it. A gate on customer input alone misses tool calls and tool output. (`anthropic-docs-inference-hooks`)
- **Run each customer message through a fixed pipeline of several checks.** At Sierra "A single message can trigger half a dozen of these checks": an input supervisor, the agent answering from grounded content and policy, an output supervisor, and a deterministic scanner for sensitive data. Red teaming runs continuously, because last quarter's robustness expires (2026-08-13). Google's Gemini stack starts from an adversarially trained model. On top it adds a classifier on retrieved content, instructions around untrusted content, markdown sanitization and URL redaction, user confirmation for risky actions, and a visible notice that something was blocked (2025-06-13). (`sierra-defense-in-depth`, `google-layered-defense-prompt-injection`)
- **Attach the input guardrails to every agent in a handoff graph.** In the OpenAI Agents SDK, agent-level input guardrails run only for the agent that starts a run. So OpenAI's support demo lists the same guardrails on its triage, flight information, booking and cancellation, seat, FAQ and refunds agents. A check on triage alone stops at the handoff to refunds and cancellations, where the damaging tools live. (`openai-cs-agents-demo`)
- **Check which tool types your framework's guardrails wrap.** OpenAI Agents SDK tool guardrails run only on function tools. They never run on handoffs, hosted tools such as HostedMCPTool and FileSearchTool, or built-in execution tools such as ComputerTool and ShellTool. Keep refunds as function tools or local MCP servers, and validate handoffs in the handoff callback. (`openai-agents-sdk-guardrails`)
- **Put mandatory checks at a layer that auto-approved calls can't skip, and check arguments inside each check.** In the Claude Agent SDK that layer is a pre-tool hook, not the approval callback. Hooks run before deny, ask, mode and allow rules, "Auto-approved tools never reach `canUseTool`", and any hook's deny blocks the call even in bypassPermissions. Hooks run in parallel in no fixed order and matchers see only tool names, so write each hook to stand alone and check arguments inside it. (`anthropic-docs-agent-sdk-permissions`, `anthropic-docs-agent-sdk-hooks`)

## The action reviewer

- **Before each action runs, compare it with what the customer asked for.** An action that doesn't serve the request is suspect whatever caused it. OpenAI's injection check makes this comparison but also reads tool output. That makes it the tool-result detector of the next bullet, not the blind action reviewer. It blocks a `wire_money` call when the user asked about the weather, and a weather result that carries bank balances, without flagging suboptimal but related actions (2025-12-15). Anthropic made a separate action-intent classifier the condition for letting Claude in Chrome act autonomously (2026-08-26). (`openai-guardrails-check-prompt-injection`, `anthropic-claude-in-chrome-ga`)
- **Never let tool results authorize an action at the real-time action reviewer, and back the reviewer with a separate tool-result detector.** Anthropic's reviewer gets only the user's messages and the proposed action, so hostile text in a page can't argue with it, and whether to show it tool results at all is a vendor tie (end of this file). Scan tool results with a separate tool-result detector that warns the agent to re-anchor on the user's request. An offline monitor (response.md) is a third component and does read them. An injection then has to slip past the first layer and still produce an action the blind second layer judges aligned. Chrome's User Alignment Critic sees only the goal and action metadata, and it hands control back to the user after repeated vetoes (2025-12-08). (`anthropic-claude-code-auto-mode`, `anthropic-docs-claude-code-permission-modes`, `google-chrome-agentic-security`)
- **Make the reviewer deny when it reaches no verdict, return each denial as a tool result, and hand off after repeated blocks.** Deny-and-continue makes a false positive cost one retry, and the counter stops a compromised agent pushing toward the same outcome. Claude Code pauses after 3 blocks in a row or 20 in a session. With no human to ask, the action never runs. Screen a delegated task before a subagent starts, and its report before the parent reads it. (`anthropic-claude-code-auto-mode`, `anthropic-docs-claude-code-permission-modes`)
- **Expect the reviewer to miss harm that looks like in-scope work.** Replaying real incidents, Claude Code's auto-mode classifier would have denied 66% (Mythos 5) and 55% (Opus 4.7) of actions. For an internal model whose attack looked like a regular CTF, it would have denied 7% (2026-09-09). Meta's AlignmentCheck auditor cut static AgentDojo attack success from 17.6% to 2.89% at utility 43.1% against 47.7%, and to 1.75% at 42.7% with PromptGuard 2 in front (self-reported, 2025-05-06). What adaptive attacks do to such numbers is in guardrails.md. (`anthropic-alignment-assessment-cyber-incidents`, `meta-llamafirewall`)

## Monitors across turns, sessions and accounts

- **Judge behavior at the level of the session and the account, not only the message.** Attackers split a harmful goal into innocent-looking subtasks. Per-request checks passed every slice of the 2025 espionage campaign. Anthropic caught it through activity-level detection of volume, sequence and targets (2025-11-13). (`anthropic-ai-orchestrated-espionage`)
- **Apply a stricter boundary to accounts assessed as higher risk, and give monitoring cross-conversation context.** Single-conversation checks miss attacks split across sessions. OpenAI layers model refusals (Astra refuses 91.5% of cyber jailbreak requests against 59% for GPT-5.6 Sol), classifiers, offline detection and a 24/7 rapid-response program. The regression suite that keeps every jailbreak you've found is in agent-evals red-team.md. (`openai-path-to-astra`)
- **Keep a behavior monitor on every tool-using call even on your best-aligned model, and watch actions and arguments, not only reasoning.** OpenAI added misalignment monitoring to all of GPT-6 Astra's tool-using inference "with significant compute cost". It did so even though Astra drew "roughly half as many" higher-severity flags as GPT-5.6 Sol over 54,000+ simulated Codex tasks. Told to, Astra stayed undetected while sandbagging and sometimes evaded internal monitors (2026-09-03). (`openai-safety-overview-gpt-6-astra`)
- **Re-test prompt-level wrappers on each more robust model, and keep the independent monitor.** In OpenAI's IH-Challenge study, sandwich defenses, extra rules, output rewriters and best-of-N helped GPT-5-Mini. On the hierarchy-trained GPT-5-Mini-R they cost more capability and sometimes robustness. An output monitor kept slowing 127 adaptive human red-teamers. Their success was 0.362 on the base model, 0.117 on the trained model and 0.071 with the monitor (2026-03-10). (`openai-ih-challenge-paper`)

## Wiring that silently fails open

- **Choose fail-closed for any gate that protects an action, and check what each hook type does on a timeout.** Anthropic's inference hooks default to "Allow the request" on failure, with a 5,000 ms timeout. Requests outside a rollout percentage below 100% go uninspected even when failure handling blocks. In the Claude Agent SDK a timed-out Stop hook counts as no decision, async hooks can't block, and hooks may not fire when a max-turns limit ends the session. (`anthropic-docs-inference-hooks-configuration`, `anthropic-docs-agent-sdk-hooks`)
- **Deny with an explicit verdict, never an error code, and size the body limit for whole transcripts.** Anything but HTTP 200 with a parseable verdict counts as a failure. Transcripts arrive untruncated (the protocol allows 64 MiB), while nginx defaults to 1 MB and Express json() to 100 kB. Under fail-open, the biggest prompts reach the model uninspected. (`anthropic-docs-inference-hooks-endpoint`)
- **A guard error must produce a block verdict and must never persist the unjudged output to session history.** In the OpenAI Agents SDK, return a tripwire on internal errors instead of raising. An output guardrail that raises lets the runner save the final-turn items to the session before the exception surfaces, so an unjudged reply with account data is replayed later. Even on a tripwire the function arguments are kept, and they "can contain data that also appeared in the rejected output". (`openai-agents-sdk-guardrails`)
- **Decide whether a blocked message stays in the history.** Each request re-sends the whole conversation. A whole-transcript check then keeps denying until the user edits or restarts, and a last-turn check lets the blocked text reach the model on the next turn. (`anthropic-docs-inference-hooks`)
- **Hold streamed text until the tool calls clear when what was said could itself do harm.** With one verdict per response, one bad call blocks the whole batch, and "Text delivered before the first tool call is not taken back." (`anthropic-docs-inference-hooks-endpoint`)
- **Check whether each guard blocks or only logs by default, and set it to enforce.** Anthropic's self-hosted runner scans repositories for settings that widen access. Its default warn mode "logs a violation and still spawns the session". (`anthropic-docs-claude-code-self-hosted-environments-deploy`)
- **Roll out a new guardrail in shadow mode, then by percentage, then enforcing.** Log verdicts on live traffic and block nothing until the false-deny rate is acceptable. Exempt groups only by explicit role, and log every change to the exemption list. (`anthropic-docs-inference-hooks-configuration`)
- **Authenticate calls from the agent platform to your guardrail server with an HMAC signature, not IP allowlists.** Add a timestamp window and constant-time comparison, and keep both secrets live during a rotation. Anthropic's inference hooks are the example. Compute the HMAC over id, timestamp and the raw body bytes, reject timestamps more than five minutes off, and decode the `whsec_` secret with standard base64, not URL-safe. The hooks' source range 160.79.106.0/24 also carries other Anthropic egress, and the old secret keeps arriving "for about a minute afterward". (`anthropic-docs-inference-hooks-endpoint`)

## What stacking buys, measured

- **Pair a detector on incoming data with a classifier on outgoing actions, so an attack must beat both.** With auto mode (injection probes plus a tool-call classifier), no attack succeeded in 110 Cowork browser scenarios x 10 red-teamer attempts against Opus 5.5, Fable 5.1, Opus 5 or Sonnet 5. The raw models fell on 0.09% to 3.64% of attempts (2026-09-22). The attacks were built against Opus 4.7 and transferred, not adapted per model. (`anthropic-system-card-opus-5-5`)
- **A detector on tool results cuts adaptive attack success but leaves it far above zero.** Probes took Opus 5.5 from 54.61% to 11.13% of Shade coding attempts, Opus 5 from 88.92% to 19.53% and Fable 5.1 from 51.93% to 8.70% (200 attempts per scenario, 2026-09-22). (`anthropic-system-card-opus-5-5`)
- **With thinking on, probes on a screen-driving agent lowered the per-attempt rate but not the number of scenarios broken, so bound such an agent by limiting what it can do.** On Shade computer use (14 scenarios, 200 attempts each), probes moved Sonnet 5 from 2.25% to 1.46% of attempts with 4 of 14 scenarios broken either way, and Opus 5.5 from 0.07% to 0.04% with 1 of 14 either way. Anthropic says differences of a few attempts at these rates are "not distinguishable from noise" (2026-09-22). (`anthropic-system-card-opus-5-5`)
- **Safeguards buy the most on the weakest models, and still don't reach zero.** In the same Shade coding run as above, probes moved Sonnet 5, the most robust model without them, only from 19.47% to 15.76% of attempts with thinking (2026-09-22). (`anthropic-system-card-opus-5-5`)
- **Before you trust a safeguard's lift, check that the raw and safeguarded runs used the same harness.** Updated browser safeguards took Sonnet 4.6 from 50.7% to 1.16% of attempts and Opus 4.8 from 31.5% to 0.08% (129 environments x 10, 2026-06-30). Anthropic later found those raw baselines came from a mismatched harness. It re-ran raw Opus 4.8 at 11.15% without re-running the safeguarded side (2026-08-19). The lift is smaller than it looks. (`anthropic-system-card-sonnet-5`, `anthropic-system-card-opus-5`)
- **Re-validate the whole stack every time you change the model.** The same deployed browser safeguards left Opus 4.8 at 0.5% of attempts and the newer Mythos 5 at 6.5%. So Anthropic built updated safeguards that took Mythos 5 to 0% of 129 scenarios before shipping (2026-06-09). Raw Mythos 5 was 29.7% in that harness and 7.80% in the 2026-08-19 re-run. How much of the gap the safeguards closed is unknown. (`anthropic-system-card-fable-5`, `anthropic-system-card-opus-5`)

## Where the answer depends on the case

- **Whether the action reviewer sees tool results depends on the vendor.** Claude Code's auto-mode reviewer gets user messages and tool calls with tool results stripped, "so hostile content in a file or web page can't manipulate" it, and Anthropic found that adding assistant messages and tool results hurt its overeagerness test set (current docs, 2026-03-25). OpenAI's Codex Auto-review sees "relevant tool calls and tool outputs" but no hidden reasoning (current docs), and its guardian policy treats tool outputs as "untrusted evidence" that can't establish user authorization (2026-09-26). (`anthropic-docs-claude-code-permission-modes`, `anthropic-claude-code-auto-mode`, `openai-codex-auto-review`, `openai-codex-guardian-approvals`)
