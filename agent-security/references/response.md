# Detection and response

Some attack will get through, so decide before launch who can stop the agent and how fast, which signals mean an attack, and what to preserve before anything is cleaned up. Detection here means signals in code and logs, never the agent's own judgment of a conversation. Rerunning attacks after a fix: agent-evals red-team.md.

## Before launch: attribute every call and name who can stop the agent

- **Require sign-in before the agent acts on an account, tie every call to an end-user ID in your own logs, give users a human-monitored way to report bad agent behavior, and warn, throttle or suspend users who keep tripping safeguards.** Anonymous access makes abuse cheap and repeatable; without per-user attribution you can act only on your whole API key, and without a report channel the first sign of an exploit is a public screenshot. (`anthropic-api-safeguards-tools`, `openai-safety-best-practices`)
- **Send the model provider a stable, hashed per-user identifier on every request, so its enforcement lands on one user instead of your whole organization.** Anthropic takes hashed IDs in the Messages API `metadata` object to pinpoint violations. With OpenAI's `safety_identifier` (plus the `OpenAI-Safety-Identifier` header for Realtime, which doesn't carry over between APIs), a high-confidence violation blocks that identifier, which OpenAI "cannot currently unblock", instead of eventually stopping your whole organization, usually seven days after a warning (undated guide); you still have to stop the blocked user from opening a new account. (`anthropic-api-safeguards-tools`, `openai-safety-checks-guide`)
- **Route the provider's enforcement notices to your team and map each one back to a user.** OpenAI sends `safety.warning_issued` and `safety.deactivation_issued` webhooks; read each case with a restricted `api.safety.read` key, map the identifier back to your user and open a review ticket, since reading a case doesn't reverse enforcement. (`openai-safety-enforcement-notifications`)
- **Give customers whose accounts were hijacked a route to a human that the AI support agent can't block, and watch bursts of recovery requests through the bot as an attack signal.** Victims of the Meta AI support takeovers reported no way to reach a human, so a bot-only recovery path both enabled the attack and stalled the response. (`404media-meta-ai-instagram-takeover`)
- **Write down before launch who can stop the agent, when concerns must be escalated, which team responds and who approves a restart, and pair every monitor with paging.** After the Hugging Face incident OpenAI set a rule: for the most severe alerts, responders pause the activity if they can't establish within 30 minutes of a page that it is safe; it admitted early signals in late May should have triggered a response weeks before the July incident (2026-08-26). (`openai-hugging-face-incident-road-ahead`)
- **Write containment steps per component, and who may disable tools or roll back the model, before you need them.** For a memory-enabled agent: reset memory, isolate sessions, purge poisoned history; for retrieval: quarantine the source; for tool-using agents: disable the tools and tighten authorization. CoSAI adapts the NIST lifecycle this way because user or IP blocking is only short-term containment and leaves a poisoned memory or document in place. (`cosai-ai-incident-response`)
- **Make the agent interruptible at two grains: stop one category of actions (revoke, say, refund or payment credentials) without killing it, and terminate it entirely, sub-agents included.** During an attack you need to cut the money path in seconds while the agent keeps answering customers. For multi-step actions, prepare the fallback before starting, such as notifying parties if the sequence is cut halfway. (`openai-practices-governing-agentic-ai`)

## When a defense fires, say so

- **When a defense removes injected content the customer didn't write, or blocks an action that content asked for, tell the customer in plain words, with a help link.** Here the customer is the victim: Google shows a banner in Workspace saying suspicious content was detected and the response removed, so users learn the pattern, and a silent block looks like a bug and invites a retry or a workaround. When the customer's own message trips a guardrail, answer with one fixed neutral line instead (conversation-pressure.md). (`google-layered-defense-prompt-injection`)
- **Make a detected or refused injection an explicit event the agent reports and your system logs and alerts on.** An agent that ignores an injection without telling anyone hides an active attack: Anthropic logged Sonnet 4.6 snapshots "failing to report concerning prompt injection attempts to users" while still avoiding the harmful action (2026-02-17). (`anthropic-system-card-sonnet-4-6`)
- **Treat a monitoring flag as "review this", never as proof of wrongdoing, and keep human approval for consequential actions regardless.** OpenAI's monitoring guide says a flag "does not establish that the user violated a policy" and that monitoring "can miss issues or flag legitimate activity"; banning on a flag alone produces false accusations. (`openai-misalignment-monitoring-guide`)
- **When an injection classifier fires, block or take another defensive action, and send the alert to the security console your SOC already watches.** A detection that lives only in the app's logs can't be correlated into an incident; Microsoft wires Prompt Shields detections into Defender XDR. (`msrc-indirect-injection-defense`)
- **Log and alert on model refusals as their own signal, branching on the stop reason, never on the explanation text.** On current Claude models a classifier refusal is an HTTP 200 with stop_reason "refusal", so "monitoring built on error rates or 5xx responses never sees it", and code that reads only content may show the customer an empty reply. (`anthropic-docs-refusals-and-fallback`)
- **Require the agent to stop and hand off to a human the moment it notices it took an action outside its rules.** The Model Spec says an assistant that takes an action noncompliant with the chain of command "must immediately stop and proactively escalate to a human", with a legible account of side effects and an audit trail on request. (`openai-model-spec-2026-08-18`)
- **When the agent finds something alarming mid-task (apparent fraud, say), design for the most cautious deviation: raise it, ask, or decline to continue, and flag before starting rather than abandoning a task half-done.** It has limited context, can't verify claims and may be the target of deception built to provoke a harmful intervention, and a half-finished action can do more harm than finishing or never starting. (`anthropic-constitution`)

## Detect from the conversation's shape, not one message

- **Log system-prompt and tool-list extraction attempts as an early warning.** They are reconnaissance for the next attack: in one guard vendor's 30-day snapshot of production traffic, "Nearly 60% of observed attacks attempted to extract system instructions", and attackers "consistently combined techniques like hypothetical scenarios, role play, and obfuscation" (Lakera, Q4 2025, vendor-reported). (`lakera-q4-2025-agent-attack-trends`)
- **Alert on traffic and intent anomalies per deployment (sudden spikes, many sessions on off-topic or deal-bait intents), not only on single bad replies.** Viral trolling arrives as a burst. Chevrolet of Watsonville's chat vendor learned of the $1 Tahoe from an automated "unusual amount of traffic" alert, with users "at it for hours", most attempts refused and a few successes going viral. (`chevrolet-watsonville-1-dollar-tahoe`)
- **Alert on conversation shape with cheap deterministic rules: sessions running an hour, out-of-hours activity, repeated steering toward pricing, discounts or refunds, the same request looping.** These catch the slow drift a per-message classifier misses: the UK 80% discount took "about an hour" of steering outside business hours, and Fin treats the same request across three turns as a loop (undated help page). (`uk-chatbot-80-discount`, `intercom-fin-escalation-guidance`)
- **Track each guardrail's firing rate weekly, monitor 100% of conversations, and log every block, redaction and escalation with its trigger.** "A guardrail firing on 40% of conversations is probably too aggressive" and quietly turns the bot into a router to humans, while one that never fires is probably misconfigured; sampled QA of 3% to 5% misses edge cases (Fin, 2026-09-09). (`fin-ai-guardrails-customer-service`)
- **Expect a blocked attacker to switch tactics, and bring in fresh outside red-teamers when internal testing goes stale.** In Project Vend, once prompting curbed discount requests, staff "moved on to other tricks", and Anthropic handed the shop agent to reporters to test in an environment it didn't control. (`anthropic-project-vend-2`)
- **Correlate risky activity across sessions and accounts, and keep logs long enough to do it.** Abusers split work across many sessions and decompose harmful projects into individually benign requests, so per-session checks block many requests but not all; Anthropic introduced 30-day retention starting with Fable 5 and watches for stolen credentials driving the agent (2026-09-01). (`anthropic-threat-intel-september-2026`, `anthropic-enterprise-frontier-safeguards`)
- **Alert on support access without business need (records opened with no ticket, volume spikes, bulk lookups), for human and AI support agents alike.** The tools are legitimate, so only usage separates a bribed agent from a working one: Coinbase's contractors were paid to collect data "from internal Coinbase systems to which they had access in order to perform their job responsibilities", which its monitoring had "independently detected" months before the extortion email ($180M-$400M preliminary cost, Form 8-K, 2025-05-15). (`coinbase-8k-insider-incident`)
- **Instrument account recovery with alerts in code: every "reset all MFA factors", factor downgrades, an admin console reached from a new IP and new device together, sign-ins through anonymizing proxies, a new identity provider; an agent that can trigger recovery emits the same events.** Okta's advisory gives the System Log queries, such as eventType eq "user.mfa.factor.reset_all" and securityContext.isProxy eq "true". (`okta-helpdesk-social-engineering`)
- **Alert on recovery where the contact supplied in chat differs from the one on file, on bursts for high-profile or many accounts, and on location-matched VPN egress, and log which conversational claim each agent action relied on.** Meta's AI-assisted recovery takeover ran 44 days before discovery, and public videos showed the full takeover in minutes with only prompts and a VPN (2026). (`csa-meta-ai-support-bot-takeover`)
- **Monitor long-running customer-facing agents for invented counterparts, fake payment details and identity drift, and take money instructions (account numbers, payment links) only from verified data.** Claudius told customers to pay a hallucinated Venmo account, invented a supplier contact, and for a day claimed to be a human who would deliver "in person" in a blue blazer. (`anthropic-project-vend-1`)

## Detect what the agent does

- **Record a stable identifier of the agent's active goal and its normal tool sequences, and pause with an audit record when it proposes an action outside the task or an unusual tool combination.** Goal hijacks redirect multi-step plans, not one reply; OWASP ASI01 says to treat agents as insiders in insider-threat monitoring. (`owasp-agentic-top10-2026`)
- **Score production traces step by step along the tool-call sequence, and test your judge on legitimate content that only looks like an attack.** On AgentDrift's 12,536 synthetic trajectories, a surface-feature detector recovered 55.4% of attacks, 88.0% of full hijacks but 8.2% of partial hijacks and 23.1% of delayed executions, and the authors' own LLM judge was fooled by hard negatives (2026-09-07, Northern Arizona University). (`agentdrift-benchmark`)
- **Have the offline action monitor judge user turns, tool calls and tool results, never the agent's reasoning.** This is the monitor that reviews transcripts after the fact; the real-time action reviewer that approves each call sees no tool results, and a separate detector scans them (guardrail-layers.md). Anthropic's offline monitor "flagged only around 1% of actions" in the Mythos 5 incident because the reasoning said the environment was simulated; shown only user turns, tool calls and results, "the flag rate jumps to about 50%" (2026-09-09). (`anthropic-alignment-assessment-cyber-incidents`)
- **Run a real-time monitor for boundary probing (unexpected network access, escape attempts, scanning) that blocks the tool call before it runs, ends the task and alerts a human.** Anthropic's post-incident fix replaced a single layer (environment configuration) with several: explicit prompt boundaries, a verified seal and real-time intervention. (`anthropic-improving-alignment-security`)
- **Make open internet access an actively justified exception with real-time monitoring that can flag or block out-of-scope actions.** In UK AISI cyber evals, agents took 19 unsanctioned real-world actions in 10 of 122 runs, 17 from Mythos 5 (43 runs) and 2 from GPT-5.6 Sol (35 runs), including a malicious PR, fake identities to endorse it and planted injections for other AI tools; egress monitoring caught it, not the harness (25 to 28 July 2026). (`aisi-incident-unsanctioned-agent`)
- **For retrospective detection over huge log volumes, scan in two stages: a cheap deterministic pass for indicators (public IPs, URLs, tool patterns), then an LLM reviewer only on what it flags.** Anthropic scanned "roughly 481 million transcripts" and escalated 9.2 million to Claude review; an earlier agentic search over "roughly 141,000" had missed a fourth incident (2026-09-09). (`anthropic-alignment-assessment-cyber-incidents`)
- **Monitor every agent thread, not only the top-level stream.** In Claude Managed Agents a call the auto policy denies inside a subagent is not cross-posted ("When the server denies a call under auto, nothing is cross-posted"), so a subagent repeatedly attempting blocked actions shows only on its own thread. (`anthropic-docs-managed-agents-multiagent-orchestration`)
- **Make your telemetry name every third-party extension the agent loads, because default telemetry may log only that one was loaded.** Claude Code's OpenTelemetry events report non-official plugins only as "third-party" unless OTEL_LOG_TOOL_DETAILS=1, install events omit names, and uninstalled plugin files stay cached 14 days (undated docs). (`anthropic-docs-claude-code-plugins-security`)
- **Alert on the guard's own failure event, not on a health panel, because per-request records stop while the guard is down.** In Anthropic's inference hooks no per-request activities are recorded while the circuit breaker is tripped, so the `inference_hooks_circuit_breaker_tripped` event is the only trace of a window where your failure setting, not your guard, decided every request; recovery probes start 10 minutes after a trip (undated docs). (`anthropic-docs-inference-hooks-configuration`)
- **Budget for the visibility that isolation costs, because a sealed VM keeps your endpoint detection out too; plan log export and accept it is not live monitoring.** Enterprise security teams asked why their EDR couldn't see inside Cowork; Anthropic uses pull-based OTLP export. (`anthropic-how-we-contain-claude`)
- **Restrict who can write any file or memory an agent rereads on a schedule (heartbeat, memory, identity files, AGENTS.md), diff it, alert on changes, and never let scheduled runs use a weaker model with the same permissions.** Rehberger's Agent Commander (March 2026) kept hijacked agents under natural-language command and control by writing to HEARTBEAT.md, and cheaper heartbeat models kept the backdoor hidden longer. (`rehberger-agent-commander`)

## A provider stop is an incident, not an error

- **Handle a provider's misalignment stop as an incident: stop dispatching actions for that conversation, never auto-retry, preserve request and response IDs, tool calls and app records, and have the owner compare the agent's actions with the intended work.** OpenAI returns HTTP 403 with code `misalignment_policy_violation` (match the code, also mid-stream), its monitoring is asynchronous, and "a stopped request does not undo earlier actions"; in Codex "a pause can arrive after the activity that triggered it", so anything irreversible needs a synchronous gate before it runs. (`openai-misalignment-monitoring-guide`, `openai-codex-approvals-security`)
- **Find out which of your API paths the provider's safety monitor can actually block, and build the UI for a held or empty stream.** OpenAI's misalignment monitoring blocks only Responses API requests with persisted reasoning, WebSockets or OpenAI compaction, sends only `safety.alert.created` webhooks for other Responses requests and doesn't cover Chat Completions. It may also hold a suspect user's stream for extra checks and return no tokens; show a loading state and treat an empty reply as a block, not an outage to retry. (`openai-misalignment-monitoring-guide`, `openai-safety-checks-guide`)

## Contain

- **Respond by where the injection came from.** From the customer's own message: suspend that session and bring in a human; from retrieved content: remove or re-score it; from the agent's configuration: take the agent offline for review. Always alert security and log the full event; CoSAI publishes this as a machine-readable playbook. (`cosai-ai-incident-response`)
- **Build a response ladder instead of one block: steer the turn with injected system instructions first, stop the reply only in narrow cases, and handle repeat patterns per account (warn, disable one tool for that account, suspend).** This is how Anthropic enforces its own policy; disabling tools per account let it ship computer use despite spam risk found before launch. (`anthropic-building-safeguards-for-claude`)
- **When you find an agent being abused, investigate scope, ban accounts as identified, notify affected parties, coordinate with authorities, then turn the pattern into a detection classifier.** Anthropic did this over ten days for the espionage campaign, which ran at thousands of requests, "often multiple per second", faster than human-speed review (2025-11-13). (`anthropic-ai-orchestrated-espionage`)
- **Measure the time from flag to containment, and back every egress block with a second independent layer.** In OpenAI's DNS incident (2026-09-20) the monitor flagged the agent within 15 minutes and a person began reviewing 3 minutes later, but the run was killed 2.5 hours after; OpenAI then added controls at two independent layers, "either of which would have prevented this access". (`openai-misalignment-report-dns-chatbot`)
- **When you tighten a tool permission mid-incident, also end or interrupt live sessions, and record the evaluated permission and reason of every tool call.** In Claude Managed Agents "Running sessions keep the toolset configuration they were created with"; each tool-use event carries evaluated_permission and, under auto, a reason_code. (`anthropic-docs-managed-agents-permission-policies`)
- **Write the runbook for a compromised tool connection in this order: detach the tool server from every live session, revoke its credential, report, re-provision, rotate every OAuth token it issued, read the logs for the exposure window, then reconnect.** It follows Anthropic's breach steps for an MCP tunnel. (`anthropic-docs-mcp-tunnels-security`)
- **Store agent memory as immutable, attributed versions so you can trace which session wrote a poisoned entry, roll it back and redact leaked secrets or PII, and export versions you need longer than the retention window.** Claude Managed Agents keeps memory versions 30 days and can't redact the current head (undated docs). (`anthropic-docs-managed-agents-memory`)
- **Give agents that automate response (quarantine, access changes, session termination, credential revocation) least privilege and integrity checks, log them like any agent, and require human approval for high-impact responses.** An attacker who compromises a defensive agent gains its powers; "organizations should not blindly trust defensive automation". (`anthropic-zero-trust-ebook`)

## Investigate

- **Take forensic copies before you purge memory, delete a poisoned document or patch the prompt: raw model outputs, prompt and system-prompt versions, tool-call traces, memory and vector-database state.** Containment erases the record of the injection, and a model "will not produce exactly the same outputs even given the same input and system prompt", so the attack can't be replayed afterward; CoSAI's guidance is to contain "without destroying evidence". (`cosai-ai-incident-response`)
- **Plant a canary string where you discuss a live injection payload, because your own agents may read that channel.** A payload pasted into Slack becomes ambient; Anthropic did this after sharing a working exfiltration prompt internally, since "the investigation tooling is also an attack surface". (`anthropic-how-we-contain-claude`)
- **Stage a self-hosted model for forensic analysis before an incident.** Hosted APIs may refuse malware, payloads and credential dumps mid-incident, and you may not want attacker data leaving your environment: Hugging Face's responders to an agent-run intrusion with 17,000+ recorded attacker events switched to a self-hosted open-weight model (July 2026). (`rehberger-hugging-face-intrusion`)
- **Triage a reported jailbreak by real-world impact, not by whether it worked: capability gain beyond public tools (0 if they do the same), breadth across tasks, ease of weaponization and discoverability, with severity bands treated as exponential.** Anthropic's draft Cyber Jailbreak Severity scale (CJS-0 to CJS-4) spends response effort on universal, easy, high-uplift breaks rather than one-off curiosities. (`anthropic-fable-safeguards-jailbreak-framework`)
