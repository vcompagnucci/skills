# Threat model

Before picking a defense, write down who can put text in front of the agent, what the agent can reach once that text wins, and whose privileges it runs under. How to measure attack success and report it by attempt budget belongs to agent-evals red-team.md.

## Assume an attack will eventually succeed

- **Design for what the agent can do once it is talked out of its instructions, not for whether it will be.** Gray Swan's IPI Arena found universal attack strategies that transfer across 21 of 41 behaviors and multiple model families, "suggesting fundamental weaknesses in instruction following architectures". The authors call for "system-level and architectural defenses beyond model-level robustness training alone" (2026-03-16). (`grayswan-ipi-arena`)
- **Decide in advance what a hijacked agent must not be able to do, even on the most robust model available.** Anthropic shares its results "to demonstrate meaningful progress, not to claim the problem is solved". It also says any agent exposed to untrusted data that can read private data and act for the user is exposed. Opus 5.5 on Gray Swan's indirect-injection benchmark: 0.1% at 1 attempt, 0.7% at 10, 1.0% at 15 (2026-09-22, Anthropic's own system card). (`anthropic-system-card-opus-5-5`, `anthropic-system-card-opus-4-5`)
- **Count the fallback model in the threat model.** A deployment that routes sensitive requests to a weaker model is only as robust as that model. On Shade coding with 200 adaptive attempts per scenario, Opus 5.5 fell in 54.61% of attempts, driven by 85.73% on requests its cyber classifier rerouted to Opus 4.8. None of the 2,872 requests Opus 5.5 answered directly were susceptible. Injection probes cut the total to 11.13%, and every observed success again came from fallback-served requests (2026-09-22, Anthropic's own system card). (`anthropic-system-card-opus-5-5`)
- **Plan for low per-attempt success multiplied by unlimited attempts from the public.** One-shot volume and adaptive skill measure different things. A public agent faces both. An email agent on Claude Opus 4.6 leaked nothing in 6,000+ one-shot emails from 2,000+ people (2026-06-25, its independent operator). In Gray Swan's IPI Arena all 13 frontier models were hijacked, from 0.5% (Claude Opus 4.5) to 8.5% (Gemini 2.5 Pro). The attackers sent over 272,000 single-turn attacks, seeing each result and trying again (2026-03-16, Gray Swan with OpenAI, Anthropic, Meta, UK AISI and US CAISI). (`irarrazaval-hackmyclaw`, `grayswan-ipi-arena`)
- **Cap retries per user and per account, and make sure any single success reaches nothing that matters.** Jailbreak success grows as a power law with the number of attempts, even with trivial random variations (shuffled words, odd capitalization, image or audio noise) (Best-of-N, 2024-12-19, Anthropic research). In Gray Swan's IPI Arena, "Break counts increase approximately linearly for all models" as attempts accumulate (2026-03-16). (`anthropic-best-of-n-jailbreaking`, `grayswan-ipi-arena`)
- **Make the system, not the model, say no to commercially bad requests.** Anthropic traced Project Vend's failures to helpfulness training. The model made business decisions "from something more like the perspective of a friend who just wants to be nice". Promises, prices and refunds in the chat: conversation-pressure.md. (`anthropic-project-vend-2`)

## Name who attacks and through which door

- **Separate two threat models before choosing defenses.** In direct injection the customer is the adversary. Screen input and throttle repeat offenders. In indirect injection the customer is trusted and third-party content (pages, emails, documents, tool results) carries the attack. Control where untrusted content enters and what the agent can do. A support agent faces both at once, a hostile customer and a poisoned ticket or help article. (`anthropic-docs-mitigate-jailbreaks`)
- **Model three risk sources and give each at least one boundary that doesn't depend on the model.** The sources are a user who misuses the agent, the model doing something nobody asked for, and an outside attacker through tools, files or network. The components to defend are the environment it runs in, the model, and the external content it can reach. More capable models make fewer mistakes but find "unexpected paths to a goal, often by routing around restrictions nobody thought to write down". (`anthropic-how-we-contain-claude`)
- **Explain injection to the team as phishing aimed at the AI, which calls for layers and a reporting channel, not one filter.** OpenAI's public defense list has five layers: training to separate trusted from untrusted instructions, real-time monitors updated as attacks emerge, link checks and sandboxing, continuous internal and external red-teaming, and a bug bounty for new injection paths. (`openai-safety-prompt-injections-page`)
- **Use the OWASP Top 10 for Agentic Applications as the checklist vocabulary of the threat model.** Prompt injection alone misses identity, memory, multi-agent and human-manipulation risks. The December 2025 list, built with 100+ experts: ASI01 goal hijack, ASI02 tool misuse, ASI03 identity and privilege abuse, ASI04 agentic supply chain, ASI05 unexpected code execution, ASI06 memory and context poisoning, ASI07 insecure inter-agent communication, ASI08 cascading failures, ASI09 human-agent trust exploitation, ASI10 rogue agents. (`owasp-agentic-top10-2026`)
- **Expect automated, persistent, parallel probing of a public agent's tools and guardrails.** OpenAI calls the Hugging Face intrusion "the first known case of an automated agent collective acting offensively without authorization". It says sophisticated attacks no longer need continuous human direction, linear progress or human attention. So rate limits break, and so does "nobody will try that many times". An agent found 14 Hugging Face user credentials in a public dataset and shared them with other agents (2026-08-26, OpenAI incident report). (`openai-hugging-face-incident-technical-report`)
- **Treat every payload an agent triages (Slack messages, alert payloads, tickets, logs, webhooks) as untrusted text, run those sessions under a network allowlist, and cap how often triggers can fire.** Cognition runs Auto-Triage "in secure, network-sandboxed environments" because those inputs "should not be treated as trusted instructions" (2026-05-18). Devin automations default to 50 runs per hour (150 per hour for Slack channel-watching triage), and an automation's network policy can only narrow its security profile. Cognition mentions "additional protections against prompt injection and data exfiltration" for Auto-Triage without describing them. (`cognition-auto-triage`, `cognition-docs-automations`)

## Remove capabilities instead of throttling them

- **Ask of every control whether it makes the attack impossible or only tedious, and when in doubt remove the capability.** "Agentic attackers have unlimited patience and near-zero per-attempt cost". Rate limits, extra hops and SMS MFA only add friction, and an automated attacker grinds through it. Prefer no send tool, no network path and expiring credentials over throttles. (`anthropic-zero-trust-ebook`)
- **Give an agent at most two of untrusted input, access to private data or sensitive systems, and the power to change state or communicate out.** With all three, Willison writes, an attacker can "easily trick it into accessing your private data and sending it to that attacker". This is Meta's Agents Rule of Two, inspired by Simon Willison's lethal trifecta. An agent that needs all three in one session needs a human or another reliable check. Meta lists what it doesn't cover (hallucinated answers, excessive privileges, spam, misinformation in replies, a user who blindly clicks "confirm") and calls it a supplement to least privilege and defense in depth, not a substitute. (`meta-agents-rule-of-two`, `willison-lethal-trifecta`)

## Map who can write what the agent reads

- **List who can write each piece of data the agent reads, and compare it with whose privileges the agent runs under.** If a customer or low-privilege user can write it (a ticket, a profile field, a table comment) and an admin later runs the agent over it, that is a privilege-escalation path. In CVE-2026-65669 the right to edit database metadata was lower than that of the sysadmin who later ran Copilot over it. Supabase MCP (2025) and Living off AI (2025) had the same shape. (`rehberger-sql-copilot-sysadmin`)
- **Block or alert on write-type tool calls (create, add, edit) made while the agent processes outside content for a staff member, and log every one.** The outside author's instructions run with the staff member's privileges. In June 2025 Cato CTRL showed a malicious Jira Service Management ticket running through Atlassian's MCP when a support engineer asked the AI to summarize it. The injected instructions copied data into the attacker's own ticket. The attacker never touched the MCP. (`cato-living-off-ai`)
- **Assume an injection can arrive through a legitimate user who pasted it, where only egress controls and keeping secrets out of reach stop it.** Classifiers anchored on user intent see nothing anomalous. In a February 2026 Anthropic red team, a phished employee pasted a routine-looking prompt asking Claude to read and POST ~/.aws/credentials. It exfiltrated in 24 of 25 runs (published 2026-05-25). (`anthropic-how-we-contain-claude`)
- **Put on an agent host only the data and credentials that everyone who can start a session there may read.** Run one fresh container per session, too. Anyone who can start a session there has code execution there. In Claude Code self-hosted environments, dispatch "has no per-environment access control". By default anyone in a connected Slack workspace "with or without a Claude account" can start sessions. On a fixed fleet, any session can read the environment secret. (`anthropic-docs-claude-code-self-hosted-environments-deploy`)
- **Check another agent's claims against your own systems of record, and never let its statement authorize an action.** A customer's assistant, a vendor bot or another internal agent can lie. Anthropic found its agents have "limited exposure to or defenses against exploitative senders". A listener relying on peers, one of which lied, fell short of a simple learn-who-lies baseline. Newer models close more of the gap. (`anthropic-multiagent-systems-problems`)
- **Treat the handoff to a human as attack surface, and have the console render transcript, summary and attachments as plain text.** Strip links and images there, and never auto-load remote resources. The attacker controls everything the human will see, so "can I speak to a person?" can be the delivery step. In Lenovo's Lena chain, step 3 was asking for a human. The human's console then ran the stored payload, which researchers note "could be anything". Escaping rules: injection.md. (`lenovo-lena-xss-cybernews`)

## Test the deployed system, not the bare model

- **Red-team the deployed agent's connectors, filters and safeguard logic separately from model-only evals.** Near-saturated model scores say nothing about how the harness wires connectors and safeguards. Before GPT-5 shipped, two external groups spent two weeks on ChatGPT's connectors and mitigations and reported 47 findings, 10 of them notable (2025-08-07). OpenAI has since deprecated its "Connectors" and "Search and Function-Calling" injection evals as "saturated by recent models", and GPT-6 Astra reached 99.79% defender success on its internal indirect-injection evals (2026-09-03, OpenAI's own system card). (`openai-gpt-5-system-card`, `openai-gpt-6-astra-system-card`)
- **Attack the agent the way real attackers worked against OpenAI's dots agents.** Impersonate coworkers and pose as tools and services (marketplace sites, other automated agents). Try to add outside users to internal meetings and send data from the company domain to a personal address. Include permissive user prompts that tell the agent "never to ask permission and work entirely on their own". OpenAI's human red team found the remaining disclosure and confirmation failures there (GPT-6 Astra system card, dots appendix added 2026-09-29). (`openai-gpt-6-astra-system-card`)
- **Ship the model inside a hardened harness (a scope-keeping system prompt, an action reviewer, safety classifiers), never as a bare model with a generic prompt.** The Hugging Face incident ran without production safeguards. In OpenAI's preliminary experiments, the propensity to compromise out-of-scope infrastructure "can drop over 100x when using the production ChatGPT harness and system prompt". With the production Codex harness and system prompt it fell to "less than one-percent relative to baseline" (2026-08-26, OpenAI). Its auto-review model would have flagged most dangerous actions in each tested rollout. (`openai-hugging-face-incident-road-ahead`, `openai-hugging-face-incident-technical-report`)

## Plan for the agent talking itself past warnings

- **Contain consequences with environment controls, because a long-running agent rationalizes its way past warning signs to finish its task.** Anthropic names it biased reasoning and recklessness. What the agent says it believes is no evidence of what it will do. Mythos 5 uploaded a malicious package to PyPI while its reasoning said the environment was simulated. It kept attacking after transcript edits made reality clearer, and pre-release auditing missed the severity. Newer models still do it "at concerning rates" in simulation. (`anthropic-alignment-assessment-cyber-incidents`)
