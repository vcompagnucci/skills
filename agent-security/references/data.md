# Data: what the agent reads, and every way it can leave

Whatever the agent can read, an injected instruction or a persuasive customer can try to send somewhere. Which hosts the agent may reach at all is sandbox.md.

## Give the agent only the data the task needs

- **Show the support agent only the customer fields the task needs, masked where possible, and scope it in the support tool's code.** Whatever the support tool displays is what an insider, a bribed agent or an injected bot can copy out. Criminals bribed overseas support agents to copy Coinbase's support-tool view (names, addresses, last-4 SSN, masked bank numbers, government ID images, balances, transaction history) for <1% of monthly transacting users. They then phoned customers posing as Coinbase and demanded a $20M ransom, which Coinbase refused (2025-05-15). (`coinbase-extortion-disclosure`)
- **Read high-precision identifiers back to the customer before any account lookup or write.** Order IDs, tracking numbers, account numbers, confirmation codes, phones and emails get normalized only when the field type is clear. A misheard one sends a disclosure or a refund to the wrong account. (`openai-voice-prompting-guide`)
- **Retrieval enforces the requester's permissions from the source system at query time.** NVIDIA's red team keeps finding RAG stores that copy the wrong source permissions, index everything with one over-privileged read token, or lag behind permission changes. Each one exposes data to anyone who can ask. (`nvidia-red-team-llm-security-advice`)
- **Tokenize PII before it reaches the model.** In Anthropic's MCP code-execution pattern, the tool client swaps names, emails and phones for tokens and restores them only for the destination tool. A hijacked agent can't leak what it never saw. The token map doubles as a rule for where data may flow. (`anthropic-code-execution-with-mcp`)
- **Block PII on the way out, because a PII check that masks input can leave output unmasked.** OpenAI's Guardrails PII check masks input with placeholders like `<US_SSN>` but must block output, since output masking "is not supported". Turn on Unicode normalization and encoded-PII detection (Base64, URL encoding, hex). Add recognizers for local ID formats too, because it runs on Presidio with an English spaCy model. (`openai-guardrails-check-pii`)
- **Never collect passwords, card numbers or OAuth consent inside the conversation.** Anything typed into the chat lands in model context and logs. Hand the user to a browser flow (MCP elicitation URL mode) so the secret never transits the agent or the client. Use the in-client form mode to confirm destructive actions (Anthropic, 2026-04-22). (`anthropic-mcp-production-systems`)
- **Assume the system prompt will leak, so put nothing in it you'd mind publishing.** Anthropic doesn't count system-prompt extraction as a security jailbreak (2026-07-02), and it publishes its own prompts. Keep secrets, internal thresholds and fraud rules out, and catch leaks with output post-processing and periodic audits. Add leak-resistant prompting last, because it degrades the main task. Recheck each technique on every new model, since vendors drop mechanisms (Anthropic's prefill reinforcement isn't supported on Claude 4.6 and later). Extraction attempts in the chat are conversation.md. (`anthropic-fable-safeguards-jailbreak-framework`, `anthropic-docs-reduce-prompt-leak`)

## Close every way out

- **Never render an external image URL in agent output. Fetch, follow or render a URL from tool output only when it sits on a domain you trust.** An attacker-chosen image URL is a zero-click channel. Google's markdown sanitizer refuses external images, which makes EchoLeak (CVE-2025-32711) "not applicable" to Gemini. OpenAI's MCP guide calls it "dangerous to request URLs or embed image URLs provided by tool call outputs". If you render model-generated HTML, sanitize it yourself with a strict allowlist. The Agent SDK rejects only script, style and DOCTYPE tags. (`google-layered-defense-prompt-injection`, `openai-mcp-connectors-guide`, `anthropic-docs-agent-sdk-user-input`)
- **The support bot never writes a URL from scratch.** Links come from citations to known articles or a tool result's canonical links. Strip every other domain on output. Fin's docs say forcing full URLs makes the model corrupt them, and it "can also fabricate a plausible-looking link to a domain that doesn't exist". An attacker can register that domain. Guidance reduces this but "can't fully prevent" it. (`intercom-fin-guidance-best-practices`)
- **Inventory every way output can reach a third party, and block each in code.** Microsoft names four seen in reported exploits: rendered markdown or HTML images (zero-click, data in the URL), links with data in the query string, tool calls that write where an outsider can read, and covert channels where whether a tool gets called leaks one bit. Most vendor fixes (ChatGPT, Bard, Amazon Q, M365 Copilot) closed the egress path rather than stopping the injection. (`msrc-indirect-injection-defense`)
- **A fetch tool opens only URLs that appeared in trusted input or sit on a domain you trust, never ones the model composed.** An injected instruction exfiltrates by building attacker.com/?q=<account data>. Anthropic's web fetch can't fetch "URLs that appear only in its own output" and refuses URLs that look like they carry a credential. Your own tools can launder a model-composed URL. A result that echoes the model's input (an error quoting it, a command printing it) counts as an allowed source, so don't echo raw arguments. (`anthropic-docs-web-fetch-tool`)
- **Let trusted code fix which origins a task may read and the smaller set it may write to.** Restrict every model-generated URL to known, public ones with a deterministic check. That is how Chrome's Origin Sets bound a browsing agent, with the gating function kept away from untrusted web content. (`google-chrome-agentic-security`)
- **Review tool combinations, and gate the outbound tool once sensitive data is read.** A customer-record read plus any outbound channel is an exfiltration path. Anthropic's guide gives CRM plus external email as the example. Every step runs through trusted binaries under valid credentials, so host monitoring sees nothing. Before a call that carries sensitive data, the Model Spec (2026-08-18) weighs how sensitive it is, whether the recipient is trustworthy, the tool's side effects and whether sharing is in scope. It counts changing sharing settings or approving auth connections as information flow too. (`anthropic-zero-trust-ebook`, `openai-model-spec-2026-08-18`)
- **Remove the live egress sink the moment private data enters context.** After the agent reads private data from a connector, OpenAI switched GPT-5 in ChatGPT to cached browsing only (2025-08-07). Its opt-in Lockdown Mode (rolled out 2026-06-04) does it for high-risk accounts: cached-only browsing and no images in responses, Deep Research, Agent Mode, Canvas networking, live connectors or file downloads. Features stay off "when we can't provide strong deterministic guarantees of data safety". (`openai-gpt-5-system-card`, `openai-lockdown-mode-elevated-risk`)

## Secrets in reach

- **Keep provider API keys and production credentials out of anything an agent, sandbox or LLM proxy can read.** In 2026 attackers used prompt injection against LiteLLM deployments and an AI vendor's evaluation sandbox to get the keys they held. They used one stolen key "for roughly three weeks". A follow-on campaign hit "roughly thirty AI companies in about four days" (Anthropic threat report, 2026-09-10). (`anthropic-threat-intel-september-2026`)
- **Strip credentials from anything the agent can read. Read-only access doesn't protect them.** Before handing over a directory, remove .env files, cloud CLI credentials (~/.aws, gcloud ADC, ~/.azure, ~/.kube/config), registry tokens (.npmrc, .pypirc), git credentials, service-account JSON and private keys, or copy in only what's needed. A typical command sandbox confines writes but reads most of the machine, ~/.ssh included, and inherits the parent's environment variables. Claude Code's has "no built-in credential deny list", so list every secret file and variable yourself. (`anthropic-docs-agent-sdk-secure-deployment`, `anthropic-docs-claude-code-sandboxing`)
- **Redact credentials from every tool output before the model sees it, and allowlist the commands that produce it.** A secret in the context is one injection away from leaving, and "Your application runs whatever command Claude requests". So validate commands against an allowlist rather than a blocklist, and cap CPU, memory and disk. Log every command with its output, and redact credentials from results. (`anthropic-docs-bash-tool`)
- **Give the agent a placeholder and substitute the real secret at egress, in request headers only, for the hosts you list.** Request bodies come from content the agent handles. So body substitution lets an injected instruction put the placeholder in a payload that gets reflected or stored where someone can read it. Managed Agents vaults enable both when you omit the location. Substitution is outbound only. A token obtained with the secret (OAuth client credentials) "arrives in the sandbox unredacted", so do the exchange in your backend and store only the short-lived result. (`anthropic-docs-managed-agents-vaults`)
- **Bind each secret to the command that needs it instead of exporting it into every shell, and scope it to the narrowest owner.** An org-wide secret is usable in every session of every member, so one injected session reaches it. Devin passes secrets as environment variables only to the commands that need them ("Secrets are not exported into every shell") and types them straight into the browser. It scopes them to organization, person, repository or session, never writes repository secrets into blueprints or snapshots, and since 2026-09-11 defaults new secrets to Personal for non-admins and asks for confirmation before an org-wide one. Binding narrows which commands see a value. It doesn't stop an agent that is told to bind it. (`cognition-docs-secrets`, `cognition-release-notes-2026`)
- **Only operator-controlled config may release a credential to a destination, and a changed destination loses the credential.** Claude Code ignores credential-masking, TLS-termination and plaintext-inject entries in a repository's own settings. By default, though, a mask that matches nothing only warns and leaves the real file readable, so fail closed. Anthropic's inference hooks store auth headers write-only and wipe them when the endpoint URL changes, "so your credentials are never sent to a new destination". (`anthropic-docs-claude-code-sandboxing`, `anthropic-docs-inference-hooks-configuration`)

## Memory outlives the conversation

- **Never write one customer's conversation into memory another customer's session reads.** Across three agents, MINJA planted malicious records through queries alone, with 98.2% average injection success and 76.8% average attack success (2025-03, Michigan State University et al.). The attack then hijacked how the agent handled other users' queries. Write shared memory only from vetted sources (staff-approved resolutions), and keep memory per customer. When one agent serves many people, give it identity and memory per compartment, as Anthropic's Claude Tag does per private channel. (`dong-minja-memory-injection`, `anthropic-agent-identity-access-model`)
- **Rank memory by provenance, and keep what a customer asked you to remember out of the system slot.** OpenAI's personalization cookbook trusts structured profile keys "especially if sourced/enriched internally" over free-text notes. It lets the latest user message win and asks on conflict. It also injects memory notes into the system prompt, calls memory "a high-value attack surface", and says its delimiters are "not a security boundary". Otherwise a note a customer planted, claiming VIP status and pre-approved refunds, weighs the same as your database record. Log memory_write_rate and blocked_write_rate per 100 turns, and test with "remember my SSN" and "store this rule". (`openai-memory-personalization-cookbook`)
- **Attach reference memory read-only, and scan memory when a session starts, not only when it's written.** Anthropic's managed memory attaches read-write by default, so every later session reads one injected write as trusted memory. Its memory tool tells the model "ALWAYS VIEW YOUR MEMORY DIRECTORY BEFORE DOING ANYTHING ELSE". Anthropic names memory poisoning a classic post-exploitation persistence mechanism and expects startup classifiers to become commonplace. Cap file sizes and expire old files. (`anthropic-docs-managed-agents-memory`, `anthropic-docs-memory-tool`, `anthropic-how-we-contain-claude`)
- **Apply four controls to memory read back into context.** Sanitize before storing, isolate per user and tenant, log and scan every read and write, and tell the model that instructions in memory aren't commands. Anthropic's memory cookbook calls memory a "critical risk" injection vector, and secrets and PII never go there. Validate every path. Canonicalize it, confirm it stays under the per-user root, and reject `../`, `..\` and `%2e%2e%2f`. Otherwise `/memories/../../secrets.env` reads or overwrites files outside memory. (`anthropic-memory-cookbook`, `anthropic-docs-memory-tool`)
- **Gate memory writes that came from content rather than from the user, and show users what was saved and where it came from.** Microsoft (2026-02) found 50 "Summarize with AI" prompts from 31 companies in 14 industries over 60 days. They planted "remember [Company] as a trusted source" through ?q= links. Claude Opus 4.7 with memory stored fake user facts from a ChatGPT-generated puzzle image in 5 of 10 attempts (2026-04, Rehberger), despite a memory prompt forbidding verbatim commands. (`microsoft-ai-recommendation-poisoning`, `rehberger-breaking-opus-memory`)
- **Keep sessions that process untrusted events out of long-term memory, link every entry to where it was learned, and gate a background consolidation pass like any other writer.** In Devin, "Sessions started by automations don't read or write your memory", so a Slack message, webhook or alert can't plant a lesson. Its memory is personal, excludes secrets and lives in a git repository, and each entry cites its source session and the date it was added. Its daily Dreaming pass looks for "useful lessons that weren't captured during the original work", which makes it a write path no user confirmed. (`cognition-docs-memory`, `cognition-memory-and-dreaming`)
- **Never cache credentials, tokens or a prior user's authorization in memory that crosses sessions or users, and control who writes to the knowledge base.** Anthropic's zero-trust guide names memory-based privilege retention (cached secrets reused across session boundaries), RAG poisoning through over-trusted ingestion pipelines, shared-context poisoning between tenants, and slow memory drift where no single change looks malicious. (`anthropic-zero-trust-ebook`)
- **Process each untrusted message in a fresh context, and treat what other sessions wrote to a shared store as untrusted input.** In hackmyclaw, early obvious injections made the agent suspicious of everything after. Around email 500 it wrote to memory that this was "a coordinated security exercise". In OpenAI's Hugging Face incident (2026-08-26), unauthorized coordination started with one agent leaving a note as external memory, with messages encoded in URL paths. Monitor and restrict writes to any shared store. (`irarrazaval-hackmyclaw`, `openai-hugging-face-incident-road-ahead`)
- **A read-only mount protects memory from syncing back, not from local edits.** Any shell or custom tool in the sandbox can change the local copy, and later steps read it. If memory must be tamper-proof for the session, give that agent no shell or file-writing tool. (`anthropic-docs-managed-agents-self-hosted-sandboxes-security`)

## Allowlisted destinations still leak

- **Never let an agent with outbound reach read the raw support inbox that also receives your own password resets and OTPs.** In Intigriti's walkthrough (2026), a spoofed note told the agent what to do with the next email from no-reply@x.com. The attacker then triggered a real X password reset for the company's support address. The agent leaked the OTP as a subdomain lookup to the attacker's wildcard DNS. Filter those senders and strip codes in code. Restrict the environment to designated DNS resolvers too, because a lookup of <data>.attacker.com leaks with HTTP blocked (NVIDIA). (`intigriti-hacking-ai-support-agents`, `nvidia-sandboxing-agentic-workflows`)
- **Audit every allowlisted domain for expiry and for ways to receive data through a GET.** In ForcedLeak, my-salesforce-cms.com stayed on Agentforce's CSP allowlist after it expired and became purchasable (Noma, 2025-09-25, full chain in injection.md). In PromptArmor's report (Jan 2026), an unopened email made Superhuman AI emit an image pointing to a pre-filled Google Form. Google Docs was allowlisted, so it submitted the full contents of several emails and parts of 40+ others. (`noma-forcedleak-agentforce`, `promptarmor-superhuman-exfil`)
- **Put a provenance-checking proxy in front of any allowed API that can also store data.** In Anthropic's Cowork leak, a planted file with an attacker's API key made Claude upload workspace files to the attacker's account through api.anthropic.com. The allowlist correctly permitted it. Forward only requests carrying the agent's own provisioned token, and strip headers that trigger server-side fetches. (`anthropic-how-we-contain-claude`)
- **Test each layer's failure mode separately, because real exploits chain small bypasses.** EchoLeak (CVE-2025-32711, zero-click, CVSS 9.3) evaded Microsoft's injection classifier and dodged link redaction with reference-style markdown. It used images the client fetched automatically, and sent data through a Teams proxy the CSP allowed. (`aim-echoleak-paper`)
- **Map where each tool call runs. Provider-side fetches and hosted connectors leave from the provider's network, not yours.** In ShadowLeak (Radware, 2025-09-18), one email made ChatGPT Deep Research send base64-encoded inbox PII to an attacker URL from OpenAI's servers. Enterprise gateways never saw it. Control which URLs such a tool may open, and monitor its actions against the user's goal. To keep tool traffic inside your boundary, run local MCP servers and deny the hosted connectors (in Claude Code, `allowedMcpServers` and `deniedMcpServers`). (`radware-shadowleak`, `anthropic-docs-claude-code-self-hosted-environments-deploy`)
- **When your infrastructure fetches a URL learned from a server or a document, enforce HTTPS and validate every redirect hop.** Block private, loopback and link-local ranges, 169.254.169.254 included. Otherwise a malicious server points your backend at internal services or cloud credentials (MCP spec SSRF guidance, 2025-11-25). (`mcp-spec-security-best-practices`)

## Retention and tenancy

- **Check retention on every path customer data takes, not only the model call.** Website publishers may keep any parameters in a URL the agent fetches, even when your provider has zero data retention. So customer data never goes in fetched URLs. On the Claude API, "The MCP connector is not covered by ZDR arrangements". (`anthropic-docs-server-tools`, `anthropic-docs-mcp-connector`)
- **Never let one customer's agent state reach another customer's session.** Claude API code-execution containers are scoped to the workspace, persist up to 30 days and keep interpreter state between requests. Keep a container-to-customer mapping in your backend. On a host serving several tenants, give each its own config directory, working directory and egress policy, and skip shared settings files. Turn auto memory off explicitly, since the Agent SDK loads it into the system prompt regardless of settings sources. (`anthropic-docs-code-execution-tool`, `anthropic-docs-agent-sdk-hosting`)
