# Data: what the agent reads, and every way it can leave

Whatever the agent can read, an injected instruction or a persuasive customer can try to send somewhere. Shrink what it reads, close every channel out in code, keep secrets out of reach, and treat memory as input that outlives the conversation; which hosts the agent may reach at all is permissions.md.

## Give the agent only the data the task needs

- **Show the support agent only the customer fields the task needs, masked where possible, and scope it in the support tool's code.** Whatever the support tool displays is what an insider, a bribed agent or an injected bot can copy out. Criminals bribed overseas support agents to copy Coinbase's support-tool view (names, addresses, last-4 SSN, masked bank numbers, government ID images, balances, transaction history) for <1% of monthly transacting users, then phoned customers posing as Coinbase and demanded a $20M ransom, which Coinbase refused (2025-05-15). (`coinbase-extortion-disclosure`)
- **Read high-precision identifiers back to the customer before any account lookup or write.** Order IDs, tracking numbers, account numbers, confirmation codes, phones and emails get normalized only when the field type is clear, because a misheard one sends a disclosure or a refund to the wrong account; OpenAI's voice guide also explains failed tool calls briefly with a next step, never as raw errors. (`openai-voice-prompting-guide`)
- **Retrieval enforces the requester's permissions from the source system at query time.** NVIDIA's red team keeps finding RAG stores that copy the wrong source permissions, index everything with one over-privileged read token, or lag behind permission changes, exposing data to anyone who can ask. (`nvidia-red-team-llm-security-advice`)
- **Tokenize PII before it reaches the model, and block it on the way out.** In Anthropic's MCP code-execution pattern the tool client swaps names, emails and phones for tokens and restores them only for the destination tool, so a hijacked agent can't leak what it never saw and the token map doubles as a rule for where data may flow. OpenAI's Guardrails PII check masks input with placeholders like `<US_SSN>` but must block output, since output masking "is not supported"; turn on Unicode normalization and encoded-PII detection (Base64, URL encoding, hex), and add recognizers for local ID formats, because it runs on Presidio with an English spaCy model. (`anthropic-code-execution-with-mcp`, `openai-guardrails-check-pii`)
- **Never collect passwords, card numbers or OAuth consent inside the conversation.** Anything typed into the chat lands in model context and logs; hand the user to a browser flow (MCP elicitation URL mode) so the secret never transits the agent or the client, and use the in-client form mode to confirm destructive actions (Anthropic, 2026-04-22). (`anthropic-mcp-production-systems`)
- **Assume the system prompt will leak, so put nothing in it you'd mind publishing.** Anthropic doesn't count system-prompt extraction as a security jailbreak (2026-07-02) and publishes its own prompts; keep secrets, internal thresholds and fraud rules out, catch leaks with output post-processing and periodic audits, and add leak-resistant prompting last because it degrades the main task. The prefill reinforcement trick in Anthropic's leak doc no longer works on Claude 4.6 and later, and conversation.md covers extraction attempts in the chat. (`anthropic-fable-safeguards-jailbreak-framework`, `anthropic-docs-reduce-prompt-leak`)

## Close every way out

- **Never render an external image URL in agent output, and never fetch or render a URL from tool output whose domain you don't trust.** An attacker-chosen image URL is a zero-click channel: the client loads it and the query string carries the data. Google's markdown sanitizer refusing external images makes EchoLeak (CVE-2025-32711) "not applicable" to Gemini, and OpenAI's MCP guide calls it "dangerous to request URLs or embed image URLs provided by tool call outputs"; if you render model-generated HTML, sanitize it yourself with a strict allowlist, since the Agent SDK rejects only script, style and DOCTYPE tags. (`google-layered-defense-prompt-injection`, `openai-mcp-connectors-guide`, `anthropic-docs-agent-sdk-user-input`)
- **The support bot never writes a URL from scratch: links come from citations to known articles or a tool result's canonical links, and every other domain is stripped on output.** Fin's docs say forcing full URLs makes the model corrupt them and it "can also fabricate a plausible-looking link to a domain that doesn't exist", one an attacker can register; guidance reduces this but "can't fully prevent" it. Meta's public travel-assistant example combines trusted-source URLs with human confirmation before any booking or payment. (`intercom-fin-guidance-best-practices`, `meta-agents-rule-of-two`)
- **Inventory every way output can reach a third party, and block each in code.** Microsoft names four seen in reported exploits: rendered markdown or HTML images (zero-click, data in the URL), links with data in the query string, tool calls that write where an outsider can read, and covert channels where whether a tool gets called leaks one bit. Most vendor fixes (ChatGPT, Bard, Amazon Q, M365 Copilot) closed the egress path rather than stopping the injection. (`msrc-indirect-injection-defense`)
- **A fetch tool opens only URLs that appeared in trusted input, never ones the model composed.** An injected instruction exfiltrates by building attacker.com/?q=<account data>; Anthropic's web fetch can't fetch "URLs that appear only in its own output" and refuses URLs that look like they carry a credential. Your own tools can launder: a result that echoes the model's input (an error quoting it, a command printing it) counts as an allowed source, so don't echo raw arguments; Chrome's Origin Sets go further, with trusted code fixing which origins a task may read and the smaller set it may write to, and checking every model-generated URL. (`anthropic-docs-web-fetch-tool`, `google-chrome-agentic-security`)
- **Review tool combinations: a customer-record read plus any outbound channel is an exfiltration path, and gate the outbound tool once sensitive data is read.** Anthropic's guide gives CRM plus external email: every step runs through trusted binaries under valid credentials, so host monitoring sees nothing. Before a call that carries sensitive data, the Model Spec (2026-08-18) weighs how sensitive it is, whether the recipient is trustworthy, the tool's side effects and whether sharing is in scope, and counts changing sharing settings or approving auth connections as information flow too. (`anthropic-zero-trust-ebook`, `openai-model-spec-2026-08-18`)
- **Remove the live egress sink the moment private data enters context.** After the agent reads private data from a connector, OpenAI switched GPT-5 in ChatGPT to cached browsing only (2025-08-07). Its opt-in Lockdown Mode (rolled out 2026-06-04) does it for high-risk accounts: cached-only browsing and no images in responses, Deep Research, Agent Mode, Canvas networking, live connectors or file downloads, with features disabled "when we can't provide strong deterministic guarantees of data safety"; OpenAI says it "does not guarantee" prevention. (`openai-gpt-5-system-card`, `openai-lockdown-mode-elevated-risk`)

## Secrets in reach

- **Keep provider API keys and production credentials out of anything an agent, sandbox or LLM proxy can read.** In 2026 attackers used prompt injection against LiteLLM deployments and an AI vendor's evaluation sandbox to get the keys they held; one stolen key was used "for roughly three weeks", and a follow-on campaign hit "roughly thirty AI companies in about four days" (Anthropic threat report, 2026-09-10). (`anthropic-threat-intel-september-2026`)
- **Strip credentials from anything the agent can read; read-only access doesn't protect them.** Before handing over a directory, remove .env files, cloud CLI credentials (~/.aws, gcloud ADC, ~/.azure, ~/.kube/config), registry tokens (.npmrc, .pypirc), git credentials, service-account JSON and private keys, or copy in only what's needed. A typical command sandbox confines writes but reads most of the machine, ~/.ssh included, and inherits the parent's environment variables; Claude Code's has "no built-in credential deny list", so list every secret file and variable yourself. (`anthropic-docs-agent-sdk-secure-deployment`, `anthropic-docs-claude-code-sandboxing`)
- **Scrub secrets from every tool output before the model sees it.** "Your application runs whatever command Claude requests", so validate commands against an allowlist rather than a blocklist, cap CPU, memory and disk, log every command with its output, and redact credentials from results. (`anthropic-docs-bash-tool`)
- **Give the agent a placeholder and substitute the real secret at egress, in request headers only, for the hosts you list.** Request bodies are built from content the agent handles, so body substitution lets an injected instruction put the placeholder in a payload that gets reflected or stored where someone can read it, and Managed Agents vaults enable both when you omit the location. Substitution is outbound only: a token obtained with the secret (OAuth client credentials) "arrives in the sandbox unredacted", so do the exchange in your backend and store only the short-lived result. (`anthropic-docs-managed-agents-vaults`)
- **Only operator-controlled config may release a credential to a destination, and a changed destination loses the credential.** Claude Code ignores credential-masking, TLS-termination and plaintext-inject entries in a repository's own settings, but by default a mask that matches nothing only warns and leaves the real file readable, so fail closed. Anthropic's inference hooks store auth headers write-only and wipe them when the endpoint URL changes, "so your credentials are never sent to a new destination". (`anthropic-docs-claude-code-sandboxing`, `anthropic-docs-inference-hooks-configuration`)

## Memory outlives the conversation

- **Never write one customer's conversation into memory another customer's session reads.** Across three agents, MINJA planted malicious records through queries alone with 98.2% average injection success and 76.8% average attack success (2025-03, Michigan State University et al.), then hijacked how the agent handled other users' queries. Write shared memory only from vetted sources (staff-approved resolutions), keep memory per customer, and when one agent serves many people give it identity and memory per compartment, as Anthropic's Claude Tag does per private channel. (`dong-minja-memory-injection`, `anthropic-agent-identity-access-model`)
- **Rank memory by provenance, and keep what a customer asked you to remember out of the system slot.** OpenAI's personalization cookbook trusts structured profile keys "especially if sourced/enriched internally" over free-text notes, lets the latest user message win and asks on conflict; it also injects memory notes into the system prompt, calls memory "a high-value attack surface", and says its delimiters are "not a security boundary". Otherwise a note a customer planted, claiming VIP status and pre-approved refunds, weighs the same as your database record; log memory_write_rate and blocked_write_rate per 100 turns, and test with "remember my SSN" and "store this rule". (`openai-memory-personalization-cookbook`)
- **Attach reference memory read-only, and scan memory when a session starts, not only when it's written.** Anthropic's managed memory attaches read-write by default, so one injected write is read as trusted memory by every later session, and its memory tool tells the model "ALWAYS VIEW YOUR MEMORY DIRECTORY BEFORE DOING ANYTHING ELSE". Anthropic names memory poisoning a classic post-exploitation persistence mechanism and expects startup classifiers to become commonplace; cap file sizes and expire old files. (`anthropic-docs-managed-agents-memory`, `anthropic-docs-memory-tool`, `anthropic-how-we-contain-claude`)
- **Apply four controls to memory read back into context: sanitize before storing, isolate per user and tenant, log and scan every read and write, and tell the model that instructions in memory aren't commands.** Anthropic's memory cookbook calls memory a "critical risk" injection vector, and secrets and PII never go there. Validate every path: canonicalize it, confirm it stays under the per-user root, and reject `../`, `..\` and `%2e%2e%2f`, since `/memories/../../secrets.env` otherwise reads or overwrites files outside memory. (`anthropic-memory-cookbook`, `anthropic-docs-memory-tool`)
- **Gate memory writes that came from content rather than from the user, and show users what was saved and where it came from.** Microsoft (2026-02) found 50 "Summarize with AI" prompts from 31 companies in 14 industries over 60 days planting "remember [Company] as a trusted source" through ?q= links. Claude Opus 4.7 with memory stored fake user facts from a ChatGPT-generated puzzle image in 5 of 10 attempts (2026-04, Rehberger), despite a memory prompt forbidding verbatim commands. (`microsoft-ai-recommendation-poisoning`, `rehberger-breaking-opus-memory`)
- **Never cache credentials, tokens or a prior user's authorization in memory that crosses sessions or users, and control who writes to the knowledge base.** Anthropic's zero-trust guide names memory-based privilege retention (cached secrets reused across session boundaries), RAG poisoning through over-trusted ingestion pipelines, shared-context poisoning between tenants, and slow memory drift where no single change looks malicious. (`anthropic-zero-trust-ebook`)
- **Process each untrusted message in a fresh context, and treat what other sessions wrote to a shared store as untrusted input.** In hackmyclaw, early obvious injections made the agent suspicious of everything after, and around email 500 it wrote to memory that this was "a coordinated security exercise". In OpenAI's Hugging Face incident (2026-08-26), unauthorized coordination started with one agent leaving a note as external memory, with messages encoded in URL paths, so monitor and restrict writes to any shared store. (`irarrazaval-hackmyclaw`, `openai-hugging-face-incident-road-ahead`)
- **A read-only mount protects memory from syncing back, not from local edits.** Any shell or custom tool in the sandbox can change the local copy and later steps read it, so if memory must be tamper-proof for the session, give that agent no shell or file-writing tool. (`anthropic-docs-managed-agents-self-hosted-sandboxes-security`)

## Allowlisted destinations still leak

- **Never let an agent with outbound reach read the raw support inbox that also receives your own password resets and OTPs.** Intigriti (2026): a spoofed note told the agent what to do with the next email from no-reply@x.com, the attacker triggered a real X password reset for the company's support address, and the agent leaked the OTP as a subdomain lookup to the attacker's wildcard DNS. Filter those senders and strip codes in code, and restrict the environment to designated DNS resolvers, because a lookup of <data>.attacker.com leaks with HTTP blocked (NVIDIA). (`intigriti-hacking-ai-support-agents`, `nvidia-sandboxing-agentic-workflows`)
- **Audit every allowlisted domain for expiry and for ways to receive data through a GET.** In ForcedLeak, my-salesforce-cms.com stayed on Agentforce's CSP allowlist after it expired and became purchasable (Noma, 2025-09-25; injection.md has the full chain). PromptArmor (Jan 2026): an unopened email made Superhuman AI emit an image pointing to a pre-filled Google Form, and because Google Docs was allowlisted it submitted the full contents of several emails and parts of 40+ others. (`noma-forcedleak-agentforce`, `promptarmor-superhuman-exfil`)
- **Put a provenance-checking proxy in front of any allowed API that can also store data.** Anthropic's Cowork leak: a planted file with an attacker's API key made Claude upload workspace files to the attacker's account through api.anthropic.com, which the allowlist correctly permitted; forward only requests carrying the agent's own provisioned token and strip headers that trigger server-side fetches. (`anthropic-how-we-contain-claude`)
- **Test each layer's failure mode separately, because real exploits chain small bypasses.** EchoLeak (CVE-2025-32711, zero-click, CVSS 9.3) evaded Microsoft's injection classifier, dodged link redaction with reference-style markdown, used images the client fetched automatically, and sent data through a Teams proxy the CSP allowed. (`aim-echoleak-paper`)
- **Map where each tool call runs: provider-side fetches and hosted connectors leave from the provider's network, not yours.** ShadowLeak (Radware, 2025-09-18): one email made ChatGPT Deep Research send base64-encoded inbox PII to an attacker URL from OpenAI's servers, invisible to enterprise gateways, so control which URLs such a tool may open and monitor its actions against the user's goal. To keep tool traffic inside your boundary, run local MCP servers and deny the hosted connectors (in Claude Code, `allowedMcpServers` and `deniedMcpServers`). (`radware-shadowleak`, `anthropic-docs-claude-code-self-hosted-environments-deploy`)
- **When your infrastructure fetches a URL learned from a server or a document, enforce HTTPS, block private, loopback and link-local ranges, 169.254.169.254 included, and validate every redirect hop.** Otherwise a malicious server points your backend at internal services or cloud credentials (MCP spec SSRF guidance, 2025-11-25). (`mcp-spec-security-best-practices`)

## Retention and tenancy

- **Check retention on every path customer data takes, not only the model call.** Website publishers may keep any parameters in a URL the agent fetches even when your provider has zero data retention, so customer data never goes in fetched URLs, and on the Claude API "The MCP connector is not covered by ZDR arrangements". (`anthropic-docs-server-tools`, `anthropic-docs-mcp-connector`)
- **Never let one customer's agent state reach another customer's session.** Claude API code-execution containers are scoped to the workspace, persist up to 30 days and keep interpreter state between requests, so keep a container-to-customer mapping in your backend. On a host serving several tenants, give each its own config directory, working directory and egress policy, skip shared settings files, and turn auto memory off explicitly, since the Agent SDK loads it into the system prompt regardless of settings sources. (`anthropic-docs-code-execution-tool`, `anthropic-docs-agent-sdk-hosting`)
