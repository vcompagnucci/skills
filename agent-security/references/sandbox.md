# Sandboxes and network egress

For agents that run code, drive a browser or fetch URLs. A customer-facing support agent that only calls your own tools needs the first bullet and none of the rest; what it may touch is permissions.md.

## Isolation for agents that run code

- **Never give an agent that reads untrusted content a shell, open internet and secrets on one machine; a customer-facing support agent gets no shell at all (agent-harness tools.md).** In-chat confirmations and prompting are not tool-invocation controls. One planted GitHub issue made Devin download attacker malware, mark it executable after a permission error, run it and hand over a remote shell with access to AWS keys (Rehberger, 2025-08-06, $500 for 30 days of access, fix status unanswered after 120+ days), so block outbound by default and require out-of-band approval for sensitive operations. (`rehberger-devin-500`)
- **Put the whole agent process inside one isolation boundary that also covers every subprocess.** A per-action classifier or a parser matching commands against rules is a permission gate, not a sandbox: it doesn't know what a command does to its target, and a sandbox around shell calls leaves file tools, MCP servers and hooks running on the host. Restrictions on direct tool calls are bypassed by any script the agent writes; Anthropic open-sourced sandbox-runtime (bubblewrap and Seatbelt) for wrapping arbitrary agents and MCP servers. (`anthropic-docs-claude-code-sandbox-environments`, `anthropic-docs-agent-sdk-secure-deployment`, `anthropic-claude-code-sandboxing`)
- **Pick isolation strength by threat: containers share the host kernel, so multi-tenant agents and untrusted content get gVisor or microVMs.** A kernel exploit from injected code escapes an OS sandbox or a container. Anthropic's secure-deployment guide prices it: gVisor ~0% on CPU-bound work, ~2x slower on simple syscalls and up to 10-200x on heavy file open/close; Firecracker boots in under 125 ms with less than 5 MiB memory overhead. (`anthropic-docs-agent-sdk-secure-deployment`)
- **The agent can never write its own configuration or retry its way out of the sandbox.** Permission settings, hooks, MCP server lists, skills, shell startup files and git hooks stay unwritable from inside, with no allow rule able to lift it, because an agent that edits them can grant itself permissions or plant a hook that runs unsandboxed next launch. Close every escape hatch: Claude Code lets the model retry a failed command with the sandbox disabled, and an allow rule like `Bash(curl *)` approves that retry with no prompt, so turn the retry off and fail when the sandbox can't start. (`anthropic-docs-claude-code-sandboxing`)
- **Prove the sandbox isolates before trusting it, and re-verify before each run.** Claude models attacked real third-party systems during evals whose prompts said there was no internet, in 4 incidents over 7 runs of 10 to 34 hours of active work each, because a misconfiguration left it open (2026-09-09, Anthropic). Test egress from inside in CI, review the config statically, have a model try to break out in a second isolated environment with no internet, and check at startup that the policy file loaded: Anthropic's runtime starts on built-in defaults when it finds none, and on Linux its write-deny list misses repositories created later. (`anthropic-alignment-assessment-cyber-incidents`, `anthropic-improving-alignment-security`, `anthropic-docs-claude-code-sandbox-environments`)
- **Enforce the boundary at the OS and network level even with the best-aligned model.** Claude Opus 5.5 without safeguards attempted to cross a sandbox boundary in 1.5% of runs across 28 handmade scenarios run seven times each (2026-09-22, Anthropic's own system card); every case stayed low severity because a stronger barrier stopped it. (`anthropic-system-card-opus-5-5`)
- **Cover each objective with independent controls, and expect agents to route around a broken tool.** In OpenAI's Hugging Face incident (2026-08-26) agents escaped network isolation through a package proxy allowed to reach the internet, then chained unknown vulnerabilities: "no single control should ever be assumed to be fully robust". In its DNS incident (training run, 2026-09-20), a search tool returning irrelevant results led an agent to query search engines from the shell, download the benchmark and reach a public chatbot through unfiltered DNS, so return a clear error and alert on agents probing alternatives. (`openai-hugging-face-incident-technical-report`, `openai-misalignment-report-dns-chatbot`)

## Network egress

- **Set the network mode explicitly, and treat every allowed host as open for writes.** Managed Agents give an API create request that omits networking unrestricted outbound access while the Console starts limited, and with an always-allow toolset nothing pauses a command sending files out. Access is "granted per host, not per operation", so an allowed host takes git push, package publish and POST with any credential, and enabling package managers also opens github.com, gitlab.com and raw.githubusercontent.com. (`anthropic-docs-managed-agents-environments`)
- **Keep two allowlists and check both: where a credential may be sent, and where the agent may connect.** A credential's host list "controls which requests use the secret, not which requests are allowed", so the network policy must also cover the host; a literal placeholder arriving at a third party means a host wasn't covered. (`anthropic-docs-managed-agents-vaults`)
- **Restrict provider-run fetch tools on their own, and keep web fetch out of sessions that mix untrusted input with sensitive data.** Web search and web fetch run on the provider's servers, so the sandbox allowlist doesn't limit them; set the tool's own allowed or blocked domains. Anthropic warns that mix "poses data exfiltration risks" and its fetch has "currently no default limit" on uses, so set a domain allowlist and a per-request cap. (`anthropic-docs-managed-agents-environments`, `anthropic-docs-web-fetch-tool`)
- **Never rely on proxy environment variables to force traffic through your egress proxy.** Not every program respects HTTP_PROXY/HTTPS_PROXY (Node.js `fetch()` ignores them by default), so remove the network interface and expose only a proxy socket, or redirect all outbound traffic to a transparent proxy with iptables. (`anthropic-docs-agent-sdk-secure-deployment`)
- **Give a browsing agent site-level permissions and a fresh profile with no saved logins, in its own low-privilege container or VM.** Anthropic calls permissions "the first line of defense" against injection in Claude in Chrome, blocks high-risk site categories, and keeps confirmation before publishing, purchasing or sharing personal data even in autonomous mode. Enforce the allowlist at the network layer, re-check it after every redirect, and block loopback, link-local and private ranges. (`anthropic-claude-in-chrome-pilot`, `anthropic-docs-browser-use-tool`)
- **Build egress allowlist-first, with deny over allow and a check on where each name resolves.** Codex's network proxy is the model: nothing reachable until allowed, deny beats allow, `*.example.com` covers subdomains but not the apex, loopback, link-local and private destinations blocked by default, names resolving to private IPs blocked even when allowlisted, failed lookups blocked; OpenAI says the DNS check "reduces DNS rebinding risk, but it does not eliminate it". Block 169.254.169.254 inside the container itself, since subnet egress rules don't intercept link-local traffic and model-directed code would inherit the host's cloud identity (or use IMDSv2 with a hop limit of 1), and keep internal hostnames off the list, because an allowed intranet name resolving to 10.0.0.0/8 still connects. (`openai-codex-approvals-security`, `anthropic-docs-claude-code-self-hosted-environments-deploy`, `anthropic-docs-claude-code-sandboxing`)
- **A hostname allowlist without TLS inspection leaks, and a proxy into your internal tools is an SSRF pivot.** Anthropic's sandbox proxy allowlists by client-supplied hostname without terminating TLS, so domain fronting reaches hosts outside the list; use a TLS-terminating proxy when exfiltration matters. A proxy the agent uses to reach internal tools gets upstream destinations limited to the smallest IP ranges covering those servers, its own egress restricted, and its image pinned by digest. (`anthropic-docs-agent-sdk-secure-deployment`, `anthropic-docs-mcp-tunnels-security`)
- **Write domain lists in ASCII and test how they match.** Look-alike Unicode domains (a Cyrillic "а" in amazon.com) bypass filters, an entry like example.com silently includes every subdomain, user-content ones too, and on Anthropic's web fetch an entry with a path never matches, so a path-scoped block blocks nothing. (`anthropic-docs-server-tools`)
- **Audit sandbox allowances that hand back what the sandbox took away.** A mounted Docker socket "effectively grants access to the host system", writable $PATH directories or shell startup files give code execution in other contexts, a broad domain like github.com is an exfiltration path, and weaker-nested-sandbox or Apple Events allowances weaken or remove isolation. (`anthropic-docs-claude-code-sandboxing`)
