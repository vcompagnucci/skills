# Glossary

Every term the claude.dev, claude.com agents, and Anthropic engineering posts coin or use in their own sense, in alphabetical order.

- **Ablation.** Removing individual system-prompt lines to measure each line's impact. (`postmortem-apr-2026`)
- **Adversarial verification.** A separate agent checks each agent's output against a rubric. (`workflows`)
- **Advisor strategy.** A faster, cheaper worker model calls a more intelligent model to check its plan and evaluate its work, coached only when needed. (`models-explained`)
- **Affordances (of agents).** The distinct ways agents perceive the actions a tool makes possible, unlike traditional software. (`writing-tools`)
- **Agent (in SWE-bench sense).** The combination of an AI model and the software scaffolding around it. (`swe-bench`)
- **Agent / environment / session.** Configuration (model, prompt, tools, guardrails) / execution context (sandbox, networking, packages) / one run pairing the two with its own sandbox. (`agentic-surfaces`)
- **Agent harness.** The scaffolding around a model: loop, tools, context management and guardrails that turn intelligence into a working agent. (`harness-patterns`)
- **Agent harness design.** Deciding what belongs in that scaffolding and, as models improve, what you can take out. (`harness-patterns`)
- **Agent loop.** Gather context, take action, verify work, repeat. (`agent-sdk`)
- **Agent Skills.** Folders of instructions, scripts, and resources that agents discover and load when relevant. Published as an open standard on December 18, 2025. (`skills-for-agents`, `agent-skills`)
- **Agent teams.** Several Claude instances working in parallel as persistent workers, claiming tasks from a shared queue or file lock without an orchestrator. (`coordination-patterns`, `c-compiler`)
- **Agent-computer interface (ACI).** The tool definitions and formats through which an agent acts, deserving HCI-level design effort. (`effective-agents`)
- **Agentic laziness.** Claude stops a long multi-part task early and calls it done after partial progress. (`workflows`)
- **Agentic search.** The agent searching the file system itself with bash tools, versus pre-embedded semantic search. (`agent-sdk`)
- **Agentic SOAR.** Security operations for agentic systems run fast enough to contend with AI-accelerated attackers. (`zero-trust`)
- **Agentic systems.** Umbrella for both workflows and agents. (`effective-agents`)
- **Agentic thinking divide.** The gap between AI deployments that compound and those that stall (named, not defined in the post). (`enterprise-agents`)
- **AI dust.** AI automations sprinkled onto existing workflows without changing the product's value proposition. (`monday`)
- **AI vendoring.** Having an LLM reimplement the functionality you use from a poorly maintained small dependency instead of relying on it. (`ai-offense`)
- **Approval fatigue.** Users no longer paying attention to what they approve after constant prompts. (`auto-mode`, `sandboxing`)
- **Attention budget.** The finite attention an LLM spends across its context, every token depletes it. (`effective-context`)
- **Augmented LLM.** The building block: an LLM enhanced with retrieval, tools, and memory. (`effective-agents`)
- **Blast radius.** The damage an agent could do if it fails, as distinct from how likely failure is. (`containment`)
- **Blastbox.** An isolation environment that hides the agent from sensitive internals without hindering it, assuming it may be hijacked. (`outtake`)
- **Brain / hands / session.** Claude plus harness, the sandboxes and tools that act, the durable event log. (`managed-agents`)
- **Bring Your Own Agent (BYOA).** Letting an externally built Claude Managed Agent join the platform as a teammate anyone can mention and assign. (`monday`)
- **Browser use tool.** Computer use for the web that adds page structure to the screenshot. (`production-apis`)
- **Cache-aware rolling buffer.** Pruning old screenshots in batches so the prompt prefix stays stable between prune events. (`computer-use`)
- **Cache-safe forking.** A side computation (compaction, summarization, skill execution) runs with the parent's exact prefix so it hits the cache. (`caching`)
- **Capability vs regression evals.** Start low as a hill to climb vs stay near 100% to catch backsliding. (`agent-evals`)
- **ci-weather.** An agent that compiles incidents, build metrics and deploy lag into a public newsroom-style CI report. (`ci-first-responder`)
- **Classify-and-act.** A classifier agent routes a task to different agents, or classifies the output at the end. (`workflows`)
- **Claude Tag.** Claude as a member of Slack channels with memory, service-account access and scheduled routines. (`ci-first-responder`)
- **Clean state.** Code fit to merge to main: no major bugs, orderly and documented, ready for the next feature. (`long-running-harness`)
- **Clear discovery / reliable orchestration / consistent performance.** The three things a skill adds on top of MCP access: where to look, in what order, to what standard. (`skills-and-mcp`)
- **Code execution with MCP.** The agent writes code against MCP servers presented as code APIs rather than calling them as tools. (`mcp-code-exec`)
- **Coding agent.** Every later session, prompted to make incremental progress and leave structured updates. (`long-running-harness`)
- **Compaction buffer.** Context space held back for the compaction prompt and the summary it produces. (`caching`)
- **Connectors.** MCP servers as surfaced inside Claude. (`what-is-mcp`)
- **Containment.** Supervising what the agent is *able* to do (sandboxes, VMs, egress controls) rather than what it does. (`containment`)
- **Context anxiety.** A model wrapping up work early as it senses its context limit approaching. Sonnet 4.5 had it, Opus 4.5 largely did not. (`agentic-surfaces`, `harness-patterns`, `managed-agents`, `harness-design-apps`)
- **Context engineering.** Curating everything Claude receives besides the prompt (system prompt, tools, skills, CLAUDE.md, memory, data, history) to keep the smallest set of high-signal tokens. (`ctx-eng`, `effective-context`)
- **Context pollution.** Irrelevant information from one subtask accumulating in context and degrading later reasoning. (`when-multi-agent`)
- **Context reset.** Clearing the context window and starting a fresh agent with a structured handoff of state and next steps, as opposed to compaction. (`harness-design-apps`)
- **Context window pollution.** Test output flooding the context with useless bytes. (`c-compiler`)
- **Context-centric decomposition.** Splitting work by the context each agent needs rather than by the type of work. (`when-multi-agent`, `coordination-patterns`)
- **Contextual Embeddings / Contextual BM25.** The two sub-techniques: embedding, and building the BM25 index over, contextualized chunks. (`contextual-retrieval`)
- **Contextual Retrieval.** Prepending chunk-specific explanatory context to chunks before indexing. (`contextual-retrieval`)
- **Data-plane injection.** Injection planted in product names, reviews, or snippets that arrive via tool results, vs user-authored injection. (`commerce-agents`)
- **Dead weight.** Harness structure built to compensate for a limitation the model no longer has. (`harness-patterns`)
- **Decoupling the brain from the hands.** Running the harness that calls Claude separately from the sandbox where code executes. (`agentic-surfaces`)
- **Deny-and-continue.** A blocked action returns to the agent as a nudge toward a safer path instead of stopping the session. (`auto-mode`)
- **Desktop Extension (.mcpb, MCP Bundle).** A zip archive of a local MCP server, its dependencies, and a `manifest.json`, installable in one click. (`desktop-extensions`)
- **Digital risk analyst.** An AI teammate that surfaces risk insights and forms opinions on exposure across asset classes, supervised by human risk managers. (`millennium`)
- **Dreaming.** A scheduled process that reviews agent sessions and memory stores, extracts patterns and curates memories. (`agentic-surfaces`)
- **Dynamic workflow.** A multi-agent script Claude writes for one task, in JS with `agent()`, `parallel()`, and `pipeline()`. (`workflows`)
- **Early victory problem.** A verifier marking work as passing after superficial testing. (`when-multi-agent`)
- **Effort.** How much compute you want spent. It mostly changes thinking, and with it how much Claude verifies and decides on its own. (`effort`)
- **Effort curve.** Score against tokens across one model's effort levels. (`effort`)
- **Effort ladder.** Running a hard task at medium and then high, and a mechanical task at low, to find the right level. (`cost`)
- **Elicitation.** The model asking the user questions. (`seeing`)
- **End-state evaluation.** Judging the final state an agent reaches rather than turn-by-turn process. (`research-system`)
- **Ergonomic tools.** Tools shaped so agents can use them effectively. (`writing-tools`)
- **Error-proofing tools.** Changing tool arguments so mistakes are hard to make (e.g. absolute paths only). (`swe-bench`)
- **Eval awareness.** A model hypothesizing that it is being evaluated and acting on that hypothesis. (`eval-awareness`)
- **Eval saturation.** The agent passes all solvable tasks, leaving no signal for improvement. (`agent-evals`)
- **Eval-driven development.** Build evals defining capabilities before the agent can fulfill them. (`agent-evals`)
- **Evaluation harness vs agent harness.** Infrastructure that runs evals vs the scaffold that makes a model an agent. (`agent-evals`)
- **Fan-out-and-synthesize.** One agent per step, each in a clean context, then a step that waits for all of them and merges their outputs. (`workflows`)
- **Finish line.** The explicit "done means..." condition in a task prompt. (`opus-5-5`)
- **Foundation / capability / impact trends.** The report's three categories: how development happens / what agents accomplish / business outcomes. (`eight-trends`)
- **Foundational / partner / enterprise skills.** Core document capabilities, vendor-built service skills, and proprietary internal-process skills. (`skills-for-agents`)
- **Full-VM mode / host mode.** Cowork's agent loop inside the VM vs. outside it with only code execution inside, moved to host mode because VM startup failures made Cowork unusable. (`containment`)
- **Game of telephone.** Information loss when subagent output passes through the coordinator, fix by writing artifacts to a filesystem and passing references. (`research-system`)
- **Generate-and-filter.** Generate many ideas, filter them by rubric or test, and drop duplicates. (`workflows`)
- **Generator-verifier.** One agent produces, another accepts or rejects with feedback until accepted or capped. (`coordination-patterns`)
- **Goal drift.** Claude slowly loses the original objective across turns, especially after compaction drops details. (`workflows`)
- **Gotchas section.** The list of known failure points in a skill, grown from real failures. The posts call it the highest-signal part of a skill. (`skills`)
- **Guided / structured chain of thought.** Prescribing reasoning stages, or separating reasoning from answer with tags. (`prompt-engineering`)
- **Hand-off vs delegation.** Hand-off transfers ownership of the conversation to a domain agent, delegation keeps the orchestrator and bounces the domain agent in and out. (`commerce-agents`)
- **Handoff tax.** The state loss, tokens, and latency paid each time an orchestrator delegates to a subagent. (`commerce-agents`)
- **Headroom.** The band between guaranteed resource allocation and the hard kill limit. (`infra-noise`)
- **Hill climbing.** Driving a metric down step by step once Claude can measure it. (`faster`)
- **HTML maximalist.** Thariq's name for himself: he stopped using Markdown for almost everything. (`html`)
- **Infinite exploration.** An unscoped "investigate" that reads hundreds of files and fills the context. (`cc-best-practices`)
- **Infrastructure noise.** Score variance from runtime configuration (resources, time limits, cluster health, latency) rather than model capability. (`infra-noise`)
- **Initializer agent.** The first session, prompted to set up the environment future sessions need. (`long-running-harness`)
- **Inner/base skill.** The skill holding the agent's functional domain knowledge and instructions. (`warp`)
- **Inter-agent contamination.** Traces of one agent's searches (e.g. autogenerated URL slugs) leaking into later agents' runs. (`eval-awareness`)
- **Just-in-time context.** Holding references (paths, queries, links) and loading data via tools at runtime. (`effective-context`)
- **Kitchen sink session.** One session mixing unrelated tasks until context is full of irrelevant information. (`cc-best-practices`)
- **Known-good compiler oracle.** A trusted reference (GCC) used to isolate which part of a monolithic task is broken. (`c-compiler`)
- **lessons.md.** A running incident log the agent appends to itself and reads before every investigation. (`ci-first-responder`)
- **Loop until done.** Keep spawning agents until a stop condition is met, instead of running a fixed number of passes. (`workflows`)
- **Max API fit.** Computing per-image the largest resolution within API limits that preserves native aspect ratio. (`computer-use`)
- **MCP (Model Context Protocol).** An open standard defining how LLMs communicate with external systems. (`what-is-mcp`)
- **MCP Client / MCP Server.** The AI-side connector vs the application side that exposes tools and data. (`what-is-mcp`)
- **Menu approach.** SKILL.md describes what's available and uses relative paths to separate files, so Claude reads only the one the task needs. (`create-skills`)
- **Meta-harness.** A system with general interfaces that accommodates many harnesses, unopinionated about which one Claude needs. (`managed-agents`)
- **M×N integration problem.** Every agent-service pair becoming a bespoke integration with its own auth and edge cases. (`mcp-production`)
- **Numbers demon.** How engineer Shelley Vohr described the model during the performance sprint. (`faster`)
- **On-demand hooks.** Hooks a skill turns on only while it's invoked, for that session (`/careful`, `/freeze`). (`skills`)
- **Opusplan.** A model alias where Opus plans in plan mode and Sonnet carries out the plan. (`cost`)
- **Orchestrator-worker pattern.** A lead agent plans and spawns parallel subagents, then synthesizes, a CitationAgent attributes claims. (`research-system`)
- **Outer/improver skill.** A scheduled observer agent that reads accumulated feedback and proposes edits to the base skill. (`warp`)
- **Overeager behavior.** The agent understands and pursues the user's goal but takes initiative beyond what the user would approve. (`auto-mode`)
- **pass^k.** The probability that all k independent trials succeed, measuring consistency (pass@k: at least one succeeds). (`agent-evals`, `think-tool`)
- **Patch gap.** The window between a patch being published and it being applied, now exploitable because models turn patches into exploits. (`ai-offense`)
- **Pet vs cattle.** A hand-tended server you can't lose vs interchangeable instances. (`managed-agents`)
- **Plugin.** A bundle of skills, connectors, slash commands and sub-agents that tells Claude how a team works. (`cowork-plugins`)
- **Pre-warming the cache.** Sending a `max_tokens: 0` request with a cache breakpoint so the first real request hits a warm cache. (`platform-cost`)
- **Prefilling.** Starting the assistant's response yourself (e.g. `{`) to force format or skip preamble. (`prompt-engineering`)
- **Presentation tools.** UI components exposed as typed tool calls the client renders. (`commerce-agents`)
- **Principle of Least Agency.** Limit what an agent can access and do with hard boundaries to contain blast radius. (`secure-sdlc`)
- **Private plugin marketplace.** An org-specific catalog for distributing plugins internally, managed by admins. (`cowork-enterprise`)
- **Process completion problem.** Regulated workflows need actions taken across several systems to finish, not just information. (`finance-agents`, `healthcare-agents`)
- **Programmatic Tool Calling (PTC).** Claude writes code in the Code Execution tool that calls tools, only the script's output enters context. (`advanced-tool-use`)
- **Progressive disclosure.** Loading context in levels only as needed: skill metadata, then the body, then bundled files, and tool definitions read on demand. (`seeing`, `ctx-eng`, `skills-explained`, `mcp-code-exec`, `agent-skills`)
- **Prompting anti-patterns.** Accumulated instructions that patched older models' weaknesses and now waste tokens or degrade frontier models. (`platform-cost`)
- **Quarantine.** Agents that read untrusted content get no privileges. The agent that acts only sees their summaries. (`workflows`)
- **Railroading.** Spelling out every step in a reusable skill so Claude can't adapt it. (`skills`)
- **Rainbow deployments.** Keeping old and new versions running while gradually shifting traffic. (`research-system`)
- **Ratchet.** A CI benchmark ceiling that can only go down, lowered automatically when the count improves. (`faster`)
- **Reactive loops.** Agents in shared state endlessly responding to each other's writes without converging. (`coordination-patterns`)
- **Reasoning-blind.** The classifier sees only user messages and tool calls, never the agent's prose or tool outputs. (`auto-mode`)
- **Reflections.** Manual post-run reviews of agent performance that become the roadmap for automated evals. (`outtake`)
- **Rich references.** Detailed inputs (HTML artifacts, test suites, code to port, rubrics) that replace plain markdown specs. (`ctx-eng`)
- **Right altitude.** The Goldilocks zone for prompts between brittle hardcoding and vague guidance. (`effective-context`)
- **Rulebook-style work.** Operations-type tasks where more effort barely helps (12% to 22%). (`effort`)
- **Runbook skills.** Skills encoding how an analyst works with data, as opposed to a knowledge skill about where data lives. (`slack-analytics`)
- **Saturation.** When a benchmark is so easy for strong models that they solve almost all of it. (`models-explained`)
- **Sectioning / voting.** The two parallelization variants: independent subtasks vs the same task run several times. (`effective-agents`)
- **Seeing like an agent.** Designing tools from the model's point of view, by reading its outputs. (`seeing`)
- **Self-improvement loop.** Base skill, human feedback, improver skill, merged edit, repeat. (`warp`)
- **Self-preferential bias.** Claude prefers its own results when it verifies or judges them. (`workflows`)
- **Sequential / parallel / evaluator-optimizer workflows.** Fixed-order handoffs / independent concurrent agents with aggregated outputs / a generator refined by an evaluator's feedback loop. (`workflow-patterns`)
- **Served content.** Skill files refreshed continuously and re-read every conversation, rather than shipped once. (`slack-analytics`)
- **Shadow mode.** New AI reviewers post comments for human approval until they earn trust. (`secure-sdlc`)
- **Shopping agent / merchant agent.** The consumer-facing agent inside the app vs. the agent that supports the people running the store. (`commerce-launch`)
- **Skills.** Folders of instructions, scripts, and resources Claude discovers and loads dynamically when relevant, "specialized training manuals.". (`skills-explained`)
- **Soak period.** A waiting window before a change that could trade off intelligence goes wide. (`postmortem-apr-2026`)
- **Sprint contract.** Generator and evaluator agreeing, before code is written, what "done" looks like for a chunk and how it will be verified. (`harness-design-apps`)
- **Static composer.** An HTML copy of the input box built into the page, so users can type before React starts. (`faster`)
- **Structured note-taking / agentic memory.** The agent persisting notes outside the context window and reading them back later. (`effective-context`)
- **Task / trial / grader / transcript / outcome.** A test case, one attempt, scoring logic, full record of a trial, final environment state (a reservation in the DB, not "your flight has been booked"). (`agent-evals`)
- **Teach Mode.** Recording a human demonstration and replaying it as context for the agent. (`computer-use`)
- **Telephone game.** Fidelity lost at each handoff between problem-type-specialized agents. (`when-multi-agent`)
- **Test-time compute harness.** Anthropic's internal harness for letting a model work much longer on a problem. (`hiring-evals`)
- **The compounding layer.** MCP as the layer whose servers gain capability as clients and spec extensions advance, without new shipping. (`mcp-production`)
- **"Think" tool.** A tool that obtains no information and changes nothing, only appends a thought to the log, giving Claude a scratchpad mid-task. (`think-tool`)
- **Throwaway editor.** A one-off HTML file for one piece of data, ending in an export button. (`html`)
- **Time blindness.** Claude can't tell time and will spend hours running tests instead of making progress. (`c-compiler`)
- **Tool Search Tool.** A tool that lets Claude search a deferred tool library and load only matching definitions. (`advanced-tool-use`)
- **Tool Use Examples.** Sample calls (`input_examples`) in a tool definition that demonstrate usage patterns. (`advanced-tool-use`)
- **Tournament.** N agents try the same task in different ways, and pairwise judging picks a winner. (`workflows`)
- **Triage agent.** A model at the front of the alert queue doing a first-pass investigation and structured disposition before a human sees it. (`ai-offense`)
- **Triggering.** Claude's ability to call a skill, governed only by name and description. (`create-skills`)
- **Trust-then-verify gap.** A plausible-looking implementation that doesn't handle edge cases because nothing verified it. (`cc-best-practices`)
- **ultracode.** The trigger word that makes Claude Code build a dynamic workflow. (`workflows`)
- **Undertriggering.** A skill runs less often than expected. Logging usage finds it. (`skills`)
- **Unhobbling.** Removing constraints that older models needed. (`ctx-eng`)
- **Verification rituals.** Instructions like "verify twice" that frontier models take literally, duplicating work. (`platform-cost`)
- **Writer/Reviewer pattern.** One session implements, a separate fresh session reviews. (`cc-best-practices`)
