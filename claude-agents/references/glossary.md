# Glossary

Every coined term or term used in a specific sense across the claude.dev corpus, alphabetical, one line each.

- **Adversarial verification** — a separate agent checks each agent's output against a rubric or criteria. (`workflows`)
- **Agentic laziness** — Claude stopping a complex multi-part task early and declaring it done after partial progress. (`workflows`)
- **Cache-safe forking** — running a side computation (compaction, summarization, skill execution) with the parent's exact prefix so it hits the cache. (`caching`)
- **Classify-and-act** — a classifier agent routes a task to different agents or behavior, or classifies the output. (`workflows`)
- **Compaction buffer** — context space reserved for the compaction prompt and the summary output. (`caching`)
- **Context engineering** — assembling everything Claude receives besides your prompt: system prompt, skills, CLAUDE.md, memory, references. (`ctx-eng`)
- **Dynamic workflow** — a multi-agent harness Claude writes on the fly (JS with `agent()`, `parallel()`, `pipeline()`) for one task. (`workflows`)
- **Effort** — an approximation of how much compute you want spent; mostly changes thinking, and with it verification and independent judgment. (`effort`)
- **Effort curve** — score against tokens across effort levels for one model. (`effort`)
- **Effort ladder** — running a hard task at medium then high, and a mechanical task at low, to find the right level. (`cost`)
- **Elicitation** — the model's ability to ask the user questions. (`seeing`)
- **Fan-out-and-synthesize** — one agent per step in a clean context, then a barrier that merges structured outputs. (`workflows`)
- **Finish line** — the explicit "done means..." condition in a task prompt. (`opus-5-5`)
- **Generate-and-filter** — generate many ideas, filter by rubric or verification, dedupe. (`workflows`)
- **Goal drift** — gradual loss of fidelity to the objective across turns, especially after lossy compaction. (`workflows`)
- **Gotchas section** — the part of a skill listing known failure points, grown from real failures; its highest-signal content. (`skills`)
- **Hill climbing** — iteratively driving a metric once Claude can measure it. (`faster`)
- **HTML maximalist** — Thariq's self-description: stopped using Markdown for almost everything. (`html`)
- **Loop until done** — spawning agents until a stop condition is met, not a fixed number of passes. (`workflows`)
- **Numbers demon** — engineer Shelley Vohr's description of the model during the perf sprint. (`faster`)
- **On-demand hooks** — hooks a skill activates only while invoked, for that session (`/careful`, `/freeze`). (`skills`)
- **Opusplan** — model alias where Opus plans in plan mode and Sonnet carries out the plan. (`cost`)
- **Progressive disclosure** — letting the agent load context incrementally as it needs it: skill files referencing files, deferred tools, subagents. (`seeing`, `ctx-eng`)
- **Quarantine** — agents that read untrusted content get no privileges; the acting agent only sees their summaries. (`workflows`)
- **Railroading** — over-specifying steps in a reusable skill so Claude can't adapt. (`skills`)
- **Ratchet** — a CI benchmark ceiling that can only go down, lowered automatically when the count improves. (`faster`)
- **Rich references** — high-fidelity inputs (HTML artifacts, test suites, code to port, rubrics) replacing plain markdown specs. (`ctx-eng`)
- **Rulebook-style work** — operations-type tasks where extra effort helps little (12% → 22%). (`effort`)
- **Seeing like an agent** — designing tools by taking the model's point of view and reading its outputs. (`seeing`)
- **Self-preferential bias** — Claude's tendency to prefer its own results when verifying or judging them. (`workflows`)
- **Static composer** — an HTML copy of the input box baked into the page so users can type before React initializes. (`faster`)
- **Throwaway editor** — a single-purpose HTML file for one piece of data, ending in an export button. (`html`)
- **Tournament** — N agents attempt the same task differently; pairwise judging picks a winner. (`workflows`)
- **ultracode** — trigger word that makes Claude Code create a dynamic workflow. (`workflows`)
- **Undertriggering** — a skill being invoked less often than expected, found by logging usage. (`skills`)
- **Unhobbling** — removing constraints that were needed for older models. (`ctx-eng`)
