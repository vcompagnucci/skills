## Architecture and multi-agent systems (`references/architecture-and-multi-agent.md`)

- **[Building Effective AI Agents](https://www.anthropic.com/engineering/building-effective-agents)** (`effective-agents`, 2024-12-19, Erik S. And Barry Zhang). The most successful agents are built from simple, composable patterns, adding complexity only when it demonstrably improves outcomes.
- **[How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)** (`research-system`, 2025-06-13, Jeremy Hadfield, Barry Zhang, Kenneth Lien, Florian Scholz, Jeremy Fox, and Daniel Ford). Multi-agent systems win on open-ended, parallelizable research mainly because they spend more tokens across separate context windows, and making them work takes delegation-focused prompting, tool design, and production engineering.
- **[When to use multi-agent systems (and when not to)](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them)** (`when-multi-agent`, 2026-01-23, Cara Phillips). Start with a single agent. Go multi-agent only for context protection, parallelization or specialization, and split work by context boundaries rather than by type of work.
- **[Building a C compiler with a team of parallel Claudes](https://www.anthropic.com/engineering/building-c-compiler)** (`c-compiler`, 2026-02-05, Nicholas Carlini). Parallel Claudes running unattended can build large projects, but only if the environment (near-perfect tests, agent-shaped output, parallelizable work) lets them orient without a human.
- **[Common workflow patterns for AI agents](https://claude.com/blog/common-workflow-patterns-for-ai-agents-and-when-to-use-them)** (`workflow-patterns`, 2026-03-05, Anthropic). Three workflow patterns (sequential, parallel, evaluator-optimizer) cover most production multi-agent needs. Try a single agent first and add a pattern only when you can measure that it helps.
- **[Multi-agent coordination patterns: Five approaches and when to use them](https://claude.com/blog/multi-agent-coordination-patterns)** (`coordination-patterns`, 2026-04-10, Cara Phillips). Pick the multi-agent pattern that fits the problem's structure rather than the one that sounds sophisticated. Start with orchestrator-subagent, watch where it struggles, and evolve.
- **[A harness for every task: dynamic workflows in Claude Code](https://claude.dev/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code/)** (`workflows`, 2026-06-02, Thariq Shihipar and Sid Bidasaria). Claude can write its own multi-agent script per task, which counters laziness, self-preference, and goal drift on long or adversarial work.
- **[Basic workflows](https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/basic_workflows.ipynb)** (`cb-workflows`, 2024-12-19, Anthropic). Code walkthrough of three workflow patterns (chaining, parallelization, routing) that trade cost or latency for better results. Demo code, not production code.
- **[Evaluator optimizer](https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/evaluator_optimizer.ipynb)** (`cb-evaluator`, 2024-12-19, Anthropic). Code walkthrough of a generator and an evaluator in a loop. Use it only when the criteria are clear and feedback measurably improves the output.
- **[Orchestrator workers](https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/orchestrator_workers.ipynb)** (`cb-orchestrator`, 2024-12-19, Anthropic). An orchestrator decides the subtasks at runtime, because the right split often can't be predicted in advance.
- **[Multi-agent teams under latency pressure and budgets](https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/latency_multi_agent.ipynb)** (`cb-latency-teams`, 2026-09-18, eloreaux-ant). Left alone, a multi-agent team optimizes for thoroughness, not speed. Give every agent the same running clock, then steer pace with a one-line nudge or a numeric budget.
- **[Using Haiku as a sub-agent](https://github.com/anthropics/claude-cookbooks/blob/main/multimodal/using_sub_agents.ipynb)** (`cb-haiku-subagent`, 2024-03-13, alexalbertt). Code walkthrough: cheap Haiku subagents extract from separate documents in parallel, and a stronger model writes their prompt and the final answer.
- **[Multiagent: coordinate a specialist team](https://github.com/anthropics/claude-cookbooks/blob/main/managed_agents/CMA_coordinate_specialist_team.ipynb)** (`cb-specialist-team`, 2026-05-03, markn-ant). Scoping each specialist's tools to its role is a real containment boundary, and the coordinator can sequence dependent hand-offs on its own.
- **[Orchestrate subagents at scale with dynamic workflows](https://github.com/anthropics/claude-cookbooks/blob/main/claude_agent_sdk/08_Dynamic_workflows.ipynb)** (`cb-dynamic-workflows`, 2026-07-22, preston-tuggle, jimmyechan-ant). Put the plan in a script instead of a model's context, so structure enforces verification and one run can coordinate hundreds of subagents.
- **[Multiagent: watch a curriculum team work in real time](https://github.com/anthropics/claude-cookbooks/blob/main/managed_agents/CMA_watch_subagents_live.ipynb)** (`cb-watch-subagents`, 2026-07-15, cj-ant). Mostly a code walkthrough of live subagent streaming and per-role effort, with a few positions on what to trust in a stream.
- **[Patterns and problems in multiagent systems](https://www.anthropic.com/research/multiagent-systems)** (`multiagent-problems`, 2026-08-13, Carolyn Zou et al.). Real multiagent systems already show herd behavior, collusion, and escalation, and these don't go away with smarter or better-aligned individual agents.

## Harness design (`references/harness-design.md`)

- **[Claude SWE-Bench Performance](https://www.anthropic.com/engineering/swe-bench-sonnet)** (`swe-bench`, 2025-01-06, Erik Schluntz). A minimal scaffold (one prompt, a Bash tool, an Edit tool) that hands control to the model, plus carefully engineered tool descriptions, took upgraded Claude 3.5 Sonnet to state of the art on SWE-bench Verified.
- **[Building agents with the Claude Agent SDK](https://claude.com/blog/building-agents-with-the-claude-agent-sdk)** (`agent-sdk`, 2025-09-29, Thariq Shihipar). Give agents a computer and design them around the loop gather context, take action, verify work, repeat. The harness behind Claude Code generalizes to non-coding agents.
- **[Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)** (`long-running-harness`, 2025-11-26, Justin Young). Long-running agents make steady progress across context windows when an initializer agent sets up a feature list, progress file, and git repo, and every later session works one feature at a time and leaves a clean, documented state.
- **[Harness design for long-running application development](https://www.anthropic.com/engineering/harness-design-long-running-apps)** (`harness-design-apps`, 2026-03-24, Prithvi Rajasekaran (Anthropic Labs)). Separating the agent that builds from a tuned, skeptical agent that grades, inside a planner-generator-evaluator harness, gets Claude past the ceilings of solo runs. Strip each harness piece once the model no longer needs it.
- **[Agent Harness Design: 3 Patterns for Harnessing Claude's Intelligence](https://claude.com/blog/harnessing-claudes-intelligence)** (`harness-patterns`, 2026-04-02, Lance Martin). A harness encodes assumptions about what Claude can't do. Build on tools Claude already knows, keep testing what you can stop doing, and keep only the boundaries that serve cache, UX, security or observability.
- **[Scaling Managed Agents: Decoupling the brain from the hands](https://www.anthropic.com/engineering/managed-agents)** (`managed-agents`, 2026-04-08, Lance Martin, Gabe Cemaj, and Michael Cohen). Because harnesses encode assumptions that go stale as models improve, virtualize the agent into stable interfaces (session, harness, sandbox) so each implementation can be swapped without disturbing the others.
- **[The evolution of agentic surfaces: building with Claude Managed Agents](https://claude.com/blog/building-with-claude-managed-agents)** (`agentic-surfaces`, 2026-06-10, Gagan Bhat and Isabella He (Applied AI)). Infrastructure, not the prompt, separates a prototype from a production agent, so decouple the harness (brain) from the sandbox (hands) and let the harness evolve with the model. Partly a product post for Managed Agents.
- **[Guides to common use cases](https://platform.claude.com/docs/en/about-claude/use-case-guides/overview)** (`uc-overview`, undated, Anthropic). A directory page. Its one position is that the Messages API, the Agent SDK, and Managed Agents trade control for how much of the implementation Anthropic runs.
- **[Hosting your agent](https://github.com/anthropics/claude-cookbooks/blob/main/claude_agent_sdk/07_Hosting_the_agent.ipynb)** (`cb-hosting`, 2026-05-22, kevintang513, anav-ant). ## Tool design (`references/tool-design.md`)

- **[The "think" tool: Enabling Claude to stop and think](https://www.anthropic.com/engineering/claude-think-tool)** (`think-tool`, 2025-03-20, Anthropic). A no-op "think" tool that gives Claude a place to reason mid-response improves policy adherence and long tool-call chains, especially when paired with domain-specific prompting (a position later superseded by extended thinking).
- **[Writing effective tools for AI agents—using AI agents](https://www.anthropic.com/engineering/writing-tools-for-agents)** (`writing-tools`, 2025-09-11, Ken Aizawa). Tools are a contract with non-deterministic agents, so design them for agents, not as API wrappers, and improve them through realistic evaluations that Claude itself analyzes and uses to refactor the tools.
- **[What is Model Context Protocol? Connect AI to your world](https://claude.com/blog/what-is-model-context-protocol)** (`what-is-mcp`, 2025-10-31, Anthropic). An introductory explainer and Connectors promo. Its position is that one open protocol turns the M×N integration problem into build-once connectivity between AI apps and external systems.
- **[Code execution with MCP: building more efficient AI agents](https://www.anthropic.com/engineering/code-execution-with-mcp)** (`mcp-code-exec`, 2025-11-04, Adam Jones and Conor Kelly). Presenting MCP servers as code APIs that the agent calls from an execution environment, instead of as direct tool calls, cuts token use and latency by loading tools on demand and keeping intermediate data out of context.
- **[Introducing advanced tool use on the Claude Developer Platform](https://www.anthropic.com/engineering/advanced-tool-use)** (`advanced-tool-use`, 2025-11-24, Bin Wu). A launch post for three beta features, arguing that agents with large tool libraries need on-demand tool discovery, tool orchestration from code, and usage examples beyond JSON schemas.
- **[Seeing like an agent: how we design tools in Claude Code](https://claude.dev/blog/seeing-like-an-agent/)** (`seeing`, 2026-04-10, Thariq Shihipar). Shape tools to the model's abilities by reading its outputs, keep the set small, and retire tools the model outgrows.
- **[Building agents that reach production systems with MCP](https://claude.com/blog/building-agents-that-reach-production-systems-with-mcp)** (`mcp-production`, 2026-04-22, Anthropic). As production agents move to the cloud, MCP becomes the integration layer that compounds, so build a remote server designed around intent and pair it with skills.
- **[Best practices for computer and browser use with Claude](https://claude.com/blog/best-practices-for-computer-and-browser-use-with-claude)** (`computer-use`, 2026-05-13, Lucas Gonzalez and Luca Weihs). Reliable computer use comes mostly from harness hygiene (downscaled screenshots, cache-aware context pruning, scoped permissions), not from more thinking or clever image tricks.
- **[Build production agents with computer use, the Skills API, and the Files API](https://claude.com/blog/computer-use-skills-api-files-api)** (`production-apis`, 2026-08-20, Anthropic). GA announcement: a production agent combines acting on software (computer and browser use), your team's expertise (skills) and your documents (files). Mostly product news with a few real positions.
- **[Threat intelligence enrichment agent](https://github.com/anthropics/claude-cookbooks/blob/main/tool_use/threat_intel_enrichment_agent.ipynb)** (`cb-threat-intel`, 2026-04-07, jannet-park). Well-described modular tools let Claude choose sources and pivot across them, replacing the query sequences an analyst would hardcode.
- **[The site reliability agent](https://github.com/anthropics/claude-cookbooks/blob/main/claude_agent_sdk/03_The_site_reliability_agent.ipynb)** (`cb-sre-agent`, 2026-02-16, benlehrburger-ant, isabella-anthropic). Clear tool descriptions drive an agent more than elaborate prompts, and narrow, checked write tools are what make it safe to let it act on production.

Code walkthrough of a minimal client-side tool loop for a support bot with simulated data. Not a production agent.
- **[Paving the way for AI agents in biology](https://www.anthropic.com/research/agents-in-biology)** (`agents-in-biology`, 2026-06-08, Laura Luebbert). ## Context engineering (`references/context-engineering.md`)

- **[Contextual Retrieval in AI Systems](https://www.anthropic.com/engineering/contextual-retrieval)** (`contextual-retrieval`, 2024-09-19, Daniel Ford). Prepending a short, Claude-generated, chunk-specific context to every chunk before embedding and BM25 indexing fixes RAG's context loss, and the gains stack with hybrid search and reranking.
- **[Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)** (`effective-context`, 2025-09-29, Prithvi Rajasekaran, Ethan Dixon, Carly Ryan, Jeremy Hadfield (Applied AI)). Context is a finite attention budget, so building agents means curating the smallest set of high-signal tokens at every turn: right-altitude prompts, minimal tools, canonical examples, just-in-time retrieval, and compaction, notes, or sub-agents for long horizons.
- **[Prompt engineering best practices for 2026](https://claude.com/blog/best-practices-for-prompt-engineering)** (`prompt-engineering`, 2025-11-10, Anthropic). The best prompt is the clearest one with the minimum necessary structure. Add advanced techniques only when they solve a specific problem. (General-audience guide. Few agent-specific positions.)
- **[The new rules of context engineering for Claude 5 generation models](https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/)** (`ctx-eng`, 2026-07-24, Thariq Shihipar). Claude 5 models are overconstrained. Delete rules, examples, and repetition, and rely on judgment and on context loaded when needed.
- **[Best practices for Claude Code](https://www.anthropic.com/engineering/claude-code-best-practices)** (`cc-best-practices`, undated, Anthropic). Most Claude Code practice follows from one constraint. The context window fills fast and performance degrades as it fills, so give Claude a check it can run and guard context aggressively.
- **[Context engineering: memory, compaction, and tool clearing](https://github.com/anthropics/claude-cookbooks/blob/main/tool_use/context_engineering/context_engineering_tools.ipynb)** (`cb-ctx-tools`, 2026-03-20, isabella-anthropic). Compaction, tool-result clearing, and memory solve different slices of the context problem. Diagnose which one your workload has before using any.
- **[Automatic context compaction](https://github.com/anthropics/claude-cookbooks/blob/main/tool_use/automatic-context-compaction.ipynb)** (`cb-auto-compaction`, 2025-11-24, PedramNavid). Automatic compaction at a token threshold keeps sequential tool-heavy work from growing context linearly. The threshold depends on the workload.
- **[Session memory compaction](https://github.com/anthropics/claude-cookbooks/blob/main/misc/session_memory_compaction.ipynb)** (`cb-session-memory`, 2026-01-16, jsham042). Build the session summary in the background before the limit, so compaction is an instant swap instead of a slow wait.
- **[Memory & context management with Claude Sonnet 4.6](https://github.com/anthropics/claude-cookbooks/blob/main/tool_use/memory_cookbook.ipynb)** (`cb-memory`, 2025-05-22, zealoushacker). The file-based memory tool and server-side context editing complement each other. One carries lessons across sessions, and the other keeps one session small.
- **[Build agents that remember your users](https://github.com/anthropics/claude-cookbooks/blob/main/managed_agents/CMA_remember_user_preferences.ipynb)** (`cb-user-memory`, 2026-04-24, gaganb-ant). Managed Agents memory is a per-customer notebook of plain files. The design choices are scoping, seeding, and auditability.
- **[Getting the most out of Opus 5.5 in Claude and Claude Code](https://claude.dev/blog/getting-the-most-out-of-opus-5-5/)** (`opus-5-5`, 2026-09-22, Addy Osmani). Hand Opus 5.5 the whole task with a finish line, name the stops you want, and read what it needs from you first.

## Cost and model choice (`references/cost-and-model-choice.md`)
