# Glossary

Every term the 45 sources coin or use in their own sense, in alphabetical order. OpenAI product names that aren't concepts are left out.

- **Agent legibility.** Optimizing the repo so an agent can reason about the whole domain from it. (`harness-eng`)
- **Agent loop / harness.** The core logic orchestrating user, model, and tool calls. (`agent-loop`)
- **Agentic loop.** A structured loop for reasoning and acting, where the model investigates, consults tools, and reports back, keeping private notes between steps. (`responses-api`)
- **Agent-native APIs.** Interfaces built around multi-step tool use and reasoning rather than single chat turns. (`devs-2025`)
- **Agent-native telemetry.** Logs that capture prompts, approvals, and tool results so defenders can see intent. (`codex-safely`)
- **Auto-review mode.** A subagent that auto-approves low-risk boundary-crossing requests so the user isn't interrupted. (`codex-safely`)
- **Blended cost per verified resolution.** All model, tool, infra, retry, human-review, escalation and rework costs divided by verified issues resolved. (`cost-quality`)
- **Codex enrichment.** Deriving a table's meaning from the code that produces it. (`data-agent`)
- **Compaction.** Replacing the conversation input with a smaller representative set of items once a token threshold is exceeded. (`agent-loop`)
- **Compaction item.** A model-produced, token-efficient representation of prior conversation state carried into the next window. (`computer-env`)
- **Context asymmetry.** Each party has partial knowledge and none sees the whole system. (`chatgpt-apps-lessons`)
- **Context package.** The structured output of the context-builder stage, input to the reasoning stage. (`responses-year`)
- **Control evaluations.** Estimating monitor recall on adversarially built distributions, including whether the monitor could collude with the agent. (`agent-monitoring`)
- **Coverage / Restraint / Retention / Actionability.** The four evaluation questions for rule-guided review. (`review-rules`)
- **Decentralized pattern / handoff.** A one-way transfer of execution and conversation state from one agent to a peer. (`practical-guide`)
- **Deferred discovery.** Making tools, skills, and plugins surfaceable only when needed instead of loading all of them into context. (`gpt56-efficiency`)
- **Delegation.** The voice model handing reasoning or tool use to a frontier model off the live path. (`gpt-live`)
- **Doc-gardening agent.** Recurring agent that finds stale docs and opens fixes. (`harness-eng`)
- **Durable project memory.** Spec, plan, constraints and status kept in files the agent re-reads to prevent drift and hold a stable definition of done. (`long-horizon`)
- **Durable thread.** A pinned, long-lived thread that is the home for a workstream. (`codex-maxxing`)
- **Evaluation flywheel.** Run, document the workflow, improve agent workflows, run the next one faster. (`repetitive-work`)
- **ExecPlan.** A self-contained, living execution plan a coding agent follows from design to implementation. (`exec-plans`)
- **Full-duplex.** A voice model that listens and speaks at the same time. (`gpt-live`)
- **Golden principles.** Opinionated mechanical rules enforced continuously by cleanup agents. (`harness-eng`)
- **HALO (Hierarchical Agent Loop Optimization).** Method that analyzes traces for recurring harness-level failures and writes a ranked report for a coding agent. (`improvement-loop`)
- **Harness.** The execution system around the model: state, streaming, tools, sandbox and approval policy, carrying work across turns. In the improvement-loop sense, the full contract around the model: instructions, tools, routing, output requirements, validation. (`codex-platform`, `improvement-loop`)
- **Harness engineering.** Designing environments, feedback loops, and control systems so agents do reliable work. (`harness-eng`)
- **Hill to climb.** A reviewed, measured finding packaged as an eval target for the coding agent. (`tax-agents`)
- **In distribution.** Tool schemas and outputs formatted like data the model likely saw in training. (`perplexity-voice`)
- **Item / Turn / Thread.** Atomic typed I/O unit with a lifecycle / one unit of agent work from user input / durable session of turns. (`app-server`)
- **Items.** Polymorphic output units that record each thing the model said or did, in order. (`responses-api`)
- **Know / do / show.** The three ways an app adds value: new context, real actions, better presentation. (`great-chatgpt-app`)
- **Language-first filtering.** Replacing filter controls with natural language mapped onto enumerated tool parameters. (`chatgpt-apps-lessons`)
- **Living SOPs.** Skills as standard operating procedures updated as the org evolves and executed consistently by agents. (`skills-shell`)
- **Loop engineering.** Connecting feedback, testing, and implementation so agents improve from real behavior. (`improvement-loop`)
- **Manager pattern.** A central agent calls specialized agents as tools and keeps control of the user. (`practical-guide`)
- **Metaprompting.** Asking the model to propose edits to its own instructions after a weak turn. (`codex-prompting`)
- **Monitorability.** How readable misbehavior is from the model's reasoning and tool traces. (`agent-monitoring`)
- **Negative control.** A prompt that should not trigger the skill, used to catch false-positive invocation. (`eval-skills`)
- **Optimistic execution.** The agent proceeds while guardrails run concurrently and raise if a constraint is breached. (`practical-guide`)
- **Oracle workflow.** Repo Prompt's pattern of a tool-less reasoning model that only analyzes a curated context package. (`responses-year`)
- **Preambles.** Short user updates sent alongside tool calls while the agent works. (`codex-prompting`)
- **Programmatic tool calling.** The model writes code that calls tools and filters or aggregates their outputs outside its context window. (`gpt56-guide`)
- **Progressive disclosure.** A skill root that routes to supporting material so the model reads only what the moment needs. (`astra-skills`)
- **Queue vs Steer.** A follow-up that waits for the current turn vs one injected into the turn in progress. (`codex-remote`)
- **Report-first workflow.** A skill that inspects and prioritizes, then asks approval before editing. (`skills-oss`)
- **Repository rules.** Concise, directory-scoped review guidance in the agent instructions file that the reviewer can apply and cite. (`review-rules`)
- **Retained reasoning.** Keeping the model's private reasoning in context across tool calls and turns. (`arc-agi-3`)
- **Review packet.** The agent's deliverable for humans, including a video walkthrough of the feature working. (`symphony`)
- **Review rows.** Field-level records of expected vs predicted value and whether the difference looks actionable. (`tax-agents`)
- **Rolling truncation.** Dropping the oldest messages once context exceeds a limit. (`arc-agi-3`)
- **Safe Url.** A mitigation that detects when information learned in the conversation would be sent to a third party and asks or blocks. (`injection-design`)
- **Side chat.** A lightweight conversation attached to the main chat for questions about the work, not the work itself. (`codex-remote`)
- **Source-sink analysis.** An attacker needs a source (a way to influence the system) and a sink (a capability dangerous in the wrong context). (`injection-design`)
- **Steering.** Adding instructions while the agent is already working. (`codex-maxxing`)
- **Stop-and-fix rule.** Repair a failed validation before moving to the next milestone. (`long-horizon`)
- **Symphony.** An orchestrator that turns a project board into a control plane where every open task gets an agent. (`symphony`)
- **Thread automation.** A heartbeat-style recurring wake-up attached to an existing thread. (`codex-maxxing`)
- **Three body problem.** User, UI and model as three parties sharing state in an agent app. (`chatgpt-apps-lessons`)
- **Turn.** The journey from user input to the agent's final message, possibly many inference and tool iterations. (`agent-loop`)
- **Visual thesis / interaction thesis.** One-sentence statements of mood and of 2-3 motion ideas the agent writes before building. (`frontends`)
- **Workflows.** Recurring analyses packaged as reusable instruction sets. (`data-agent`)
