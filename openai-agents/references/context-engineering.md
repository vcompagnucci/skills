# Context engineering

What goes into the model's window, in what order and role, what lives in files outside it, and how to keep it useful over long runs. Draws on OpenAI's engineering posts about the Codex loop, its internal data agent and a benchmark harness experiment, developer-blog guides, guest posts from Dagster, Perplexity and Alpic, the Codex guides, Agents SDK docs and cookbooks on memory, personalization, session trimming, compaction, prompt optimization and Goals, the GPT-5 and 5.1 prompting guides (2025, kept only where still standing), a partner cookbook on temporal knowledge graphs, and the Codex repo itself (what OpenAI ships: system prompts by model, context fragments, compaction and memory prompts).

## Layer the context

- **Assemble initial context in layers, most specific last.** In Codex: harness instructions and the tool list, a message describing the sandbox, developer instructions, user instructions merged from global and per-folder instruction files (repo root down to the working directory), skills, the environment (cwd, shell), then the user message. The AGENTS.md spec in Codex's shipped system prompts adds precedence: deeper files win, direct system, developer and user instructions beat any file, and files already injected "don't need to be re-read". (`agent-loop`, `repo-system-prompts`, `codex-best-practices`)
- **Make every injected item a typed, bounded fragment.** In the Codex repo each thing the harness injects (time reminder, AGENTS.md, turn aborted, memory, token budget) is its own typed fragment under `codex-rs/core/src/context/`, with a role, a kind and wrapper tags. The repo's AGENTS.md makes it a review rule: "No unbounded items", nothing over 10K tokens, and a new item that can exceed 1K tokens is flagged P0 for manual review. A shipped review skill checks the same rules. Caps are set per source (memory at 8,900 bytes, a recap at 8,192 tokens). (`repo-context`, `repo-agents-md`, `repo-review`)
- **Tell the model what it can't observe.** Codex injects the current time, tokens left in the window and in a shared budget, that "The user interrupted the previous turn on purpose" and aborted tools "may have partially executed", that an image was resized, and that the user was on a different model before. (`repo-context`)
- **Keep personality a swappable slot.** The 5.2-codex prompt template has a placeholder filled by a "friendly" or a "pragmatic" file, each with its own values, tone and way of escalating. (`repo-system-prompts`)
- **Ground a domain agent in several kinds of context, not just schemas.** OpenAI's data agent uses six layers: table usage (schema, lineage, past queries), human annotations, definitions derived from the code that produces each table, company docs ingested with permissions, memory, and live queries when the rest is missing or stale. An offline daily pipeline embeds the first layers, and at query time it retrieves only what's relevant, which keeps latency predictable across 70k datasets. (`data-agent`)
- **Meaning often lives in the code that produces the data.** Schemas show shape. Pipeline code shows assumptions, freshness and scope, which is how the agent tells apart two tables that look alike (one counts logged-out users, one doesn't). (`data-agent`)
- **Frame each piece with the right role.** Perplexity found that background sent as user input makes the model act as if the user said every paragraph aloud, and too much as system blurs what it knows, what was supplied and what is being asked. Page content while scrolling should read as background awareness. (`perplexity-voice`)
- **Keep what your code needs apart from what the model sees.** The Agents SDK docs split local context (user id, loggers, data fetchers, never sent to the model) from the conversation history, which is "the **only** data it can see". To get a fact in, pick one of four doors: the instructions for always-useful facts like the date, the input, a tool the model calls when it decides it needs the data, or retrieval. (`sdk-context`)
- **Carrying the conversation forward is a third decision.** Explicit history, a session store or server-side ids is its own choice, separate from local state. OpenAI's migration cookbook adds that continuing a conversation into new turns and resuming a paused run (after an approval) are different mechanisms, and advises one continuation strategy per conversation. (`sdk-context`, `claude-sdk-migration`)
- **Feed context in small pieces so overflow degrades gracefully.** A 10,000-token update into a window with 5,000 tokens left wiped all prior history. Chunks of about 2,000 tokens meant truncation trimmed a little instead. (`perplexity-voice`)
- **Decide who needs to know what.** In an agent app the user, the UI and the model each hold part of the state. Alpic's first instinct to share everything was a mistake: the model doesn't need images and pricing variants, and some state must stay hidden. They split tool output into a model-visible channel and a UI-only one, and tag components with a line like "User is viewing reviews" that feeds the next turn. A guest post drawn from two dozen apps. (`chatgpt-apps-lessons`)

## Instruction files as a map

- **Give the agent a map, not a 1,000-page manual.** One big instruction file crowded out the task, made everything important, rotted and couldn't be checked. What worked was an entry file of about 100 lines pointing into a structured docs directory (design docs with verification status, an architecture map, quality grades, plans with decision logs). Linters and CI check freshness and cross-links, and a recurring agent opens fix-up PRs for stale docs. (`harness-eng`)
- **Keep it short and grow it from repeated mistakes.** "A short, accurate AGENTS.md is more useful than a long file full of vague rules." Add a rule only after a repeated mistake, and when the agent makes the same one twice, ask it for a retrospective and update the file. Codex's shipped /init prompt asks for 200 to 400 words specific to the repo and never overwrites an existing file. (`codex-best-practices`, `repo-agents-md`)
- **Split instruction files by responsibility.** Agent identity and response rules, workspace conventions, reusable workflows, reference material and scripts each get their own place, and reference material stays out of the main prompt (`claude-sdk-migration`). The memory cookbook puts longer task instructions in workspace files (README, AGENTS.md) so the agent's instructions stay about behavior and boundaries. (`memory-compaction`)
- **Prune always-on instructions and make them situational.** "Before every edit, read architecture.md, database.md, deployment.md" burns context on a typo fix. Say which doc serves which situation. (`astra-skills`)
- **Docs written well for humans double as agent instructions.** Dagster rewrote its contributor guide for people and "inadvertently significantly improved" the agent: hierarchy, structure, and rules with their reasons. A guest post. (`dagster-docs`)

## The repo as system of record

- **If the agent can't see it, it doesn't exist.** Decisions in chat, docs or people's heads have to be pushed into the repo. Prefer boring, well-known dependencies the model can reason about. (`harness-eng`)
- **Keep code, docs and examples together.** Dagster favors one repo because you can point the agent at a starting file and let it explore. With the iOS, backend and Android repos in one environment, the Sora team's agent read the iOS models and planned the Android version. (`dagster-docs`, `sora-android`)
- **Give the agent a workspace and a map, not pasted documents.** The memory cookbook stages source files, a machine-readable manifest with stable document ids and an outputs folder in a sandbox instead of pasting documents into the prompt. The agent cites documents by those ids. (`memory-compaction`)
- **Missing context produces guesses, not refusals.** When the Sora team's agent lacked context, it wasn't "refusing to cooperate". It was guessing. (`sora-android`)

## Memory

- **Give each carrier of state one job.** Compaction keeps the current run going, memory helps later runs start better, and a cited, human-reviewed artifact holds the facts people rely on. The cookbook warns against memory as "a shadow compliance record". Its memory prompt says "Store workflow lessons, not case-specific facts": "use the manifest first" is a good memory, "Northwind Logistics violated policy" is not. No live run results are shown. (`memory-compaction`)
- **Keep memory outside the conversation, in files you can open, edit and diff.** A repo holds code and a vault holds rolling context: people, decisions, open loops. In git, the diff shows what the agent chose to remember. Record what changed, not vague impressions. Codex ships this: its memory folder is a git repo, consolidation reads the diff since the last run, and a stray edit "is probably a user change". (`codex-maxxing`, `repo-memory`)
- **Write memory offline in two passes, behind a no-op gate.** Codex's shipped memory prompts extract each session first ("Will a future agent plausibly act better because of what I write here?", "No-op is allowed and preferred"), then a second agent consolidates into a small summary always loaded into the system prompt. Session logs are "immutable evidence" and are read as data, not instructions. (`repo-memory`)
- **Save the user's words, aimed at the user's time.** The v1 prompt: "Optimize for future user time saved, not just future agent time saved." Keep the quoted correction and grep-able strings instead of "the user prefers evidence-backed debugging". Weight user messages over tool output over assistant messages, and leave unadopted brainstorming out. (`repo-memory`)
- **Store the non-obvious corrections, and let the agent ask to save them.** The data agent couldn't filter an experiment until memory held the exact gate string. Memories are global or personal, and users can edit them. (`data-agent`)
- **Say when an answer comes from memory.** Verify drift-prone facts when cheap, otherwise flag the answer as memory-derived and possibly stale. v2: "Memory is not proof of current behavior." (`repo-memory`)
- **Codex's memory, v1 to v2: less machinery, less inference.** v2 drops the handbook, memory skills and step budget, writes only a summary under 10,000 bytes, and says "do not retrieve history speculatively". It warns that broad rules inferred from past tasks mislead ("Ordinary behavior is not a personal preference"): "show me the plan before editing this" becomes "the user asked to show a plan", not "the user prefers". Inside a session, the agent edits memory only when the user explicitly asks, and the offline passes do the rest. (`repo-memory`)
- **Hold memory as state when decisions need a coherent current picture.** OpenAI's personalization cookbook says retrieval over past interactions is "brittle to phrasing, prone to missing overrides, and unable to reconcile conflicts or updates over time". Structured fields plus dated notes support "belief updates instead of fact accumulation". Its test before building any of it: would remembering this materially help the task? If unclear, skip it. Argued for a travel concierge, no measurement. (`context-personalization`)
- **Stage new memories per session, promote only the durable ones, and write the precedence into the prompt.** Notes land in session scope first. An end-of-session pass dedupes, resolves conflicts by most recent date and drops anything scoped to "this time" or "today": "I am vegetarian" was promoted, "This time, I like to have a window seat" was discarded. The prompt ranks the current message over session notes over global memory, which is a default, not a constraint. Because memory lands in the system prompt, it is checked at capture, consolidation "*and* injection time". (`context-personalization`)
- **Decide which runs may write memory, and scope it by layout, not by agent name.** In the Agents SDK's sandbox memory, sub-agents, checkers and one-off tool agents read but don't write because they "do not add much signal". A GTM agent and an engineering agent in one workspace keep separate memories because their layouts differ. The SDK's consolidation keeps only the newest 256 raw memories, a forgetting mechanism so memory reflects "the newest environment". (`sdk-sandbox`)
- **Record when a fact was true, and retire it instead of deleting it.** A partner cookbook gives each stored fact a validity window and a type (static, dynamic, opinion, prediction), and marks a contradicted fact invalid with a pointer to the fact that replaced it. Without that, answers mix old and current values, like an old credit rating read as the current one. It forgets by scoring facts on recency, source trust and query hits, and runs the pruned store in shadow mode against the full one before routing traffic to it. A worked pipeline, no accuracy measured. (`temporal-agents`)
- **Capture decisions before closing a run.** Why an option won, what's preferred now, the dead ends. Otherwise they vanish into the chat. Give each run an index file so later agents can find past runs. (`repetitive-work`)

## Long runs: compaction and retained reasoning

- **Keep the model's reasoning across turns.** Dropping it makes the agent rediscover the task every step. On ARC-AGI-3, keeping reasoning and compacting instead of truncating took the score from 13.3% to 38.3% with about 6x fewer output tokens and no model change. Earlier, carrying reasoning forward scored 5% better on TAUBench, 73.9% to 78.2% on its retail set. (`arc-agi-3`, `responses-api`, `gpt5-prompting`)
- **Compact, don't truncate.** Rolling truncation drops the oldest observations and keeps the window near full. Compaction replaces history with a smaller set of items. In Codex it grew from a manual summary command into automatic compaction that carries an opaque state of the model's understanding. (`arc-agi-3`, `agent-loop`)
- **Write the summary as a handoff to a new model.** Codex's shipped compaction prompt (`compact/prompt.md`) asks for "a handoff summary for another LLM that will resume the task": progress and key decisions, constraints and user preferences, what remains, critical references. The resuming model is told another model wrote it and to avoid duplicating work. (`repo-context`)
- **Guard summaries against their usual errors.** Codex's recap prompt separates "proposed, queued, implemented, tested, published, and installed work", keeps unresolved caveats over commit IDs, says "Missing history is not evidence that work was not done", and is built from the user-visible conversation, never tool output. The session-memory cookbook adds a silent contradiction check against instructions and tool logs, "the most recent update wins", "UNVERIFIED rather than guessing", and a 200-word cap under fixed headings. In its sample run the missing ticket number came back as "Identifiers: UNVERIFIED". (`repo-context`, `session-memory`)
- **Match compaction to how the model was trained.** OpenAI's models are trained to keep private reasoning and summarize when long, which is how its own products run them. Tolerating small overages near the limit lets a request be compacted instead of rejected. (`arc-agi-3`, `computer-env`)
- **Plan for it from the start.** "Use compaction as a default long-run primitive, not an emergency fallback." The Agents API ships it that way, compacting automatically as a session nears its limit so a model works for hours across several windows (a product claim, no numbers). (`skills-shell`, `agents-api`)
- **Compact at workflow boundaries, and say what must survive.** After a major phase and before the next evidence batch, not after every turn. The instructions name what to keep: current batch, cited facts, open questions, artifact paths, unresolved reviewer concerns. Automatic is the simple default, and a fixed threshold or forced checkpoint is more predictable. Compacting inside the turn also costs latency: the Agents SDK's stream can stay open "for a few seconds after the last output token", so for fast turn-taking compact between turns or during idle time. (`memory-compaction`, `sdk-sessions`)
- **Cut history only at whole-turn boundaries.** A turn is one real user message plus everything until the next one (reasoning, replies, tool calls and results), so a trim never orphans a tool result from its call. The session-memory cookbook applies the cut on read as well as write, and picks how many turns to keep from the distribution of turns per conversation. (`session-memory`)
- **Make compaction a transactional rewrite.** Two sources guard the same race. The Agents SDK restores the previous history if a rewrite fails, serializes every write with compaction, and skips a compaction scheduled before another run changed history "instead of replacing newer history". The session-memory cookbook re-checks and recomputes the boundary after its summarizer returns, so turns that arrived meanwhile aren't lost. (`sdk-sessions`, `session-memory`)
- **Prompt for progress updates only on models built for them.** Before GPT-5.3-Codex, Codex's mid-run updates were system-generated, and prompting for plans or status updates made the model stop before finishing. From GPT-5.3-Codex on, these preambles are promptable. (`codex-prompting`)
- **Keep the labels on past messages.** Codex needs each earlier assistant message marked as a progress update or a final answer, or performance "degrades significantly". (`codex-prompting`)

## Prompting habits

- **Guide the goal, not the path.** Highly prescriptive prompts pushed the data agent down wrong paths. Higher-level guidance plus the model's own reasoning was more robust. (`data-agent`)
- **Stronger models need less scaffolding.** Recipes that helped earlier models now hurt. Telling the model to run tests causes extra testing because it already checks its work. Strong "ask first" language written for an overreaching model makes a well-aligned one stop early. Re-audit at each model change, and let the new model audit your instructions. Cursor hit this at GPT-5 (2025-08): a "Be THOROUGH" context-gathering block written for older models made it search repeatedly on small tasks, and softening it fixed that. Codex ships this: prompts for models trained on its harness run about 80 lines against roughly 280 to 330 for general models, with no AGENTS.md spec, planning examples or preamble rules. (`astra-skills`, `repo-system-prompts`, `gpt5-prompting`)
- **Each model generation adds rules for failures seen and drops what it no longer needs.** In Codex's shipped prompts, default to GPT-5.1 added "Autonomy and Persistence" ("do not stop at analysis or partial fixes") and strict plan-status rules. 5.1 to 5.2 deleted the whole user-updates spec and added "Parallelize tool calls whenever possible". On the codex line, 5.1-codex-max added a frontend section against "AI slop", and the 5.2-codex template added "Don't use emojis" and names the model's weakness: "You struggle using the git interactive console." (`repo-system-prompts`)
- **A new model shifts its defaults, so prompt against the shift.** The GPT-6 Astra prompting guide in the Codex repo says the newer model asks where earlier ones assumed, delegates less, tests more broadly than needed and over-formats. The counters: bias toward action, treat "can you..." as an instruction, skip tests for "reversible, low-impact changes", no approval flows "due to hypothetical risk". (`repo-prompting`)
- **Tell the agent what happens to its actions.** Cursor's GPT-5 agent kept stopping to ask. Saying its edits show up as proposals the user can reject ("your code edits can be quite proactive, as the user can always reject"), and that it should implement a plan and then ask for acceptance, cut the interruptions on long tasks. A partner's report, no numbers. (`gpt5-prompting`)
- **Scale ambition to how much the context constrains the task.** Codex's shipped prompts: new work with no prior context, "be ambitious and demonstrate creativity". An existing codebase, "surgical precision", without gold-plating. (`repo-system-prompts`)
- **Remove soft exceptions and contradictions from the prompt.** Each "if it makes things simpler" is a fork the model takes differently per run. OpenAI says contradictions "often reduce performance and increase latency, especially in reasoning models". Over 30 generated scripts, removing them kept exactness at 100% while average peak memory fell from 3,626 KB to 578 KB and time from 7.9 s to 7.0 s. One task on one laptop. The GPT-5 guide gives the mechanism: a precise follower "expends reasoning tokens" reconciling a conflict, like a scheduling prompt that demands recorded consent yet books urgent cases "without contacting" the patient. (`prompt-optimization`, `gpt5-prompting`)
- **Underspecified prompts fall back to common training patterns.** For frontends, state hard constraints first (one H1, two typefaces, one accent) and give real copy, which the post calls the simplest quality lever. (`frontends`)
- **Fix failure modes by metaprompting, and only measured ones.** After a weak turn, ask the model how to change its instructions, sample several times, keep what's common, then check with an eval. The repo's migration guide adds: run representative traces first, "Change prompts only for measured failures", and make a surgical edit instead of rewriting a working prompt stack. The GPT-5.1 guide splits it into two calls: a root-cause pass that quotes the prompt lines behind each failure mode, then a separate surgical patch, with one group of related failures per call. (`codex-prompting`, `repo-prompting`, `gpt51-prompting`)

## Where the answer depends on the case

- **How specific instructions should be: the posts constrain different things.** The frontend guide gets distinctive output from hard numeric rules on the result (`frontends`). The Astra post says step-by-step recipes written for earlier models now hinder a stronger one (`astra-skills`).
- **Whether truncation is acceptable: the posts describe different workloads.** For voice, Perplexity treats trimming a little old history as graceful degradation (`perplexity-voice`). On a long reasoning task, truncation hurt and compaction replaced it (`arc-agi-3`).
- **How to phrase a stored memory: the sources describe different agents.** Codex's coding-agent memory keeps the user's quoted words and records "the user asked", because inferred preferences mislead (`repo-memory`). The personalization cookbook, for a travel concierge, normalizes each note into a durable statement like "Prefers aisle seats." and avoids "User said..." (`context-personalization`).
- **Whether the agent may fix memory mid-run: the shipped defaults differ.** Codex's v2 edits memory inside a session only on explicit request and leaves the rest to offline passes (`repo-memory`). The Agents SDK's sandbox memory lets an agent that finds stale memory fix it in the same run by default (`sdk-sandbox`).
