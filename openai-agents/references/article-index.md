## Architecture and multi-agent systems (`references/architecture-and-multi-agent.md`)

- **[A practical guide to building agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)** (`practical-guide`, 2025-04-17, OpenAI). Build an agent only where judgment, sprawling rules, or unstructured data defeat deterministic code, start with one agent in a loop, and split or add guardrails only as real failures demand.
- **[An open-source spec for Codex orchestration: Symphony](https://openai.com/index/open-source-codex-orchestration-symphony)** (`symphony`, 2026-04-27, Alex Kotliarskyi, Victor Zhu, Zach Brock). Once agents code well, human attention is the bottleneck, so stop supervising sessions and let agents pull work from the task tracker, with an orchestrator guaranteeing every open task has an agent running.
- **[How Codex ran OpenAI DevDay 2025](https://developers.openai.com/blog/codex-at-devday)** (`codex-devday`, 2025-10-10, Dominik Kundel). A coding agent pays off most when you delegate many short, loosely prompted tasks in parallel and review the results, rather than craft one careful prompt at a time.
- **[Codex collaboration modes and orchestrator](https://github.com/openai/codex/tree/b334d5b3f2d9)** (`repo-multi-agent`, snapshot 2026-09-26, openai/codex). Codex separates "planning" from "doing" as a mode that only the harness can switch, and treats sub-agents as a coordination job with explicit rules about isolation, recursion, and waiting. Files: `codex-rs/collaboration-mode-templates/templates`, `codex-rs/core/templates/agents`, `codex-rs/core/templates/collab`.
- **[Introducing AgentKit](https://openai.com/index/introducing-agentkit)** (`agentkit`, 2025-10-06, OpenAI). Mostly a product launch. What transfers: OpenAI retired its visual workflow canvas in favor of code or plain prompting and customers credit end-to-end evals with measurable gains.
- **[Agent orchestration](https://github.com/openai/openai-agents-python/blob/main/docs/multi_agent.md)** (`sdk-multi-agent`, undated, OpenAI (openai-agents-python docs)). Choose between letting the LLM decide the flow and fixing the flow in code, trading open-ended capability for predictable speed, cost and performance, and mix the two freely.
- **[SchemaFlow: Agentic Database Change Impact Analysis, SQL Generation, and Eval Guardrails](https://developers.openai.com/cookbook/examples/partners/schemaflow_design_guide/schemaflow_cookbook)** (`schemaflow`, 2026-06-05, OpenAI cookbook (partner)). Instead of asking one model for the final SQL, split a risky change into typed stages with deterministic gates between them, so bad state is caught before the next stage consumes it and a defect can be traced to the stage where it started.
- **[Introducing ChatGPT agent: bridging research and action](https://openai.com/index/introducing-chatgpt-agent)** (`chatgpt-agent`, 2025-07-17, OpenAI). One agent with several routes to the same information, working on one computer that keeps state across tools, beat keeping a GUI-acting agent and a research agent as separate products.
- **[Agents SDK docs: handoffs.md](https://github.com/openai/openai-agents-python/blob/main/docs/handoffs.md)** (`sdk-handoffs`, 2026-09-20, OpenAI (openai-agents-python docs)). A handoff is a tool call the model picks, and what the receiving agent gets to see is a separate decision you have to make on purpose, because reshaping the transcript does not redact it.
- **[openai-cs-agents-demo (sample repo)](https://github.com/openai/openai-cs-agents-demo)** (`repo-cs-agents`, 2025-12-18, OpenAI (sample repo)). OpenAI's airline demo routes through a triage agent to specialists that receive the known booking state in their instructions, chain their own tool calls, and hand off once per message. What OpenAI ships in a demo, thin evidence.

## Harness design (`references/harness-design.md`)

- **[Why we built the Responses API](https://developers.openai.com/blog/responses-api)** (`responses-api`, 2025-09-22, Steve Coffey, Prashant Mital). An agent interface should be a structured reason-and-act loop that keeps the model's reasoning state across steps and returns every action as an ordered item, not a single chat message.
- **[Unrolling the Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop)** (`agent-loop`, 2026-01-23, Michael Bolin). The agent loop is a growing prompt re-sent each iteration, so a harness should keep it stateless, append-only for cache hits, and compacted before the context window runs out.
- **[Unlocking the Codex harness: how we built the App Server](https://openai.com/index/unlocking-the-codex-harness)** (`app-server`, 2026-02-04, Celia Chen). To reuse one agent harness across many surfaces, expose it through a bidirectional, backward-compatible event protocol built on three primitives (item, turn, thread) with server-held state.
- **[Codex as a platform: build on the open agent harness](https://developers.openai.com/blog/codex-as-a-platform)** (`codex-platform`, 2026-08-19, Nicolas Bonamy, Derrick Choi). The reusable part of an agent is the harness loop, so embed a proven harness inside software built around the actual job instead of moving the job into a generic chat window.
- **[From model to agent: Equipping the Responses API with a computer environment](https://openai.com/index/equip-responses-api-computer-environment)** (`computer-env`, 2026-03-11, Bo Xu, Danny Zhang, Rohit Arunachalam). A model becomes an agent when it gets a computer: a shell in an isolated workspace with files, a database, policy-controlled network, skills, and compaction, so data is staged for the model to query rather than pasted into the prompt.
- **[Speeding up agentic workflows with WebSockets in the Responses API](https://openai.com/index/speeding-up-agentic-workflows-with-websockets)** (`websockets`, 2026-04-22, Brian Yu, Ashwin Nathan). As inference gets faster, the per-request overhead around it dominates agent latency, so the loop should keep state across turns instead of rebuilding it every call.
- **[How we built a realtime system for responsive voice AI in six months](https://openai.com/index/continuous-voice-interaction-with-gpt-live)** (`gpt-live`, 2026-08-03, Justin Uberti, Zahan Malkani). A realtime agent should keep its live path small and never blocked, and push reasoning, tools, compaction, and bookkeeping onto asynchronous side paths.
- **[Run long horizon tasks with Codex](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex)** (`long-horizon`, 2026-02-23, Derrick Choi). Long-horizon agent work succeeds through durable project memory in files, checkpointed milestones with validation, and a disciplined loop, not through one clever prompt.
- **[Using PLANS.md for multi-hour problem solving](https://developers.openai.com/cookbook/articles/codex_exec_plans)** (`exec-plans`, 2025-10-07, aaronfriel). A self-contained, living design document that a stateless agent can restart from lets one prompt drive hours of autonomous implementation.
- **[Codex-maxxing for long-running work](https://openai.com/index/codex-maxxing-long-running-work)** (`codex-maxxing`, 2026-06-22, Jason Liu). Long-running agent work needs a durable home: persistent threads, reviewable memory outside the conversation, recurring check-ins, verifiable goals, and a human deciding the irreversible steps.
- **[How enabling two settings tripled our scores on the ARC-AGI-3 benchmark](https://openai.com/index/how-two-settings-tripled-our-arc-agi-3-scores)** (`arc-agi-3`, 2026-07-29, Ilan Bigio, Ted Sanders). Agents learn over long tasks only if the harness keeps their past reasoning and compacts history instead of truncating it, so benchmarks measure harness choices as much as models.
- **[Codex system prompts, by model](https://github.com/openai/codex/tree/b334d5b3f2d9)** (`repo-system-prompts`, snapshot 2026-09-26, openai/codex). Codex ships a long, example-heavy prompt for general models and a short one for models trained on the harness, and each model generation adds rules for observed failures while cutting scaffolding the model no longer needs. Files: `codex-rs/core`, `codex-rs/core/templates/model_instructions`, `codex-rs/core/templates/personalities`, `codex-rs/models-manager`, `codex-rs/protocol/src/prompts/base_instructions`.
- **[Codex protocol v1](https://github.com/openai/codex/tree/b334d5b3f2d9)** (`repo-protocol`, snapshot 2026-09-26, openai/codex). Separate the agent engine from any UI with a submission queue and an event queue, and structure work as Session, Task, and Turn, where one turn's output is the next turn's input. Files: `codex-rs/docs`.
- **[Codex goals and continuation](https://github.com/openai/codex/tree/b334d5b3f2d9)** (`repo-goals`, snapshot 2026-09-26, openai/codex). A long-running goal survives across turns only if the harness re-injects it each turn, forbids shrinking it, and demands evidence-based audits before the agent may call it complete or blocked. Files: `codex-rs/ext/goal/templates/goals`.
- **[Introducing the Agents API](https://openai.com/index/introducing-the-agents-api)** (`agents-api`, 2026-09-10, OpenAI). Long-running agents need a harness that manages context, tool loading and subagents, and that harness has to be reworked as models change, so OpenAI now ships the Codex harness itself as a maintained service.
- **[The next evolution of the Agents SDK](https://openai.com/index/the-next-evolution-of-the-agents-sdk)** (`agents-sdk-evolution`, 2026-04-15, OpenAI). Separate the agent harness from the compute where model-written code runs, because that split is what gives you security against injection, durable runs and parallel scale.
- **[Using Goals in Codex: Persistent Objectives for Long-Running Work](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)** (`codex-goals`, undated, OpenAI cookbook). Long, uncertain tasks need a persistent completion contract, not a bigger prompt: the objective persists, the agent continues, and evidence alone decides when it is done.
- **[Migrate from the Claude Agent SDK to the OpenAI Agents SDK](https://developers.openai.com/cookbook/examples/agents_sdk/migrate-from-claude-agent-sdk/readme)** (`claude-sdk-migration`, undated, OpenAI cookbook). OpenAI argues the trusted application should own the agent loop, secrets, and approvals, with the sandbox as a tool, whereas the Claude pattern puts the harness inside the sandbox. All claims below are OpenAI's description, not Anthropic's.
- **[Migrate a Legacy Codebase with Sandbox Agents](https://developers.openai.com/cookbook/examples/agents_sdk/sandboxed-code-migration/sandboxed_code_migration_agent)** (`code-migration`, undated, OpenAI cookbook). Split a migration into task-sized shards, run each in a fresh sandbox that gets only its own checkout, and have the host harness validate every returned patch before anyone applies it.
- **[Iterating development workflows with Codex](https://developers.openai.com/cookbook/examples/codex/iterating-development-workflows-with-codex)** (`codex-iterating`, 2026-08-03, OpenAI cookbook). Run agent work as human-gated phases over files that each own one kind of truth, keep planned and observed apart, and close with an evidence-backed retrospective that routes every lesson to exactly one owner.
- **[Build an SRE agent for incident response](https://developers.openai.com/cookbook/examples/agents_api/apps/sev_bot/readme)** (`api-sev-bot`, 2026-09-10, OpenAI cookbook). An incident agent should investigate with read-only tools, turn the one risky step into a proposal that waits on a human, and tie its session to the alert so duplicates, follow-ups and resolution land in one place.
- **[Agents SDK docs: running_agents.md](https://github.com/openai/openai-agents-python/blob/main/docs/running_agents.md)** (`sdk-running`, 2026-09-08, OpenAI (openai-agents-python docs)). The runner is a loop with named ways to end, and the robust version turns the model's slips into model-visible errors, re-checks tool inputs right before they execute, and plans a controlled ending for every way a run can fail.
- **[Agents SDK docs: agents.md](https://github.com/openai/openai-agents-python/blob/main/docs/agents.md)** (`sdk-agents`, 2026-08-19, OpenAI (openai-agents-python docs)). An agent is a model plus instructions, tools and optional runtime behavior; the one design lesson beyond configuration is that forcing a tool call without releasing it loops forever.

- **[New tools for building agents](https://openai.com/index/new-tools-for-building-agents)** (`new-tools-agents`, 2025-03-11, OpenAI). ## Context engineering (`references/context-engineering.md`)

- **[Inside OpenAI's in-house data agent](https://openai.com/index/inside-our-in-house-data-agent)** (`data-agent`, 2026-01-29, Bonnie Xu, Aravind Suresh, Emma Tang). A data agent is only as correct as its grounding, so layer context (schemas, human notes, the producing code, company docs, saved corrections, live queries), keep tools few, guide the goal not the path, and guard quality with continuous evals.

- **[Using Codex for education at Dagster Labs](https://developers.openai.com/blog/codex-for-documentation-dagster)** (`dagster-docs`, 2025-10-27, Colton Padden (Dagster, guest)). - **[Designing delightful frontends with GPT-5.4](https://developers.openai.com/blog/designing-delightful-frontends-with-gpt-5-4)** (`frontends`, 2026-03-20, Brian Fioca, Alistair Gillespie, Kevin Leneway, Robert Tinn). An agent produces distinctive work, not generic defaults, when you constrain it up front, ground it in real content and references, and give it a tool to inspect and verify its own output.
- **[Codex prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)** (`codex-prompting`, 2026-02-25, nm-openai, bfioca-openai). A coding agent performs best when its prompt pushes autonomy and end-to-end persistence and its tools stay as close as possible to the formats and commands the model was trained on.
- **[Automating repetitive work at OpenAI with Codex](https://developers.openai.com/blog/automating-repetitive-work-at-openai-with-codex)** (`repetitive-work`, 2026-08-25, Jeremy Lewi). Instead of scripting each repetitive workflow, run it with an agent inside a shared artifact that records intent, actions, decisions, and outcomes, so each run makes the next one easier.
- **[How Codex assembles and compacts context](https://github.com/openai/codex/tree/b334d5b3f2d9)** (`repo-context`, snapshot 2026-09-26, openai/codex). Files: `codex-rs/context-fragments/src`, `codex-rs/core/src/context`, `codex-rs/prompts/templates/compact`.
- **[Prompting and model-migration references bundled with Codex](https://github.com/openai/codex/tree/b334d5b3f2d9)** (`repo-prompting`, snapshot 2026-09-26, openai/codex). Swapping an agent's model is a behavior migration, not a string replacement: preserve each call site's role and contract, change prompts only for measured failures, and retune the prompt for how the new model's defaults shifted. Files: `codex-rs/skills/src/assets/samples/openai-docs/references`.
- **[The Codex repo AGENTS.md and the /init prompt](https://github.com/openai/codex/tree/b334d5b3f2d9)** (`repo-agents-md`, snapshot 2026-09-26, openai/codex). The team that builds Codex steers its own agent with a long, rule-dense AGENTS.md whose most transferable rules protect the model's context: build it incrementally, cap every injected item, and treat large items as reviewable risk. Files: `AGENTS.md`, `codex-rs/tui/assets`.
- **[Codex memory: read and write prompts](https://github.com/openai/codex/tree/b334d5b3f2d9)** (`repo-memory`, snapshot 2026-09-26, openai/codex). Codex builds memory offline in two phases (extract per session, then consolidate into a small always-loaded summary), and the v2 prompts cut the machinery and pull back from eagerly inferring user preferences. Files: `codex-rs/ext/memories/templates/memories`, `codex-rs/memories/write/templates/extensions/ad_hoc`, `codex-rs/memories/write/templates/memories`.
- **[Context management](https://github.com/openai/openai-agents-python/blob/main/docs/context.md)** (`sdk-context`, undated, OpenAI (openai-agents-python docs)). Keep two kinds of context apart: local state your code uses, which the model never sees, and the conversation history, which is the only thing the model can see.
- **[Building Reliable Agents with Memory and Compaction](https://developers.openai.com/cookbook/examples/agents_sdk/building_reliable_agents_memory_compaction)** (`memory-compaction`, undated, OpenAI cookbook). Give each carrier of state one job: compaction keeps the current run going, memory carries workflow lessons to future runs, and a reviewed artifact holds the facts people rely on.
- **[Context Engineering - Short-Term Memory Management with Sessions](https://developers.openai.com/cookbook/examples/agents_sdk/session_memory)** (`session-memory`, 2025-09-09, OpenAI cookbook). Trimming and summarizing fail in opposite ways, losing context versus poisoning it, so pick by workload, cut history only at whole-turn boundaries, and write summaries as a structured, fact-checked handoff that you evaluate like any other component.
- **[Context Engineering for Personalization - State Management with Long-Term Memory Notes](https://developers.openai.com/cookbook/examples/agents_sdk/context_personalization)** (`context-personalization`, 2026-01-05, OpenAI cookbook). For an agent that must apply what it knows about a user consistently, keep memory as structured state with scopes and precedence rather than as documents to retrieve, and guard it at capture, consolidation and injection because it goes straight into the system prompt.
- **[GPT-5 Prompt Migration and Improvement using the new prompt optimizer](https://developers.openai.com/cookbook/examples/gpt-5/prompt-optimization-cookbook)** (`prompt-optimization`, 2025-08-07, OpenAI cookbook). Soft permissions and contradictions in a prompt create forks the model takes differently from run to run, so remove them and measure the change over many samples.
- **[Agents SDK docs: sessions/index.md](https://github.com/openai/openai-agents-python/blob/main/docs/sessions/index.md)** (`sdk-sessions`, 2026-09-20, OpenAI (openai-agents-python docs)). Treat conversation history as a store of items that the runner reads before each turn and appends to after it, keep what is stored apart from what the model is shown, and make any rewrite of that store, like compaction, safe against failure and concurrent writers.
- **[GPT-5 prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/gpt-5_prompting_guide)** (`gpt5-prompting`, 2025-08-07, OpenAI cookbook). A model that follows instructions precisely rewards clean, explicit prompts and punishes contradictions and leftover scaffolding, so calibrate eagerness, thresholds and product context in the prompt.
