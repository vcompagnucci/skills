## Harness design (`references/harness-design.md`)

- **[Why we built the Responses API](https://developers.openai.com/blog/responses-api)** (`responses-api`, 2025-09-22, Steve Coffey, Prashant Mital). An agent interface should be a structured reason-and-act loop that keeps the model's reasoning state across steps and returns every action as an ordered item, not a single chat message.
- **[Unrolling the Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop)** (`agent-loop`, 2026-01-23, Michael Bolin). The agent loop is a growing prompt re-sent each iteration, so a harness should keep it stateless, append-only for cache hits, and compacted before the context window runs out.
- **[Unlocking the Codex harness: how we built the App Server](https://openai.com/index/unlocking-the-codex-harness)** (`app-server`, 2026-02-04, Celia Chen). To reuse one agent harness across many surfaces, expose it through a bidirectional, backward-compatible event protocol built on three primitives (item, turn, thread) with server-held state.
- **[Codex as a platform: build on the open agent harness](https://developers.openai.com/blog/codex-as-a-platform)** (`codex-platform`, 2026-08-19, Nicolas Bonamy, Derrick Choi). The reusable part of an agent is the harness loop, so embed a proven harness inside software built around the actual job instead of moving the job into a generic chat window.
- **[From model to agent: Equipping the Responses API with a computer environment](https://openai.com/index/equip-responses-api-computer-environment)** (`computer-env`, 2026-03-11, Bo Xu, Danny Zhang, Rohit Arunachalam). A model becomes an agent when it gets a computer: a shell in an isolated workspace with files, a database, policy-controlled network, skills, and compaction, so data is staged for the model to query rather than pasted into the prompt.
- **[Speeding up agentic workflows with WebSockets in the Responses API](https://openai.com/index/speeding-up-agentic-workflows-with-websockets)** (`websockets`, 2026-04-22, Brian Yu, Ashwin Nathan). As inference gets faster, the per-request overhead around it dominates agent latency, so the loop should keep state across turns instead of rebuilding it every call.
- **[How we built a realtime system for responsive voice AI in six months](https://openai.com/index/continuous-voice-interaction-with-gpt-live)** (`gpt-live`, 2026-08-03, Justin Uberti, Zahan Malkani). A realtime agent should keep its live path small and never blocked, and push reasoning, tools, compaction, and bookkeeping onto asynchronous side paths.
- **[Run long horizon tasks with Codex](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex)** (`long-horizon`, 2026-02-23, Derrick Choi). Long-horizon agent work succeeds through durable project memory in files, checkpointed milestones with validation, and a disciplined loop, not through one clever prompt.
- **[Using PLANS.md for multi-hour problem solving](https://developers.openai.com/cookbook/articles/codex_exec_plans)** (`exec-plans`, 2025-10-07, aaronfriel). A self-contained, living design document that a stateless agent can restart from lets one prompt drive hours of autonomous implementation.
- **[Codex-maxxing for long-running work](https://openai.com/index/codex-maxxing-long-running-work)** (`codex-maxxing`, 2026-06-22, Jason Liu). Long-running agent work needs a durable home: persistent threads, reviewable memory outside the conversation, recurring check-ins, verifiable goals, and a human deciding the irreversible steps.
- **[How enabling two settings tripled our scores on the ARC-AGI-3 benchmark](https://openai.com/index/how-two-settings-tripled-our-arc-agi-3-scores)** (`arc-agi-3`, 2026-07-29, Ilan Bigio, Ted Sanders). Agents learn over long tasks only if the harness keeps their past reasoning and compacts history instead of truncating it, so benchmarks measure harness choices as much as models.
- **[Codex system prompts, by model](https://github.com/openai/codex/tree/b334d5b3f2d9)** (`repo-system-prompts`, snapshot 2026-09-26, openai/codex). Codex ships a long, example-heavy prompt for general models and a short one for models trained on the harness, and each model generation adds rules for observed failures while cutting scaffolding the model no longer needs. Files: `codex-rs/core`, `codex-rs/core/templates/model_instructions`, `codex-rs/core/templates/personalities`, `codex-rs/models-manager`, `codex-rs/protocol/src/prompts/base_instructions`.
- **[Codex protocol v1](https://github.com/openai/codex/tree/b334d5b3f2d9)** (`repo-protocol`, snapshot 2026-09-26, openai/codex). Separate the agent engine from any UI with a submission queue and an event queue, and structure work as Session, Task, and Turn, where one turn's output is the next turn's input. Files: `codex-rs/docs`.
- **[Codex goals and continuation](https://github.com/openai/codex/tree/b334d5b3f2d9)** (`repo-goals`, snapshot 2026-09-26, openai/codex). A long-running goal survives across turns only if the harness re-injects it each turn, forbids shrinking it, and demands evidence-based audits before the agent may call it complete or blocked. Files: `codex-rs/ext/goal/templates/goals`.
- **[Introducing the Agents API](https://openai.com/index/introducing-the-agents-api)** (`agents-api`, 2026-09-10, OpenAI). Long-running agents need a harness that manages context, tool loading and subagents, and that harness has to be reworked as models change, so OpenAI now ships the Codex harness itself as a maintained service.
- **[The next evolution of the Agents SDK](https://openai.com/index/the-next-evolution-of-the-agents-sdk)** (`agents-sdk-evolution`, 2026-04-15, OpenAI). Separate the agent harness from the compute where model-written code runs, because that split is what gives you security against injection, durable runs and parallel scale.

- **[Building a safe, effective sandbox to enable Codex on Windows](https://openai.com/index/building-codex-windows-sandbox)** (`windows-sandbox`, 2026-05-13, David Wiesen). A coding agent's sandbox must enforce write and network limits at the OS level while still fitting open-ended developer workflows, and no single primitive does both, so you compose one.

- **[Understanding prompt injections: a frontier security challenge](https://openai.com/index/prompt-injections)** (`prompt-injections`, 2025-11-07, OpenAI). - **[Continuously hardening ChatGPT Atlas against prompt injection attacks](https://openai.com/index/hardening-atlas-against-prompt-injection)** (`atlas-injection`, 2025-12-22, OpenAI). - **[Keeping your data safe when an AI agent clicks a link](https://openai.com/index/ai-agent-link-safety)** (`link-safety`, 2026-01-28, OpenAI). - **[Evaluating chain-of-thought monitorability](https://openai.com/index/evaluating-chain-of-thought-monitorability)** (`cot-monitorability`, 2025-12-18, OpenAI). Watching an agent's reasoning catches far more misbehavior than watching its actions and outputs, so it can be a load-bearing control layer, but only if you measure it and keep it.
- **[Safety in building agents](https://developers.openai.com/api/docs/guides/agent-builder-safety)** (`docs-agent-safety`, undated, OpenAI). Design workflows so untrusted text never directly drives agent behavior, so keep it out of privileged instructions, pass only structured fields between steps, and gate every tool call, knowing this reduces risk but never removes it.
- **[Guardrails and human review](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals)** (`docs-guardrails-review`, undated, OpenAI). Automatic guardrails and human approval are two different controls that together decide whether a run continues, pauses or stops, and the check belongs next to the tool that causes the side effect.
- **[Guardrails](https://github.com/openai/openai-agents-python/blob/main/docs/guardrails.md)** (`sdk-guardrails`, undated, OpenAI (openai-agents-python docs)). Put a fast, cheap check in front of an expensive agent, choose deliberately whether it blocks or runs alongside, and make sure a rejected output never survives into the agent's saved history.
- **[Human-in-the-loop](https://github.com/openai/openai-agents-python/blob/main/docs/human_in_the_loop.md)** (`sdk-human-in-loop`, undated, OpenAI (openai-agents-python docs)). A human approval is a durable pause in the same run, one approval surface for every nested agent, and the paused state is untrusted data that must stay on the server and be resumed only by an authenticated, authorized reviewer.
- **[Tracing](https://github.com/openai/openai-agents-python/blob/main/docs/tracing.md)** (`sdk-tracing`, undated, OpenAI (openai-agents-python docs)). Trace every step of an agent run as nested spans under one workflow trace, and treat trace data as sensitive, so redaction must fail closed.
- **[Building Governed AI Agents: A Practical Guide to Agentic Scaffolding](https://developers.openai.com/cookbook/examples/partners/agentic_governance_guide/agentic_governance_cookbook)** (`governance`, undated, OpenAI and Altimetrik (partner post)). Treat guardrails as versioned, centrally distributed, measured infrastructure, layered with per-agent checks, so teams can ship agents without a review bottleneck.

## Agents in production (`references/agents-in-production.md`)

- **[How we used Codex to build Sora for Android in 28 days](https://openai.com/index/shipping-sora-for-android-with-codex)** (`sora-android`, 2025-12-12, Patrick Hum, RJ Marsan). A coding agent multiplies a small team only when humans lay the foundation and invariants by hand, plan with the agent before it codes, and feed it concrete examples. The bottleneck then moves to human decisions and review.
- **[15 lessons learned building ChatGPT Apps](https://developers.openai.com/blog/15-lessons-building-chatgpt-apps)** (`chatgpt-apps-lessons`, 2026-02-04, Nikolay Rodionov (Alpic, guest)). When an agent sits between a user and a UI, the core design problem is deciding what each of the three parties knows and when, and web habits like lazy loading and filter sidebars work against it.
- **[OpenAI for Developers in 2025](https://developers.openai.com/blog/openai-for-developers-2025)** (`devs-2025`, 2025-12-30, Vaibhav Srivastav, Katia Gil Guzman). Once agents run multi-step jobs instead of single requests, building them becomes as much system design (async, events, budgets, evals) as prompting.
- **[From prompts to products: One year of Responses](https://developers.openai.com/blog/one-year-of-responses)** (`responses-year`, 2026-03-11, Eva Sasson). Five production builders show that useful agent systems come from separating roles (context gathering vs reasoning, monitoring vs acting) and from cutting user steps, not from one monolithic prompt.
- **[How Perplexity Brought Voice Search to Millions Using the Realtime API](https://developers.openai.com/blog/realtime-perplexity-computer)** (`perplexity-voice`, 2026-03-25, Paul Fryzel (Perplexity), Charu Jaiswal). A voice agent at scale works when you feed context in small, correctly-framed pieces, keep a small tool set with outputs shaped like ordinary tool data, and tune for messy real-world conditions.
- **[Mastering remote engineering work from your phone](https://developers.openai.com/blog/mastering-codex-remote-for-engineering)** (`codex-remote`, 2026-06-23, Thomas Ricouard). A remote interface to a running agent should expose the few decisions that unblock it (context, redirection, approval, review), not shrink a terminal onto a small screen.
- **[Codex realtime backend prompt](https://github.com/openai/codex/tree/b334d5b3f2d9)** (`repo-realtime`, snapshot 2026-09-26, openai/codex). A voice agent works as a thin conversational front that delegates all real work to a backend executor, hides the split from the user, and never filters or refuses on the backend's behalf. Files: `codex-rs/prompts/templates/realtime`.
- **[Best practices](https://learn.chatgpt.com/guides/best-practices)** (`codex-best-practices`, undated, OpenAI). Treat a coding agent as a teammate you configure over time: prompt with a done condition, move repeated guidance into an instructions file, package repeated workflows as skills, and automate only what already works by hand.
- **[Building an AI-Native Engineering Team](https://learn.chatgpt.com/guides/build-ai-native-engineering-team)** (`ai-native-team`, undated, OpenAI). As agents sustain longer tasks, split each phase of the work into what you delegate, what you review, and what you own, with the agent as first-pass implementer and humans keeping judgment and final sign-off.
