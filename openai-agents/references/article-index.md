## Architecture and multi-agent systems (`references/architecture-and-multi-agent.md`)

- **[A practical guide to building agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)** (`practical-guide`, 2025-04-17, OpenAI). Build an agent only where judgment, sprawling rules, or unstructured data defeat deterministic code, start with one agent in a loop, and split or add guardrails only as real failures demand.
- **[An open-source spec for Codex orchestration: Symphony](https://openai.com/index/open-source-codex-orchestration-symphony)** (`symphony`, 2026-04-27, Alex Kotliarskyi, Victor Zhu, Zach Brock). Once agents code well, human attention is the bottleneck, so stop supervising sessions and let agents pull work from the task tracker, with an orchestrator guaranteeing every open task has an agent running.
- **[How Codex ran OpenAI DevDay 2025](https://developers.openai.com/blog/codex-at-devday)** (`codex-devday`, 2025-10-10, Dominik Kundel). A coding agent pays off most when you delegate many short, loosely prompted tasks in parallel and review the results, rather than craft one careful prompt at a time.

## Harness design (`references/harness-design.md`)

- **[Why we built the Responses API](https://developers.openai.com/blog/responses-api)** (`responses-api`, 2025-09-22, Steve Coffey, Prashant Mital). An agent interface should be a structured reason-and-act loop that keeps the model's reasoning state across steps and returns every action as an ordered item, not a single chat message.
- **[Unrolling the Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop)** (`agent-loop`, 2026-01-23, Michael Bolin). The agent loop is a growing prompt re-sent each iteration, so a harness should keep it stateless, append-only for cache hits, and compacted before the context window runs out.
- **[Unlocking the Codex harness: how we built the App Server](https://openai.com/index/unlocking-the-codex-harness)** (`app-server`, 2026-02-04, Celia Chen). To reuse one agent harness across many surfaces, expose it through a bidirectional, backward-compatible event protocol built on three primitives (item, turn, thread) with server-held state.
- **[Codex as a platform: build on the open agent harness](https://developers.openai.com/blog/codex-as-a-platform)** (`codex-platform`, 2026-08-19, Nicolas Bonamy, Derrick Choi). The reusable part of an agent is the harness loop, so embed a proven harness inside software built around the actual job instead of moving the job into a generic chat window.
- **[From model to agent: Equipping the Responses API with a computer environment](https://openai.com/index/equip-responses-api-computer-environment)** (`computer-env`, 2026-03-11, Bo Xu, Danny Zhang, Rohit Arunachalam). A model becomes an agent when it gets a computer: a shell in an isolated workspace with files, a database, policy-controlled network, skills, and compaction, so data is staged for the model to query rather than pasted into the prompt.
- **[Speeding up agentic workflows with WebSockets in the Responses API](https://openai.com/index/speeding-up-agentic-workflows-with-websockets)** (`websockets`, 2026-04-22, Brian Yu, Ashwin Nathan). As inference gets faster, the per-request overhead around it dominates agent latency, so the loop should keep state across turns instead of rebuilding it every call.
- **[How we built a realtime system for responsive voice AI in six months](https://openai.com/index/continuous-voice-interaction-with-gpt-live)** (`gpt-live`, 2026-08-03, Justin Uberti, Zahan Malkani). A realtime agent should keep its live path small and never blocked, and push reasoning, tools, compaction, and bookkeeping onto asynchronous side paths.
- **[Run long horizon tasks with Codex](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex)** (`long-horizon`, 2026-02-23, Derrick Choi). Long-horizon agent work succeeds through durable project memory in files, checkpointed milestones with validation, and a disciplined loop, not through one clever prompt.
- **[Using PLANS.md for multi-hour problem solving](https://developers.openai.com/cookbook/articles/codex_exec_plans)** (`exec-plans`, 2025-10-07, aaronfriel). A self-contained, living design document that a stateless agent can restart from lets one prompt drive hours of autonomous implementation.
- **[Codex-maxxing for long-running work](https://openai.com/index/codex-maxxing-long-running-work)** (`codex-maxxing`, 2026-06-22, Jason Liu). Long-running agent work needs a durable home: persistent threads, reviewable memory outside the conversation, recurring check-ins, verifiable goals, and a human deciding the irreversible steps.
- **[How enabling two settings tripled our scores on the ARC-AGI-3 benchmark](https://openai.com/index/how-two-settings-tripled-our-arc-agi-3-scores)** (`arc-agi-3`, 2026-07-29, Ilan Bigio, Ted Sanders). Agents learn over long tasks only if the harness keeps their past reasoning and compacts history instead of truncating it, so benchmarks measure harness choices as much as models.

## Tool design (`references/tool-design.md`)

- **[What makes a great ChatGPT app](https://developers.openai.com/blog/what-makes-a-great-chatgpt-app)** (`great-chatgpt-app`, 2025-11-24, Corey Ching). A capability you expose to an agent should be a small set of clearly named tools that add something the model cannot do alone, not a port of your whole product.
- **[Supercharging Codex with JetBrains MCP at Skyscanner](https://developers.openai.com/blog/skyscanner-codex-jetbrains-mcp)** (`skyscanner-mcp`, 2026-01-11, Jack Waller (Skyscanner, guest)). Give a coding agent the same feedback loops human developers use (IDE inspections, predefined test and lint runs) and it verifies and fixes its own output in fewer cycles.
- **[Making private MCP servers reachable without making them public](https://developers.openai.com/blog/connect-private-mcp-servers-to-openai-products)** (`private-mcp`, 2026-06-26, Denys Kurylenko). Connect a hosted agent to private tools by having the private side dial out over a narrow, inspectable, explicitly configured path, instead of opening the network.
- **[How we built OWL, the new architecture behind our ChatGPT-based browser, Atlas](https://openai.com/index/building-chatgpt-atlas)** (`atlas-owl`, 2025-10-30, Ken Rockot, Ben Goodger). ## Context engineering (`references/context-engineering.md`)

- **[Inside OpenAI's in-house data agent](https://openai.com/index/inside-our-in-house-data-agent)** (`data-agent`, 2026-01-29, Bonnie Xu, Aravind Suresh, Emma Tang). A data agent is only as correct as its grounding, so layer context (schemas, human notes, the producing code, company docs, saved corrections, live queries), keep tools few, guide the goal not the path, and guard quality with continuous evals.
- **[Harness engineering: leveraging Codex in an agent-first world](https://openai.com/index/harness-engineering)** (`harness-eng`, 2026-02-11, Ryan Lopopolo). When agents write all the code, the engineer's job becomes designing the environment, making everything legible to the agent, and enforcing invariants mechanically, because human attention is the only scarce resource.
- **[Using Codex for education at Dagster Labs](https://developers.openai.com/blog/codex-for-documentation-dagster)** (`dagster-docs`, 2025-10-27, Colton Padden (Dagster, guest)). A coding agent is only as good as the written structure around it, and if it can build working code from your docs alone, your docs are complete enough for humans.
- **[Designing delightful frontends with GPT-5.4](https://developers.openai.com/blog/designing-delightful-frontends-with-gpt-5-4)** (`frontends`, 2026-03-20, Brian Fioca, Alistair Gillespie, Kevin Leneway, Robert Tinn). An agent produces distinctive work, not generic defaults, when you constrain it up front, ground it in real content and references, and give it a tool to inspect and verify its own output.
- **[Codex prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)** (`codex-prompting`, 2026-02-25, nm-openai, bfioca-openai). A coding agent performs best when its prompt pushes autonomy and end-to-end persistence and its tools stay as close as possible to the formats and commands the model was trained on.
- **[Automating repetitive work at OpenAI with Codex](https://developers.openai.com/blog/automating-repetitive-work-at-openai-with-codex)** (`repetitive-work`, 2026-08-25, Jeremy Lewi). Instead of scripting each repetitive workflow, run it with an agent inside a shared artifact that records intent, actions, decisions, and outcomes, so each run makes the next one easier.

Instructions accumulated to steer weaker models become noise or brakes on a stronger one, so re-audit skills, repo instructions, and boundaries at each model change.

## Cost and model choice (`references/cost-and-model-choice.md`)

Agent cost now depends more on architecture than on buying the biggest model: reuse past work, parallelize where it fits, move deterministic work into code, and right-size model and effort per step.
- **[Optimizing customer support agents for cost and quality](https://developers.openai.com/cookbook/examples/agent_optimization/optimizing_agents_for_cost_and_quality)** (`cost-quality`, 2026-09-14, emreokcular, lara-openai). ## Evals and verification (`references/evals-and-verification.md`)

- **[Testing Agent Skills Systematically with Evals](https://developers.openai.com/blog/eval-skills)** (`eval-skills`, 2026-01-22, Dominik Kundel, Gabriel Chua). Improve an agent skill by evaluating it like any prompt: run the agent, record the trace and artifacts, and score them with a few deterministic checks plus a structured rubric.
- **[Custom Code Review rules for Codex](https://developers.openai.com/blog/custom-code-review-rules-for-codex)** (`review-rules`, 2026-07-20, Hari Srikanth). A review agent catches what the diff alone hides when given a few scoped, consequential invariants with a stated safe path, written next to the code they govern.
- **[Build an Agent Improvement Loop with Traces, Evals, and Codex](https://developers.openai.com/cookbook/examples/agents_sdk/agent_improvement_loop)** (`improvement-loop`, 2026-05-12, PASFIELD-OAI). Improve an agent by connecting traces, human and model feedback, generated evals, and a trace-level diagnosis into one loop whose output is a ranked harness change set a coding agent implements, rather than tuning prompts in isolation.
- **[Building self-improving tax agents with Codex](https://openai.com/index/building-self-improving-tax-agents-with-codex)** (`tax-agents`, 2026-05-27, Aravind Srinivasan, Samay Shamdasani, Arthur Fernandes Araujo, John de Wasseige). An agent self-improves when the product captures expert corrections as structured evidence and a coding agent turns repeated, reviewed failures into bounded eval-backed tasks.
- **[Building games with Astra](https://developers.openai.com/blog/how-to-build-games-with-astra)** (`astra-games`, 2026-09-04, Thomas Ricouard). For work judged by feel, the human describes the experience and gives feedback from use, while the agent gets its own instruments (state hooks, named scenes, journey tests, counters) to reproduce, measure, and verify changes.

## Safety and containment (`references/safety-and-containment.md`)

- **[Designing AI agents to resist prompt injection](https://openai.com/index/designing-agents-to-resist-prompt-injection)** (`injection-design`, 2026-03-11, Thomas Shadwell, Adrian Spânu). Prompt injection now looks like social engineering, so defend by constraining what a manipulated agent can do, not only by filtering inputs.
- **[How we monitor internal coding agents for misalignment](https://openai.com/index/how-we-monitor-internal-coding-agents-misalignment)** (`agent-monitoring`, 2026-03-19, Marcus Williams et al.). A strong model reading full agent transcripts (reasoning plus actions) after the fact catches misbehavior that only shows up in real, tool-rich sessions, and it is one layer of defense in depth.
- **[Running Codex safely at OpenAI](https://openai.com/index/running-codex-safely)** (`codex-safely`, 2026-05-08, OpenAI). Run a coding agent productively inside a bounded environment where low-risk actions are frictionless, higher-risk actions stop for review, and logs capture intent, not just events.
- **[Building a safe, effective sandbox to enable Codex on Windows](https://openai.com/index/building-codex-windows-sandbox)** (`windows-sandbox`, 2026-05-13, David Wiesen). A coding agent's sandbox must enforce write and network limits at the OS level while still fitting open-ended developer workflows, and no single primitive does both, so you compose one.

## Agents in production (`references/agents-in-production.md`)

- **[How we used Codex to build Sora for Android in 28 days](https://openai.com/index/shipping-sora-for-android-with-codex)** (`sora-android`, 2025-12-12, Patrick Hum, RJ Marsan). A coding agent multiplies a small team only when humans lay the foundation and invariants by hand, plan with the agent before it codes, and feed it concrete examples. The bottleneck then moves to human decisions and review.
- **[15 lessons learned building ChatGPT Apps](https://developers.openai.com/blog/15-lessons-building-chatgpt-apps)** (`chatgpt-apps-lessons`, 2026-02-04, Nikolay Rodionov (Alpic, guest)). When an agent sits between a user and a UI, the core design problem is deciding what each of the three parties knows and when, and web habits like lazy loading and filter sidebars work against it.
- **[OpenAI for Developers in 2025](https://developers.openai.com/blog/openai-for-developers-2025)** (`devs-2025`, 2025-12-30, Vaibhav Srivastav, Katia Gil Guzman). Once agents run multi-step jobs instead of single requests, building them becomes as much system design (async, events, budgets, evals) as prompting.
- **[From prompts to products: One year of Responses](https://developers.openai.com/blog/one-year-of-responses)** (`responses-year`, 2026-03-11, Eva Sasson). Five production builders show that useful agent systems come from separating roles (context gathering vs reasoning, monitoring vs acting) and from cutting user steps, not from one monolithic prompt.
- **[How Perplexity Brought Voice Search to Millions Using the Realtime API](https://developers.openai.com/blog/realtime-perplexity-computer)** (`perplexity-voice`, 2026-03-25, Paul Fryzel (Perplexity), Charu Jaiswal). A voice agent at scale works when you feed context in small, correctly-framed pieces, keep a small tool set with outputs shaped like ordinary tool data, and tune for messy real-world conditions.
- **[Mastering remote engineering work from your phone](https://developers.openai.com/blog/mastering-codex-remote-for-engineering)** (`codex-remote`, 2026-06-23, Thomas Ricouard). A remote interface to a running agent should expose the few decisions that unblock it (context, redirection, approval, review), not shrink a terminal onto a small screen.
