# Iterate

How to improve a prompt once it exists: criteria before the draft, one change at a time, failures read as symptoms, audits, metaprompting and optimizers, versions and rollback. The measurement loop itself (one change per attempt, the frozen test set, search budgets) is agent-evals, improve.md; per-model migration is models.md.

## Before the first draft

- **Write the success criteria as checkable numbers, and a way to test them, before the first draft.** A prompt change made without a test can't be told apart from noise, and "answers support questions well" can't be tested. xAI's example is "resolves at least 85% of a 500-ticket sample without inventing a policy, with a median latency under 20 seconds"; Amazon's Nova guide lists task, role, response style and criteria for length, format, factuality and faithfulness before any wording. (`anthropic-prompt-engineering-overview`, `xai-text-best-practices`, `amazon-nova-prompting-best-practices`)
- **Check first whether a different model meets the latency or cost criterion more cheaply than prompt work.** Some failures are not prompt problems, and a model change may solve them outright (models.md "Migrating to a new model"). (`anthropic-prompt-engineering-overview`)
- **Run the task with no instructions first, then write only what the gaps call for.** It makes the instructions answer observed failures instead of imagined ones: Anthropic's sequence is run without the instructions, build three scenarios, record a baseline, write minimal instructions that pass, iterate. (`anthropic-skill-authoring-best-practices`)
- **Draft from a policy document with a strong model, then review every line.** OpenAI recommends having a strong model turn a help-center document into unambiguous instructions written as directions for an agent (2025-04-17). Its numbered-list output predates newer guidance against mandatory step-by-step procedures on frontier models (the audit list below), so keep the conditions and policy facts and pick the procedure format with procedures.md. (`openai-practical-guide-building-agents`, `anthropic-reducing-cost-claude-platform`)
- **When a meta-prompt generates subagent prompts, keep the skeleton and use a light role.** Anthropic's agent-creator recipe (2025-11-17) produces numbered responsibilities, a step-by-step process, quality standards, output format, edge cases, a minimal tool set and a description starting "Use this agent when..." with 2-4 <example> trigger blocks. Its "elite AI agent architect" opener and "compelling expert identity" step predate Anthropic's prompting post (2025-11-10) saying heavy role prompting is often unnecessary on modern models. (`anthropic-claude-code-plugin-prompts`, `anthropic-prompt-engineering-best-practices-2026-blog`)
- **Pick one persona deliberately and test it; skip automatic per-question persona selection.** Persona gender, type and domain shift accuracy unpredictably, and while the oracle best persona would help, automatic selection performed no better than random (Zheng et al., 2024-10-09). (`zheng-persona-system-prompts`)

## Changing a prompt safely

- **Change one section at a time, down to single words, and re-run the conversations that failed before plus a fixed regression set, in staging before production.** Several simultaneous edits make an improvement or a regression impossible to attribute, and probabilistic regressions show only across many runs; Hume suggests starting with 10-20 gold-standard conversations. One word can change behavior: swapping "inaudible" for "unintelligible" improved gpt-realtime's handling of noisy input (2026-02-25). (`elevenlabs-agents-prompting-guide`, `hume-evi-prompting-guide`, `openai-realtime-prompting-guide`)
- **Test each added component with a benign request, a boundary request and an adversarial request.** Adding several components at once hides which one caused over-refusal or leakage (Microsoft's safety system message templates, 2026-07-31). (`microsoft-safety-system-message-templates`)
- **Add rules against an eval one at a time, because some pairs interfere.** MOSAIC (2026-01-26) found statistically significant conflicting pairs (readability targets against lexical constraints) and reinforcing ones (factuality with evidence). (`capitalone-mosaic-instruction-compliance`)
- **Revise a production prompt in small dated versions and carry unchanged sections forward byte for byte.** Small diffs keep tested behavior intact and regressions attributable. Anthropic's Sonnet 5.5 app prompt went from 2026-09-28 to 2026-10-07 by naming a new model and adding one `<medical_guidance>` section, and the Opus 5 to 5.5 revision left four sections identical. (`anthropic-system-prompt-sonnet-5-5`, `anthropic-system-prompt-opus-5`, `anthropic-system-prompt-opus-5-5`)
- **Measure a thinking-steering line like any prompt change.** If thinking still triggers wrongly at the chosen effort, add one line that moves the threshold ("When in doubt, respond directly." or "This task involves multistep reasoning. Think carefully before responding."), try a more direct variant if it doesn't take, and measure trigger rate, tokens, latency and quality. The discouraging line is unreliable on Haiku 5.5 and Sonnet 5.5 (models.md "Claude"). (`anthropic-thinking-steering`)
- **After two failed corrections of the same issue in a coding-agent session, clear the context and write a better first prompt with what you learned.** Failed attempts clutter the context, and a clean session with a better prompt almost always beats a long corrected one (Claude Code docs, read 2026-10-22); Cognition likewise finds an agent fixes a messed-up state much worse than it starts clean. (`anthropic-claude-code-best-practices-docs`, `cognition-coding-agents-101`)

## Reading failures

- **Before adding a line to fix a failure, classify it: the requirement is missing, it is present but not reliably followed, or it is a tool, implementation or observability defect.** Only the first is fixed by more instructions; the second usually needs a deterministic check or a domain invariant, the third a code fix. OpenAI's analyst prompt already had strong citation and grounding rules yet conflated SOC 2 Type I with Type II, and its eval gate passed 5/5 while those domain errors persisted, so the ranked fix was a fact ledger plus validators (2026-05-12); probing each layer is agent-evals, improve.md. (`openai-agent-improvement-loop`)
- **Read a failure as a symptom of the prompt.** A rule ignored though it is written means the file is too long; the model asking what the file already answers means the phrasing is ambiguous. Microsoft's table adds: over-refusal means a rule is too broad, so add explicit allowed help; inconsistency across runs means conflicts, so prioritize and shorten; invented facts mean no "when unsure" rule, so add one (2026-07-31). (`anthropic-claude-code-best-practices-docs`, `microsoft-safety-system-message-templates`)
- **Check every must-have instruction in evals, because an overloaded prompt drops instructions silently.** As instruction density rises, errors shift from half-following to omission: IFScale measured an omission-to-modification ratio of 34.88 for llama-4-scout at 500 instructions and above 20-30 for llama-4-maverick and claude-3.5-haiku (2025-07-15). (`distyl-ifscale-instruction-density`)
- **Test system-prompt rules deep into the conversation, not only on turn one.** Adherence falls over turns, faster when turns build on each other, and worst when the user's request conflicts with the system message: SysBench measured 500 system messages of 5 turns each on 16 models (2024-10-22), and later multi-turn studies point the same way. (`pku-sysbench-system-message-following`)
- **After writing or layering instruction files, ask the agent to summarize its current instructions and check which files it reports, in what order.** Discovery rules (overrides, byte caps, filenames) drop files silently, and this is the cheapest check that the prompt you wrote is the prompt it got: `codex --ask-for-approval never "Summarize the current instructions."` (`openai-codex-agents-md-guide`)
- **In a large stack of skills and instruction files, make the model cite the file behind every pause, permission request or divergence.** Without attribution you can't tell which loaded file caused a stop. OpenAI's GPT-6 guide asks it to "name and link to the exact SKILL.md file you read, quote the relevant instruction, and briefly explain how it applies", separating explicit requirements from its own interpretation. (`openai-using-gpt-6-prompting`)

## Auditing an existing prompt

- **For a verdict on each line, match it against common-lines.md first.** It covers the lines that recur in real prompts, each with its verdict, rewrite and evidence.
- **Audit for the six anti-patterns that hobble frontier models: verification rituals, thoroughness or emphasis boosters, mandatory procedures and scratchpads, stale few-shot examples, contradictory rules, and dated configuration such as manual thinking budgets.** Frontier models take them literally, with extra tool calls, duplicated reasoning, verbosity or outright API rejection; examples are "verify twice", "Be maximally thorough" and "CRITICAL: YOU MUST ALWAYS" (2026-09-08). (`anthropic-reducing-cost-claude-platform`)
- **Remove those legacy anti-patterns during a migration; it improves cost and accuracy together.** On an Opus 4.8 to Opus 5.5 support benchmark, the model swap cut cost 18% (Anthropic's rounded figure) and `prompt-audit` cut a further 9% while raising accuracy 2 percentage points, also Anthropic's rounded figure (2026-09-08, 44-ticket internal benchmark 2026-09-25). Contradictory refund rules had made Opus 5.5 withhold four owed refunds while asking for confirmation, and a manual scratchpad led it to write the tool call inside its reasoning without running it on three tickets. (`anthropic-reducing-cost-claude-platform`, `anthropic-what-a-task-costs-on-opus-5-5`)
- **Before tuning anything else, fix three defects: contradictory instructions, a missing or vague output format, and few-shot examples that disagree with the instructions.** They are what OpenAI's optimizer targets: on GPT-5 judged adherence rose 4.40 to 4.90 and code quality 4.73 to 4.90 over 30 runs, and on GPT-5-mini robustness rose 0.32 to 0.54 and grounding 0.80 to 0.95 on FailSafeQA (2025-08). (`openai-prompt-optimizer-cookbook`)
- **Audit instruction files for lines written for older models, references to files or commands that no longer exist, and contradictions across files.** Instruction files rot as models and repos change, and old-model compensations hurt newer models; Claude Code ships this as `/doctor prompt-audit` (v2.1.283+), which proposes edits without applying them. (`anthropic-claude-code-memory`)
- **Before shipping, run the prompt past a strong model acting as a critic that quotes the offending lines and returns a surgical edit.** xAI's audit prompt asks it to identify "Ambiguity", "Missing definitions", "Conflicting, incomplete, or vague instructions" and "Unstated assumptions", and says "Do NOT list issues you are unsure about." It is a review aid, never a substitute for evals. (`xai-voice-prompting-guide`)
- **Delete lines that restate what the model already does by default, and keep each requirement in the eval set.** Piling requirements into one prompt lowers adherence to each: CMU found 65.2% of requirements from real developer prompts met when unstated, and each requirement alone met 98.7% of the time against 85.0% (gpt-4o) and 79.7% (Llama-3.3-70B) with 19 together (2025-05-19). (`cmu-prompt-underspecification`)
- **To test or prune one instruction, replay twice a session it seemed to misdirect, from the same snapshot and model, once with it and once without, and compare quality, tool calls, tokens, runtime and cost.** A single-instruction replay turns a hunch that a rule is noisy into evidence, and OpenAI suggests having the agent run the experiment itself: "Replay that same prompt twice from the same repository snapshot and model" (2026-10-14), and reports no result for it. (`openai-maintaining-software-gpt-6`)
- **For prompts on smaller or cheaper models, rewrite the instruction stack once: group rules by category, merge duplicates, and write a precedence note wherever two rules conflict.** The rewrite recovered up to +11 points of follow rate on weaker models and left strong models unchanged, and controls tie the gain to the rewrite rather than extra tokens or reordering (2026-07-31). (`anand-instruction-stacking-collapse`)

## Metaprompting and optimizers

- **Fix only measured failures by metaprompting: after a weak turn, ask the model how to change its instructions, sample several times, keep what's common, and check with an eval.** Make a surgical edit rather than rewriting a working prompt stack, and feed review comments in too: a maintenance team had the agent draft its own first prompt, commented on the draft PRs it opened, then had it read those comments and write the prompt for the whole codebase (2026-10-14). (`openai-codex-prompting-guide`, `openai-repo-system-prompts`, `openai-maintaining-software-gpt-6`)
- **Split the fix into two calls: a root-cause pass over one failure family, then a separate surgical patch.** Guessing which line caused a behavior is unreliable, and mixing families in one call makes the model miss threads. Paste the system prompt and the traces and ask, per failure mode, to "quote or paraphrase the specific lines or sections of the system prompt that are most likely causing or reinforcing it"; then ask for a revision that keeps structure and length, with patch notes. OpenAI's example found "be concise" against "err on the side of completeness" (2025-11-13). (`openai-gpt-5-1-prompting-guide`)
- **Iterate with two instances: one helps write the instructions, a fresh one uses them on real tasks, and you carry the tester's misses back to the author.** The tester exposes gaps the author's context hides, as in "I noticed Claude B forgot to filter test accounts when I asked for a regional report." (`anthropic-skill-authoring-best-practices`)
- **Pick the optimizer by what you have: a single prompt (zero-shot rewrite), a few failing examples with written feedback (few-shot refinement), or a labeled set and a metric (data-driven optimization that can also pick demonstrations).** Google's platform offers exactly these three (2026-10-21), and OpenAI's prompt optimizer and DSPy GEPA map onto the same split. With no labels during a model move, Google's data-driven optimizer takes a `source_model` whose answers serve as ground truth and rewrites the system instruction for the target model. (`google-vertex-prompt-optimizer`, `google-vertex-data-driven-optimizer`)
- **Give an optimizer one narrow grader per output property where the prompt fails, with Good or Bad labels and specific critiques, and review the optimized prompt by hand before shipping.** Optimization is only as good as its graders (building them is agent-evals, evaluators.md), and an optimized prompt can regress on specific inputs: "We recommend building narrowly-defined graders for each of the desired output properties where you see your prompt failing." (`openai-prompt-optimizer-doc`)
- **Prefer reflective instruction optimization (GEPA) to few-shot-demo optimization, with a metric that returns a written reason per failure and separate train, validation and test sets.** GEPA beat MIPROv2 by >10% (+12% on AIME-2025) with prompts up to 9.2x shorter, beat GRPO by +6% on average with up to 35x fewer rollouts, and a Qwen3-8B-optimized prompt gained +9% on GPT-4.1-mini unchanged (2025-07-25). Without a validation set its reflection model reuses training data and overfits; it is still DSPy's featured optimizer (docs fetched 2026-10-22), and search discipline is agent-evals, improve.md. (`stanford-gepa-reflective-prompt-evolution`, `dspy-gepa-optimization-tutorial`)
- **Fix prompts from failing eval cases and confirm on a held-out set.** Rules added from observed failures generalize better than speculative ones, but only a held-out set shows it: Anthropic's hillclimber added routing rules and a refund-cap cross-reference on Sonnet 5 at low effort, moving train from 88.9% to 98.9% and held-out to 90.5% against 78.6% for the original at one fifth the cost, Anthropic's rounded figure (14 tickets, 2026-09-08). (`anthropic-reducing-cost-claude-platform`)
- **Online prompt improvement works when the guideline set is capped and pruned.** SCOPE distills guidelines from execution traces, keeps 10 strategic guidelines per domain pruned for conflicts and duplicates apart from immediate corrections, and raised HLE success from 14.23% to 38.64% without human edits (2026-05-28). (`huawei-scope-prompt-evolution`)

## Versions and rollout

- **Pin production to an explicit prompt version or environment label, never "latest", and check your tool's default.** Braintrust serves the latest version by default, so an untested UI save reaches users with no redeploy, while Langfuse serves the "production" label and returns a 404 rather than falling back. Score each version on a labeled set and roll back by moving the pointer to the previous immutable version, which needs no code deploy; LangSmith keeps the history of what each environment pointed to. (`braintrust-version-prompts`, `anthropic-cookbook-prompt-versioning-rollback`, `langfuse-prompt-version-control`, `langsmith-manage-prompts`)
- **Version the model name and inference settings with the prompt text, and promote each version only through its eval gate.** A prompt tested on one model or setting is a different artifact on another: MLflow stores `model_config` with each immutable version, OpenAI's cookbook keeps `{"version": "v001", "status": "promoted", "promotion_gate": "manual_review"}` beside the prompt, and Managed Agents bumps the version on each change and returns 409 on a stale one, with per-session overrides only for experiments. The whole bundle is agent-harness, SKILL.md rule 8. (`mlflow-prompt-registry`, `openai-agent-improvement-loop`, `anthropic-managed-agents-agent-setup`)
- **Review every prompt change as a diff against the version it replaces, with a written reason.** Diffs show which lines a regression came from; Deepgram suggests a changelog block at the top of the prompt, and Braintrust stores a version comment of up to 5,000 characters next to the diff. (`deepgram-prompting-voice-agents`, `braintrust-version-prompts`, `langfuse-prompt-version-control`)
- **Name who may change standing instructions or move the production pointer, apart from who uses the agent.** A prompt edit changes production as much as a code change: Langfuse and LangSmith let only admins or named owners promote, and Asana restricts permanent memory and behavior edits to admins and editors while everyone else's feedback applies only to the current task (2026-09-29). (`langfuse-prompt-version-control`, `langsmith-manage-prompts`, `anthropic-asana-agents-you-can-coach`)
- **Mark every model-workaround line in a source comment with the defect it covers and the evidence that keeps it, and delete it when the model is fixed.** Unlabeled workarounds stay after the model changes and steer the next one wrong. A Grok template comments that the model treats its creators' remarks as its own preferences and that "A fix to the underlying model is in the works." (2025-11-17), and a Gemini CLI comment says to "run the major benchmarks, such as SWEBench, prior to committing any changes" to the Context Efficiency section. (`xai-grok-prompts`, `github-copilot-vscode-agent-prompts`, `gemini-cli-system-prompt-modern`)
- **Ship a new model's prompt behind an experiment flag, and route by generation with a catch-all so an unknown future model gets the nearest tested prompt.** Copilot added a Sonnet 5 prompt (2026-07-08), removed it when the model did fine on the 4.6 prompt (2026-07-24) and re-added it behind a flag (2026-08-04), while sending "every other current and future model, including Opus 4.7 and 4.8" to the 4.6 Opus prompt. Without a flag each reversal is a release. (`github-copilot-vscode-agent-prompts`)

## Where the answer depends on the case

- **Where the prompt of record lives.** Whichever you choose, gate promotion on the same regression set.
  - OpenAI (docs read 2026-10-22): prompts in application code, with prompt builders next to the feature, typed arguments, fixtures and evals before changes, and rollout behind feature flags; its reusable prompt objects (`v1/prompts`) shut down 2026-11-30 after de-emphasis from 2026-06-03. (`openai-prompt-engineering-guide`, `langsmith-manage-prompts`)
  - Anthropic (Managed Agents docs, read 2026-10-22; cookbook 2026-04-07): the prompt as one field of a server-side versioned agent config, pinned and rolled back by version. Langfuse, LangSmith and Braintrust also deploy by label; sync such a platform to git (LangSmith's commit webhook), since platform edits can skip code review. (`anthropic-managed-agents-agent-setup`, `anthropic-cookbook-prompt-versioning-rollback`, `langsmith-manage-prompts`)
