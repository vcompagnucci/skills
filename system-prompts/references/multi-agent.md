# Multi-agent prompts

What to write when one agent works through others: the brief a subagent gets, what it is told about reporting back, routing descriptions and handoff rules, the orchestrator's delegation rules, and reviewer and advisor prompts. Whether to split at all, fork versus fresh, caps on depth and spend, and who keeps the conversation are agent-harness, multi-agent.md.

## Write the brief

- **Put everything the subagent needs into the brief: file paths, error messages, decisions made, the user's objective.** A fresh subagent starts without the parent's conversation, skills or files read, so the brief is the only content that passes (a fork inherits the history; agent-harness, multi-agent.md). Gemini CLI's delegation input says: "You must include original user's objective as well as questions and any extra context and questions you may have." (`anthropic-agent-sdk-subagents`, `gemini-cli-subagent-prompts`)
- **Give each subagent an objective, an output format, the tools and sources it may use, clear task boundaries, an effort budget and where to stop.** The boundaries say what the other subagents cover and what is out of scope for this one, because without detailed task descriptions Anthropic's "agents duplicate work, leave gaps, or fail to find necessary information": its research lead first wrote briefs like "research the semiconductor shortage", and one subagent explored the 2021 automotive chip crisis while 2 others duplicated each other on current supply chains. OpenAI's Agents API example names the question, the evidence and the merge, "Ask each to extract customer-visible changes and required migration steps using only its release notes.", and ends "Do not invent missing details." (`anthropic-research-system`, `openai-agents-api-multi-agent`)
- **Size the effort budget to the query's complexity, because agents judge effort poorly on their own.** Anthropic's Research system embeds scaling rules in its prompts: simple fact-finding requires 1 agent with 3-10 tool calls, direct comparisons might need 2-4 subagents with 10-15 calls each, and complex research might use more than 10 subagents "with clearly divided responsibilities" (Claude Opus 4 lead, Sonnet 4 subagents, 2025-06-13). Overinvestment in simple queries was a common failure before the rules; the orchestrator's side is "Anchor the number of subagents" below. (`anthropic-research-system`)
- **Make the design decisions in the brief, and pass the context behind the task.** Actions carry implicit decisions: given a bare subtask, Cognition's subagent built a Super Mario background for a Flappy Bird clone, and two subagents with the same task chose clashing styles. Devin's docs say the agent "can get stuck without a clear path or when faced with too many interpretations", so name the reference to follow ("Use authTemplate.rs as a reference to maintain consistency in error handling."); decide what you know, delegate what you don't. (`cognition-dont-build-multi-agents`, `devin-instructing-devin-effectively`)
- **Tell the orchestrator that each subagent sees only its brief, so every brief carries the full detail and the constraints shared by all subagents.** Models write terse briefs to other models, and without the line each subagent re-tests tools or reviews without knowing what the change was for. Anthropic's code-review command: "Do not test tools or make exploratory calls. Make sure this is clear to every subagent that is launched." smolagents uses a deliberate fiction, "Since this team member is a real human, be as detailed and verbose as necessary in your task description." (templates last changed 2025-08-26), and Deep Agents, Kimi and Gemini CLI get the same result by saying the subagent has no other context. (`anthropic-claude-code-plugin-prompts`, `smolagents-prompt-templates`)
- **When an agent stays off track after several corrections, start a fresh session with every instruction in the first message.** Cognition finds an agent fixes a messed-up state much worse than it starts clean, which matches Laban et al.'s measured drop when requirements arrive across turns ("LLMs get lost in multi-turn"). (`cognition-coding-agents-101`, `laban-llms-lost-multi-turn`)

## Tell the subagent how it reports

- **Tell every subagent that its caller sees only its final message, and say what that message must contain and in what format.** Intermediate tool calls and findings stay inside the subagent, and without the line it leaves findings in earlier turns and ends with "Done". Deep Agents: "The calling agent only sees your final assistant message, not your intermediate work". Kimi: "The main agent cannot see your context, it can only see your last message". (`anthropic-agent-sdk-subagents`, `langchain-deepagents-prompts`, `kimi-cli-system-prompts`)
- **Put the delegation rules in the delegation tool's description, where the parent reads them as it decides.** Deep Agents' task tool says: "Each invocation is stateless by default: the agent sees only the prompt you give it and returns a single final report." It tells the parent to state exactly what to return, to relay a summary because the user never sees the report, and to say whether the subagent should create, analyze or only research; a one-line note on forked subagents was load-bearing, because without it the model refused to delegate to them (2026-10-14). (`langchain-deepagents-prompts`)
- **Ask for a report shape that survives failure and parses.** smolagents requires three parts, a short outcome, a detailed outcome and extra context, even when the task failed. Gemini CLI shows each subagent its output schema as a complete JSON example. (`smolagents-prompt-templates`, `gemini-cli-subagent-prompts`)
- **Have exploration subagents return a short list of key files, and tell the parent to read those files itself before designing.** A summary loses detail the parent needs. Anthropic's feature-dev asks each explorer for 5-10 key files, then tells the parent: "Once the agents return, please read all files identified by agents to build deep understanding" (2025-10-09). (`anthropic-claude-code-plugin-prompts`)
- **Send a bounded search subagent an explicit last-turn message that ends exploration and demands the answer in its format.** Without it the subagent spends its last iteration on one more search and returns nothing usable. Copilot's search subagent gets "OK, your allotted iterations are finished -- you must produce a list of code references as the final answer", which its code says matches how the model was trained to be coaxed to a final answer. (`github-copilot-vscode-agent-prompts`)

## A subagent can't ask the user

- **Tell the subagent who its caller is, that it can't ask the end user anything, and where ambiguity goes.** A question ends the turn waiting for a reply that never comes, and it reaches the parent model, not the human. Kimi: "You must treat the parent agent as your caller. Do not directly ask the end user questions." Qwen Code's headless mode: "Never ask the user a question, even if the user explicitly requests one", and the blocker becomes the final result. (`kimi-cli-system-prompts`, `qwen-code-system-prompts`)
- **Give the subagent a stop condition it can check.** Subagents written like chat agents stall waiting for clarification or stop at the first relevant file. Gemini CLI's investigator updates a "Questions to Resolve" list after every observation: "Your mission is complete **ONLY** when your `Questions to Resolve` list is empty". Its CLI-help subagent answers ambiguous questions as best it can, because it cannot ask. (`gemini-cli-subagent-prompts`)
- **Tell each subagent whether it may spawn agents of its own, and bound any loop it runs.** Without a rule, recursion has no floor. Anthropic's clean-context verification loop gives up after 3 attempts by default, set as `max_attempts: int = 3`; the caps themselves live in code (agent-harness, multi-agent.md). (`anthropic-multi-agent-when-and-how`)

## Define each specialist

- **Write a one-line routing description apart from the specialist's own instructions.** The router reads the description; the specialist reads its instructions. OpenAI's support demo: handoff_description="Updates seats and handles medical or special service seating." Salesforce Agentforce pairs a classification description with a scope read after routing: "Handle resending reservation confirmations, but do not create new reservations." (`openai-agents-define-agents`, `openai-cs-agents-demo-prompts`, `salesforce-agentforce-natural-language-instructions`)
- **Keep subagent descriptions short enough to sit in every session and specific enough to single out one agent.** Detail goes in the subagent's system prompt, which loads only when it runs, and Claude Code warns above 15,000 tokens of combined descriptions; its sample reads "Expert code reviewer. Use proactively after code changes." Gemini CLI writes each description to the parent as a routing rule ("Invoke this tool for..."). (`anthropic-claude-code-subagents`, `gemini-cli-subagent-prompts`)
- **Give a custom subagent one job, a tool surface that matches it, and lines that stop it drifting into adjacent work.** OpenAI's Codex docs call narrow, opinionated agents the best ones, and their PR reviewer is four lines: "Review code like an owner. Do not edit files. Prioritize correctness, security, behavior regressions, and missing test coverage." (`openai-codex-subagents-doc`)
- **Write a custom subagent's system prompt complete on its own.** In Claude Code it replaces the base system prompt and receives only environment details, so verification, scoping and safety disappear unless you restate them. (`anthropic-claude-code-subagents`)
- **Define each subagent as a typed contract, not prose alone, and study Gemini CLI's Codebase Investigator as a complete example.** Gemini CLI's subagents carry a routing description, an input schema whose field asks for the user's full objective because the subagent can't ask follow-up questions, an output schema, a read-only tool allowlist, and caps in config (codebase_investigator: maxTimeMinutes 10, maxTurns 50, temperature 0.1; generalist: maxTurns 20). The investigator's prompt holds a sole purpose, DO and DO NOT lists (DO NOT: "Write the final implementation code yourself."), the scratchpad, the termination rule, and a JSON report schema with a worked example; the delegation message wraps the objective in `<objective>` tags. (`gemini-cli-subagent-prompts`, `gemini-cli-prompt-override-and-ci`)

## Handoffs and the user-facing agent

- **Decide who owns the final answer before you write a specialist's prompt.** A handoff specialist takes over the conversation, so its prompt must handle the user; a specialist called as a tool returns a bounded result for the manager to synthesize. Mixing the two leaves nobody, or two agents, talking to the user; choosing the pattern is agent-harness, multi-agent.md. (`openai-agents-orchestration-handoffs`)
- **Open every agent in a handoff system with a short block: it is one of several agents, transfers are tool calls named `transfer_to_<agent_name>`, and the user never hears about them.** The Agents SDK ships it as the recommended prefix (file dated 2025-03-11): "Transfers between agents are handled seamlessly in the background... do not mention or draw attention to these transfers in your conversation with the user." (`openai-agents-sdk-handoff-prompt-prefix`)
- **Allow one handoff per message.** Several transfers in one turn race over who owns the reply. OpenAI's reference support system writes it into every specialist prompt: "Never emit more than one handoff per message: do your prep (at most one tool call) and then hand off once." (`openai-cs-agents-demo-prompts`)
- **When a voice model fronts a backend agent, give the voice prompt its role, speaking style and a delegation policy (what the backend can do, when to delegate, when not to), and keep procedures and tools in the backend's instructions.** A spoken "I'm checking that" starts no backend work, so the voice layer guesses while it waits; tell it never to state a price, confirm a booking or report completion before the backend result arrives (OpenAI, gpt-live-1). Its trained delegation token is models.md. (`openai-prompting-gpt-live`)
- **When a different model takes over a conversation, tell it so, and tell it not to call tools from the history that aren't in its own set.** The history is out of distribution for the new model, and Cursor saw it try the previous model's tools; Cursor still recommends one model per conversation, or a fresh subagent (2026-04-30). (`cursor-continually-improving-agent-harness`)

## The orchestrator's prompt

- **Say when to delegate: large, independent work, fanned out in one turn.** Spawning defaults differ by model and follow the prompt: GPT-6 Astra delegates less than many harnesses want (OpenAI), and Opus 4.8 spawns fewer subagents (Anthropic). Anthropic's line: "Spawn multiple subagents in the same turn when fanning out across items or reading multiple files." (`openai-using-gpt-6-prompting`, `anthropic-prompting-opus-4-8`)
- **Say when not to delegate, and back it with hard caps in the harness.** Opus 5 and Fable 5 delegate readily and multiply cost on small tasks, so Anthropic writes "Do not delegate work you can finish yourself in a handful of tool calls" and forbids subagents for checking your own work. Copilot's GPT-6 prompt: "Do not spawn sub-agents unless the user, their instructions, or applicable skills explicitly ask for sub-agents, delegation, or parallel agent work." (`anthropic-prompting-opus-5`, `github-copilot-vscode-agent-prompts`)
- **Anchor the number of subagents to the task, with effort-scaling rules.** Early agents in Anthropic's research system spawned 50 subagents for simple questions. Anthropic's orchestration example scales the count to the request: a focused review of a module of a few hundred lines rarely needs more than ten subtasks. (`anthropic-orchestration-mode-example`, `anthropic-research-system`)
- **Once it delegates, tell the lead agent to only coordinate and to wait for every subagent before ending its turn.** Without the coordinate-only rule the lead duplicates the work, and without the wait it ends the turn with workers still running. Codex's orchestrator: when sub-agents work, "your only role becomes to coordinate them", and "Do not perform the actual work while they are working." (`codex-orchestrator-and-init`)
- **In a team of peers, say the others are equally capable with the same tools, and that messages between agents may be read by a human.** Agents that assume weaker peers over-specify or redo work, and unprompted inter-agent messages carry grammar and spacing errors. Codex's GPT-6 role message: "`send_message` calls may be read by a human, so ensure they are legible. Always put proper spaces between words and/or numbers." (`codex-model-messages-gpt-6`, `openai-using-gpt-6-prompting`)
- **In a planner and worker system, have planners make the design decisions, with no two subtasks deciding the same question, then write worker briefs a cheaper model can follow.** Cursor's swarm built split-brain designs, two planners implementing one concept differently, until planner prompting fixed it. On a SQLite build, workers cost $9,373 with GPT-5.5 everywhere against $411 with Composer 2.5 under an Opus 4.8 planner (totals $10,565 vs $1,339), and the new harness reached 73-85% at 4h against 11-77% (Cursor, 2026-07-20). (`cursor-agent-swarm-model-economics`)
- **Show the lead agent elapsed time against a budget in each message, and keep a hard timeout in code.** Without time signals it paces as if time were free, and a budget mostly makes it parallelize more, where lower effort cuts the work. Anthropic appends "elapsed 340s / 1200s"; with no sensible budget, one sentence: "Time matters here: do not spend time that can be avoided, and the earlier a correct result is obtained, the better." Small agent teams finished considerably sooner at comparable quality (Anthropic research-task evals, Opus 5.5, docs read 2026-10-22). (`anthropic-prompting-opus-5-5`)

## Reviewers, validators and advisors

- **Brief a reviewer with the diff and none of the coder's conversation, and tell the coder to filter its findings against the user's instructions and scope.** Cognition found review works best with no shared context, but without the filter the pair loops, disobeys the user or goes out of scope; Devin Review catches an average of 2 bugs per PR on Devin-written PRs, 58% of them severe by Cognition's rough estimate (2026-04-22). (`cognition-multi-agents-working`)
- **Add a validation pass: a fresh subagent per finding, drop what it can't confirm, and set a high bar with a do-not-flag list.** The list names pre-existing issues, linter-catchable issues and anything uncertain. Anthropic's code-review command: "If you are not certain an issue is real, do not flag it. False positives erode trust and waste reviewer time." (`anthropic-claude-code-plugin-prompts`)
- **Name the model tier for each step of an orchestrated command.** Anthropic's code-review command (2026-03-12) uses Haiku for the eligibility check and CLAUDE.md listing, Sonnet to summarize, 4 parallel review agents (2 Sonnet for CLAUDE.md compliance, 2 Opus for bugs), then Opus to validate bug findings and Sonnet to validate rule findings: "Use Opus subagents for bugs and logic issues, and sonnet agents for CLAUDE.md violations". (`anthropic-claude-code-plugin-prompts`)
- **For alternative designs, give parallel architect subagents deliberately different briefs.** Identical briefs produce near-identical designs, so Anthropic's feature-dev gives 3: minimal change, clean architecture, and pragmatic balance (2025-10-09). (`anthropic-claude-code-plugin-prompts`)
- **When a cheaper agent consults a stronger model, pass a fork of its full context, and tell the stronger model to name a file to read and volunteer guidance beyond the question.** A subset of context produced uninformed advice, and the stronger model's default is to "make up some theories". Cognition's primary asks broad questions ("what should I do?"), and the stronger model says which file to read and to ask again. A reviewer wants clean context; an advisor wants all of it. (`cognition-multi-agents-working`)
