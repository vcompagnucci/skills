# Voice agents

What changes when the agent's words are spoken: the prompt controls the words, never the sound, so every speaking rule is a rule about which words come out. Moving a chat agent to the phone also needs language.md "Language on a voice channel" (output language and when to switch, accent, a voice per language, one spelling per name); escalation and fallback lines are procedures.md, sample phrases and example transcripts are examples.md, and the voice prompt's sections are anatomy.md and structure.md.

## Tell the model it is speaking

- **Open an output-rules section that tells the model it is talking by voice: plain text, one to three sentences, one question at a time, numbers, phone numbers and emails spelled out, no https URLs.** The LLM in a speech-to-text, LLM, text-to-speech pipeline doesn't know it is there and writes markdown, lists and long replies that TTS reads badly. LiveKit's opening: "You are interacting with the user via voice, and must apply the following rules to ensure your output sounds natural in a text-to-speech system" (`livekit-agents-prompting-guide`)
- **Write speaking style as rules about the words produced.** Instructions about pronunciation or pace don't map to audio, and word-level rules do (xAI, speech-to-speech). xAI's line: "Spoken word only: no markdown, no bullet lists, no emojis, no stage directions.", with 1-2 short sentences per turn. (`xai-voice-prompting-guide`)
- **Set reply length as a sentence count with a shape, and write turn-taking as explicit caps.** Text-trained models answer in paragraphs that a caller forgets, and several questions at once confuse callers. AWS's baseline answers in the first 1-2 sentences and stays within 3-5 short sentences with no lists; Vapi's: "Keep your responses to a maximum of two sentences. Never list more than three options at a time.", one question per turn, and a stated way to end a turn, such as a clarifying question. (`aws-nova-sonic-2-voice-prompts`, `vapi-voice-prompting-guide`)
- **When a screen sits next to the voice, have the voice give the takeaway and leave the detail to the screen.** OpenAI's realtime front never reads out tables, diffs or code the user can already see, keeps pacing and verbosity requests for the whole task, and never claims running work can't be redirected. The backend is told its input is an unpunctuated transcript and to answer briefly, because verbose output adds latency. (`openai-repo-system-prompts`)
- **If the agent must open the call, tell it to greet the user, with what you know about them.** Gemini's Live API waits for user input before responding, so without the line the agent sits silent. (`google-gemini-live-api-best-practices`)

## Numbers, identifiers and names

- **Give the spoken form of each kind of value the agent says, as written-to-spoken pairs, and state the date order for your users' locale.** Digits and symbols like @ or £ make fast TTS mispronounce or hallucinate, and one shown form beats a described rule: Retell replaces a rule about months, ordinals and years with "April ninth, twenty twenty-seven". ElevenLabs' starter prompt is a list of pairs, such as "$42.50" to "forty-two dollars and fifty cents", and "01/02/2023" is January second in the US and the first of February elsewhere. (`vapi-voice-prompting-guide`, `retell-general-prompting-principles`, `elevenlabs-tts-best-practices-normalization`)
- **For each identifier the agent reads aloud, write one rule and one worked example, and only for the types the task needs.** Phone numbers digit by digit with a pause between groups, emails letter by letter, websites with real words read normally and initials spelled, times with AM/PM; check the platform's presets first so the prompt stays short. Retell's email rule: "Say "at" for @ and "dot" for periods." (`retell-pronunciation-examples`)
- **Round the numbers and times a caller doesn't need exactly, and say dates as words, but read exact values (IDs, phone numbers, confirmation codes) in full.** Callers can't hold a figure like 9,847 or a time like 2:34:17 PM; precision that helps on a screen hurts on a call (AssemblyAI). (`assemblyai-voice-agent-prompting-guide`)
- **On a small low-latency TTS voice, have the LLM write numbers, money, dates, times, phone numbers, URLs and abbreviations as spoken words, or normalize them in code before TTS.** Smaller TTS models don't generalize how numbers are read, and voice agents usually run the fast one: "$1,000,000" came out as "one million dollars" on Eleven Multilingual v2 and "one thousand thousand dollars" on Eleven Flash v2.5 (ElevenLabs docs, live page read 2026-10-22). (`elevenlabs-tts-best-practices-normalization`)
- **Find out what the voice platform already appends to your prompt before writing speech rules, and write your own only if you turn that layer off.** Hume's prompt expansion adds normalization, brevity, silence handling and expression guidance, and ElevenLabs' default normalization adds number-to-words lines. Duplicates cost latency, and switching the layer off without replacing it gets "$500" read character by character and leaves [user silent] and [continue] messages unhandled. (`hume-evi-prompting-guide`, `elevenlabs-tts-best-practices-normalization`)
- **If the prompt makes the model write values as words, state the machine format with an example in every tool parameter that takes an email, phone number or ID.** The conversation then holds spoken forms ("john at gmail dot com") that the model copies into tool calls. ElevenLabs' example: "formatted as written characters (e.g., 'ORD123456')"; its post-LLM normalizer is the more reliable alternative, keeping transcripts written, at a small latency cost. (`elevenlabs-agents-prompting-guide`)
- **Collect one field per turn, spell names and emails back, and confirm all fields together at the end, correcting only the one that changed.** Speech-to-text is unreliable on proper nouns and multi-field questions confuse callers, but read-backs on soft data like interest or timeline make the call feel like a form (Vapi). (`vapi-voice-prompting-guide`)
- **Read identifiers back character by character before acting on them.** OpenAI's realtime demo runs authentication as a state machine (name, phone, date of birth, last four digits) that reads each value back digit by digit, again after any correction, before calling the verification tool. It is demo code, with no measurement. (`openai-repo-realtime-agents`)
- **Give the agent a pronunciation guide and a glossary as two separate lists.** "Pronounce all names properly" gives no information, since the model can't know how a name sounds or what users' jargon means. Deepgram's examples: "Pronounce "Dr. Nguyen" as "Doctor Win."" for the TTS and ""PCP" means primary care provider." for understanding. (`deepgram-prompting-voice-agents`)
- **Refer to tools in the prompt by what they do ("transfer to a specialist"), never by resource ID or slug.** Long slugs in prompt prose leak into speech. If the model won't call a tool, fix the tool's description instead of adding prompt text, because blank auto-generated descriptions on transfer and hang-up tools bias the model against them (Vapi; writing descriptions is agent-harness, tools.md). (`vapi-voice-prompting-guide`)

## Preambles, interruptions and how it sounds

- **Allow one short spoken preamble only before slow tools, multi-step reasoning, record or policy checks and escalations, naming the action.** Used well it masks latency, and as filler it adds perceived latency; skip it for direct answers, confirmations, unclear audio and silence, and never "Let me think..." (OpenAI, gpt-realtime-2, which writes them by default, so test the default first). OpenAI's example: "I'll check that order now." If your platform fills tool latency itself, ban the narration as Deepgram does: "call it WITHOUT narrating what you're about to do". (`openai-prompting-realtime-models`, `deepgram-prompting-voice-agents`)
- **For a passage the agent must say verbatim, quote it in full with "word-for-word", name the interruption marker it will receive, and say what to do on interruption; gate tools until the passage is done.** Without a barge-in rule the agent abandons the required text or restarts it every time. Webex's template, on "If the system detects a user interruption, signaled by [USER BARGE-IN DETECTED]", says "Stop immediately.", explains the disclosure is required, and offers to resume from the interrupted word or restart. (`webex-ai-agent-guidelines`)
- **Define a voice personality as observable speech patterns (word choice, how sentences start, how it repairs a misunderstanding) and add a rule to rotate openers.** Asking for friendliness changes nothing, and without a variation rule every turn opens with "Sure" or "Got it". LiveKit's rule: "Don't open consecutive turns with the same word or acknowledgment." (`livekit-agents-prompting-guide`)
- **If the agent should sound human, give disfluencies and emotional expression a vocabulary and a frequency matched to the persona, with a calm baseline.** Without frequency rules the output sounds robotic or manic, and a clinical agent needs lighter fillers than a sales rep. Vapi's baseline is 2-4 disfluencies per turn and a turn budget of 5-7 turns for booking and 8-12 for qualification; emotion tags render only in cascaded pipelines, and realtime speech models ignore them. (`vapi-voice-prompting-guide`, `livekit-agents-prompting-guide`)

## Escalation and fallbacks on a call

- **When you turn a chat agent into a voice agent, carry over its escalation triggers and fallback lines from procedures.md, "Escalation, fallbacks and retries".** That section holds the countable trigger the realtime voice guides use (failed tool attempts or consecutive no-match and no-input events), the transfer sentence to say while calling the tool, and Deepgram's fallback line for out-of-scope topics. Copy the counts and lines from there; this file doesn't repeat them.

## Prompt size and platform limits

- **Keep a voice prompt small and stable, and move per-user data, reference text, full tool schemas and error catalogs to dynamic variables, retrieval or code.** The whole prompt is resent every turn, so each token adds time to first audio that the caller hears as dead air. Hume recommends 2,000-5,000 tokens with a supplemental LLM, as an approximate range, and ElevenLabs says prompts over 2000 tokens increase latency and cost. (`hume-evi-prompting-guide`, `elevenlabs-agents-prompting-guide`)
- **On a speech model that reads only the start of the prompt, put every instruction about how the agent sounds near the top.** Hume EVI 3 has an 8,000-character prompt limit and truncates to 7,000 at runtime for speech generation, so tone and pacing lines placed later are silently dropped while the text LLM still sees them. (`hume-evi-prompting-guide`)
