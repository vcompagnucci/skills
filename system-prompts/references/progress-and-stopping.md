# Progress and stopping

What an agent says while it works, how it keeps track of a long task, when it may end its turn, how it handles context and step budgets, and what it checks before it calls the work done. What it may do without asking is in tools-and-autonomy.md, and a procedure's own done condition is in procedures.md.

## Progress updates

- **Define "preamble" before you use it, and prompt progress updates for the model family you run.** The word means opposite things: in OpenAI-family prompts (Codex, OpenCode's GPT prompt, Copilot's GPT-6 channel) and Zed it is a required progress note, "a brief one- to two-sentence preamble explaining what you're about to do", while Claude Code-lineage and Gemini-style prompts (Crush, Kilo) ban it as filler before the answer. Copying either line across switches off trained updates or invites filler, and Copilot's Opus 5 prompt has no update rule at all (2026-10-07). (`zed-agent-system-prompts`, `crush-agent-prompts`, `github-copilot-vscode-agent-prompts`)
- **Check the model's current guide before keeping an old progress-update block, because the advice has reversed more than once.** GPT-5 (2025-08-07) wanted thorough preambles. OpenAI's Codex guide (2026-02-25) said prompting for plans or updates made Codex models before GPT-5.3-Codex stop early, since their updates were system-generated, and gpt-5.3-codex made them promptable again only with the phase field kept. Cadences differ by model (every 1-3 steps with a floor of 6 steps or 10 tool calls on Codex 5.3, at least every 6 steps or 8 tool calls on GPT-5.1), and models.md holds the per-family rules. (`openai-gpt-5-prompting-guide`, `openai-gpt-5-1-prompting-guide`, `openai-gpt-5-6-prompt-guidance`, `openai-codex-prompting-guide`)
- **Give updates their own channel, a content rule and a time floor, and make the final answer stand on its own.** GPT-5.6 guidance: "send a one- or two-sentence user-visible update that states the first step", then update only when a phase begins or a finding changes the plan, never narrating routine calls. Codex's GPT-6 prompt (2026-10-06) adds that the user "should not be left without a commentary update for more than 60 seconds", keeps questions and the answer out of updates, and says "The final answer must always be fully self-contained" because updates collapse once it appears. (`openai-gpt-5-6-prompt-guidance`, `codex-prompt-gpt-6-family`)
- **In a latency-sensitive app on a reasoning model, ask for a short preamble before the deeper reasoning so the user sees text sooner.** OpenAI's reasoning doc gives this as the way to cut time to first visible token. On GPT-5.5 and GPT-5.4, tag it `phase: commentary` and the answer `final_answer`, or the preamble gets treated as the final answer and the run stops early. (`openai-reasoning-models-doc`)
- **If long tool-calling turns still go quiet, have the harness count silent steps and append a one-turn reminder after five, for example.** Stop after two or three reminders and leave each in place, since deleting them breaks the cache and preserved thinking. Anthropic's text: "say in a few words what you're doing, then continue"; on Opus 5.5 it halved the share of tasks with a long silent stretch, by Anthropic's rough count, at no measurable cost; the counter is agent-harness, loop.md. (`anthropic-prompting-opus-5-5`, `anthropic-prompting-sonnet-5-5`)
- **Delete update scaffolding the model no longer needs or can't act on.** Anthropic says Opus 4.7 and later give regular updates on their own, so remove forced cadences like "After every 3 tool calls, summarize progress"; on Opus 5.5 they arrive as thinking blocks, empty unless the app sets `thinking.display`. Cursor removed all mid-turn messaging language for Codex models, which can't talk until the turn ends, and the final code improved (2025-12-04). (`anthropic-migration-opus-5-5`, `anthropic-thinking`, `cursor-codex-model-harness`)
- **Where updates thin out, ask for them, say what one contains, and bound them by rate.** Current Claude models "write fewer progress updates at higher [effort] and in long tool chains"; an update notes what the model just found and what it does next. Claude Fable 5.1's app prompt bounds the rate: "one short sentence every couple of tool calls" (2026-09-01). (`anthropic-thinking`, `anthropic-system-prompt-fable-5-1`)

## Plans and state on long runs

- **Give a plan tool a floor and one step in progress at a time.** Codex's shipped prompts skip planning for "straightforward tasks", which they put at the easiest 25%, by their rough count, and ban single-step plans and steps the agent can't carry out. GPT-5.1's prompt added strict status rules ("Do not let the plan go stale"), and the goal prompts warn that updating a plan doesn't replace doing the work. (`openai-repo-system-prompts`)
- **On a long run, have the agent keep its task list in a file and rewrite it as it goes.** A file survives the compaction that summarizes older turns, and rewriting it puts the goals at the end of the context where attention is strongest. Anthropic's Opus 5.5 line: "Keep a checklist in TASKS.md. Tick each item when it's done, and add anything new you find." Manus tasks average 50 tool calls by its own count (July 2025), and its todo.md counters drift across them. (`anthropic-getting-the-most-out-of-opus-5-5`, `manus-context-engineering-lessons`)
- **For a multi-hour run, keep four files the agent rereads: a frozen spec, a milestone plan with a validation command per milestone, a runbook, and a status and decision log.** The spec holds goals, non-goals, hard constraints, deliverables and "Done when", and the runbook says the plan is the source of truth and to validate and fix after each milestone. OpenAI credited this memory for a 25-hour uninterrupted GPT-5.3-Codex run at Extra High (the author's estimate, 2026-02) that kept one definition of done. (`openai-long-horizon-tasks-codex`)
- **Decide in advance what the agent does when reality leaves the plan.** Long runs always hit unknowns, and a default avoids the stall and leaves a trail to review. Anthropic: "If you hit an edge case that forces you to deviate from the plan, pick the conservative option, log it under 'Deviations', and keep going." (`anthropic-fable-field-guide-unknowns`)

## When to stop

- **After each tool result, have the agent ask whether the request can now be answered with useful evidence.** If yes it answers; if not it names the missing fact and takes the smallest useful fallback. A bare instruction to minimize tool loops can cost required evidence, so OpenAI's GPT-5.6 line says "do not let loop minimization outrank correctness, required evidence, calculations, or required citations". (`openai-gpt-5-6-prompt-guidance`)
- **Name the stops you don't want and the ones you do, plus the report format.** Generic "keep going" is weaker than naming the patterns: a summary that announces the next step, an offer to continue, a list of non-blocking decisions, stopping at a milestone. Opus 5.5's guide puts this at the end of the system prompt ("If you notice yourself inviting the user to redirect you or offering to wait, delete it and do the next thing."), next to when to stop before anything destructive and a report of "Blocked on me, Changed, Found". (`anthropic-prompting-opus-5-5`, `anthropic-getting-the-most-out-of-opus-5-5`)
- **Open an unattended agent's anti-early-stop block with the fact that nobody is watching, word for word.** Anthropic's Fable 5.1 sentence carries much of the effect: "You are operating autonomously. The user is not watching in real time and cannot answer questions mid-task". List any confirmations you still want right after it. (`anthropic-prompting-fable-5-1`)
- **Treat a text-only end of turn as a report, not completion.** Keep the task's parts in a checklist; when a turn ends with items open and no blocker, send a short message naming them ("Your task list still has open items: migrate the remaining two endpoints and update their tests. Continue with them."), and stop after two or three automatic continuations so a stuck run shows (agent-harness, loop.md). (`anthropic-prompting-opus-5-5`)
- **Label an automatic "keep going" turn as synthetic and say what it can't stand in for.** Loops let models treat the continuation as approval or shrink the goal to what exists. Qwen Code's turn says "This is a synthetic continuation turn. It contains no new real user input", that a phrase in the objective is no evidence the user supplied it, that completion needs the tool result proving each requirement, and to hand off when the budget is spent. (`qwen-code-system-prompts`)
- **To keep an agent working past the main task, redefine when it may end the turn instead of saying "be persistent".** Codex's persistent mode ends only when no follow-up would usefully continue the original task, bounds each follow-up by purpose and outcome rather than a count, wants new approval for new authority, and says "A pending, running, inconclusive, or unchanged result is not by itself completion." (`codex-model-messages-gpt-6`)
- **Pair every persistence instruction with a loop guard.** OpenAI's Codex starter: if the agent re-reads or re-edits the same files without clear progress, "stop and end the turn with a concise summary and any clarifying questions needed". (`openai-codex-prompting-guide`)
- **When high effort makes the agent start its own review rounds, tell it to stop and report once the asked work passes its checks.** Anthropic's Sonnet 5.5 line, "When the work the user asked for is done and its checks pass, stop and report.", with a deeper review offered at the end, stopped reviewer subagents and cut session cost by a third, by Anthropic's estimate, at no quality change (coding tasks, max effort). (`anthropic-prompting-sonnet-5-5`)
- **Give the agent a fixed shape for saying it's stuck, after it finishes everything not blocked.** "Need more info" costs the user a round trip. Crush asks for "(a) what you tried, (b) exactly why you are blocked, and (c) the minimal external action required", plus each missing item's reason, acceptable substitutes and what was tried. (`crush-agent-prompts`)

## Context and step budgets

- **Tell a long-running agent that a new message mid-work steers the active task, and that compaction doesn't change the task.** After compaction the latest message looks like the whole job. Codex's GPT-6 prompt: "Compaction does not end the task." and "Do not restart from scratch, redo completed work, or repeat commentary updates already delivered." (`codex-prompt-gpt-6-family`)
- **Show the model its remaining context only with instructions on what to do about it.** A visible countdown makes Claude Fable 5 offer to summarize or start a new session, so Anthropic's reassurance reads "You have ample context remaining. Do not stop, summarize, or suggest a new session on account of context limits." Codex's reminder at 6144 tokens left (off by default) asks for notes with goal, decisions, progress, next steps and item IDs, and says "Do not mention them in user-facing messages." When to compact is agent-harness, compaction.md. (`anthropic-prompting-fable-5`, `codex-model-messages-gpt-6`)
- **Give a long-running agent a checkpoint against its step budget.** Agents that never look hit the limit with nothing to show. browser-use: "When you reach 75% of your step budget, critically evaluate whether you can complete the full task in the remaining steps." (`browser-use-system-prompts`)

## Checks before "done"

- **Say what counts as a real check and what to say when none can run.** Which models report a change done without exercising it at low effort is in models.md "Claude". Anthropic's Sonnet 5.5 guide has a paragraph that names tests, the type-checker, the build or the changed command, says "A syntax-only check, or a check command that failed to start, does not count", and otherwise tells the model to "say which one you did not run and why instead of reporting the change as done" (2026-09-28). (`anthropic-building-with-claude-sonnet-5-5`)
- **Give every delegated task a concrete check the agent can run itself, and build those checks before you rely on "verify your work".** "Make sure it works" is not a criterion: Devin's docs ask to "verify that it has at least 500 rows" or to "confirm the endpoint returns status 200 and includes all required fields". In OpenAI's GPT-6 Astra game build, screenshots alone missed problems that named test scenes, readable state counters and browser tests caught (2026-09-04). (`devin-instructing-devin-effectively`, `openai-building-games-with-astra`)
- **Name each validation tool in the prompt with the moment to run it and what to do when it fails.** A polished answer with missing citations is the failure it prevents. OpenAI's cookbook: if a validator reports unsupported claims, missing files or empty artifacts, "revise the answer/artifacts before finalizing", or say the claim is unknown. (`openai-agent-improvement-loop`)
- **Before an agent reports success, have it run a short named checklist against the request and the observed state.** It re-reads the request and lists every requirement, checks counts and filters, confirms each action took effect, confirms every reported value appears in tool output, and reports failure if a blocker remains. browser-use's 6 checks end on "Partial results with `success=false` are more valuable than overclaiming success." (`browser-use-system-prompts`)
- **When strict compliance with several output rules matters, add a pass that lists which rules the draft broke and rewrites it.** Revising is easier than getting everything right the first time. IBM's Instruction Boosting added up to 7 points at 2 instructions and up to 4 points at 10, so the gain shrinks as rules pile up (2025-10-16). (`ibm-boosting-instruction-following-at-scale`)
