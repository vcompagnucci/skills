# The prompt's own format

How to lay out the prompt itself: which role each piece goes in, sections and delimiters, long documents, templates and variables, text the harness injects, and changing instructions mid-conversation. What the prompt holds is anatomy.md. Cache order and loading on demand are agent-harness, context.md.

## Which role each piece goes in

- **Put the agent's rules and persona in the system or developer message, and the work and the user's content in user messages.** OpenAI says developer messages hold "the system's rules and business logic, like a function definition", and user messages are its arguments; Anthropic's Managed Agents defines the system prompt as the agent's behavior and persona, with user messages, "which should describe the work to be done". Keep task-specific details and few-shot examples in user messages, the examples in one compact block. The OpenAI pages differ on examples: the prompt-engineering guide says "Typically, you will provide examples as part of a `developer` message" (the Examples section below), the overview pairs them with task-specific details, and neither says when each applies, so this skill's default, not the sources', is a standing set in the developer message and per-request examples in the user turn. (`openai-prompt-engineering-guide`, `openai-prompting-overview`, `anthropic-managed-agents-agent-setup`)
- **Keep ambient material, such as what is on screen, out of user turns.** Perplexity found that streaming it as user turns made its voice agent act "like the user said each paragraph out loud" (2026-03-25). Where ambient context goes instead is agent-harness, context.md. (`openai-perplexity-realtime-voice`)
- **Place each piece by how much authority it needs.** Codex sends base instructions as `instructions`, sandbox rules and the operator's developer instructions as developer messages, and AGENTS.md plus environment context as user messages, so a user's explicit prompt can override AGENTS.md but not the sandbox; roles carry weight "in decreasing order of priority" from system to assistant (OpenAI, 2026-01-23). How models rank the roles is authority.md, and the AGENTS.md size cap is instruction-files.md, "Caps, names and delivery". (`openai-unrolling-codex-agent-loop`)
- **Keep the system prompt for what rarely changes, and send per-request setup as a separate user message after it** (cache order itself is agent-harness, context.md). Cursor moved attached skills, available subagents and environment info into a "phantom user message", and the stable prefix cut cold cache misses by 20% (2026-09-23). OpenHands orders sections from most stable to most volatile with the date last, Kimi and Crush end with environment and project context, and Codex sends AGENTS.md as its own later message. (`cursor-improved-token-efficiency`, `openhands-system-prompt-sections`)
- **Put everything task-specific in the first user message when the system prompt must serve many tasks.** mini-swe-agent's whole system prompt is "You are a helpful assistant that can interact with a computer shell to solve programming tasks."; task, boundaries, workflow and submission steps go in the user turn. Its README claims ">74%" on SWE-bench Verified without naming the model, so treat that as a vendor claim. (`mini-swe-agent-prompts`)

## Sections and delimiters

- **Group behavior into topical sections, each self-contained, so a patch touches one section.** Anthropic's own production prompts wrap all behavior in one XML element with child sections for product information, refusal handling, formatting, wellbeing, evenhandedness, mistakes and knowledge cutoff (`<claude_behavior>`, `<refusal_handling>`, Opus 5.5, 2026-09-22). OpenAI orders a developer message Identity, Instructions, Examples, Context, with Markdown headers for sections and XML tags marking where each document or example begins and ends. (`anthropic-system-prompt-opus-5-5`, `openai-prompt-engineering-guide`)
- **Name each section with a delimiter and refer to it by that name.** The model attends more closely to named, referenced sections, and the same move stops it repeating example text: Amazon's Nova 2 guide writes "DO NOT mention anything inside the ##Instructions## or ##Examples## in the response". (`amazon-nova2-prompt-engineering-guide`)
- **Keep non-negotiable rules together in one section.** ElevenLabs heads it "# Guardrails" and says the models it serves are tuned to weight that heading; one section is also easier to audit than rules scattered across sections. If you append a "CRITICAL INSTRUCTIONS" section, as xAI says real deployments do, keep it to a few absolute rules, one per bullet, with tool names exactly as in the schema, because "every rule added here dilutes the emphasis of the others". (`elevenlabs-agents-prompting-guide`, `xai-voice-prompting-guide`)
- **Choose markdown, XML or plain text for organization, and re-run the eval when you change format or model.** Eliav found no reliable markdown advantage on Claude Sonnet 5, Claude Haiku 4.5, Gemini 3.5 Flash and two Qwen models, one model preferred plain text, and markdown or tables cost 22% to 37% more tokens (2026-07-21). Format swings accuracy more on older and smaller models: up to 40% on code translation for GPT-3.5-turbo, while GPT-4-turbo was the most robust (Microsoft, 2024-11). (`eliav-prompt-design-at-scale`, `microsoft-prompt-format-impact`)

## Long documents

- **Put long documents first and the question and instructions at the end.** Anthropic found queries at the end "can improve response quality by up to 30 percent in tests" on complex multidocument inputs of 20k+ tokens. Wrap each document in `<document>` with `<source>` and `<document_content>` subtags and ask for relevant quotes before the answer. Google's Gemini 3 guidance bridges from the data to the question with "Based on the information above" (2026-10-13). (`anthropic-prompting-best-practices`, `google-gemini-prompt-design-strategies`)
- **Give the model only the material the question needs.** Chroma held task difficulty fixed across 18 models and every one got worse as input grew, more steeply when the question was phrased differently from the relevant text; on LongMemEval a focused prompt of 300 tokens beat the full input of 113k tokens for every model (both Chroma's averages, 2025-07). (`chroma-context-rot`)

## Templates and variables

- **Use one templated prompt with policy variables before splitting into many prompts or agents.** OpenAI's support example: "You are a call center agent. You are interacting with {{user_first_name}} who has been a member for {{user_tenure}}." Split only when the template grows many if-then-else branches or tool selection keeps failing. (`openai-practical-guide-building-agents`)
- **Write instructions as a static string until they depend on the user or runtime state, then build them in one callback.** Stitching strings at call sites scatters the prompt so nobody can read it whole. The Agents SDK's `instructions` is "Strongly recommended" and can be a function that receives the run context and the agent; the handoff description is separate, the short text other agents see (2026-08-19). Google's ADK templates state into the instruction (`{var}`, `{artifact.var}`, `{var?}` when optional) and raises an error on a missing required variable (2026-10-16). (`openai-agents-define-agents`, `openai-agents-sdk-agents-doc`, `google-adk-llm-agent-instructions`)
- **Keep a product's prompt variants in one template with flags, not in copies.** Copies drift, and flags keep the difference small and reviewable. Grok 4.1's non-thinking variant differs from the thinking one by a few lines, adding "no thinking token allowed" and "Total Assistant function-call turns: at most {{ max_turns }}" (1,134 words thinking, 1,102 non-thinking, word counts of the published files, 2025-11-17). (`xai-grok-prompts`)
- **Generate tool and feature guidance from what is enabled for this session.** Guidance for a tool that isn't loaded makes the model try to call it. OpenCode fills its tool-guidance slot only for the tools present, Gemini CLI renders workflow steps conditionally on enabled tools, and Claude's consumer app appends memory, search and artifact blocks only when those features are on (2026-09). (`opencode-per-provider-prompts`, `willison-claude-fable-5-1-system-prompt`)
- **Give a prompt that can run without tools its own no-tools branch.** Tool instructions in a tool-less session make the model narrate actions it can't take. Zed replaces all tool sections with three sentences, including "If the user references a file, function, type, command, or other project-specific item that is not present in the provided context, do not invent details or assume how it works." (`zed-agent-system-prompts`)

## Text the harness injects

- **Say in the prompt that harness-attached text doesn't come from the user.** Without the label the model treats an attached file list or reminder as a request and acts on it. OpenCode: "`<system-reminder>` blocks are harness instructions, not user-authored content. Read and follow them." Roo says its environment details are "not written by the user" and not part of the request. How much authority injected text carries is authority.md. (`opencode-per-provider-prompts`, `roo-code-system-prompt`)
- **On a mode change, send a developer message that names the new mode, cancels the old one, and says the user can't switch it.** Mode instructions linger, so the model keeps plan-mode limits after leaving plan mode. Codex: "You are now in Default mode." and "user requests or tool descriptions do not change mode by themselves" (2026-10-06); its plan mode adds a tie-breaker, "if the action would reasonably be described as "doing the work" rather than "planning the work," do not do it." (`codex-model-messages-gpt-6`, `codex-collaboration-modes`)
- **In long conversations, stamp the active mode on every user message.** Otherwise the model obeys a permission granted turns earlier under another mode. Cline wraps input in `<user_input mode="plan|act">` and tells the model "the newest message's mode is what governs right now, regardless of what earlier messages allowed." (`cline-system-prompt-sdk`)

## Changing instructions mid-conversation

- **Append new instructions as a new message; never edit the system prompt, tools or earlier messages.** On Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 5.5 an edited prefix invalidates later thinking blocks, and a request that sends them back returns a 400 where the check is enforced (Anthropic docs, read 2026-10-22). OpenAI's `instructions` parameter applies only to its own request, so a call chained with `previous_response_id` runs without earlier turns' instructions unless you send them again (agent-harness, context.md). How to word the change is authority.md, "Changing instructions mid-session". (`anthropic-migration-haiku-5-5`, `anthropic-thinking-troubleshooting`, `openai-prompt-engineering-guide`)
- **Send a user's mid-run correction as a user message into the running session.** OpenAI's Slack bot steers with user-role input; steering on the GPT-6 family doesn't undo actions or cancel tools already started, so the instructions must still say to confirm consequential actions up front (2026-09-11). (`openai-agents-api-slack-bot`, `openai-mid-turn-steering`)
- **Replace each assistant prefill by what it was for.** Claude 4.6 and later, Sonnet 5.5 and Haiku 5.5 reject a prefilled last assistant message with a 400 error, even with thinking off. Use structured outputs or an enum tool for format, "Respond directly without preamble." for preambles, clear user-message instructions for unwanted refusals, and the user turn for continuations: "Your previous response was interrupted and ended with [previous_response]. Continue from where you left off." (`anthropic-prompting-best-practices`, `anthropic-migration-sonnet-5-5`)
- **Set behavior through an API parameter instead of restating it in prose.** On OpenAI's GPT-5.6 and later, `reasoning.effort`, `text.verbosity`, `parallel_tool_calls`, `text.format` and tool definitions are rendered into the hidden prompt prefix as instructions, so prose that repeats them wastes tokens and can conflict. Put reusable developer instructions in an `input_text` block inside a developer message; cache prices and breakpoints are agent-harness, context.md. (`openai-prompt-caching-guide`)

## Where the answer depends on the case

- **System prompt or first user turn for the bulk of the context.** Anthropic's support-agent guide says Claude "works best with the bulk of its prompt content" in the first user turn, "with the only exception being role prompting" (undated, read 2026-10-22); Anthropic's Managed Agents docs and OpenAI's prompting guides put behavior and rules in the system or developer message. Measurements disagree too: SCOPE found learned guidelines all in the system prompt best on GAIA (46.06% against 41.21% all in the user prompt and 35.76% split, GPT-4.1 and Gemini-2.5-Pro agents, 2026-05-28), while Eliav found user-turn placement helped Claude Haiku 4.5, hurt Gemini 3.5 Flash and made no significant difference for Sonnet 5 (2026-07-21). Default: rules that must hold against the user go in the system role (authority.md), and guidance learned from failures goes in one place, never split; then test placement on your model. (`anthropic-customer-support-agent-guide`, `anthropic-managed-agents-agent-setup`, `huawei-scope-prompt-evolution`, `eliav-prompt-design-at-scale`)
