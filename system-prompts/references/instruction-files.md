# Instruction files

AGENTS.md, CLAUDE.md and the other rules files a coding agent loads: what goes in, how long they run, how they load and layer, and who wins when they conflict. Checking which files the agent actually loaded is iterate.md; how loading and caching work is agent-harness, context.md.

## Start small and grow from mistakes

- **Start the file with build and test commands, conventions and what counts as done, and nothing else.** Rules written up front are guesses, and OpenAI says "A short, accurate AGENTS.md is more useful than a long file full of vague rules." Codex's shipped /init prompt asks for 200-400 words specific to the repo and never overwrites an existing file; when the agent finds the right files but reads too many, add routing guidance naming which directories to prioritize. (`openai-codex-customization-doc`, `openai-codex-best-practices`, `codex-orchestrator-and-init`)
- **Add a rule only after the agent repeats a mistake or you leave the same review comment twice, and keep the file in git so the team shares it.** Rules from real friction stay practical: when the agent repeats a mistake, ask it for a retrospective and update the file (OpenAI), or have it fix the rule from the issue or PR (Cursor). Cognition writes the fix as a rule or a step-by-step procedure, such as every file to touch when adding a service route, and also commits a list of common mistakes that an agent checks each PR against. To test one rule, replay the session with and without it (iterate.md, "Auditing an existing prompt"). (`openai-codex-best-practices`, `cursor-rules-docs`, `cognition-coding-agents-101`)
- **Move rules you repeat in every task prompt into the file, and workflows you keep re-explaining into a skill.** OpenAI lists "Overloading the prompt with durable rules" as a common first-use mistake, and repeated rules drift between sessions; "if you keep reusing the same prompt or correcting the same workflow, it should probably become a skill." (`openai-codex-best-practices`)
- **Write the file as an onboarding document that points to the source systems and leaves the data in them.** Given both the file and detailed CSVs, the agent prefers the granular files, so a high-level answer needs an explicit instruction; in multi-day runs the file can be the plan the agent edits as it resolves issues. (`anthropic-cb-chief-of-staff`)
- **Write the docs for humans and let them double as agent instructions.** Dagster rewrote its contributor guide for people, with hierarchy, structure and rules with their reasons, and "inadvertently significantly improved" its agent (a guest post on OpenAI's blog). (`openai-dagster-docs`)

## Write lines the agent can act on

- **Write each line concrete enough to verify, and put what must happen every time in a hook.** An instruction file is context the model reads, not configuration it enforces: "Use 2-space indentation", not "format code properly". Anthropic calls CLAUDE.md instructions advisory and hooks deterministic, so a linter that runs after each edit belongs in a hook. (`anthropic-claude-code-memory`, `anthropic-cc-best-practices`)
- **Tell a coding agent what to leave out of the change.** Pre-existing bugs and unmentioned behavior go in the summary as follow-ups, an ambiguity gets its most directly supported reading, and tests are committed only where asked or where the repo keeps them. Anthropic's line ends "don't fix, optimize or extend it in this change unless the requested behavior cannot work without it; report it as a follow-up in your summary."; on Fable 5.1 unrequested additions and committed test code dropped substantially with no measurable change in task success (docs read 2026-10-22). (`anthropic-prompting-fable-5-1`)
- **Write each code-review rule as the behavior to flag plus a safe path, scoped to the code it governs, and leave formatting and lint to CI.** A prohibition with no acceptable alternative produces flags the author can't act on, and broad rules made noise where small scoped sets did not. OpenAI's example pairs a ban on filtering treatment comparisons on post-exposure behavior with "Safe path: build cohorts from assignment or exposure; report conversion as an outcome."; rule-guided Codex Code Review recovered 98% of required custom findings against 58.3% for the baseline (2026-07). Drop any rule whose removal wouldn't change the review. (`openai-codex-agents-md-guide`, `openai-codex-code-review-rules`)
- **Put notes for human maintainers in block HTML comments only in a harness that strips them.** Claude Code strips block-level comments from CLAUDE.md before injection (comments inside code blocks stay), and Deep Agents strips them from AGENTS.md memory before the system prompt, so there a rule's history costs no tokens. No other source here says its harness strips them, so check yours before relying on it. (`anthropic-claude-code-memory`, `langchain-deepagents-prompts`)
- **Keep how the agent talks to you in your global file and team and codebase rules in the repo file.** Personal style in the shared file imposes one developer's preferences on the team and bloats what everyone loads; the file nearest the working directory takes precedence. (`openai-codex-customization-doc`)

## Keep the always-on file small

- **Keep the always-on file short and mostly gotchas, and cut what the agent can find or already knows.** For each line ask whether removing it would cause mistakes, because "Bloated CLAUDE.md files cause Claude to ignore your actual instructions!" and the file is resent every turn. (`anthropic-cc-best-practices`)
- **Hold each CLAUDE.md under 200 lines and each Cursor rule under 500, with rules for one part of the codebase in path-scoped files.** Anthropic's docs give the 200-line target (read 2026-10-22) and note that imports save nothing, because imported files load too. Cursor gives the 500-line cap (read 2026-10-22) and leaves out linter rules, commands the agent knows (npm, git, pytest), rare edge cases and copied code. (`anthropic-claude-code-memory`, `cursor-rules-docs`)
- **Give the agent a map, not a manual.** OpenAI's harness team found one big file crowded out the task, made everything important, rotted and couldn't be checked; what worked was a 100-line AGENTS.md (OpenAI's figure, given as approximate, 2026-02) pointing into a versioned docs/ directory with design docs carrying verification status, an architecture map, quality grades and plans with decision logs. Linters and CI check freshness and cross-links, a recurring agent opens fix-up PRs for stale docs, and the team shipped 1,500 PRs (also approximate) in 5 months with 3 to 7 engineers, 3.5 PRs per engineer per day (2026-02). (`openai-harness-engineering`)
- **Say which doc serves which situation instead of loading all of them always.** "Before every edit, read architecture.md, database.md, and deployment.md." burns context on a typo fix; OpenAI's better line says "Use architecture.md for service boundaries, database.md for schema changes" (2026-09-11). (`openai-rethinking-skills-prompts-gpt-6-astra`)
- **Sort rules by how they should load.** Always-on content rides in the system prompt every message, so keep it for what applies everywhere, and use path-glob rules for conventions tied to paths, description-only rules the model opens when relevant, and manual rules for rare procedures (Windsurf's `always_on`, `glob`, `model_decision`, `manual`; global rules capped at 6,000 characters, each workspace file at 12,000, fetched 2026-10-22). OpenHands loads a nested AGENTS.md only when a file under `<dir>/**` is touched, while Codex concatenates nested files and lets the deepest win; either way, say in the prompt how nested files apply. Loading mechanics are agent-harness, context.md. (`windsurf-cascade-memories-rules`, `openhands-repo-instructions-and-skills`)
- **Put anything that must always be in context in the file body, because a file mention is only a pointer.** Cursor states referenced files are not inlined in its editor, CLI or cloud agents; the agent reads them later with its tools, so a rule relying on an unread reference silently doesn't apply. (`cursor-rules-docs`)
- **Use the always-loaded file to make a skill mandatory under a stated condition, and let the skill hold the procedure.** OpenAI's Agents SDK repos write "Run `$code-change-verification` when runtime code, tests, examples, or build/test behavior changes." The line is still advisory, so a step that must run every time also gets a hook. (`openai-skills-oss-maintenance`)

## Caps, names and delivery

- **Keep the combined files under the harness's byte cap, with specialized rules in nested files near the code.** Codex concatenates global, repo root and current directory, so the nearest file wins by coming last, and stops adding files at the 32 KiB `project_doc_max_bytes` default (read 2026-10-22); the guide calls it the "combined size" without saying whether the global file counts, so when you measure a real setup, give the cut point both ways; guidance past the cap is dropped silently, the docs call that truncation, not skipping, and their fix for an oversized file is to "split large files across nested directories to keep critical guidance intact" (docs read 2026-10-22). It sends the result as a user-role message headed "# AGENTS.md instructions" and the directory, inside <INSTRUCTIONS> tags, prefers AGENTS.override.md, and on a mid-session edit says "These AGENTS.md instructions replace all previously provided AGENTS.md instructions." (2026-10-17). (`openai-codex-agents-md-guide`, `codex-agents-md-injection`)
- **Put the critical lines at the top.** Devin auto-loads only the first 16 KiB (16,384 bytes) of each AGENTS.md, measured per file (fetched 2026-10-22) and the rest isn't auto-loaded: the agent opens it only if it decides to, so a long file's tail goes unread without warning; longer or situational guidance belongs in skills or referenced files. Claude Code differs: it "loads a CLAUDE.md file of up to 4 MiB in full and skips a larger file" (docs read 2026-10-22), so there a long file costs adherence, not its tail. (`devin-agents-md`, `anthropic-claude-code-memory`)
- **Write shared project rules in AGENTS.md and keep vendor-named files for model-specific steering.** OpenHands loads AGENTS.md, AGENT.md, CLAUDE.md, GEMINI.md and .cursorrules, goose loads .goosehints and AGENTS.md, Codex reads AGENTS.md and AGENTS.override.md, and Claude Code reads AGENTS.md only when no CLAUDE.md exists. If your harness reads several, decide which model sees which: OpenHands shows CLAUDE.md only to Claude models and GEMINI.md only to Gemini models, so Claude tuning doesn't leak into a GPT session. (`openhands-repo-instructions-and-skills`, `goose-hints-loader`, `codex-agents-md-injection`, `anthropic-claude-code-memory`)
- **To share one AGENTS.md and still steer Claude Code, write a CLAUDE.md that imports it with `@AGENTS.md` and holds the Claude-only lines below the import.** Claude reads the imported file first, then the rest; Anthropic's example puts "Use plan mode for changes under `src/billing/`." under a `## Claude Code` heading (docs read 2026-10-22). The import loads AGENTS.md in full at launch and saves no context, so both files together count against the 200-line budget. (`anthropic-claude-code-memory`)
- **When you merge files from several levels, head each one with whose it is and what it covers.** Without labels the model can't tell a personal preference from a project rule. goose injects "### Global Hints", then "### Project Hints" with "These are hints for working on the project in this directory.", then "### Subdirectory Hints" with the directory in parentheses, loading from the git root down so the most specific comes last. (`goose-hints-loader`)
- **Turn off built-in instructions that compete with yours instead of out-shouting them.** Two sources on one behavior conflict, so the Agent SDK sets `includeGitInstructions: false` and an empty commit and PR `attribution` rather than adding a stronger rule. (`anthropic-agent-sdk-modifying-system-prompts`)

## Who wins

- **Write the file as defaults the user can override, scoped to the repo's work.** Under the AGENTS.md convention the closest file to the edited code wins, an explicit chat prompt overrides every file, and nothing is required (60k+ open-source projects; OpenAI's main repo had 88 files; read 2026-10-22). OpenAI models treat a relevant AGENTS.md as implicitly delegated by the user and "should typically follow instructions in relevant AGENTS.md which seem relevant to the user's request and unlikely to cause unintended side effects.", so rules that look unrelated or risky get discounted. (`agentsmd-org-site`, `openai-model-spec-changelog`)
- **Say in the prompt that the user's explicit instructions beat a skill's, and audit the files you load.** Better instruction following makes a stray line costly: GPT-6 Astra is "more sensitive to instructions contained in skills and other files, such as AGENTS.md", and conflicting guidance can make it pause and block work early. OpenAI's line: "The user's instructions take precedence over guidelines provided in a skill." Codex's default prompt has a pause name and link the exact SKILL.md, quote the rule and separate requirement from reading (iterate.md, "Reading failures"), and adds "If a skill does not explicitly require approval, default to proceeding within the user's authorized scope" (2026-09-29). (`openai-using-gpt-6-prompting`, `openai-repo-system-prompts`, `openai-repo-update-0929`)
- **State three things about each instruction file: where it appears, who wins on conflict, and what it can't override.** Codex's base prompt (2026-06-23) says "More-deeply-nested AGENTS.md files take precedence in the case of conflicting instructions.", puts direct system, developer and user instructions above any file, and says injected files don't need re-reading; its GPT-6 templates move that to the wrapper the harness injects. Without the three the model can't resolve a file against the system prompt or the user. (`codex-base-instructions-default`, `openai-unrolling-codex-agent-loop`)
- **Decide how much a repo file may govern, and write it down.** Codex ranks direct instructions above the file; Gemini CLI lets GEMINI.md override workflows, tech stack, style and tool defaults, but it "cannot override Core Mandates regarding safety, security, and agent integrity", ranking subdirectories over workspace root over extensions over global (2026-09-29); OpenHands allows repo files "for coding style, project conventions, and documentation guidance only" and marks them unverified (2026-07-22). Without a stated boundary a repo file can switch off safety rules, or the model ignores repo conventions as lower priority. (`gemini-cli-system-prompt-modern`, `openhands-repo-instructions-and-skills`, `codex-base-instructions-default`)
- **Check the assembled context for conflicts, not each file alone.** When two instructions contradict, the model may pick one arbitrarily, which looks like flakiness. Resolving a conflict is rule-sets.md. (`anthropic-claude-code-memory`)
