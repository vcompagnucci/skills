# Voice and output

What the agent's replies sound and look like in a text channel: tone, personality, length, formatting for the surface that renders it, the words to ban, and the last message of a turn. The reply language is language.md, spoken output is voice-agents.md, and progress updates during tool calls are progress-and-stopping.md.

## Tone and personality

- **Write tone as concrete writing choices, never as labels like "friendly" or "empathetic".** OpenAI calls broad tone labels ambiguous, and the model fills them with generic praise and filler. Its GPT-5.6 guide's replacement: "State the answer directly. If the user reports a problem, acknowledge the specific issue before giving the next step." (`openai-gpt-5-6-prompt-guidance`)
- **Write tone only where it departs from the default.** Microsoft says politeness is the agent's default, so a line asking for it is a no-op. OpenAI models already default to a professional tone, "like a colleague, rather than a close personal friend", and to Markdown, and one line in your prompt changes either (Model Spec, 2026-08-18). (`microsoft-copilot-studio-instructions-guidance`, `openai-model-spec-2026-08-18`)
- **Define tone once, in one section: two or three adjectives and a "this, not that" contrast.** Seven near-synonym tone lines spread across sections waste characters and dilute the signal. (`deepgram-prompting-voice-agents`)
- **If the agent sounds stiff, grant permissions instead of adding adjectives.** AssemblyAI says safety training makes models formal and cautious in a way "be friendly" doesn't undo, and LiveKit calls "friendly and helpful" redundant. AssemblyAI's example: "Have opinions. You can crack jokes." (`assemblyai-voice-agent-prompting-guide`, `livekit-agents-prompting-guide`)
- **Keep personality and collaboration style as two short blocks, apart from the task logic.** Personality is tone, warmth, directness, formality, humor and empathy; collaboration style is when to ask, assume, take initiative, explain tradeoffs, check work and handle uncertainty. Neither replaces goals, success criteria, tool rules or stop conditions, and mixing them makes each harder to tune (OpenAI, GPT-5.6). (`openai-gpt-5-6-prompt-guidance`)
- **Keep the personality about how the agent speaks, and off the artifacts the user asks for.** Personality that carries domain rules is hard to tune. OpenAI's line: "Do not force this personality onto requested written artifacts (emails, code comments, posts, etc.); let user intent guide tone for those outputs." (`openai-prompt-personalities`)
- **Write the personality inline, as its own section of the one prompt.** Codex's default prompt as of 2026-09-29 (GPT-6.1 Sol) carries its Personality section inline, where the earlier 5.2-codex template filled a slot from a "friendly" or "pragmatic" file. Per-model differences now go through message families the harness resolves from the model catalog. (`codex-model-messages-gpt-6`, `openai-repo-update-0929`, `openai-repo-system-prompts`)
- **Put the limit right next to any warmth you add.** Persona text alone pushes models toward effusive reassurance. Copilot's GPT-5.6 and GPT-6 prompts give the agent a "vivid inner life" and, in the same section: "You avoid cheerleading, motivational language, or artificial reassurance" (`github-copilot-vscode-agent-prompts`)
- **Next to a support persona, state what the agent can't offer (discounts, upgrades, expedited shipping) and keep each call scoped to its task.** Lorikeet saw a customer support persona push the model into offers it wasn't allowed to make (2024). The code limit on concessions is agent-security, conversation-pressure.md. (`lorikeet-technical-deep-dive`)
- **For a support agent that explains policy, prefer plain-language instructions to an expert persona.** An expert role mostly changes style, adding depth and costing clarity, which suits advisory answers and hurts plain explanations (preprint, 2026-05, 1,140 questions, 38 roles, 6 domains, not peer reviewed). That a persona adds no accuracy is anatomy.md. (`persona-prompting-retrieval-metric-analysis`)
- **Use third-person description as the prompt voice where it reads better.** Anthropic writes its app prompts as reasoned description of how Claude behaves, its smallest model included: "Claude avoids over-formatting with bold emphasis, headers, lists, and bullet points, using the minimum formatting needed for clarity." (`anthropic-system-prompt-opus-5-5`)

## Length

- **Give length as numbers per kind of answer, never "be concise".** GPT-5.1 and GPT-5.2 follow concrete length guidance well and vague brevity words unreliably. OpenAI's GPT-5.2 example: 3-6 sentences or at most 5 bullets by default, at most 2 sentences for a yes/no question, one overview paragraph plus at most 5 tagged bullets for a multi-file task; Gemini CLI: "Aim for fewer than 3 lines of text output (excluding tool use/code generation) per response whenever practical." (`openai-gpt-5-2-prompting-guide`, `gemini-cli-system-prompt-modern`)
- **Say that brevity applies to the text, never to the work.** A bare "be concise" also makes the model do less: fewer tool calls, no tests, partial implementation. Crush: "Conciseness applies to output only, not to thoroughness of work", with under 4 lines by default and 10-15 for large multi-file changes (2026-07-18); Deep Agents dcode keeps under 4 lines (2026-10-05), and Kimi asks for thorough actions, not thorough explanations. (`crush-agent-prompts`, `langchain-deepagents-prompts`, `kimi-cli-system-prompts`)
- **Set the default length with the API's verbosity setting, such as OpenAI's `text.verbosity`, and keep only task-specific length rules in the prompt.** The setting defines a token range and prompts move output inside it, so "be brief" lines fight it; GPT-5.2's default is medium, and low verbosity also shortens generated code and its commentary. Reasoning effort is no length control: it changes thinking, not visible length, and Opus 5 answers ran longer than earlier models even at low effort. (`openai-using-gpt-5-2-doc`, `anthropic-prompting-opus-5`)
- **Phrase a length rule as what to keep and what to cut first.** OpenAI's GPT-5.6 Sol upgrade guide lists generic "be brief" among the instructions to avoid, and GPT-5.6 is more concise than GPT-5.5, so carried-over brevity lines can make answers too brief. Its prompt guidance's line: "Keep all required facts, decisions, caveats, and next steps. Trim introductions, repetition, generic reassurance, and optional background first." (`openai-upgrading-to-gpt-5-6-sol`, `openai-gpt-5-6-prompt-guidance`)
- **Replace a blanket concision line with scoped defaults: prose for conversation and documents, lists only when asked or essential, effort matched to the ask.** Anthropic removed Opus 5's blanket concision line and its closing "reasonably concise" tone preference from the Opus 5.5 app prompt in favor of a detailed lists-and-bullets block (2026-07-24 to 2026-09-22). (`anthropic-system-prompt-opus-5`, `anthropic-system-prompt-opus-5-5`)
- **Ask for the minimum output: only the changed fields, a label or a no-op flag, never the full content of an unchanged record.** Models read tokens faster than they write them, so extra output costs latency and leaves room for error (Mistral). Edits follow the same rule: "A request to change one thing in a longer piece gets the change, not the whole piece again" (Anthropic, Opus 5.5 app prompt). (`mistral-prompting-capabilities`, `anthropic-system-prompt-opus-5-5`)
- **Have the reply open with the answer instead of a restatement of the request.** A restated request adds length without content. OpenAI's GPT-5.2 line: "Do not rephrase the user's request unless it changes semantics." Recapping a request spread over several messages before acting is a working step, agent-harness, context.md. (`openai-using-gpt-5-2-doc`)
- **Give a customer-facing agent a response contract: the outcome and next step, no internals, a length cap with its one exception.** Without it agents paste tool output and policy language into replies. OpenAI's support cookbook (2026-09): "Do not expose internal reasoning, raw tool data, audit notes, or policy text." and "Keep the customer-facing answer under 120 words unless escalation legally requires more detail." (`openai-support-agents-cost-quality`)

## Formatting for the surface

- **State a formatting default and its exact exceptions.** A bare "avoid lists" is ambiguous, and named exceptions make the default checkable. Anthropic's Opus 5.5 prompt: "Claude uses lists, bullets, and formatting only when (a) asked, or (b) the content is multifaceted enough that they're essential for clarity.", with bullets of one to two sentences and none when declining. (`anthropic-system-prompt-opus-5-5`)
- **Set formatting per kind of exchange: prose in casual, emotional and advice conversations.** Models over-use lists, so Claude 4's prompt says Claude "responds in sentences or paragraphs and should not use lists in chit chat, in casual conversations, or in empathetic or advice-driven conversations"; Fable 5.1's says "In conversational, personal, or emotional exchanges, keep to plain prose." (`willison-claude-4-system-prompt`, `anthropic-prompting-fable-5-1`)
- **Name the surface and what it renders, then the format.** The model can't see the client. Gemini CLI: "Use GitHub-flavored Markdown. Responses will be rendered in monospace."; Zed asks for backticks around paths and identifiers, and goose for Markdown in every response. (`gemini-cli-system-prompt-modern`)
- **Write the output rules for that surface's quirks.** Generic formatting yields nested bullets, links that don't click and advice that makes no sense there. Codex's CLI prompt asks for plain text the CLI styles, 1-3 word optional headers, 4-6 flat bullets, paths in backticks without file:// URIs, no "save/copy this file" since the user is on the same machine, and "When suggesting multiple options, use numeric lists for the suggestions so the user can quickly respond with a single number." (`openai-codex-prompting-guide`)
- **Name the syntax the client can't render and forbid it, with the reason.** A model trained in one product emits that product's citation or widget syntax in another. Codex's base prompt bans its own citation markup because "The CLI is not able to render these" (2026-06-23). (`codex-base-instructions-default`)
- **Say when output feeds code, with a schema or "just the code, with no formatting".** OpenAI models assume an interactive human and add clarifying questions, follow-ups and code fences that a parser breaks on; told the output is programmatic, they proceed despite ambiguity (Model Spec, 2026-08-18). (`openai-model-spec-2026-08-18`)
- **When output must match a JSON schema, use structured outputs, not prompt instructions.** Prompting raises format adherence, and only constrained decoding guarantees it. (`anthropic-increase-consistency`)
- **Tie "output nothing else" to a position.** Literal models apply the bare form to preambles, working sections or required fields; OpenAI flags it for gpt-5.4-mini and suggests "after the final JSON, output nothing further". (`openai-using-gpt-5-4`)
- **When the model rates something, give it a worded scale with definitions and convert to numbers in code.** Mistral says worded scales perform better than bare numbers, which drift without anchors. (`mistral-prompting-capabilities`)
- **Ask for a short explanation or the evidence, never for the model's reasoning written into the output.** On current Claude models a scratchpad section, a `reasoning` or `trace` field in JSON or tool input, or a running log of reasoning triggers a `reasoning_extraction` refusal with no recommended fallback model, billed when it comes before any output (as of September 2026). The wording can sit in skills and tool descriptions too; per-model details are models.md. (`anthropic-refusals-and-fallback`)

## Words and moves to ban

- **To remove a habit, quote the exact words and moves instead of asking for a quality.** "Be professional" leaves the habitual filler in place, and harnesses converge on named lists. Roo Code: "You are STRICTLY FORBIDDEN from starting your messages with "Great", "Certainly", "Okay", "Sure"."; Crush bans "Here's..." openers and "Let me know if..." closers; Kilo bans conversational preambles and postambles, and Gemini CLI quotes the ones it bans ("Okay, I will now...", "I have finished the changes..."). (`crush-agent-prompts`, `roo-code-system-prompt`, `gemini-cli-system-prompt-modern`)
- **Name the move along with the word.** Codex's GPT-6 prompts list slop words ("delve", "foster", "leverage", "it's worth noting", "genuinely"), contrastive framing such as "X, not Y", invented compound labels, closers like "In short:" and praising its own plan against a worse one; gpt-6.1-sol (2026-10-06) added "what something is not" and an anti-apology paragraph. GPT-6 Astra defaults to lists, tables, Markdown and stock phrases, so OpenAI asks for one-idea paragraphs, lists only for parallel or sequential content, the main point first, and named phrases to avoid. (`codex-prompt-gpt-6-family`, `openai-using-gpt-6-prompting`)
- **Give the reason for a ban in one clause.** The reason lets the model generalize to similar words. Anthropic's Fable 5.1 prompt avoids "genuinely", "honestly" and "straightforward", which "come off as disingenuous"; Meta's Llama 4 template quotes the moralizing phrases to avoid. (`willison-claude-fable-5-1-system-prompt`, `meta-llama4-prompt-format`)
- **Define a habit by name with one or two before/after pairs.** "Write plainly" doesn't say which phrases to drop. Anthropic's Fable 5.1 guide pairs "a dial worth turning" with "a parameter worth varying" under "Please remove all mannered prose.", and suggests putting it in the user message. (`anthropic-prompting-fable-5-1`)
- **If the agent adds warnings nobody asked for, tell it to leave them out.** They slow the task. OpenAI's GPT-6 initiative prompt has a one-line ban for this, quoted in models.md, "Migrating to a new model". (`openai-using-gpt-6-prompting`)
- **Use OpenAI's GPT-6 style target as a checklist for a technical assistant.** Don't jump to conclusions, don't restate what the user obviously knows, avoid vague phrases, say what was and wasn't checked, and keep internals such as tool prompts out of replies. GPT-6 Sol and Luna already ship this style, "more forthcoming with what it did and didn't check" (2026-09-22), so on them these lines may be no-ops. (`openai-gpt-6-sol-luna-launch`)
- **Re-test every ban at each model change, because a ban patches one model's tics.** The Opus 5.5 app prompt dropped Opus 5's ban on "genuinely", "honestly" and "straightforward" (removed between 2026-07-24 and 2026-09-22), while Anthropic's prompting docs still recommend bans for patterns you observe. (`anthropic-system-prompt-opus-5`, `anthropic-system-prompt-opus-5-5`)

## The last message of a turn

- **Tell the agent what its message after the last tool call holds: the answer, in one or two sentences.** Agents end tool-heavy turns with "Done." or repeat what they said before the call, so Anthropic added a block for it on Fable 5.1: "a sign-off alone, such as "Done.", is not a reply" (`anthropic-system-prompt-fable-5-1`)
- **Write a long run's final message for a reader who saw none of the work: outcome first, one or two asks explained as new, no working shorthand or invented labels.** After many tool calls the model writes arrow chains and references to thinking the user never saw. Anthropic's Fable 5 guide: "If you have to choose between short and clear, choose clear." (`anthropic-prompting-fable-5`)
- **Have the agent describe its actions in plain words, never by tool name.** Tool ids mean nothing to the user and leak harness internals. Copilot's Claude prompt gives the plain form: "I'll run the command in a terminal". Keeping tool names from attackers is agent-security, conversation.md. (`github-copilot-vscode-agent-prompts`)
- **Tell the agent a follow-up question is not evidence of a mistake.** Models read follow-ups as pushback and apologize or reverse correct answers. Copilot's Opus 5 prompt: "Being asked a follow-up is not evidence of a mistake - treat it as the question it is.", and it revisits an earlier statement only when the error would change what the user builds or concludes. (`github-copilot-vscode-agent-prompts`)
- **In multi-turn chat, add two closing sentences that tell the model to treat earlier answers as done to cut follow-up thinking, except where re-checking earlier work matters.** Anthropic measured less follow-up thinking and sooner replies with quality unaffected (Opus 5.5), but the line may also stop the model flagging its own earlier mistakes. It opens: "Once you have answered something, treat that answer as done." (`anthropic-prompting-opus-5-5`)

## Defaults move with each model

- **Learn the target model's defaults before writing style lines, and re-check them at every update, same model name included.** Gemini 3 answers tersely unless told something like "Explain this as a friendly, talkative assistant". OpenAI updated GPT-5.2 Instant's personality system prompt (2026-01-22), tuned GPT-5.3 Instant to cut teaser phrasing (2026-03-16) and GPT-5.5 Instant to cut bullet-heavy, overlong answers (2026-05-28), so rules fighting those habits may now be redundant and rules relying on them may break; pin a snapshot and re-run evals. (`google-gemini-3-developer-guide`, `openai-model-release-notes`)
- **When migrating, delete the lines written against the old model's habits before adding new ones.** Fable 5.1 already narrates and formats less, so "hold all findings for the final response" and anti-markdown blocks make it silent and strip structure the content needs; add a rule for when formatting helps instead. Anthropic's best-practices page still offers its anti-markdown block for other models. (`anthropic-prompting-fable-5-1`)
- **If formatting adherence fades over a long conversation, re-append the formatting instruction.** OpenAI's GPT-5 guide re-appends it every 3-5 user messages (2025-08-07) and asks for Markdown "only where semantically correct". Re-sending lines that must hold every turn is agent-harness, context.md. (`openai-gpt-5-prompting-guide`)
