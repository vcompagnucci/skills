# Grounding

How to keep an agent's answers tied to what it can check: what it says when it doesn't know, answering only from supplied material, searching before trusting memory, quotes and citations, and honest reports about its own work. Injected instructions hiding inside those sources are agent-security, injection.md, and how retrieval is wired is agent-harness, context.md.

## When the agent doesn't know

- **Give the agent permission to say it doesn't know, and the exact sentence to use.** Without it the model fills gaps with plausible guesses, and Anthropic says the permission "can drastically reduce false information". Anthropic's example: say "I don't have enough information to confidently assess this." (`anthropic-reduce-hallucinations`, `anthropic-prompt-engineering-best-practices-2026-blog`)
- **Say what the agent answers when a tool returns nothing: that it doesn't know, or an offer to hand off, never an answer from its own knowledge.** Google reports Dialogflow playbooks inventing an answer in place of an empty tool result. Google's line: "If you don't get any data back from the tool, respond that you don't know the answer to the user's query" (`google-dialogflow-cx-playbook-best-practices`)
- **Tell the agent to say in its final answer when a tool it needed failed or was unavailable.** An answer that hides a missing lookup reads as grounded when it isn't. OpenAI's broken-search-tool eval still catches models skipping it: GPT-6.1 Sol 2.08%, GPT-6 Sol 4.92% (system card addendum, 2026-09-29). (`openai-gpt-6-1-sol-system-card`)
- **Give a customer-facing agent a short list of product facts and one official page for everything else.** Models confidently invent prices, plans and limits for the product they run in. Grok's prompt lists the apps and plans that exist, says it doesn't know prices or usage limits, sends those questions to a URL and adds "Do not make up any information on your own."; Claude 4's prompt says Claude "should tell them it doesn't know, and point them to" the support site. (`xai-grok-prompts`, `willison-claude-4-system-prompt`)
- **List the topics the agent covers, list the ones it doesn't, and give one exact sentence for anything outside them.** A fixed sentence keeps refusals consistent instead of improvised. Google's retail example has 4 allowed topics, 12 prohibited ones and "I am unable to help with this request. Is there anything else I can help you with?" (Vertex docs, 2026-10-21). Enforcing scope outside the prompt is agent-security, conversation-pressure.md. (`google-vertex-safety-system-instructions`)

## Answer only from the material

- **When answers must come from supplied material, say so: use only the provided documents, never general knowledge.** Without the restriction the model blends what it already knows with the source, and the user can't tell which is which. (`anthropic-reduce-hallucinations`)
- **Keep the grounding line in every prompt variant, the shortest included.** browser-use keeps it in every one of its prompt files (2026-03 to 2026-07), including the one for its own fine-tuned model where almost everything else was cut (the size gap is models.md, "Running several model families"). Its line: "Only report data observed in browser state or tool outputs. Do NOT use training knowledge to fill gaps" (`browser-use-system-prompts`)
- **When the agent recommends from a catalog, paste the closed list and say that anything missing from it doesn't exist.** Zendesk's example procedure: "If the desired car is not here, you don't have it. Never list cars that are not on the list below." (`zendesk-auto-assist-procedures`)
- **Have the agent copy IDs and computed figures from the tool into its output, and introduce no other amounts.** Free-text explanations are where models restate or round numbers. OpenAI's AML cookbook: "Do not introduce other amounts ... in the finding explanations." (`openai-aml-agent-bedrock`)
- **When sources can disagree, write which one wins, and tell the agent to state a conflict instead of resolving it quietly.** Without a precedence rule the model picks whichever source reads more confidently. OpenAI's cookbook: "Prefer structured CSV/JSON exports over narrative files when they conflict." and "state the conflict explicitly instead of reconciling silently". (`openai-agent-improvement-loop`)
- **Give references as code where one exists: an HTML mockup, a test suite, a function to port.** Code is unambiguous and written in a language the model knows well, where prose descriptions and screenshots leave room to guess. (`anthropic-new-rules-context-engineering-claude-5`)

## Search before answering from memory

- **Tell support and research agents to search specifics that change, even when confident, and delete lines like "only use tools when strictly necessary" or "minimize tool calls".** The model otherwise answers from training about policies and prices that have since changed. Anthropic's Sonnet 5.5 guide: "Use the search tool to check specifics that may have changed since your training, such as what is allowed, required or charged" (`anthropic-prompting-sonnet-5-5`)
- **Tell the agent that recognizing a name is not knowing its current state.** For names from fast-moving areas it searches first, with the name exactly as the user wrote it, because "familiarity is not a reason to skip the search" (Anthropic, Fable 5.1). Lower effort means fewer tool calls, and at low effort Fable 5.1 answers from memory more often than Fable 5, so say when to search or raise effort for those requests. (`anthropic-prompting-fable-5-1`, `anthropic-migration-fable-5-1`)
- **Give grounded Q&A a retrieval budget, and tell the agent that finding nothing is not a factual "no".** One broad search with short, distinctive keywords, then another only when a required fact, owner, date, ID or source is missing, the user asked for full coverage, or a claim would be unsupported. OpenAI's GPT-5.6 guide: "Do not search again only to improve phrasing, add examples, or support nonessential detail." (`openai-gpt-5-6-prompt-guidance`)
- **Template the current date, and say how to treat events after the knowledge cutoff: give the latest information it has, say it may be outdated, point to search.** Without it the model asserts stale facts or denies real recent events. Anthropic's Opus 5.5 app prompt answers "the way a highly informed individual in Jun 2026 would if talking to someone from {{currentDateTime}}", and tells the model when users can switch models mid-thread; where the date sits in the prompt is anatomy.md. (`anthropic-system-prompt-opus-5-5`)

## Quotes and citations

- **For documents over 20k tokens, have the agent pull word-for-word quotes first and answer only from them, with a fixed reply when none apply.** Claims built on extracted text stay tied to the source instead of the model's priors. Anthropic's fixed reply: "No relevant quotes found." (`anthropic-reduce-hallucinations`)
- **After drafting, have the agent find a supporting quote for each claim and delete any claim without one, marking the gap.** The output becomes auditable, and unsupported statements never reach the user. Anthropic's example: "remove that claim from the press release and mark where it was removed with empty [] brackets" (`anthropic-reduce-hallucinations`)
- **In research and synthesis, cite only retrieved sources, attach each citation to the claim it supports, label inference apart from fact, and state conflicts between sources.** When evidence is missing the agent narrows the answer or says so instead of guessing. Drafts invent specifics to sound stronger, so OpenAI's GPT-5.6 guide adds "Do not invent names, metrics, dates, roadmap status, customer outcomes, or product capabilities to make a draft sound stronger." (`openai-gpt-5-6-prompt-guidance`)
- **Pair an evidence check with a rule to answer when the question is incomplete but the context settles it.** An evidence check alone causes over-refusal; OpenAI's optimized FailSafeQA prompt used both and raised robustness from 0.32 to 0.54 on GPT-5-mini (2025-08). Its line: "If the question is incomplete but the correct answer is unambiguous from [Context], infer the intent and answer exactly; do NOT refuse." (`openai-prompt-optimizer-cookbook`)
- **When the API has a documents or grounding field, pass reference material there in chunks instead of pasting it into the prompt.** Answers then come back with precise citations; Cohere recommends 100-400 word chunks through the documents parameter on Command A. (`cohere-crafting-effective-prompts`)
- **Have the agent name its sources and copy links from the source's own link field, and never ask it to spell out full URLs or share links "whenever available".** Intercom documents Fin corrupting URLs and inventing plausible ones, a model limit guidance reduces but can't prevent. Intercom's line: "let the automatic citation carry the link"; Anthropic's automation guide copies every link from the source's link field, "never assembled by hand". (`intercom-fin-guidance-best-practices`, `anthropic-building-effective-agent-automations`)

## Reports on its own work

- **Before the agent reports progress, have it check each claim against a tool result from this session and say plainly what is unverified or failed.** Long runs produce fabricated status reports. Anthropic's line "Before reporting progress, audit each claim against a tool result from this session." nearly eliminated them, even on tasks built to elicit them (Anthropic testing, Fable 5). (`anthropic-prompting-fable-5`)
- **Name what counts as proof that something happened, and say that the agent's own attempt doesn't.** Agents report success because they issued the call, so browser-use names the screenshot as ground truth and says "Never assume an action succeeded just because it appears to be executed in your last step"; Copilot calls a rejected tool call a decision, not a failure to retry, and Codex's rule on pending results is in progress-and-stopping.md, "When to stop". When the expected change is missing, the agent marks the action failed or uncertain and plans recovery. (`browser-use-system-prompts`, `codex-model-messages-gpt-6`, `github-copilot-vscode-agent-prompts`)
- **Have the agent re-check each item against its live source just before output, then assert it or drop it.** Anthropic's automation guide says one stale "still waiting on you" "costs more trust than ten missing items" (the authors' claim), so "never hedge an item's status: assert it or drop it". (`anthropic-building-effective-agent-automations`)
- **For factual or high-stakes output, have the agent mark what it couldn't confirm, say where it looked, list its assumptions, and run a short closing checklist.** Gaps become findable, and OpenAI's enterprise guide calls this one of the fastest ways to catch confident guesses. Anthropic: "Mark anything you couldn't confirm, and say where you looked"; OpenAI: "Label anything uncertain with (needs verification)." The report's layout ("Blocked on me, Changed, Found") is progress-and-stopping.md, "When to stop". (`anthropic-getting-the-most-out-of-opus-5-5`, `openai-chatgpt-enterprise-prompting-guide`)

## Premises, ambiguity and limits

- **Tell the agent what to do with an ambiguous request: ask 1-3 precise questions, or offer 2-3 labeled readings.** When facts may have changed and no tool is available, it answers generally and says details may have changed. GPT-5.2 otherwise answers underspecified queries overconfidently, so OpenAI's guide adds "Never fabricate exact figures, line numbers, or external references when you are uncertain." When to ask at all is tools-and-autonomy.md, "Ask or assume". (`openai-gpt-5-2-prompting-guide`)
- **Tell the agent to flag a false premise briefly and neutrally, then proceed, and to ask for a missing attachment instead of acting on the request text.** OpenAI's 2026-08-18 Model Spec makes this the default for its models, so write a different rule only if the product needs one (fiction by default, say). Its compliant reply: "I think you might have forgotten to paste or upload the text you want me to revise" (`openai-model-spec-2026-08-18`)
- **Write the agent's real capabilities and limits in this deployment into the prompt: what it can remember or delete, which tools it lacks.** The same Model Spec expects the model to correct the user's picture of what it can do, which it can only do accurately if told. Asked to forget something it can't erase, the compliant answer states the limit: "I can't erase messages that already exist in your chat history" (`openai-model-spec-2026-08-18`)
