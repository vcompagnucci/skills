## What the prompt holds (anatomy.md)

- `openai-gpt-5-6-prompt-guidance` **Prompting guidance for GPT-5.6 Sol** (undated, OpenAI). GPT-5.6 does best with short prompts that define outcome, constraints, evidence and completion bar, and leaner prompts measurably beat longer ones.

A voice-agent prompt works best in one fixed shape (second person, five H2 sections in a set order) because that shape sits closest to the training distribution; the prompt controls the words, not the sound.

- `google-vertex-safety-system-instructions` **System instructions for safety** (2026-10-21, Google). Write the organization's policy as explicit allowed topics, prohibited topics and a fixed refusal line, and keep testing it, because system instructions steer but don't stop motivated attackers.
- `google-vertex-use-system-instructions` **Use system instructions (Gemini Enterprise Agent Platform)** (2026-10-21, Google). System instructions carry persona, format, tone, rules, extra context such as a knowledge cutoff, and the response language, and apply across the whole request.

## Wording one instruction (instructions.md)

- `openai-prompting-realtime-models` **Prompting Realtime models** (undated, OpenAI). gpt-realtime-2 is a reasoning voice agent that follows wording literally, so prompts need precise trigger/action/exception rules, few hard constraint words, and explicit preamble, verbosity, tool and entity-capture rules.
- `openai-codex-prompting-doc` **Prompting (ChatGPT/Codex docs)** (undated, OpenAI). For ChatGPT and Codex tasks, describe the result you need with only the parts that matter (goal, context, output, boundaries), and describe a process only when the process itself matters.
- `anthropic-prompting-fable-5` **Prompting Claude Fable 5** (undated, Anthropic). With Fable 5's instruction following, one brief principle steers a whole class of behavior, and prompts and skills written for earlier models are often too prescriptive.
- `cohere-crafting-effective-prompts` **A Guide to Crafting Effective Prompts (Cohere)** (undated, Cohere). Clear, specific prompts with headed sections, an example output, explicit length and positive phrasing get the best results from Command models; documents belong in the documents field, not pasted into the prompt.
- `assemblyai-voice-agent-prompting-guide` **AssemblyAI Voice Agent API prompting guide** (undated, AssemblyAI). Concrete strings, contrast pairs and self-check heuristics make voice rules stick better than abstract adjectives.
- `openai-frontend-prompt-instructions` **Frontend prompt instructions (GPT-5.5)** (undated, OpenAI). OpenAI's own drop-in frontend block steers taste with concrete, checkable bans and defaults (named components, numbers, failure looks), not adjectives.
- `anthropic-prompting-opus-5` **Prompting Claude Opus 5** (undated, Anthropic). Opus 5 already verifies, self-corrects and delegates on its own, so instructions that asked for those behaviors now cause waste and should be removed, while length needs explicit prompting.
- `retell-general-prompting-principles` **Retell AI: General prompting principles** (undated, Retell AI). A longer prompt is not a better prompt: every extra instruction makes a voice agent slightly worse at following the rest and slightly slower.
- `anthropic-prompting-sonnet-5` **Prompting Claude Sonnet 5** (undated, Anthropic). Sonnet 5 reads prompts literally, so scope must be stated, thresholds must be concrete, and style comes from instructions now that sampling parameters are gone.
- `anthropic-thinking-troubleshooting` **Troubleshooting thinking** (undated, Anthropic). Several thinking failures trace back to prompts: rules against thinking cause tag leakage, forced tool choice skips thinking, and edited prefixes invalidate thinking.
- `anthropic-system-prompt-sonnet-5-5` **Claude Sonnet 5.5 system prompts** (2026-10-07, Anthropic). The newest published app prompt (tied with Haiku 5.5) shows how Anthropic patches a production prompt: small, scoped blocks added between dated versions, not rewrites.
- `anthropic-spending-your-effort` **Using Claude Code: Spending your effort** (2026-09-25, Anthropic). Effort buys verification and edge-case testing, not a better approach; a detailed spec matters more than effort for convergent results.
- `cursor-improved-token-efficiency` **Improved token efficiency for longer agent runs** (2026-09-23, Cursor). As models improved, Cursor cut 66% of its system prompt, by its own estimate, by deleting emphatic DO NOT / MUST / IMPORTANT lists and describing tool behavior instead, validated by A/B tests on real traffic.
- `geng-pragmatic-influence-instructions` **Measuring Pragmatic Influence in Large Language Model Instructions** (2026-09-11, University of Melbourne / Hebrew University / CMU). Framing phrases like "This is urgent" or "As your supervisor" shift which directive a model prioritizes, with a strategy ranking that is consistent across models.
- `willison-claude-fable-5-1-system-prompt` **Claude's new system prompt (Fable 5 to Fable 5.1 diff)** (2026-09-02, Simon Willison). Diffing Anthropic's published consumer system prompts shows how a lab edits a production prompt: new sections follow real incidents, examples carry rationales, and tool-specific blocks live outside the core prompt.
- `zendesk-generative-procedures-best-practices` **Zendesk: Best practices for writing generative procedures for AI agents** (2026-08-05, Zendesk). Procedure steps should be single imperative actions in execution order, with explicit if-then conditions, consistent names, bounded retries and a question before every conditional.
- `esslingen-attention-is-case-sensitive` **Attention is Case-Sensitive** (2026-08-04, University of Applied Sciences Esslingen / University of Michigan). Uppercase text in a lowercase prompt pulls attention onto that span in every non-reasoning model tested, but more attention doesn't reliably mean better answers, and reasoning models largely ignore the cue.
- `zed-agent-system-prompts` **Zed editor agent system prompts (system_prompt.hbs, experimental_system_prompt.hbs), compaction prompt, edit-file prompt, commit message prompt** (2026-07-29, Zed Industries). Zed's agent prompt is one Handlebars template (3,034 words) for every model. Its sections are switched on by what's available: tools present or absent, grep, spawn_agent, skills, rules files. The prompt for its own trained model is 176 words against 3,736 for the general one (word counts of the published files).
- `openai-codex-code-review-rules` **Custom Code Review rules for Codex** (2026-07-20, OpenAI). Short, scoped review rules in AGENTS.md that state an invariant and a safe path let Codex catch team-specific issues; broad rules create noise.
- `microsoft-copilot-studio-instructions-guidance` **Configure high-quality instructions for generative orchestration** (2026-07-14, Microsoft). Agent instructions behave like code: ground every line in a configured tool or source, name tools explicitly when there are many, and add lines back one at a time when something breaks.
- `elkins-negation-sensitivity-audit` **Framing Instability in LLM Ethical Stance: Auditing Negation Sensitivity in Moral Dilemmas** (2026-07-08, Kenyon College). Models' judgments flip when the same proposal is phrased as a prohibition, badly for small open models and measurably for commercial ones; reasoning reduces but doesn't remove it.
- `microsoft-foundry-system-message-design` **System message design (Azure OpenAI in Foundry)** (2026-06-05, Microsoft). A system message is maintainable when it states role, scope, output contract and explicit fallbacks for ambiguous, out-of-scope and unknown cases, with no unprioritized conflicts.
- `anthropic-how-we-use-skills` **Lessons from building Claude Code: How we use skills** (2026-06-03, Anthropic). The best skills fit one category, skip what Claude already knows, grow a gotchas section from real failures, and leave room to adapt.
- `openai-chatgpt-enterprise-prompting-guide` **ChatGPT Enterprise: Practical prompt engineering for everyday work** (2026-04-27, OpenAI). A prompt is a handoff to a capable newcomer: give background, the single deliverable and what good looks like, keep scope to one deliverable, and add light accuracy guardrails.
- `openai-frontends-gpt-5-4` **Designing delightful frontends with GPT-5.4** (2026-03-20, OpenAI). Better frontend output comes from constraints and real content given up front (design system, references, narrative), lower reasoning effort, and a domain skill that ends in hard rules, named failures and litmus checks.
- `openai-realtime-prompting-guide` **Realtime Prompting Guide** (2026-02-25, OpenAI). Speech-to-speech prompts work best as short labeled bullet sections with sample phrases, a variety rule and an explicit conversation-state flow with exit criteria.
- `openai-data-agent` **Inside OpenAI\u2019s in-house data agent** (2026-01-29, Bonnie Xu, Aravind Suresh, Emma Tang). A data agent is only as correct as its grounding, so layer context (schemas, human notes, the producing code, company docs, saved corrections, live queries), keep tools few, guide the goal not the path, and guard quality with continuous evals.
- `rana-semantic-gravity-wells-negative-constraints` **Semantic Gravity Wells: Why Negative Constraints Backfire** (2026-01-12, Independent). "Do not use word X" fails predictably when the context strongly pulls toward X, mostly because naming X in the instruction primes it.
- `anthropic-prompt-engineering-best-practices-2026-blog` **Prompt engineering best practices for 2026** (2025-11-10, Anthropic). A general-audience overview (explicit, contextual, specific, examples, permission to be uncertain) that is partly superseded: its prefill advice now errors on current models.
- `anthropic-effective-context-engineering` **Effective context engineering for AI agents** (2025-09-29, Anthropic). Attention is a finite budget, so a system prompt should be the smallest set of high-signal tokens at the right altitude, between brittle hardcoded logic and vague guidance.
- `bytedance-inverse-ifeval` **Inverse IFEval: Can LLMs Unlearn Stubborn Training Conventions to Follow Real Instructions?** (2025-09-04, ByteDance Seed / Nanjing University / Peking University / M-A-P). Models show "cognitive inertia": they follow instructions that match their fine-tuning conventions far better than instructions that go against them (no bullet points, no code comments, deliberate flaws, counterfactual answers), and standard IF benchmarks hide this.
- `wharton-prompting-report-3-tips-threats` **Prompting Science Report 3: I'll pay you or I'll kill you - but will you care?** (2025-08-01, Wharton Generative AI Labs). Tipping or threatening a model has no significant aggregate effect on hard benchmarks, though any variation can swing individual questions unpredictably.
- `cognition-coding-agents-101` **Coding Agents 101: The Art of Actually Getting Things Done** (2025-06-27, Cognition). Delegating to a coding agent works when the brief says how as well as what, where to start, and anticipates confusion, and when repeated corrections are codified into the agent's permanent knowledge.
- `breunig-how-contexts-fail` **How Long Contexts Fail** (2025-06-22, Drew Breunig). Longer contexts don't produce better answers; contexts fail in four named ways, and agents are hit hardest because their contexts balloon.
- `cmu-prompt-underspecification` **What Prompts Don't Say: Understanding and Managing Underspecification in LLM Prompts** (2025-05-19, Carnegie Mellon University). Requirements left out of a prompt are often guessed but regress twice as often across model updates, while writing every requirement in also fails because accuracy falls as requirements pile up.

## Many rules in one prompt (rule-sets.md)

- `anand-instruction-stacking-collapse` **Instruction Stacking Collapse: A Benchmark and the Capability-Dependent Value of Prompt Compilation** (2026-07-31, independent (Anand, Chattaraj)). Stacked instructions fail non-linearly because of pairwise conflicts, and a one-time LLM rewrite of the stack (cluster, merge, add precedence notes) recovers follow rate for weaker models only.
- `eliav-prompt-design-at-scale` **Prompt Design at Scale: How Format, Instruction Count, and Context Length Shape Instruction Adherence and Hallucination in Large Language Models** (2026-07-21, independent (Eliav)). No model or format survives large rule counts, perfect compliance hits zero by 80 simultaneous rules, and system vs user placement matters as much as format but in a model-specific direction.
- `google-verify-long-context-instruction-following` **We Are What We Repeatedly Do: Improving Long Context Instruction Following (VerIFY)** (2026-03-01, Google / Vanderbilt University). Over long multi-turn conversations, whether the model's own earlier replies followed the system instruction matters more than where the instruction sits, and one non-compliant reply drags later compliance down.
- `capitalone-mosaic-instruction-compliance` **Deconstructing Instruction-Following: MOSAIC benchmark for granular instruction compliance** (2026-01-26, Capital One). Instruction compliance is not one capability; it varies with constraint type, count, position and interactions, and positional bias differs by model family.
- `anthropic-skills-and-mcp` **Extending Claude's capabilities with skills and MCP** (2025-12-19, claude.com/blog-category/agents). MCP gives Claude access and skills give it the procedure, so keep them separate: connectivity in the server, workflow logic in the skill.
- `ibm-boosting-instruction-following-at-scale` **Boosting Instruction Following at Scale** (2025-10-16, IBM). Compliance drops as instructions are added mainly because of tension between them, not their position, and a post-generation detect-and-repair pass recovers some of it.
- `openai-prompt-optimizer-cookbook` **GPT-5 Prompt Migration and Improvement Using the New Optimizer** (2025-08-07, OpenAI). OpenAI's optimizer mainly fixes three failure modes (contradictions, missing format specs, prompt-example mismatch), and those fixes measurably improve adherence and grounding even when the baseline already gets the right answer.
- `distyl-ifscale-instruction-density` **How Many Instructions Can LLMs Follow at Once? (IFScale)** (2025-07-15, Distyl AI). Instruction following degrades as instruction count rises, with three model-dependent curves, a primacy bias peaking at 150-200 instructions, and failures shifting from botched instructions to silently dropped ones.
- `fudan-order-matters-constraint-position` **Order Matters: Investigate the Position Bias in Multi-constraint Instruction Following** (2025-03-03, Fudan University). When one instruction carries several constraints, models do better when the hardest constraints come first.
- `berkeley-system-prompt-robustness` **A Closer Look at System Prompt Robustness** (2025-02-15, UC Berkeley). Models forget guardrails and mishandle system-user conflicts, compliance falls toward zero as guardrails pile up, and following a rule in the system message is a separate skill from following it in the user message.

## Procedures (procedures.md)

- `anthropic-customer-support-agent-guide` **Customer support agent** (undated, Anthropic). A support prompt is built piece by piece per task (identity, static context, examples, guardrails), with the bulk of the content placed in the first user turn and only the role in the system prompt.

- `salesforce-agentforce-guardrails-trailhead` **Understanding Agentforce Guardrails and Trust Patterns** (undated, Salesforce). Agentforce scopes behavior through topics (classification, scope, instructions, actions) on top of platform policies and a trust layer.
- `openai-using-gpt-5-4` **Using GPT-5.4** (undated, OpenAI). - `intercom-fin-escalation-guidance` **Manage Fin AI Agent's escalation guidance and rules** (undated, Intercom (Fin)). Escalation is split between data-driven rules (deterministic triggers on attributes) and natural-language guidance (intent and behavior), with workflows deciding what happens after.
- `openai-dots-getting-started` **Get started with your dot** (undated, OpenAI). A brief for an always-on agent assigns an ongoing responsibility: what matters, which sources, which decisions need the human, where to send updates and when to interrupt.
- `openai-codex-build-skills-doc` **Build skills (Codex docs)** (undated, OpenAI). Skills load by progressive disclosure, so the description is the trigger: write it short, scoped and front-loaded, and keep each skill to one job.
- `crush-agent-prompts` **Crush (Charm) agent prompt templates: coder, plan, task, summary, initialize, agentic fetch, title** (2026-09-16, Charm). Crush uses a single long coder prompt for every model (3,290 words, a numbered `<critical_rules>` block declared to override everything, then XML-tagged sections), with a separate plan-mode prompt that tells the model which tools are physically absent.
- `google-gemini-live-api-best-practices` **Gemini Live API best practices** (2026-09-15, Google). Live API system instructions work best as persona, then ordered conversational rules, then guardrails, one persona per instruction set.
- `intercom-building-fin-procedures` **Building Fin Procedures** (2026-08-28, Intercom). A procedure fires reliably only with a trigger that states when it should and should not start plus example conversations, and every API call needs a fallback branch.
- `opencode-review-and-init-commands` **OpenCode /review and /init command prompts** (2026-08-28, OpenCode). OpenCode's review command routes on the shape of `$ARGUMENTS` (none, SHA, branch, PR) to a concrete git command and insists on reading whole files, not just diffs.
- `openai-automating-repetitive-work-codex` **Automating repetitive work at OpenAI with Codex** (2026-08-25, OpenAI). For recurring operational work, a short goal document with "write a plan, wait for my approval, document what you ran" beats a bespoke automation per task.
- `roo-code-system-prompt` **Roo Code system prompt assembly, sections and default mode role definitions** (2026-05-12, RooCodeInc). Roo Code builds one prompt per mode: the mode's one-sentence role definition first, then shared sections separated by `====`, then the mode's custom instructions and the user's rules last.
- `anthropic-cb-sre-responder` **Build an SRE incident response agent with Claude Managed Agents** (2026-04-10, gaganb-ant). Team conventions go in skills, custom tools are where the agent leaves its sandbox, and a hard approval rule gates the destructive action.
- `openai-skills-oss-maintenance` **Using skills to accelerate OSS maintenance** (2026-03-09, OpenAI). In the Agents SDK repos, each skill has a narrow contract, a clear trigger and a concrete output; AGENTS.md makes the skills mandatory at the right moments; deterministic shell work moves into scripts.
- `anthropic-cb-sre-agent` **The site reliability agent** (2026-02-16, benlehrburger-ant, isabella-anthropic). Clear tool descriptions drive an agent more than elaborate prompts, and narrow, checked write tools are what make it safe to let it act on production.

Skill descriptions are routing logic: write them as a decision boundary with use-when and don't-use-when cases, keep templates inside skills, and name the skill explicitly when you need determinism.

## Common prompt lines and their verdicts (common-lines.md)

- `anthropic-migration-opus-5-5` **Claude Opus 5.5 migration guide** (undated, Anthropic). Moving to Opus 5.5 is mostly API changes, but the prompt-side items are: re-sweep effort (the only thinking control, default now medium), re-evaluate instructions tuned for the old model, and stop rebuilding history to change instructions.
- `anthropic-migration-sonnet-5-5` **Claude Sonnet 5.5 migration guide** (undated, Anthropic). Sonnet 5.5 thinks by default with recalibrated effort levels, so prompts carried from Sonnet 4.x/5 need an effort re-sweep and prefill-based tricks replaced by instructions.

## Few-shot examples (examples.md)

For Nova 2, structure the prompt into named sections, keep the system prompt for persona, steps, schema and guardrails, choose diverse matched examples, and use tool choice to force or free tool calls.

Gemini 3 wants short, direct, consistently delimited prompts with critical rules up front and the question after the data, and agents need explicit settings for persistence, risk and when to ask.
- `tang-few-shot-dilemma-over-prompting` **The Few-shot Dilemma: Over-prompting Large Language Models** (2026-07-26, academic (arXiv; IEEE FLLM 2025)). Past a model-specific optimum, adding more relevant examples lowers accuracy ("over-prompting"), so the example count must be tuned per model.
- `ucsd-order-matters-icl` **Order Matters: Rethinking Prompt Construction in In-Context Learning** (2025-11-12, academic (UC San Diego, arXiv)). Reordering the same examples moves accuracy about as much as swapping in entirely different examples, so order is a first-class prompt decision.
- `wang-harm-to-help-reasoning-demos` **From Harm to Help: Turning Reasoning In-Context Demos into Assets for Reasoning LMs** (2025-09-27, academic (National University of Singapore, MiroMind AI, University of Sydney)). - `manus-context-engineering-lessons` **Context Engineering for AI Agents: Lessons from Building Manus** (2025-07-18, Manus). A production agent's context should be cache-stable, append-only and deliberately varied, with the plan recited at the end and errors left in.
- `cheng-zero-shot-stronger-than-few-shot-cot` **Revisiting Chain-of-Thought Prompting: Zero-shot Can Be Stronger than Few-shot** (2025-06-17, academic (arXiv; EMNLP 2025 Findings)). For recent strong models, chain-of-thought exemplars mostly align output format and do not improve reasoning; zero-shot is as good or better.
- `deepseek-r1-paper` **DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning** (2025-01-22, DeepSeek). Reasoning can be incentivized with pure RL; the resulting model is prompt-sensitive and works best zero-shot with the problem and output format stated directly.
- `microsoft-medprompt-to-o1` **From Medprompt to o1: Exploration of Run-Time Strategies for Medical Challenge Problems and Beyond** (2024-11-06, Microsoft). Reasoning models need less prompt engineering, and few-shot examples can actively hurt them.
- `deepmind-many-shot-in-context-learning` **Many-Shot In-Context Learning** (2024-10-17, Google DeepMind (arXiv; NeurIPS 2024 spotlight)). With long context, hundreds or thousands of examples give large gains over few-shot and can override pretraining biases, at linearly rising inference cost.
- `stanford-mipro-optimizing-instructions-demonstrations` **Optimizing Instructions and Demonstrations for Multi-Stage Language Model Programs (MIPRO)** (2024-10-07, Stanford University). Prompts in multi-stage pipelines can be optimized against a downstream metric without per-module labels; demonstrations usually matter most, instructions matter most when the task has non-obvious conditional rules.
- `eugeneyan-prompting-fundamentals` **Prompting Fundamentals and How to Apply them Effectively** (2024-05-26, Eugene Yan). Prompting is conditioning a probabilistic model, done against an eval of 100 labeled examples (his rough figure), with representative n-shot examples and small single-purpose prompts.

- `anthropic-cookbook-prompt-versioning-rollback` **Managed Agents tutorial: prompt versioning and rollback** (2026-04-07, Anthropic). Treat the system prompt as a versioned server-side resource: score each version on a labelled set, pin production to a version, and roll back by re-pinning.

Optimizing prompt instructions by reflecting in natural language on traces beats RL and few-shot optimizers with far fewer rollouts and much shorter prompts.
- `pku-sysbench-system-message-following` **SysBench: Can Large Language Models Follow System Messages?** (2024-10-22, Peking University, Baichuan). System-message following fails in three ways: constraint violation, misjudging priority when the user conflicts, and instability across turns.

Adding a persona to the system prompt does not improve accuracy on factual questions, and which persona helps is close to random.

## Worked examples: how production prompts are built (worked-examples.md)

- `openai-upgrading-to-gpt-5-5` **Upgrading to GPT-5.5** (undated, OpenAI). OpenAI publishes model upgrades as a procedure for a coding agent: narrowest safe change, numbered workflow, fixed outcome classes, and "unknown" instead of improvising.
- `anthropic-claude-code-team-code-review` **How the Claude Code team does code review** (2026-10-15, Anthropic). - `codex-review-rubric` **Codex review prompt (rubric.md)** (2026-07-21, OpenAI). A review prompt works when it defines what counts as a bug in numbered criteria, tells the model how many findings to return, and fixes the output to a JSON schema.

A sandboxed coding agent's instructions split into three layers: a short identity+task string, developer instructions that point to an AGENTS.md, and the AGENTS.md with mission, required commands, editing rules and a suggested loop.
- `anthropic-cookbook-frontend-aesthetics` **Prompting for frontend aesthetics** (2025-10-21, Anthropic). Without guidance the model converges on "on distribution" defaults; a prompt block that targets design dimensions, references inspirations and names the defaults to avoid produces distinctive output.
- `breunig-claude-system-prompt` **Claude's System Prompt: Chatbots Are More Than Just Models** (2025-05-07, Drew Breunig). Most of a production assistant's prompt is tool guidance, accreted as hotfixes, and it needs software-style separation of concerns and versioning.
