# Many rules in one prompt

What happens when one prompt carries many rules: conflicts between them, how many a model keeps at once, when to repeat one, and where a rule sits in a list. Wording a single rule is instructions.md; splitting a long prompt into loaded procedures is procedures.md, under Move procedures out of the system prompt.

## Resolve conflicts before shipping

- **Remove contradictions before shipping and after every edit.** Better instruction following makes them worse, not better: frontier models follow "always refund within policy" and "never issue refunds without escalation" each literally instead of reconciling them (Anthropic, 2026-09-08). OpenAI's CareFlow example pairs "Never schedule an appointment without explicit patient consent recorded in the chart" with auto-assigning the earliest slot "without contacting the patient"; GPT-5 "expends reasoning tokens" reconciling it (2025-08-07), and OpenAI repeats for GPT-5.6 that "conflicting rules can create more instability than missing detail." (`anthropic-reducing-cost-claude-platform`, `openai-gpt-5-prompting-guide`, `openai-gpt-5-6-prompt-guidance`)
- **Resolve each conflict by saying which rule wins in which case.** OpenAI's fix for CareFlow adds one line: "Do not do lookup in the emergency case, proceed immediately to providing 911 guidance." Conflicts also hide across sources: Claude Code transcripts held "leave documentation as appropriate" and "DO NOT add comments" in one request, and an MCP server that says to return JSON next to a skill that says to use markdown tables makes Claude guess. (`openai-gpt-5-prompting-guide`, `anthropic-new-rules-context-engineering-claude-5`, `anthropic-skills-and-mcp`)
- **Remove soft exceptions as well as contradictions.** Each softener such as "if they make things simpler" is a fork the model takes differently from run to run; OpenAI says contradictions "often reduce performance and increase latency, especially in reasoning models". Across 30 generated scripts, removing them kept exactness at 100.0% while average peak memory fell from 3626.3 KB to 577.5 KB and average time from 7.906 s to 6.977 s, on one task (2025-08-07). (`openai-prompt-optimizer-cookbook`)
- **Check stacked format and content rules pairwise.** Compliance collapses from interference, not from count alone: stacking up to 20 of 24 verifiable instructions dropped follow rate from 96% (the paper's approximate figure) to as low as 20% on Claude Sonnet 4.6, GPT-5-mini and Gemini 2.5 Flash, and one "output JSON" constraint was jointly unsatisfiable with nine others (Anand and Chattaraj, 2026-07-31). (`anand-instruction-stacking-collapse`)
- **Put the tie-break inside the rule it governs, and give the agent one order for the rest.** AgentIF found meta constraints (rules about other rules) in "approximately 25%" of real agent instructions, and models did worst on the kind that selects which rule to follow (2025-05). Google's evaluated agent template says "Resolve conflicts in order of importance", ranking "Policy-based rules, mandatory prerequisites, and constraints" first and the user's stated preferences last, so the model reorders a request instead of breaking a prerequisite (2026-10-13). (`tsinghua-agentif-benchmark`, `google-gemini-prompt-design-strategies`)
- **Word the rule that must win as the stricter one.** On 2025-era models (GPT-4o, Claude 3, Llama-3.1, Qwen2, Mistral) IHEval found performance rose when the high-priority instruction was the stricter-worded one and fell when the conflicting one was (2025-03-28). How current models rank system, developer and user is authority.md. (`amazon-iheval-instruction-hierarchy`)

## Treat rules as a budget

- **Cut a line before you add one.** Adherence falls with every added instruction: at 500 simultaneous keyword instructions the best of 20 models reached 68%, with o3 at 62.8%, claude-3.7-sonnet 52.7% and claude-opus-4 44.6% (IFScale, 2025-07). Count your guardrails too: pass rates on GPT-4o, GPT-4o mini, DeepSeek V3, o3-mini and DeepSeek R1 approached zero by 20 (Berkeley, 2025-02-15), and real GPT-Store prompts often carry that many. (`distyl-ifscale-instruction-density`, `berkeley-system-prompt-robustness`)
- **At 40 simultaneous rules (Eliav's rough threshold), restructure instead of rewording.** Eliav calls that range "a redesign point, not a tuning point": the perfect-response rate reached zero by 80 rules for every model, format and placement tested (Claude Sonnet 5, Claude Haiku 4.5, Gemini 3.5 Flash, two Qwen models; 2026-07-21). Move rules into later turns, tools, loaded procedures or a validation pass. Count the way the study did: each rule was one "programmatically verifiable" constraint (a word-count range, a required or forbidden word, an exact first word), so, applied to a prompt, a bullet that makes two separate demands counts as two (for example, asking for the order number and the email on the order is one demand, while verifying the customer and then giving the status from the tool is two). When you report a count, show what you counted, as a tally per section for a long prompt. (`eliav-prompt-design-at-scale`)

## Repeat a rule only after it slips

- **State each rule once, and add a second copy only for a rule your tests show being dropped.** Anthropic says repetition was a workaround for older models that under-attended to the start of context, so on Claude 5 models tool-usage instructions go once, in the tool description (2026-07-24). Voice vendors split on this in undated docs with no measurement: ElevenLabs repeats the 1-2 most important instructions and LiveKit reinforces realism rules across sections, while Retell states each rule once because copies drift; its worked example cut a restaurant prompt from 970 words to 300, both figures given as approximate. Re-sending must-hold lines every turn is agent-harness, context.md. (`anthropic-new-rules-context-engineering-claude-5`, `elevenlabs-agents-prompting-guide`, `livekit-agents-prompting-guide`, `retell-general-prompting-principles`)
- **When the agent breaks a standing rule mid-conversation, remind it in the next turn or rewrite the bad reply in the history.** In Google DeepMind's VerIFY on Gemma, the best compliance came from the instruction at every turn plus compliant history, while stacking every strategy backfired on protected-word rules because repetition primed the forbidden words (2026-03-01). The reminder it tested opens "As a reminder, for all turns in this conversation". (`google-verify-long-context-instruction-following`)

## Order inside a list

- **List the hardest constraints of one instruction first.** Fudan found models of different architectures and sizes "more performant when presented with the constraints in a "hard-to-easy" order", at 7 and 9 constraints in single- and multi-round settings (2025-03-03). Where a critical rule goes in a long list depends on the model (next section). (`fudan-order-matters-constraint-position`)

## Where the answer depends on the case

- **How many rules a model keeps.** The measurements disagree because they count different things, so treat your own count as a budget and measure it. IFScale (2025-07-15) keeps reasoning models near-perfect "through moderate densities (100-250 instructions)" of keyword rules; Eliav (2026-07-21) sees perfect responses reach zero by 80 rules; Berkeley (2025-02-15) sees pass rates approach zero by 20 guardrails; MOSAIC (Capital One, 2026-01-26) finds compliance unpredictable from 7 to 15 output constraints and dropping past 15, most for DeepSeek-R1 8B and Qwen3. Prompt length on real agent prompts is anatomy.md "Length". (`distyl-ifscale-instruction-density`, `eliav-prompt-design-at-scale`, `berkeley-system-prompt-robustness`, `capitalone-mosaic-instruction-compliance`)
- **Where to put a critical rule.** Test it at its real position on your model, because the studies split. IFScale (2025-07-15) found a primacy effect in every model, peaking at 150-200 instructions (an approximate range in the paper) and fading to a ratio of 1.0-1.5 past 300; IBM (2025-10-16) found "no consistent relationship between IF rates and instruction position" in up to 10 instructions on Llama-3.3-70B, Llama-3.1-8B, Qwen2.5-72B, Mixtral-8x7B and Mixtral-8x22B. MOSAIC (2026-01-26) found Llama, Qwen3 and DeepSeek favor early constraints while Claude 3.7 Sonnet, Gemini 2.5 Flash and Mixtral favor late ones. (`distyl-ifscale-instruction-density`, `ibm-boosting-instruction-following-at-scale`, `capitalone-mosaic-instruction-compliance`)
