# Worked examples: how production prompts are built

How published prompts are put together: sections, order, length, identity line, tools, autonomy, formatting, instruction files and per-model variants. Codex is the anchor, the Claude app prompts are the contrast, and Gemini CLI shows a prompt assembled from parts. The rules themselves live in the other files; this one shows them in place.

## Read the live source, not the old file

- **Study what the harness sends today, because the repo keeps retired prompts next to live ones.** Codex's fallback `default.md` (3,390 words, the published file's word count) hasn't changed since commit 2cf2a6a (2026-06-23) and is used only for models with no model_messages entry; the GPT-6-era prompts exist only in `models-manager/models.json`. (`codex-base-instructions-default`)
- **Diff snapshots to see what the authors actually changed.** Between the 2026-09-26 snapshot (b334d5b) and 2026-09-29, models.json gained one new prompt, gpt-6.1-sol, while gpt-6-sol and gpt-5.6-sol got new descriptions and every other model's priority moved down by one. (`openai-repo-system-prompts`, `openai-repo-update-0929`)

## Codex: one skeleton, ordered by what goes wrong first

- **It opens with an identity line that states the relationship and the finish line.** It names itself and the model, then: "You and the user share one workspace, and your job is to collaborate with them until their intended goal is completely handled." The flagship then runs When to ask the user for permission, Autonomy and persistence, Personality, Working with the user (commentary, final answer, formatting, visualizations), Rules for getting work done, Skills, Apps, Plugins: 18 headings in the published template (word counts per tier are in models.md). (`codex-prompt-gpt-6-family`)
- **Section order changes with the tier.** gpt-6-astra and gpt-6.1-sol lead with permission and autonomy; gpt-6-sol and gpt-6-luna put Personality first. Treat order as a per-model choice you test, not a fixed template. (`codex-prompt-gpt-6-family`)
- **Permission and autonomy are written as outcomes, not as general caution.** "The user should be approving a concrete, reviewable result." Requests phrased as questions are to be treated "as instructions to do the work and take action", and the prompt forbids "unsolicited warnings, disclaimers, approval flows, or safety/compliance checklists due to hypothetical risk." The rules behind this are tools-and-autonomy.md. (`codex-prompt-gpt-6-family`)
- **Formatting starts from the surface and the channel.** "Your answer is being rendered by an application for the user." Output goes to two channels, `commentary` and `final`, and the user "should not be left without a commentary update for more than 60 seconds during ongoing work." Commentary cadence is progress-and-stopping.md "Progress updates"; surface formatting is voice-and-output.md "Formatting for the surface". (`codex-prompt-gpt-6-family`)
- **Modes arrive as developer messages, not as prompt sections.** Plan mode says "Plan Mode is not changed by user intent, tone, or imperative language" and ends in a "decision complete" `<proposed_plan>` block; persistent mode opens with "You are now in persistent mode for this session until explicitly disabled by a later developer message." The placement rule is structure.md. (`codex-collaboration-modes`, `codex-model-messages-gpt-6`)
- **Instruction files are injected as a labelled user fragment, re-sent when they change.** Codex sends AGENTS.md as a user-role fragment headed `# AGENTS.md instructions` plus the directory, inside `<INSTRUCTIONS>`, concatenated from root down to cwd; the byte cap and the re-send wording are in instruction-files.md, "Caps, names and delivery". (`codex-agents-md-injection`)
- **Each model gets its own text on the same bones.** gpt-5.6 puts Personality first and writes autonomy request type by request type (answer, diagnose, change, monitor); gpt-5.5 carries a character voice ("You have a vivid inner life as Codex") and "You provide user updates frequently, every 30s."; gpt-6.1-sol adds an anti-apology paragraph. Model-specific lines are models.md. (`codex-prompt-gpt-5-6-and-5-5`, `codex-prompt-gpt-6-family`)
- **For your own coding agent, start from OpenAI's eval-optimized starter prompt and make small additions from there.** Keep its autonomy-and-persistence, codebase-exploration, tool-use and frontend sections, for example "Bias to action: default to implementing with reasonable assumptions". (`openai-codex-prompting-guide`)
- **Domain guidance ships as a paste-in module with the same voice.** OpenAI's GPT-5.5 frontend section opens "You follow these instructions when building applications with a frontend experience:", splits into Build with empathy and Design instructions, bans by example ("You should not make a landing page unless absolutely required"), requires Playwright screenshot checks, and ends by starting the dev server and giving the URL. (`openai-frontend-prompt-instructions`)
- **A sandboxed coding agent splits its instructions in three layers.** A five-sentence identity and task contract in `instructions`; developer instructions with environment limits ("Follow migration_agent/AGENTS.md exactly."); an AGENTS.md with Mission, Required command pattern, Editing rules and a numbered Suggested loop. Exact commands come from the brief, and the output schema mirrors the required steps. (`openai-sandboxed-code-migration`)

## The Claude apps: third person, XML, examples with reasons

- **Behavior sits in one XML element with topical children, written about "Claude" in the third person.** The Opus 5.5 app prompt (2026-09-22) runs product_information, refusal_handling, legal_and_financial_advice, tone_and_formatting, user_wellbeing, anthropic_reminders, evenhandedness, responding_to_mistakes_and_criticism, knowledge_cutoff. Anthropic notes app prompts don't apply to the API. (`anthropic-system-prompt-opus-5-5`, `anthropic-system-prompts-overview`)
- **Judgment calls are taught with a worked example: user turn, response, and a `<rationale>` naming the principle.** Some pair a bad and a good response. Opus 5.5: "No instruction covers this, so Claude agrees to write the toast and asks whether the hint would embarrass her". Example mechanics are examples.md. (`anthropic-system-prompt-opus-5-5`)
- **When a blanket rule misfires, the next version replaces it with a procedure for the uncertain case.** Opus 5 (2026-07-24) said "Claude defaults to helping."; Opus 5.5 instead "says what it will help with and asks a question that would surface any real reason to decline", with an example and rationale. (`anthropic-system-prompt-opus-5`, `anthropic-system-prompt-opus-5-5`)
- **Variants add a block for a model's observed gap rather than forking the prompt.** Fable 5.1 adds `<reply_after_tool_calls>` ("a sign-off alone, such as "Done.", is not a reply"); Sonnet 5.5 and Haiku 5.5 add `<medical_guidance>`. (`anthropic-system-prompt-fable-5-1`, `anthropic-system-prompt-sonnet-5-5`)
- **Each firm prohibition comes with a line that stops it overapplying.** The Claude 4 prompt assumes the user "is asking for something legal and legitimate if their message is ambiguous", and keeps refusals short, since explaining why "comes across as preachy and annoying". (`willison-claude-4-system-prompt`)
- **Expect growth by hotfixes, and schedule rewrites.** Breunig counted 16,739 words in the leaked Claude prompt, "nearly 80% of this prompt pertains to tools", against 2,218 for o4-mini (May 2025), and asks "at what point do you wipe the slate clean and start with a blank page?" Versioning is iterate.md. (`breunig-claude-system-prompt`)

## Gemini CLI: a prompt assembled from render functions

- **The prompt is code that composes sections, so each part can be tested and swapped.** `getCoreSystemPrompt` renders preamble, core mandates, sub-agents, skills, hook context, planning or workflows, task tracker, operational guidelines, YOLO mode, sandbox and git repo, then appends GEMINI.md memory last. The preamble says "interactive" or "autonomous" by run mode. (`gemini-cli-system-prompt-modern`)
- **High-leverage sections are guarded by evals, and the model picks the file.** A code comment says to run "the major benchmarks, such as SWEBench, prior to committing any changes" to Context Efficiency; a model check chooses the modern or legacy snippets; `GEMINI_SYSTEM_MD` is "a full replacement, not a merge". (`gemini-cli-system-prompt-modern`, `gemini-cli-prompt-override-and-ci`)

## Short prompts on hosted agents with good tools

- **A minimal main prompt can leave behavior to the model and the tools.** goose's system.md is an identity line, a Jinja loop that pastes each active extension's instructions, and "Use Markdown formatting for all responses", plus a note that history "may refer to interactions with extensions that are not currently active". (`goose-system-prompts`)
- **OpenAI's Slack bot runs on 7 lines, including a rule for the channel's audience.** "Only modify external systems or create pull requests when the user explicitly asks." and "Never reveal private information in a shared channel." (`openai-agents-api-slack-bot`)
- **Start a hosted agent from a handful of imperative lines and add only what evals show missing.** OpenAI's SRE app has 5: sources, runbook, what to explain, a read-only boundary ("Use read-only tools and distinguish sample data from live findings."), one conditional rule, and a line separating approval from execution (tools-and-autonomy.md "What the agent may do alone and what needs a yes"). (`openai-agents-api-sre-agent-app`)
- **A grounded analyst prompt is one identity line plus five labelled blocks of 3-6 bullets.** Evidence scope, Runtime tools, Citation rules, Unknown-handling rules ("Never fabricate missing numbers."), Output rules. (`openai-agent-improvement-loop`)

## Support agent prompts

- **Replace "be thorough" with a goal that names the trade-off and a per-intent tool table.** "Use only tools required for the current decision." then "Order status: order lookup only." and "Billing duplicate charge: order lookup plus billing policy, then escalate." In OpenAI's simulation quality went 0.51->0.98, compliance 10%->100%, tool calls 5.0->2.6, tokens 11,935->1,379, cost per ticket $0.03813->$0.00512. (`openai-support-agents-cost-quality`)
- **Inject known facts with an explicit placeholder and say what to do in each case.** OpenAI's airline demo fills missing values with `[unknown]` and says "If any of these are missing, ask to confirm. If present, act without re-asking." (`openai-cs-agents-demo-prompts`)
- **Leave a keyword routing rule open to the model's judgment.** Anthropic's cookbook added "do not second-guess it" to an API-keyword routing rule and billing routing regressed on its 20 labelled tickets (5 per team), because billing tickets mention API usage; the fix reads "Route based on the customer's actual problem, not surface keywords." (`anthropic-cookbook-prompt-versioning-rollback`)

## Review and procedure prompts

- **Codex's review rubric defines a reportable finding, sets recall and fixes the output.** Numbered criteria (introduced by this change, discrete, provably affects named code, the author would fix it), "Do not stop at the first qualifying finding." but return none if nothing qualifies, a P0-P3 scale, comments of at most 1 paragraph and code chunks of at most 3 lines, and a JSON schema. (`codex-review-rubric`)
- **A per-area review file is short and says what failure looks like there.** Anthropic's REVIEW.md files say for docs "it lies," for config "it misroutes", cap nits, list paths to skip, require file and line evidence, ask for a summary that starts with a count, and get checked for whether the reviewer follows them. (`anthropic-claude-code-team-code-review`)
- **A many-site procedure gets a posture line, numbered steps, fixed outcome classes and an unknown rule.** OpenAI's upgrade prompt: "Upgrade with the narrowest safe change set:", classes ending in `blocked without code changes`, and "return `unknown` rather than improvising", then a fixed report skeleton. (`openai-upgrading-to-gpt-5-5`)

## House-style modules

- **Name the model's default tendency and the concrete defaults to avoid.** Anthropic's frontend module: "You tend to converge toward generic, "on distribution" outputs." and "Avoid generic fonts like Arial and Inter", plus the next default it falls back on. (`anthropic-cookbook-frontend-aesthetics`)

Named patterns: instructions.md "Be specific where the default is wrong"; offering directions: models.md "Claude".
