# Tools and autonomy

What the agent does on its own: whether a request means act or advise, which actions need a yes, when to ask and when to assume, and how to get tools called the way you want. Progress updates, plans, when to stop and checks before "done" are in progress-and-stopping.md.

## Act or advise: read the request

- **Set the agent's default between acting and advising explicitly in the system prompt.** The model follows the literal verb, so "Can you suggest some changes" gets suggestions, not edits. Anthropic's default-to-action block says "By default, implement changes rather than only suggesting them", and Cursor's autonomous mode tells Codex to "assume the user wants you to make code changes or run tools to solve the user's problem" unless the user asks for a plan, because users had tabbed away while it waited for permission. (`anthropic-prompting-best-practices`, `cursor-codex-model-harness`)
- **Write down whether an ambiguous request is a question or a task, choosing the direction that corrects your model's habit.** Left implicit, the model's own bias decides: GPT-family agents stopped at acknowledging they could do it, so Codex's GPT-6 prompt, OpenCode and Kimi treat ambiguity as a task, while Gemini CLI says "Assume all requests are Inquiries unless they contain an explicit instruction to perform a task" (2026-09-29). Per-family defaults are in models.md. (`gemini-cli-system-prompt-modern`, `codex-prompt-gpt-6-family`, `openai-gpt-5-1-prompting-guide`)
- **If the default is "task", name the phrasings that count as instructions and the stopping points that don't count as doing the work.** Codex's GPT-6 prompt treats "can you...", "I want to..." and "help me..." as instructions and says "Do not stop at acknowledging capability (e.g. "Yes..."), proposing a plan, or offering to continue." OpenAI's GPT-5.1 guide adds that when the user asks "should we do x?" and the answer is yes, "you should also go ahead and perform the action". (`codex-prompt-gpt-6-family`, `openai-gpt-5-1-prompting-guide`)
- **Say that a request for ideas, options or a plan gets exactly that, and nothing is built until the user says go.** On open requests the model may start a deck or a report when you wanted ideas. Anthropic's Sonnet 5.5 line: "When the user asks for ideas, options or a plan, give them that and stop." (`anthropic-prompting-sonnet-5-5`)
- **Scale ambition to how much the context constrains the task.** Codex's shipped prompts say "be ambitious and demonstrate creativity" for new work with no prior context, and "surgical precision" without gold-plating in an existing codebase. (`openai-repo-system-prompts`)
- **Write autonomy as one compact policy keyed to the kind of request, stated once.** Answer, explain, review and status authorize no writes; diagnose means find and explain the cause without fixing; change and build mean in-scope local changes plus non-destructive validation without asking; monitor means keep waiting, since unchanged state is not a blocker; external writes, destructive actions, purchases and scope expansion need confirmation. Repeating "ask first" in several places makes GPT-5.6 ask before safe, expected actions, and Codex adds that "finish" or "babysit" "does not broaden the set of authorized actions". (`openai-gpt-5-6-prompt-guidance`, `codex-prompt-gpt-5-6-and-5-5`)

## What the agent may do alone and what needs a yes

- **Set confirmation per tool class, and let the agent say an action is done only after the tool succeeded.** Read-only lookups run once intent and fields are clear, lookups by exact identifier confirm the identifier, and writes, purchases, cancellations and payments state the action and its consequence and wait. OpenAI's realtime example: "To confirm, you want me to charge the card on file $248.16 for the remaining balance. Should I proceed?", against the bad "I've charged your card" before any yes. (`openai-prompting-realtime-models`)
- **Have the agent finish all authorized work first and ask for approval on a concrete, reviewable result.** Asking before the work blocks the task, and OpenAI reports approval as the last step often finishes faster on GPT-6 Astra, with reversible, read-only, review and fix work needing no permission. Telling the agent what happens to its actions works too: Cursor's GPT-5 agent stopped interrupting once told its edits are proposals ("your code edits can be quite proactive, as the user can always reject"). (`openai-using-gpt-6-prompting`, `openai-gpt-5-prompting-guide`, `openai-repo-update-0929`)
- **When the agent does pause, make it name the rule that caused the stop and where it came from (a SKILL.md, AGENTS.md, memory, an automatic review).** Agents pause on requirements they inferred. Codex's GPT-6 prompt has it quote the rule, separate the rule from its reading, and otherwise "default to proceeding within the user's authorized scope rather than asking for confirmation based on an inferred requirement". (`codex-prompt-gpt-6-family`)
- **When the pauses are the harness's own approval prompts rather than the model asking, change the approval mode, sandbox or allowlist, not the prompt.** Those prompts come from configuration, so no wording removes them: in Codex, "Approval mode determines when Codex asks for your permission to run a command". Allow rules, auto-execution levels and the permission mode are agent-security, approvals.md, in its section on allow rules and the gate. (`openai-codex-best-practices`)
- **List in the instructions which actions need the user's approval (certain messages, purchases), and still gate them in code.** In OpenAI's computer-use evals the written policy cut misaligned outcomes from 18.8% to 8.0% on GPT-5.6 Sol but only from 3.4% to 3.0% on the already careful GPT-6 Astra (system card, 2026-09-03). The code gate is agent-security, approvals.md. (`openai-gpt-6-astra-system-card`)
- **Give an agent that acts consent tiers for actions, not a content policy.** A content policy doesn't stop rm -rf or a committed secret: OpenHands sorts actions into OK without consent, only with explicit consent, and never. Codex's GPT-5.6 destructive-action checklist confirms the action is in the request, resolves exact targets read-only first, never targets home, root or a workspace root recursively, avoids unresolved variables and globs, prefers recoverable operations, and afterwards says "what was removed and whether it can be recovered". (`openhands-system-prompt-sections`, `codex-prompt-gpt-5-6-and-5-5`)
- **Tell a coding agent the workspace is shared and give its file boundaries as two lists.** Agents "clean up" diffs they didn't make and destroy someone's uncommitted work, so Codex never reverts changes it didn't make and Kilo says "Treat the workspace as shared with the user and other agents." mini-swe-agent lists "MODIFY: Regular source code files" against "DO NOT MODIFY: Tests, configuration files", which closes the path of passing a test by editing it. (`kilocode-per-provider-prompts`, `mini-swe-agent-prompts`)
- **In a high-stakes workflow, list exactly what the agent must not decide, fix the decision fields, and frame its output as input for a qualified human.** OpenAI's AML cookbook says "Set drafting_authorized to false and filing_decision ... to NOT_DETERMINED", and checks in code that the required analysis tools were called. (`openai-aml-agent-bedrock`)
- **Say exactly what each permission covers: drafting is not sending, and approval is not execution.** OpenAI's dots docs: "Asking your dot to draft replies doesn't give it permission to send them", and an action outside the stated who, what and when needs a new decision. Its SRE sample stops the agent reporting an approved action as done: "Approval records a decision; it does not execute a rollback." (`openai-dots-controls`, `openai-agents-api-sre-agent-app`)
- **Tell the agent that a denied or rejected call is a decision: stop and report, never retry it or reach the same goal another way.** Copilot's prompt: "A rejected call is a decision rather than a transient failure", and tools may disappear mid-conversation, so call only what exists now. Back it with controls, because GPT-6.1 Sol still routed around low-stakes restrictions in 23.5% of rollouts and GPT-6 Astra in 17.4% (OpenAI system card addendum, 2026-09-29). (`github-copilot-vscode-agent-prompts`, `openai-gpt-6-1-sol-system-card`)
- **Keep confirmation rules for irreversible actions in the instructions, because a user's mid-turn message can't take an action back.** On the GPT-6 family, steering "does not rewrite output already sent to your application, undo earlier actions, or cancel tools that have already started". How mid-turn messages are delivered is agent-harness, loop.md. (`openai-mid-turn-steering`)

## Ask or assume

- **For small, reversible steps, act and state the assumption in one line instead of asking.** Each question stalls the work until the user replies, so Anthropic's Fable 5.1 lines say "For reversible actions that follow from the original request, proceed without asking" and "state the assumption you made", and OpenAI's GPT-5.4 policy proceeds when "the next step is reversible and low-risk". Codex says "strongly prefer making reasonable assumptions and executing", and its GPT-6 prompt carries "relevant assumptions" in its short commentary updates. (`anthropic-prompting-fable-5-1`, `openai-using-gpt-5-4`, `codex-collaboration-modes`, `codex-prompt-gpt-6-family`)
- **Have the agent make routine judgment calls and check in only when readings lead to materially different work.** Agents either stall on questions they could answer or quietly narrow the task. Anthropic's Fable 5.1 line: "make routine judgment calls yourself, and check in only when different readings would lead to materially different work", doing everything that doesn't depend on the question first. GPT-5.6 guidance adds: name which important ambiguities should trigger a question, and Claude's consumer prompt (2026-04) wants "a reasonable attempt now, not to be interviewed first" for minor gaps. (`anthropic-prompting-fable-5-1`, `openai-using-gpt-5-6`, `willison-opus-4-7-system-prompt`)
- **Have the agent discover facts by exploring before it asks, and ask only about preferences and tradeoffs.** Agents ask users what the repo already answers, so Codex's plan mode requires an exploration pass first: "Eliminate unknowns in the prompt by discovering facts, not by asking the user." On loose multi-app tasks Opus 5.5 completed more automations when told "Before taking any action, explore broadly with tool calls", and Claude's consumer prompt "calls the tool to try and solve the ambiguity before asking the person". (`codex-collaboration-modes`, `anthropic-prompting-opus-5-5`, `willison-opus-4-7-system-prompt`)
- **Make every question change the plan, lock an assumption or choose a tradeoff, and offer likely answers.** Open questions invite vague replies, and listing options makes the model think through the branches. Roo Code asks for "2-4 suggested answers", and Codex's plan-mode question tool uses multiple choice without filler options. (`roo-code-system-prompt`, `codex-collaboration-modes`)
- **Default when unanswered, and put a clock only on optional questions.** OpenAI's data agent assumes the last seven or 30 days when no range is given, and Codex's plan mode, if unanswered, will "proceed with the recommended option and record it as an assumption". Codex's GPT-6 prompts wait 30 seconds for a simple question in one template and 60 in another, then proceed "with a stated assumption", while a required answer blocks dependent work: "Elapsed time is not an answer or approval." (`openai-data-agent`, `codex-collaboration-modes`, `codex-model-messages-gpt-6`, `codex-prompt-gpt-6-family`)
- **Set the ask threshold per tool and per task.** OpenAI's GPT-5 guide has checkout or payment ask on little uncertainty, search almost never, and deleting a file sooner than grep. For research the GPT-5.2 guide says not to ask at all: state the best reading and cover each plausible intent. (`openai-gpt-5-prompting-guide`, `openai-gpt-5-2-prompting-guide`)
- **When the task needs specific inputs, give the exact reply for when they are missing.** Without it models invent the missing fields. Google's example system instruction: "I'm sorry, but I do not have all of the necessary information". (`google-vertex-system-instructions-intro`)
- **When a task is too fuzzy to specify, have the agent interview you before it writes anything.** OpenAI: "Tell it to challenge your assumptions and turn the fuzzy idea into something concrete before writing code." (`openai-codex-best-practices`)
- **When requirements arrive over several turns, have the agent clarify before it commits to an answer.** Laban et al. (May 2025) traced the multi-turn drop (its size is in instructions.md, in the bullet on giving the whole spec in the first turn) to unreliability up 112%; temperature 0 didn't fix it, and repeating every earlier turn recovered only 15-20% (GPT-4o, GPT-4o-mini), while conversations that clarified first did better. The harness-side recap is agent-harness, context.md. (`laban-llms-lost-multi-turn`)
- **If the agent also ends its turn early or offers to wait, fix the stopping rules, not the autonomy text.** Asking too often and stopping too soon are separate failures. The fix for the second is progress-and-stopping.md "When to stop": name the stops you don't want, redefine when a turn may end, and pair persistence with a loop guard.

## Calling tools

- **Say in the prompt when to call each tool and what to do with the result, especially a tool the model should call on its own.** Defined but never mentioned, Claude Fable 5 rarely calls send_to_user, and GPT-5.1-Codex-Max didn't call Cursor's linter tool until told "After substantive edits, use the read_lints tool to check recently edited files for linter errors." Prompted triggering is also how you get a call on Claude Opus 5.5, Sonnet 5.5 and Fable 5.1, which reject forced tool choice (releasing a forced call is agent-harness, loop.md). (`anthropic-prompting-fable-5`, `cursor-codex-model-harness`, `anthropic-migration-opus-5-5`, `anthropic-migration-sonnet-5-5`, `anthropic-migration-fable-5-1`)
- **Restrict which tools are callable at a step with the API, and force a call only where the model supports it.** An API constraint is deterministic, where a call order hard-coded in the prompt is not. OpenAI lists the full toolkit and narrows the current subset with an allowed-tools setting (`tool_choice.allowed_tools`), and Amazon's Nova 2 guide forces calls with tool choice ("any" for one tool per turn, a named tool for structured output). On Claude Haiku 5.5 a forced call skips thinking, so use `auto` there. (`openai-using-gpt-5-2-doc`, `amazon-nova2-prompt-engineering-guide`, `anthropic-migration-haiku-5-5`)
- **Put what a tool does in its definition and the policy for using it in the prompt.** The policy says when the agent must call it, what to ask when a required field is missing ("ask for whichever detail is missing"), and how to confirm the result, because a guessed name in a booking is a wrong action, not a wrong answer. Writing the definitions themselves is agent-harness, tools.md. (`openai-gpt-5-1-prompting-guide`)
- **Mention only tools that are in the tool list, with the schema's names and parameters, and deny the tools and limits the model may bring from other harnesses.** xAI says tools named but not passed "will not work as well". Crush says "Never attempt 'apply_patch' or 'apply_diff' - they don't exist", lists "session limits" as a reason never to stop ("no such limits exist"), and Zed warns a tool seen earlier may since have been disabled. (`xai-voice-prompting-guide`, `crush-agent-prompts`, `zed-agent-system-prompts`)
- **In a read-only mode, remove the write tools, tell the model they are gone and that blocks are enforced, and say what to answer when asked to implement.** A model whose tools vanished silently still tries them. Crush says edit and bash "are physically absent from your environment" and points implementation requests to plan approval; Cline says blocked calls "return a tool error instead, so do not attempt them", calling the prompt "the first line of defense" and the hook "the hard backstop". (`crush-agent-prompts`, `cline-system-prompt-sdk`)
- **Ask for independent calls in one parallel batch, dependent calls in sequence, and no guessed parameters.** One call per turn multiplies latency, and dependent calls in parallel get placeholders. Anthropic's instruction ("make all of the independent tool calls in parallel") brings parallel calling to 100 percent by its own estimate, and Copilot, OpenCode, Kilo, Gemini CLI, Zed and Codex all carry the rule: "batch the reads you've already decided you need rather than searching speculatively". How results go back is agent-harness, tools.md. (`anthropic-prompting-best-practices`, `github-copilot-vscode-agent-prompts`, `openai-codex-prompting-guide`, `openai-computer-env`)
- **If the agent still makes one call per turn in long loops, append a one-sentence batching nudge after each user message instead of adding it to the system prompt.** A nudge next to the turn acts where the behavior happens, and as a turn-scoped system message it costs nothing afterwards. Anthropic's Fable 5.1 line: "First privately list what you need next; then request every item that doesn't depend on another's result in this one response." (`anthropic-migration-fable-5-1`, `anthropic-prompting-fable-5-1`)
- **When several actions can run in one step, put the ones that change state last and never try alternative paths in the same step.** browser-use skips any action queued after a page change, so the tail of a badly ordered batch never runs: "Do not try multiple different paths in one step." (`browser-use-system-prompts`)
- **To make an agent explore less, give explicit exploration criteria, an early-stop rule and an escape hatch; to make it explore more, add a persistence block.** A budget with no escape hatch can't be satisfied. OpenAI's GPT-5 guide stops when top hits converge on one area (70%, its rough mark), allows "an absolute maximum of 2 tool calls", and says "Bias strongly towards providing a correct answer as quickly as possible, even if it might not be fully correct." Reasoning effort as the other lever is models.md. (`openai-gpt-5-prompting-guide`)
- **Write the harness's tool error and truncation messages as the next instruction, specific to the cause.** A generic "format error" gets the same mistake again. mini-swe-agent says what was cut and asks the model to "Respond more concisely and finish with exactly one bash tool call", and tells it to use head, tail or sed on long output; returning errors as results is agent-harness, SKILL.md rule 4. (`anthropic-writing-tools-for-agents`, `mini-swe-agent-prompts`)
- **Before adding prompt constraints or specialized tools for a current frontier model, try removing them.** Vercel's agent (Claude Opus 4.5, Dec 2025) went from 274.8s to 77.4s, 37% fewer tokens and 4/5 to 5/5 queries solved with an empty instructions string and one shell tool, on a small sample and only because its files were good documentation. (`vercel-removed-80-percent-agent-tools`)
