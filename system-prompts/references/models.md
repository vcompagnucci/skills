# Models

What changes by model family, and how to move a prompt to a new model. Vendors rewrite this advice with every generation, so it goes stale first: a newer per-model guide replaces a bullet here under SKILL.md "Which source wins".

## Settings before wording

- **Read the per-model prompting page before general advice, and treat a technique that names a model as measured on that model only.** Vendor pages give opposite advice for different models, and general pages carry text written for older models with only the model name updated. OpenAI's general prompt-engineering page still tells gpt-6-astra coding prompts to "require thorough testing", while the GPT-6 guide and the 2026-09-11 Astra post say that causes over-testing. (`anthropic-prompting-best-practices`, `openai-prompt-engineering-guide`, `openai-using-gpt-6-prompting`, `openai-rethinking-skills-prompts-gpt-6-astra`)
- **Set reasoning effort explicitly on every request, record it with every result, and only then tune wording.** Effort governs every output token (thinking, tool calls, text), so lower effort also means fewer, terser tool calls, and wording tuned at one level misfires at another. Defaults differ by model and version: grok-4.7 defaults to high and grok-4.3 to low, Qwen3.8 to xhigh (2026-08), DeepSeek V4.1 to 75 of 100 (2026-10-17); Claude and GPT defaults are in their sections. (`anthropic-effort`, `xai-text-best-practices`, `qwen38-27b-model-card`, `deepseek-v4-1-flash-prompt-encoding`)
- **Before raising effort to fix a failure, check the prompt for a missing success criterion, dependency rule, tool-routing rule or verification loop.** A missing rule looks like a reasoning failure, and effort cuts missed edge cases but not wrong readings: on Terminal-Bench 3.0, Fable 5.1 went from 140 to 214 of 370 passed between low and max effort while "picked the wrong reading" failures rose from 25 to 47 (Anthropic internal runs, labels from a model judge, 2026-09-25). OpenAI's reasoning guide says "Treat `reasoning.effort` as a tuning knob, not the primary way to recover quality.", and its GPT-5.6 guide replaces generic "be brief", "be thorough" and "think step by step" lines with exactly those criteria, dependencies and stop conditions. (`openai-gpt-5-6-prompt-guidance`, `anthropic-spending-your-effort`, `openai-reasoning-models-doc`, `openai-upgrading-to-gpt-5-6-sol`)
- **Give a reasoning model the goal, the hard constraints, an output contract and what counts as done, and leave the intermediate steps to it.** It reasons internally, so "think step by step" costs time without accuracy: Wharton measured o3-mini +0.029, o4-mini +0.031 and Gemini 2.5 Flash -0.033 on GPQA Diamond, at 20-80% more time (2025-06-08). OpenAI compares a reasoning model to a senior co-worker you give a goal and a non-reasoning GPT model to a junior one who needs explicit instructions. Capitals or odd casing steer a reasoning model less, since its thinking filters casing cues in favor of meaning (Dillitzer et al., Qwen3 thinking models, 2026-08-04; emphasis in general is instructions.md). (`openai-reasoning-models-doc`, `openai-reasoning-best-practices`, `wharton-prompting-report-2-chain-of-thought`, `openai-prompt-engineering-guide`, `esslingen-attention-is-case-sensitive`)
- **With reasoning off or at the lowest setting, spell the logic out in the prompt.** The model no longer plans internally, so the GPT-5 and 5.1 guides put planning before each tool call and keep-going reminders back in, and the GPT-5.1 guide says asking it to think carefully about which functions to call helps at effort none. On non-reasoning models chain of thought helped on average (Gemini 2.0 Flash +0.135, Sonnet 3.5 +0.117) but broke questions they otherwise got right (-0.131 and -0.172 for Gemini Flash 2.0 and Pro 1.5) and added 35-600% time (Wharton, 2025-06-08). (`openai-support-agents-cost-quality`, `openai-gpt-5-1-prompting-guide`, `openai-reasoning-best-practices`, `wharton-prompting-report-2-chain-of-thought`)

## Migrating to a new model

- **Migrate in this order: read the target model's newest prompting guide, switch the model with the prompt identical, set reasoning effort and verbosity explicitly (pin the old effective effort; verbosity where the API has a setting), run representative evals, remove obsolete scaffolding, add only the smallest instruction that fixes a measured regression, and re-run after each change.** A wholesale rewrite hides whether a change came from the model, the effort, the prompt, the tools or the runtime, and OpenAI's guides from GPT-5.2 (2025-12-11) to GPT-5.6 keep the order from the switch on: "do not rewrite a working prompt stack wholesale". The guide comes first because Anthropic says "Read the one for your model first", and the GPT-5.2 guide says prompts migrate cleanly "especially when reasoning effort, verbosity, and scope constraints are preserved during the initial transition" (on GPT-5.6 the setting is `text.verbosity`). Test the old effort and one level lower; the eval loop itself is agent-evals, improve.md. (`openai-upgrading-to-gpt-5-6-sol`, `openai-gpt-5-6-prompt-guidance`, `openai-gpt-5-2-prompting-guide`, `anthropic-prompting-best-practices`, `openai-using-gpt-6-prompting`)
- **Try a lower effort and a smaller family member before adding prompt text.** Text that compensated for the old model is often unnecessary on the next: GPT-5.6 Sol at low beat GPT-5.5 at high on Agents' Last Exam with the harness held constant, and GPT-5.6 Luna at xhigh scored 84.04% on BrowseComp for $1.33 against 84.36% for $33.27 from GPT-5.5 at xhigh (OpenAI, 2026-08-13). Harness settings moved scores more than prompt changes (retained reasoning is agent-harness, context.md). (`openai-builders-guide-gpt-5-6`, `openai-gpt-5-6-prompt-guidance`)
- **Treat an upgrade as a prompt migration: test the new model's native behaviors and delete the instructions that now fight them.** Stronger models need less scaffolding: Anthropic removed over 80% of Claude Code's system prompt for Opus 5 and Fable 5 with no measurable loss on coding evals (2026-07-24), under the line "less scaffolding, more curation", with every-session instructions kept in the system prompt, instruction files or skills (`anthropic-new-rules-context-engineering-claude-5`). Cognition rebuilt Devin around Sonnet 4.5's self-written notes, parallel calls and context awareness for 2x speed and +12% on Junior Developer Evals (2025-09-29), though the model's notes dropped task details, so prompting still mattered. (`openai-rethinking-skills-prompts-gpt-6-astra`, `anthropic-prompt-engineering-best-practices-2026-blog`, `cognition-rebuilding-devin-sonnet-4-5`)
- **Delete old persistence and thoroughness shouting before you add anything.** Wording written for under-eager models makes agentic ones overreach: unrelated edits, extra abstractions, going on after the task is done. Kilo's GPT-4-era prompt says "You MUST iterate and keep going until the problem is solved" (1,904 words, all caps) where its GPT-5.5 prompt says "Prefer the smallest correct fix over broad rewrites" (1,309 calm words, word counts of the published files, 2026-09-21), and at GPT-5 (2025-08) Cursor's "Be THOROUGH" context-gathering block made the model search repeatedly on small tasks until softened. (`kilocode-per-provider-prompts`, `openai-rethinking-skills-prompts-gpt-6-astra`, `openai-gpt-5-prompting-guide`)
- **Rewrite "ask first" language written for an overreaching model, and grant explicit permission for known-safe workflows.** Those boundaries make a stronger model stop too early. Name the safe case, such as disposable local fixtures with no production access where the agent may run, fix and rerun without asking; Codex's default prompt says "Do not introduce unsolicited warnings, disclaimers, approval flows, or safety/compliance checklists due to hypothetical risk." (`openai-rethinking-skills-prompts-gpt-6-astra`, `openai-repo-update-0929`)
- **Reread every "always" and "never" after a migration and assume each will be applied literally, including in cases you didn't intend.** Stronger instruction following turns guidance into law: OpenAI saw "Always say X when Y" go from vague guidance on preview realtime models to literal adherence on gpt-realtime, and wrote "Assume instructions will be followed" (2025-09-12). Cursor finds OpenAI models more literal than Claude, which tolerates imprecise instructions, so it tunes prompts per provider and model version (2026-04-30), and it found GPT-5.6 Sol so sensitive to literal and emphasized wording that prompts tuned for other models sent it into runaway spirals (2026-07-20). (`openai-realtime-api-developer-notes`, `cursor-continually-improving-agent-harness`, `cursor-agent-swarm-model-economics`)
- **To move a workflow to a cheaper model, run the same prompt on both, diff the findings, and prompt the cheaper model against its recurring miss.** The gap is often one pattern a prompt can correct, and the next release can make the correction obsolete, so revisit it at every release. GPT-6.1 Sol Ultra produced 92% of GPT-6 Astra Ultra's findings at 14% of the API cost ($15.12 vs $109.06), and most misses were constant feature flags used as dependencies of other flags (OpenAI, 2026-10-14). (`openai-maintaining-software-gpt-6`)
- **When a model hedges or wraps up early as its context fills, saying the task seems too big, fix the prompt, and put a reminder that it has room left at both the start and the end.** Cursor saw this context anxiety in one model and fixed it with prompt changes (2026-04-30). Cognition found the start alone wasn't enough for Sonnet 4.5, and its harness fix (the 1M beta capped at 200k) worked better than prompting (2025-09-29). (`cursor-continually-improving-agent-harness`, `cognition-rebuilding-devin-sonnet-4-5`)

## Running several model families

- **Start from your family's column, because the same line helps one family and hurts another.** Harness teams converged independently: Claude 5 gets short prompts with scope and environment facts and no verification or task-tracking rules; GPT-5.x/6 gets long prompts with explicit autonomy, persistence, progress commentary and bounded exploration; Gemini is held back from proactivity, extra reads and narrated tool calls; Kimi gets anti-loop caps; small local models are told to act rather than explain. Copilot's GPT-6 prompt block runs 5,849 words against 1,144 for Opus 5 (word counts of the published source, markup included; 2026-09 and 2026-07). (`github-copilot-vscode-agent-prompts`)
- **Fork a full per-model prompt only where you measured a difference; otherwise keep one base and append a short per-family suffix.** Full forks each carry duplicate tool and mode sections that drift. Cline deleted its 12 per-model variants (2026-06-24) for one act prompt, 599 words in the published file (2026-09-15), while Copilot and Codex keep forks; OpenHands appends a short <IMPORTANT> block per family, telling Claude to "fail fast instead of masking misconfigurations" and GPT-5 to send a preamble "using 8 - 12 words" (2026-10-02). (`cline-model-variants-2026-05`, `cline-system-prompt-sdk`, `openhands-system-prompt-sections`)
- **Key each suffix by exact model id, append it last, and copy its text verbatim from the vendor's guide.** Keying by provider prefix leaks one model's corrections onto its siblings, and pasted vendor text stays diffable when the guide changes. LangChain's Deep Agents keeps empty Haiku 4.5 and Sonnet 4.6 profiles as an "audit anchor" recording that the guide had nothing for them; Aider instead names the habit, with `lazy_prompt` for the GPT-4 family and `overeager_prompt` for Claude 3.7 and Opus 4.6-4.7, Gemini 2.5 and 3, and GPT-5 through 5.5 ("Do what they ask, but no more."). (`langchain-deepagents-prompts`, `aider-coder-prompts`)
- **Resolve more than the system prompt per model.** Differences show up in the other pieces too, and a registry that swaps only the system prompt leaves them tuned for the wrong model. Copilot's registry resolves 6 pieces per model (system prompt, reminders, tool-reference hint, identity rules, safety rules, the tag around the user's request) by explicit matcher, then family prefix, then fallback, so xAI models get `user_query` where the default is `userRequest` (2026-08-30). (`github-copilot-vscode-agent-prompts`)
- **For a model fine-tuned on your harness, cut the prompt down to identity, mode, grounding and the hard constraints.** It already knows the action format and rules, and repeating them costs tokens and can conflict with what it learned. Browser-use's prompt for its own model is 176 words (2026-03-18) against 3,736 for general models (2026-05-23), and Codex's prompts for models trained on its harness run 68 to 80 lines against 275 to 331 (word and line counts of the published files), with no AGENTS.md spec, planning examples or preamble rules. (`browser-use-system-prompts`, `openai-repo-system-prompts`)

## Claude

- **On the Claude 5 generation, write short prompts that state scope and environment facts, without verification passes, task-tracking rules or worked examples.** Rules written to push older models make this one do too much of each, so remove them rather than adding counter-rules. Copilot's Opus 5 prompt says "Build what was asked, at the size it was asked" (2026-07-24), and Anthropic's own list turns examples into interface design, everything up front into loading when needed, repeated instructions into one tool description, and deletes "think carefully" lines. (`github-copilot-vscode-agent-prompts`, `anthropic-new-rules-context-engineering-claude-5`)
- **On Fable 5.1, Fable 5, Opus 5.5, Opus 5 and Sonnet 5.5, let built-in thinking carry the reasoning and read the summarized thinking (`thinking.display`).** A prompt that pushes reasoning into the response, in <thinking> tags for instance, can be declined with the `reasoning_extraction` refusal category, which server-side fallback doesn't retry. A short explanation of the answer is still fine. (`anthropic-prompting-best-practices`, `anthropic-new-rules-context-engineering-claude-5`)
- **Set Claude's effort explicitly and re-sweep it at every model change.** A prompt validated at one default runs a level higher or lower after a migration: Opus 5.5 and Haiku 5.5 default to medium and other current models to high, so Opus 5.5 with effort omitted runs one level lower than Opus 5 did, and Sonnet 5.5's levels are recalibrated (docs, read 2026-10-22). (`anthropic-effort`)
- **To get less thinking, lower effort; write no "don't think" rules.** On Opus 5 with thinking disabled such rules increase leaked tool calls and <thinking> tags in visible text, and a leaked tool call never runs. A harness may append "Please think hard before responding." on planning steps and "Answer directly without deliberating." on routine ones, but the discouraging phrase doesn't reliably cut thinking on Haiku 5.5 (2026-10-07) or Sonnet 5.5 (2026-09-28), where lowering effort per message is the lever. (`anthropic-thinking-troubleshooting`, `anthropic-thinking-steering`, `anthropic-building-with-claude-sonnet-5-5`)
- **Exception on Sonnet 5.5: for JSON answers that need a few steps of working out, end the system prompt with "Think the problem through before you answer." under adaptive thinking.** With structured outputs the model can reason only in thinking, and at low or medium effort it often skips thinking and loses accuracy. At high effort the line brings accuracy close to xhigh for a modest token increase, with smaller gains at low and medium, and it does nothing under `between_tools` (2026-09-28). (`anthropic-prompting-sonnet-5-5`)
- **On Sonnet 5.5 and Haiku 5.5 at low effort, require a real check before code is reported done.** At low effort they report changes done without exercising them. Anthropic's paragraph says "When you change code that can be run, built, or type-checked, run a real check that exercises the change before reporting it done" and asks which check was skipped and why; skipped checks became rare on Sonnet 5.5 with no measurable quality change (2026-09-28), and Haiku 5.5 checked more often and improved at more tokens (2026-10-07). (`anthropic-prompting-sonnet-5-5`, `anthropic-prompting-haiku-5-5`)
- **On Opus 5, delete instructions that ask for verification or re-checks rather than rewriting them.** They compound with the model's own self-checking: removing "include a final verification step", "use a subagent to verify" and "double-check your answer" cut wasted tokens with no loss in quality (2026-07-24). It is the opposite of the low-effort Sonnet 5.5 rule because the line belongs to the model and effort, not the repo. (`anthropic-prompting-opus-5`)
- **Moving to Sonnet 5.5, remove refusal steering, tool-call retry shims and "do not be lazy", recount prompt length, then re-run evals before tuning anything else.** Anthropic lists these workarounds for Sonnet 5 prompts moving to Sonnet 5.5 only, so in any other migration treat them as the kinds of lines to look for, not a measured result; its general migration list likewise says to reduce anti-laziness prompting (Claude 4.6 models). Ritual instructions that patched older models cost money and accuracy on newer ones (the audit that finds them, with its numbers, is in iterate.md). Sonnet 5.5's tokenizer turns the same text into 30% more tokens than Sonnet 4.6, Sonnet 4.5 or Haiku 4.5 (Anthropic's approximate figure, depending on the content), so old length budgets and cost estimates run low (docs, read 2026-10-22). (`anthropic-building-with-claude-sonnet-5-5`, `anthropic-prompting-best-practices`, `anthropic-reducing-cost-claude-platform`, `anthropic-migration-sonnet-5-5`)
- **Get tone and variety from instructions, since temperature, top_p and top_k return a 400 error on Sonnet 5 and later and on Haiku 5.5.** Prompts that relied on sampling for variety lose it; the Haiku 5.5 guide says to "use prompting to guide the model's behavior instead" (2026-10-07). Anthropic's Sonnet 5 example asks the model to "propose 4 distinct visual directions tailored to this brief" first and implement only the one the user picks (docs, read 2026-10-22). (`anthropic-prompting-sonnet-5`, `anthropic-migration-haiku-5-5`)
- **Give Haiku 5.5 the same complete prompt you would give Sonnet, then check that its guidance is sufficient.** Anthropic doesn't write a shorter or more imperative prompt for its smallest model: Haiku 5.5's app prompt has Sonnet 5.5's sections and voice plus a paragraph on memory, 4,255 words against 3,195 (word counts of the published 2026-10-07 prompts). (`anthropic-system-prompt-haiku-5-5`, `anthropic-system-prompt-sonnet-5-5`)
- **When you narrow Sonnet 5's scope ("do exactly what was asked"), add a rule to preserve existing public interfaces.** Copilot found the bare scope limit cut Sonnet 5's token cost but made it skip needed backwards-compatibility shims, which looked like adjacent work. Its line: "always preserve existing public interfaces: never remove or change the signature of module-level functions, exported names, or class methods" (2026-08-04). (`github-copilot-vscode-agent-prompts`)

## GPT

- **For a support agent on GPT, start from OpenAI's effort table: customer support and chat assistants at `low`, voice and classification at `none`, `xhigh` only when evals show a clear benefit.** Effort values are model-dependent, and a copied setting can fail with HTTP 400 or spend latency a support chat doesn't need: GPT-6 Astra rejects `none`, gpt-5.5 defaults to `medium`, and GPT-6.1 Sol rejects `none` and `minimal` and defaults to `medium` (read 2026-10-22). GPT-6.1 Sol launched with no prompting guide of its own (2026-09-29), so use the Astra guidance, compare against Astra on your evals, and test low effort first, where responses with a factual error fell from 11.4% on GPT-6 Sol to 7.7% (deliberately hard prompts, OpenAI). (`openai-reasoning-models-doc`, `openai-gpt-6-1-sol-launch`)
- **On GPT-6 Astra, add an explicit initiative block (infer intent from context, bias to action, persist until the goal is done, treat "can you...", "I want to...", "help me..." as instructions to do the work), and replace blanket "ask when unsure" rules with the list of decisions that count as consequential in your product.** OpenAI's GPT-6 prompting docs (read 2026-10-22) and the Astra skills post (2026-09-11) say Astra is more likely than GPT-5.6 Sol to ask and stop where the user expected it to continue, which supersedes the launch post's "It uses context to fill in routine gaps" (2026-09-03); its trained behavior is to proceed "with sensible assumptions where appropriate" and wait on consequential decisions. The guide says "Do not stop at acknowledging capability", proposing a plan, or offering to continue. In OpenAI's impossible-task scope eval, GPT-5.6 Sol exceeded the authorized target 48% of the time without safeguards against 0% for Astra (2026-09-03). (`openai-using-gpt-6-prompting`, `openai-gpt-6-astra-launch`)
- **Prompt against the new model's shifted defaults, as Codex's default prompt did for GPT-6.1 Sol (2026-09-29).** The Astra guide names the shifts (asks where earlier models assumed, delegates less, tests too broadly, over-formats), and Codex shipped its counters almost verbatim, adding "Avoid unnecessary apologies and self-blame" for when the user merely asks a follow-up or corrects their own message. (`openai-repo-system-prompts`, `openai-repo-update-0929`)
- **Tie verification instructions to the model: keep them for GPT-5.x and smaller models, calibrate them for GPT-6 Astra.** Astra tests on its own, so the old "always run the tests" reminder produces broader tests than small tasks need. The GPT-5.5 docs (read 2026-10-22) say "After making changes, run the most relevant validation available"; the Astra guidance says "Do not write tests for reversible, low-impact changes that mirror the implementation" and widens checks only when failures justify it, and Codex's GPT-6.1 Sol prompt drops the "that mirror" condition: "Do not write tests for reversible, low-impact changes or that mirror the implementation." (`openai-using-gpt-5-5`, `openai-using-gpt-6-prompting`, `openai-repo-update-0929`)
- **Retune the prompt per tier when you move it to the GPT-6 family.** Codex ships gpt-6-astra 3,314 words, gpt-6.1-sol 3,366, gpt-6-sol 2,949 and gpt-6-luna 2,790, while all three GPT-5.6 tiers share one 2,826-word prompt (measured 2026-10-22, models.json changed 2026-10-06). The smallest tier gets blunter rules: luna drops the "can you... = do it" paragraph and says "Do not add or run tests unless the user asks you to test or verify implementation." (`codex-prompt-gpt-6-family`, `codex-prompt-gpt-5-6-and-5-5`)
- **On GPT-6-class models, replace long procedural prompts with a short goal plus explicit safeguards: what to preserve, what never to touch, output granularity, and an anti-stopping line when you want full coverage.** OpenAI's Core Experimentation team merged 1,400+ PRs deleting 800k+ lines from variations of a one-paragraph prompt (5 engineers, 2 weeks part-time, 2026-10), including "Reconcile every production-referenced constant; do not stop after producing a conservative shortlist." GPT-5.6 Sol removed dead code only when given an area and validation criteria, while Astra took a one-line request and gathered its own evidence from past PRs, chat threads, trackers and production profiles. (`openai-maintaining-software-gpt-6`)
- **Write an Astra task as the outcome plus the invariants that must hold, and a bug as the symptom plus the invariant it breaks.** OpenAI's case studies got a full scene from one outcome-only prompt while Astra checked its own previews; the human's levers were a plan gate on big changes, a backup before rebuilding, and a stop condition such as "Iterate until the house, furniture, and garden are detailed and the geometry is correct." (2026-09-04). (`openai-architectural-visualization-astra`)
- **Pick the GPT-6 model and effort as one choice, starting where OpenAI does.** Codex starts GPT-6 Sol at medium, GPT-6 Luna at high and GPT-6 Astra at low, then adjusts per task (low for scoped tasks, medium or high for debugging, extra high for long agentic work). OpenAI's ladder runs Luna Low, Luna Extra high, GPT-6.1 Sol Medium, Sol Extra high, Astra Low, Astra Medium, Astra Extra high, with Astra Low for "Concise writing and content adaptation that preserve facts and nuance"; test the adjacent rungs before adding prompt text to make a cheaper rung work (read 2026-10-22). (`openai-codex-best-practices`, `openai-model-selection-gpt-6`)
- **Change GPT-6 effort mid-conversation with a `configuration_update` input item before the next user message, and keep "think harder now" out of the prompt.** It changes effort only and keeps a runtime knob out of the instructions: `{"type": "configuration_update", "reasoning": {"effort": "high"}}`. Why it keeps the cache is agent-harness, context.md. (`openai-reasoning-models-doc`)
- **Bound exploration with a concrete exit test when GPT-5.x or 6 over-explores in your harness.** Copilot's GPT-5.5, 5.6 and 6 prompts say "Before the first edit, gather only enough nearby evidence to state one falsifiable local hypothesis" and one cheap check that could disconfirm it, treat further searching as drift, and validate right after the first edit (2026-09-19). Codex's own GPT-6 prompt has no such routine, so two harnesses prompt the same model differently. (`github-copilot-vscode-agent-prompts`)
- **Re-audit at each GPT generation, because each one adds rules for failures seen and drops what it no longer needs.** In Codex, the GPT-5.1 default added "Autonomy and Persistence" ("do not stop at analysis or partial fixes") and strict plan-status rules, and 5.2 deleted the whole user-updates spec and added "Parallelize tool calls whenever possible". On the codex line, 5.1-codex-max added a frontend section against "AI slop", and the 5.2-codex template added "Don't use emojis." and "You struggle using the git interactive console." (`openai-repo-system-prompts`)
- **On GPT-5.5 and later, drop the "Today's date is..." line unless the product needs a non-UTC or simulated date.** OpenAI's docs say "The model is already aware of the current UTC date.", and a line that changes daily costs tokens and breaks the static prefix (docs, read 2026-10-22). (`openai-using-gpt-5-5`)
- **For gpt-5.4-mini and nano, write a longer, more structured prompt than for the flagship, and route ambiguous or planning-heavy work to a bigger model.** Mini is more literal and makes fewer assumptions, and nano should get only narrow, closed-output tasks. OpenAI's default pattern is task, critical rule, exact step order, edge cases or clarification behavior, output format, one correct example, and it says not to rely on "you MUST" alone but to use "numbered steps, decision rules, and explicit action definitions." (`openai-using-gpt-5-4`)
- **For frontend and simple design work on GPT-5.4, start at low effort and give the design system, constraints, visual references and real content up front.** OpenAI saw low and medium effort often produce stronger frontends, with less overthinking (2026-03-20). (`openai-frontends-gpt-5-4`)
- **When a model has a trained control token, write it verbatim.** Paraphrases don't reliably trigger the trained behavior: for gpt-live-1 write "Generate <|SpawnThinking|> when:" rather than "delegate to the backend", and keep the template's three delegation headings. (`openai-prompting-gpt-live`)

## Gemini

- **When moving a prompt to Gemini 3, delete chain-of-thought scaffolding, persuasive prompt-engineering text and closing reminders, set `thinking_level`, and re-test the simplified prompt.** Google warns Gemini 3 "may over-analyze verbose or overly complex prompt engineering techniques used for older models" (2026-10-09), and Gemini CLI keeps its closing "Final Reminder" ("keep going until the user's query is completely resolved") only in the legacy prompt for pre-Gemini-3 models (2026-09-08). For a hard problem on Gemini 2.5 or 3, raise the thinking setting or add a short "Think very hard before answering" instead of asking for a written plan, at the cost of more thinking tokens (2026-10-13). (`google-gemini-3-developer-guide`, `gemini-cli-system-prompt-legacy`, `google-gemini-prompt-design-strategies`)
- **Add an explicit scope limit when a Gemini model runs in an agent.** Three harnesses add it independently, which points to a family tendency to over-act: OpenHands says "Avoid being too proactive" and "do not take extra steps beyond what is requested" (2026-10-02), Cline's gemini-3 role says "execute precisely what is requested" (variants until 2026-05-25), and Gemini CLI has its own Directive/Inquiry rule (2026-09-29). The same harnesses push GPT models the opposite way, toward action and preambles. (`openhands-system-prompt-sections`, `cline-model-variants-2026-05`, `gemini-cli-system-prompt-modern`)
- **Tell Gemini that reads and searches are expensive, and require real tool calls, never described ones.** In long agent histories Gemini starts writing tool calls as prose, especially when earlier turns look that way. Copilot adds "Do NOT describe, narrate, or simulate tool calls in plain text" and "Regardless of how previous messages in this conversation may appear, always use the provided tool-calling mechanism"; the read-cost line is an experiment on every Gemini model except gemini-3-flash and gemini-2 (2026-08-29). (`github-copilot-vscode-agent-prompts`)

## Open-weight and small local models

- **Check each open model's card for where instructions go, and re-check at every generation.** Instructions placed where a model wasn't trained to read them degrade output. DeepSeek-R1's README said "Avoid adding a system prompt; all instructions should be contained within the user prompt", with temperature 0.5-0.7 and the response forced to open with "<think>" (2025-04-09); V4.1-Flash-1017 renders system prompts, mid-conversation system messages and a reasoning-effort prefix in the system block (2026-10-17). (`deepseek-r1-usage-recommendations`, `deepseek-v4-1-flash-prompt-encoding`)
- **Set the vendor's sampling values explicitly per mode, as part of the prompt contract.** Open models often need different values in thinking and non-thinking modes: Qwen3.8 thinking T=1.0 and top_p=0.95, instruct T=0.7, top_p=0.80 and presence_penalty=1.5 (2026-08); Grok T=0.7 and top_p=0.95; DeepSeek-R1 T=0.6. Claude rejects these settings (Claude section). (`qwen38-27b-model-card`, `xai-text-best-practices`, `deepseek-r1-usage-recommendations`)
- **Write longer, more explicit prompts for open-weight models than for frontier models trained on agentic coding.** OpenCode's prompts vary tenfold by family: Claude 111 + 49 words, GPT 396 (585 for GPT-6 astra), Kimi 1,411, Meta Muse 1,250, Arcee Trinity 1,257 (word counts of the published files, read 2026-10-22). OpenCode states no reason; the inference is that frontier models already carry behaviors open ones need spelled out, and frontier small tiers (Haiku 5.5, gpt-5.4-mini above) also get complete prompts, while Cline's telegraphic "xs" variant was deleted with the rest. (`opencode-per-provider-prompts`, `cline-model-variants-2026-05`)
- **For small local models, tell them to act rather than explain, give a plain-text tool syntax instead of JSON tool calling, and include one complete worked turn.** They describe what to do instead of doing it and handle native tool schemas poorly. goose's tiny-model prompt runs a shell command from a line starting with "$" (its worked turn answers "how many files are in /tmp?" with "Let me check." and `$ ls -1 /tmp | wc -l`, 2026-10-07); Continue's fallback uses fenced tool blocks under 9 rules such as "The tool code block MUST be the last thing in your response", and its parser accepts common variations because weak models still deviate (2026-03-26). (`goose-system-prompts`, `continue-system-messages`)
- **Cap identical repeated calls with a number on families that loop, such as Kimi.** Some families repeat the same call when a result disappoints them, and a count is checkable where "avoid loops" isn't. Copilot's Kimi prompt carries that count (2026-07-30); the line itself is quoted in instructions.md, in the bullet on putting a number on every limit. (`github-copilot-vscode-agent-prompts`)
