# Language

Which language the agent answers in, when it switches, which register it uses, and how quality changes per language, in text and on voice. Detecting the user's language in code and passing it as a field is agent-harness, context.md.

## Name the reply language

- **Name the reply language and the exact condition for switching, never a bare "respond in the user's language".** Blanket language lines cause unwanted switching, and OpenAI lists them among the GPT-5.6 anti-patterns; left alone, Claude infers the language from the conversation, which drifts. Anthropic's example: "Always respond in French, regardless of the language the user writes in." (`openai-upgrading-to-gpt-5-6-sol`, `openai-gpt-5-6-prompt-guidance`, `anthropic-multilingual-support`)
- **When you know the language before the conversation (an account setting, the dialed number, a menu choice), put it in the prompt as a variable, or route to a single-language agent per language.** Anthropic says to interpolate a runtime choice instead of letting the model infer it from the message. Retell found multilingual speech recognition less accurate per language, with close languages such as Cantonese and Mandarin confused regardless of provider, so mirror only when you can't know in advance. (`anthropic-multilingual-support`, `retell-multilingual-agent`)
- **When following the user's language is the product requirement, write the switch rule out: what triggers a switch, what doesn't, and no mixing.** Without any line the output language follows the system prompt unpredictably (Google). Bare mirror lines such as Google's "Respond in the same language as the query." (2026-10-21) or AWS's "Always reply in the language spoken. DO NOT mix with English." lose to OpenAI's newer condition: "Only switch languages if the user explicitly asks or provides a substantive utterance in another language." (`google-vertex-use-system-instructions`, `aws-nova-sonic-2-voice-prompts`, `openai-prompting-realtime-models`)
- **Keep the language instruction on its own line, add one example reply in the target language, and keep temperature low.** Cohere's Language Confusion Benchmark (15 languages, 2024-06) found even the best models drifting: line-level pass rates in the low 90s% for the best, Llama 2/3 in the 30s%, and Command R at 69% with the instruction folded into other text, 85% isolated, 80.6% with one-shot. At temperature 1, Command R's word-level pass rate fell to 83.5% on average (72.0% Japanese, 69.5% Chinese), and a demonstration in a different language from the reply hurt. (`cohere-language-confusion-benchmark`)

## Prompt language and per-language quality

- **Write the prompt in whichever language you can write natively, and add a reply-language line when the prompt is in English.** Enomoto et al. (NAACL 2025) found no overwhelming advantage for English instructions once translation artifacts were removed, and more wrong-language replies with them: 9.94/8.23/7.08% against 7.13/6.43/6.22% on lexical simplification and 4.33/4.36/2.98% against 2.16/1.47/1.76% on reading comprehension (llama3-i 8B, qwen2-i 7B, mistral-nemo-i 12B). Target-language instructions gave more "There is no information" non-answers, and Zendesk says procedures perform the same in all major languages (2026-08-05). (`enomoto-english-vs-target-language-instructions`, `zendesk-generative-procedures-best-practices`)
- **Keep a working prompt or procedure in the language it was tested in instead of machine-translating it into one language.** Translation loses meaning: in Enomoto et al. a translated instruction dropped a quantifier and changed the task, and English instructions translated into Japanese lost their numerical information and scored lower on lexical simplification. (`enomoto-english-vs-target-language-instructions`, `zendesk-generative-procedures-best-practices`)
- **Test every language your users write in before launch, and route low-resource languages to the larger model or a human.** Quality stays near English in major languages and drops steeply in low-resource ones, more on small models. Anthropic's table, English=100%: Claude Sonnet 4.5 Spanish 98.2%, Japanese 96.8%, Hindi 96.7%, Swahili 91.1%, Yoruba 79.7%; Claude Haiku 4.5 Spanish 96.4%, Swahili 78.3%, Yoruba 52.7% (live page read 2026-10-22, no Claude 5 figures published). (`anthropic-multilingual-support`)

## Translation, register and sources

- **For translation, name the source language, the target language and the output shape.** Explicit languages are more reliable than automatic detection. Anthropic's example: "Translate the user's message from German to Korean. Respond with only the translation." For natural replies, ask for idiomatic speech as a native speaker would use it, and keep user text in its native script, since transliterated input degrades results. (`anthropic-multilingual-support`)
- **In languages with a formal and an informal "you" (tu/vous, du/Sie, tú/usted), choose the register and state it.** Otherwise the agent mirrors whatever the customer uses, and the brand's register changes from one conversation to the next (Intercom, 2026-05-14). (`intercom-fin-pronoun-formality`)
- **In a multilingual support agent, keep the reply language separate from the source language.** Intercom's order (2026-08-24): content in the customer's language first, then default-language content translated into the customer's language, and no other language as fallback. An agent grounded only on English docs with no reply-language rule risks answering in English (an inference, not Intercom's claim). (`intercom-fin-multilingual-setup`)

## Language on a voice channel

- **On a voice agent, set the output language and the switching condition, and set accent separately; never write "mirror the user", "respond naturally in the user's language" or "sound local".** Broad rules make the model switch on an accent, filler words, backchannels or a single foreign word (OpenAI, gpt-realtime-2). OpenAI's single-language version: "The conversation will be only in English." followed by "Do not respond in any other language even if the user asks." (`openai-prompting-realtime-models`)
- **To pin one language on a realtime audio model, state it in strong terms, and set the language whenever you set an accent.** Gemini Live detects and mirrors the spoken language by default, and an accent instruction alone doesn't fix the language. Google's line: "RESPOND IN {OUTPUT_LANGUAGE}. YOU MUST RESPOND UNMISTAKABLY IN {OUTPUT_LANGUAGE}." (`google-gemini-live-api-best-practices`)
- **Before the call starts, set a voice for every language the agent may switch to, and spell each name one way for the whole call.** Twilio (2026-08-19): a switch with no voice set falls back to that language's default voice, so an English male voice can turn into a Spanish female one, and voice settings can't change mid-session. (`twilio-conversationrelay-best-practices`)
- **In gendered languages (Spanish, Portuguese, French, Italian, Hindi, Russian, Polish), state the assistant's gender in the identity line to match the selected voice.** Verbs and adjectives agree with the speaker, so a Portuguese "I am tired" in the masculine ("cansado", not "cansada") can contradict the female voice the caller hears; Hindi always needs it (AWS, Nova 2 Sonic). AWS's example: "You are a warm, professional, and helpful female AI assistant." (`aws-nova-sonic-2-voice-prompts`)
